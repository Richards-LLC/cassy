### Fixed — Focused proof for data, migration and fixture changes

- **Package proof names the specs that read the change, and accepts their runs** — Was: a delivery that renamed a Prisma migration, edited a JSON catalogue or edited a test fixture widened to a package proof. The park then printed `worker-check -- jest <file>.sql|.json`, which the capped runner always refuses. Passing runs of the specs that read those files did not count. Now: the gate finds the test files in that package that read a changed input through a relative path: the JSON file itself, the fixture module, or the migrations directory. It prints one runnable `worker-check` command for exactly those specs and accepts their whole-file passes at the delivered tip as the package proof. When no spec reads the input that way, the gate names a changed JavaScript file to run, or describes the run it needs, never a command that cannot run.
