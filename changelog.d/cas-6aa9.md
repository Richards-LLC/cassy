### Fixed — Factory

- **Capped JavaScript checks parse TypeScript type imports, and name the spot when they can't parse** — Was: a valid TypeScript test using `importOriginal<typeof import('#imports')>()`, the usual Vitest partial-mock pattern, made the capped runner refuse the whole file with "JavaScript parse error" and no location. Prisma's generic tagged template, `prisma.$queryRaw<Row[]>` followed by a template literal, failed the same way. Both are gaps in tree-sitter-typescript 0.23.2, the newest grammar release, and the delivery could not park. Now: those type arguments are blanked before parsing, so line numbers, offsets and test titles are unchanged. A parse error in the unchanged base revision, or in a non-test source file, no longer blocks the delivery. Any remaining parse error in the tip names its `path:line:column` and the text it could not read.
