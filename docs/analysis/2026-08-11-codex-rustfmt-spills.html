Investigation · 11 August 2026

Codex worker rustfmt spills

Root cause, ruled-out hypotheses, and the guard-versus-normalization decision.

Verdict

High confidence: the spills are caused by model-issued formatter commands, not Codex auto-save or a hidden tool default. Mutating cargo fmt selects Cargo targets; direct rustfmt follows child modules unless skip_children=true is explicit.

Trigger 1: Cargo scope

cargo fmt --all explicitly rewrote the workspace and immediately exposed broad churn.

Trigger 2: module traversal

Direct rustfmt on mod.rs and lib.rs recursively formatted children not named on the command line.

Reasoning chain

The 2026-08-11 chronology is a controlled A/B sequence. The worker ran Cargo formatting, observed churn, and restored it. It then ran direct rustfmt on apparent task files, observed a different child-module spill, and restored that too. The clean boundary between experiments excludes residue from the first command.

Rustfmt traversal also reconciles cas-bb1c: “targeted by path” did not mean “limited to that path” because one target was the crate's lib.rs.

Ruled out: auto-save

Each confirmed spill starts at an explicit shell call; no formatter write precedes it.

Ruled out: check mode

Retained check invocations are non-mutating; confirmed writes follow mutating commands.

Ruled out: concurrent writer

The restore → rustfmt → immediate status sequence attributes the warm second spill to one command.

What would falsify this

A clean worktree gaining formatting-only changes before any formatter process starts, direct rustfmt with skip_children=true changing an unlisted child, or process-level evidence of another writer in the one-second windows would overturn the conclusion.

Next actions

Implement now Worker guard and Codex configuration

Route unified exec through cas hook PreToolUse. Deny mutating worker cargo fmt and direct mutating rustfmt without explicit skip_children=true. Preserve checks, stdout-only output, and supervisor authority. Fresh cas init/update configuration now converges both CAS pre- and post-tool hooks while preserving custom groups. The official Codex Hooks documentation confirms that unified exec is exposed as Bash and nested code-mode calls honor hook decisions.

Operator decision One-time normalization plus CI gate

An isolated cargo fmt --all normalization followed immediately by a CI cargo fmt --all -- --check gate would remove chronic baseline drift, at the cost of a large blame-noise commit. Do not run it from a worker. Normalization reduces future noise but does not replace scope enforcement.
