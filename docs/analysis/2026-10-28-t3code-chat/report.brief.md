# Brief: T3 Code chat rendering study

## Single idea

Commander should make message content easier to inspect with labeled code, usable tables and typed work details, while retaining its existing Glass conversation model.

## Contract

Research × practitioner. Thesis, sources, evidence, counter-evidence, confidence, implications and provenance. This is a source study and a proposed design, with no measured product improvement or product screenshots.

## Hero form

Before/after pair: the exact same authored code line moves from an unlabeled fence to a language-labeled, highlighted frame with copy and wrap affordances. Its geometry makes the first recommendation visible without inventing performance scores. Both sides are labeled schematic, and neither claims to be a running product.

## Emotional register

Clear, curious, composed: Commander's display serif, violet action role, quiet source lines and opaque reading surfaces over the house aurora.

## Distinctive move

The report treats a chat message as an inspectable object: the opening code-frame sketch returns as a tool-detail sketch, making information hierarchy tangible.

## Deliberately omitted

No KPI row, adoption score or speed claim: source inspection cannot measure user benefit. No upstream screenshot: running upstream was prohibited. No theme transplant, motion demo or replacement UI: the recommendations fit Commander's existing tokens and safe DOM renderer. No arbitrary chart scale: recommendations are ordinal judgments with stated dependencies.
