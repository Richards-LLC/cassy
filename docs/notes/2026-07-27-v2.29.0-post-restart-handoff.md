## 1. FIRST THING: verify the fixes actually took

None of the ten fixes were exercised by a running factory — the daemon ran 2.28.5 the entire session. They are verified by tests and by independent re-runs, **not** by live use. Confirm these four before trusting the factory again.

**a. Version is actually live.** `cas --version` must report 2.29.0. Prior releases have shipped and stayed inert because the daemon wasn't restarted — see [[project_v2_28_5_bug_sweep_release]] and the 2.28.1–2.28.4 notes, all of which had "activation pending".

**b. The stale commit guard is gone.** `.git/hooks/pre-commit` in the main checkout contained an unconditional `CAS factory worker guard` dated Jun 15, blocking *any* commit on any non-`factory/*` branch — including yours. The fix removes it automatically on next factory start. Check:

```
grep -l "CAS factory worker guard" .git/hooks/pre-commit   # expect: no match
git commit --allow-empty -m "probe"                        # expect: succeeds, then reset
```

If it's still there, the migration didn't run — that's a real regression in the cas-2491 fix, not a leftover.

**c. Message delivery works.** This is the big one. Send a normal (non-urgent) message to a worker and confirm it *arrives*, by grepping the recipient's transcript — **not** by trusting `message_status`, which reported `delivered` all session for messages that never landed:

```
~/.claude/projects/-home-pippenz-Petrastella-cas-src--cas-worktrees-<worker>/*.jsonl
```

**d. Close works without bypass.** Every close in this session needed `bypass_code_review=true` because the ZERO-COMMIT catch-22 was live. Post-restart a worker should close its own merged task unaided. If it still can't, cas-7efe didn't take.

## 5. Operating lessons that outlived the session

- **Verify delivery by transcript grep, not `message_status`.** See [[feedback_verify_worker_delivery_by_transcript_grep]].
- **Never kill on a stall alert alone.** Four false positives in one session, every one recommending `cas factory kill` on a healthy worker. `cas factory is-wedged` was right every time. See [[feedback_worker_status_message_vs_activity_log]].
- **Worker worktrees share the ref store** (`git-common-dir`), so supervisor merges are visible instantly — no push/fetch needed. I diagnosed a "stale ref" problem that didn't exist; the epic tip was simply moving.
- **Temp worktree for merges** needs `ZIG=<repo>/.context/zig/zig` or the build panics.
- **Run gates with `env -u CAS_SESSION_ID -u CAS_FACTORY_MODE -u CAS_FACTORY_SESSION`** or ~13 spurious failures appear.
