1

Put the basics in place

On an Apple Silicon Mac, first run uname -m. It must print arm64; if it does not, stop and contact the operator because the published Mac release is Apple Silicon only. Keep Homebrew's login-shell setup in ~/.zprofile, but put Cassy's binary path in ~/.zshenv so MCP subprocesses inherit it too.

if [[ "$(uname -m)" != "arm64" ]]; then
  echo "Unsupported Intel Mac: this Cassy release is Apple Silicon only. Contact the operator."
  exit 1
fi

brew install git node
npm install -g @anthropic-ai/claude-code

grep -qxF 'eval "$(/opt/homebrew/bin/brew shellenv)"' ~/.zprofile 2>/dev/null || echo 'eval "$(/opt/homebrew/bin/brew shellenv)"' >> ~/.zprofile
eval "$(/opt/homebrew/bin/brew shellenv)"
grep -qxF 'export PATH=$HOME/.local/bin:$PATH' ~/.zshenv 2>/dev/null || echo 'export PATH=$HOME/.local/bin:$PATH' >> ~/.zshenv
export PATH="$HOME/.local/bin:$PATH"
2

Install Cassy

curl -fsSL https://raw.githubusercontent.com/Richards-LLC/cassy/main/scripts/cas-install.sh | bash
cas --version
mkdir -p ~/.claude
cas update --user

The installer downloads the official published release and clears its macOS quarantine attribute. It is the supported path; do not replace it with a hand-written curl-and-tar sequence.

cas update --user refreshes Cassy’s built-ins for AI tools that are already installed; it does not install Claude, Codex, or Grok for you.

3

Sign in to Cassy Cloud once

Ask Daniel for your personal Cloud API key. This is machine setup, not project setup.

cas login --token <YOUR-PERSONAL-API-KEY>
cas whoami

Cassy stores this sign-in at ~/.cas/cloud.json. Every new project can inherit it. Keep the key out of repositories and screenshots.

Use the token command. It is the reliable path; you do not need the browser approval page.
4

Initialize the actual project

mkdir -p ~/code && cd ~/code
git clone <YOUR-REPOSITORY-URL>
cd <repository>
cas init
cas doctor
cas cloud team show
cas cloud status

Do not run cas init in ~. If it refuses there, that is the safeguard working. If the team is not visible, confirm Daniel has added your Cloud account, then use cas cloud team set <uuid> or cas cloud team auto on.

5

Connect the Mac to Commander

The hub is a small loopback service that hub.petrastella.io pairs with. Tailscale Serve is optional and gives the Petra Stella tailnet an HTTPS path to it.

# Optional: tailnet HTTPS
brew install --cask tailscale
open -a Tailscale

cas hub service install --tailscale-serve
cas hub service status
cas hub pair

On macOS this is a user-level launchd service: it starts at login and survives a reboot. Open Commander, choose Pair a machine, then follow the code flow. Use cas hub service install without the flag if you do not want tailnet access. Use cas hub service uninstall to remove the service later without deleting the hub identity or pairings.

6

Make source-checkout updates easy

cas-update is the day-to-day updater when you keep a Cassy source checkout. It builds from source, so it needs Xcode Command Line Tools, Rust, Git, and the repository. It is not required for the release-binary setup above.

xcode-select --install
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh -s -- -y --default-toolchain stable
source "$HOME/.cargo/env"
mkdir -p ~/code && cd ~/code
git clone https://github.com/Richards-LLC/cassy.git
cd ~/code/cassy
git submodule update --init --recursive
contrib/shell-helpers/install.sh
grep -qxF 'export CAS_SRC=$HOME/code/cassy' ~/.zprofile 2>/dev/null || echo 'export CAS_SRC=$HOME/code/cassy' >> ~/.zprofile
export CAS_SRC="$HOME/code/cassy"
cas-update --dry-run

The installer copies the canonical helper to ~/.local/bin/cas-update. Plain cas-update pulls/builds the current source, installs cas, and migrates and syncs local Cassy projects. The CAS_SRC export is required because the helper does not use the directory where you run it; without it, it looks for ~/Petrastella/cas-src.

Mac restart note. The helper’s automatic process-turnover check uses Linux /proc, so it does not verify or restart old Cassy processes on macOS. After a normal cas-update, manually quit and restart any running cas serve or hub process/service. Check cas hub service status, then restart the service if needed.
cas-update --sync-only     # migrate/sync only; no build or process change
cas-update --no-restart    # build/install/migrate/sync; leave runtimes alone

Where keys go

What you needCorrect home
Cassy Cloud credentialcas login --token … writes ~/.cas/cloud.json.
Optional shell-supplied AI keyExport it in ~/.zprofile (or use that provider’s normal login).

Cassy does not read ~/.zprofile, ~/.zshrc, or ~/.zshenv itself. Your login shell provides the environment to programs it starts. Cassy’s optional AI enrichment uses OPENAI_API_KEY by default; semantic-search status also recognizes VOYAGE_API_KEY. When you explicitly choose a Claude or Codex profile, Cassy removes inherited key/token variables so the chosen login cannot be silently overridden.

printf '%s\n' 'export OPENAI_API_KEY="<key from Daniel>"' >> ~/.zprofile
source ~/.zprofile
Quick recovery

If something feels wrong

  • cas is missing: run source ~/.zprofile or open a new terminal.
  • Commander cannot connect: run cas hub service status; check Tailscale if you enabled it; pair again if asked.
  • Claude Code shows Cassy as disconnected in /mcp: its MCP config uses the bare cas command. Use the absolute ~/.local/bin/cas path in .mcp.json, or put the PATH export in ~/.zshenv when Claude Code is launched outside a login shell.
  • A project is unhappy: from its repository run cas doctor.
  • Cloud is not connected: repeat cas login --token …, then cas whoami.
