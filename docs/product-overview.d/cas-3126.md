## Core Concepts

Factory lane CI always uses the existing self-hosted `cas-lane-light` pool,
including impact own/ring tests and the legacy non-slim lane checks. Busy lanes
queue locally instead of consuming the hosted capacity used by release PRs,
frozen-train validation, merge-group validation and Release Prebuild. The train
and queue keep their shared validation graph. The release supervisor records
native job start waits and PR-to-queue timing on the next real release; routing
isolation does not itself establish the one-minute start target.
