## Core Concepts

A release train can have its owner transferred explicitly. The current owner prepares a transfer that names a registered successor. The first prepare enrolls the train in `refs/cas/train-owner/<train>`, a shared, append-only Git ref. The ref records the owner's process identity, the train generation, its phase and the exact target SHA. While the train is enrolled, Cassy publishes the target only by updating the target and the authority ref in one atomic push. Worktree merges, train drops and the daemon's main sync all publish this way, and generic pushes to an enrolled target are refused.

Prepare moves the authority to draining, and every publication leased on the earlier record then fails at the remote. Quiesce records that fence, together with fresh provider checks: no armed pull-request auto-merge, no merge-queue entry and no active workflow run. Accept by the named successor issues a fresh generation and updates the task's owner projection. Queued merges and messages from the earlier generation then hold. An owner that restarts without a transfer keeps its generation through the existing mailbox predecessor claim. Stale heartbeats, unreachable hosts and caller-supplied JSON never count as quiescence.

Residual gap (detect-and-hold): a raw Git credential holder or an older Cassy binary can still push the target directly. Cassy detects the diverged target and holds the train until the operator runs the local, operator-only `adopt-target` for that exact SHA. `force` lets the operator record an unauthenticated attestation that a dead owner's hosts and credentials are stopped. Provider APIs are not atomic with Git, so a pull request merged between the provider check and the authority write is also detected only as divergence.
