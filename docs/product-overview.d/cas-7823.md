## Core Concepts

- **Find or file** - Cassy files a new issue or task only when no open one already names the same wrong output. The key is the refusal's registry gate codes plus its normalized text (lowercased, ids and numbers collapsed, at least four words): the first line of `actual` for `system action=report_cas_bug`, the last line of a finding's repro. A matching open issue gets the report as an evidence comment with +1; a matching open task gets an evidence note; a report with no key is refused. Finding task creates that match an open task are held by G-148 until `confirm_warning=true` says the defect is different, QA ledger findings that match add a +1 note instead of a follow-up, and filed issues record the key as a `Fingerprint` line so later reports with wrapped wording still match.
