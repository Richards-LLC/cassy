## Core Concepts

**One scope per uncertain input.** Park's focused-proof demand and `worker-check` resolve an input that static selection cannot classify through the same function, so the command park prints is one the runner accepts and records. A changed spec keeps its own stability proof and is never an input that another spec must read. A Vue component whose Vitest config inherits `plugin-vue` from `./vite.config` proves through `vitest related --run`. A JSON file widens only the specs that register tests from it, whether through an `it.each` table, a loop or a local factory function. A spec that reads the file inside a test body, such as a locale dictionary, does not widen. Runner configs and `.d.ts` files register no tests and owe no run of their own; the tests a config lists keep their proof, run under it. A package with no test file, such as a Maizzle email package, owes no run. A Playwright fixture module that no spec imports proves through the suite of the config that owns its directory, run under that config.

**Honest runner verdicts.** `worker-check` admits a run only when both the process and its report pass. A nonzero exit beside a passing report is refused with the exit status, not as an assertion failure. A selected test that the run reports skipped is refused as not run. An `it.each` table written with `as const` or `satisfies` names its rows. A table whose rows cannot be named runs its whole spec five times with no name filter, and every iteration must report the same rows. A Playwright setup project that a related run depends on passes without counting toward the proof.
