## Core Concepts

**One scope per uncertain input.** Park's focused-proof demand and `worker-check` resolve an input that static selection cannot classify through the same function, so the command park prints is one the runner accepts and records. A changed spec keeps its own stability proof and is never an input that another spec must read. A Vue component whose Vitest config inherits `plugin-vue` from `./vite.config` proves through `vitest related --run`. A changed JSON file widens a test file only when that file's collection-time code uses it: a table, a loop, a test title or any call at module or `describe` level, including an imported helper such as `registerCases(rows)`. Reads inside a test, a hook, or a helper that only tests call do not widen it, which covers most locale dictionary readers. A module outside test files registers no tests from data. A test API is recognised only at the root of a callee, so `/re/.test(x)` elsewhere in a module no longer blocks classification. Runner configs and `.d.ts` files register no tests and owe no run of their own; the tests a config lists keep their proof, run under it. A package with no test file, such as a Maizzle email package, owes no run. A Playwright fixture module that no spec imports proves through the suite of the config that owns its directory, run under that config.

**Honest runner verdicts.** `worker-check` admits a run only when both the process and its report pass. A nonzero exit beside a passing report is refused with the exit status, not as an assertion failure. A selected test that the run reports skipped is refused as not run. An `it.each` table written with `as const` or `satisfies` names its rows. A table whose rows cannot be named runs its whole spec five times with no name filter, and every iteration must report the same rows. A Playwright setup project that a related run depends on passes without counting toward the proof.
