## Core Concepts

- **Home-gateway worker transport** - a project can route its Claude and Codex workers through the operator's own model hub with `factory.gateway.enabled = true`. The hub endpoint and client key file usually live in the user-level `~/.cas/config.toml` (`factory.gateway.endpoint`, `factory.gateway.key_file`); only the project's own `enabled` turns it on, and `clients` limits which harnesses are routed. Only loopback and tailnet endpoints are accepted, and the key file must be mode 0600. Workers keep the account directory native selection chose, so hooks, MCP and sessions are unchanged; Claude gets the hub as its base URL and Codex a per-launch provider override, with no write to the account directory. The key is read from its file when the worker process starts and never appears in argv, configs or logs. Before launch, the hub's model listing must answer for the key; if it does not, the worker starts direct on the same account. `worker_status` shows `transport: gateway <endpoint>` or `transport: direct (gateway fallback: <reason>)`. Requests carry a `cassy/<worker>` client identifier in the user agent. With the setting absent or false, worker launches are unchanged.
