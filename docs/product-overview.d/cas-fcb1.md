## Core Concepts

**Runnable test-proof prescriptions.** Park never demands a capped run that can't happen. The runner comes from the test API a file imports, so a Vitest spec that drives a browser with Playwright's library gets a Vitest run. Any JavaScript selection that runs no test (for example `vitest related` for a page no test imports, or a named changed-test run that matches no runtime name) runs the owning package instead, and park accepts that package's passing run for the changed tests and inputs inside it. `cas factory worker-check -- <runner> <package>/package.json` runs a package directly, and it is what park prescribes when a package has no JavaScript change to name. Deleted files owe no proof. Specs the QA journey registry declares, and helpers only those journeys import, follow the journey lane (batch QA), not worker capped passes. A passing receipt at the exact commit counts from any worktree of the repository, so a supervisor can prove a stopped worker's delivery from that worker's worktree.
