# Documentation upkeep at task park

G5 and G6 check the committed delivery before its merge request. They use the
task's attributed diff, including deleted paths and rename sources. Uncommitted
document edits do not satisfy a gate. Existing documentation debt does not block
an unrelated delivery.

| Gate | Refuses when the document is untouched | Decision escape |
| --- | --- | --- |
| G5 `.claude/CODEMAP.md` | A named literal file or directory disappears, or a new directory appears directly beneath a parent whose map enumerates children | `codemap unchanged: <reason>` |
| G6 `docs/PRODUCT_OVERVIEW.md` | A configured domain file changes, a structural addition/deletion/rename touches a watched directory, or the registry adds a live journey or switches between live and dead | `overview unchanged: <reason>` |

A new file inside an existing directory is advisory for CODEMAP. A missing
CODEMAP or overview disables its own gate. Malformed, unrelated registry content
warns and leaves the independent path checks active. Watch targets resolve per key: a
`[project_overview]` section in the delivered `.cas/config.toml` (or, when
`.cas/` is not tracked, the local project config), then the tracked
`<!-- cas:project-overview ... -->` TOML block in the delivered overview, then
targets derived from tracked paths (`schema.prisma` files and existing
pages/routes/components directories). When nothing is declared or derived, park
passes with `UPKEEP WARNING G6: no product paths are watched` and `cas qa impact`
repeats it.

Update the named document in the delivery, or record one decision with a reason:

```text
task action=notes id=<task> note_type=decision notes="codemap unchanged: <reason>"
task action=notes id=<task> note_type=decision notes="overview unchanged: <reason>"
```

Use your harness's tool prefix, then retry `task action=close id=<task>`. Empty
reasons and progress-note quotations do not waive a gate. Authenticated supervisor
close overrides also record the refusal they waived.

## Stages and adoption

`upkeep.codemap` and `upkeep.product_overview` accept `off`, `observe`, and
`enforce`. The default is `enforce`. `observe` writes would-refusals to task notes
and passes; `off` disables that gate. Notes and park/close receipts expose current
warnings and observe summaries. `UPKEEP OBSERVE G5|G6:` and `UPKEEP ESCAPE G5|G6:`
rows share the registry gates' deduplicated accounting and epic escape count.

New `cas init` projects and successful `cas qa journeys --seed` runs select
`enforce`, for these keys and for `qa.registry.enforce` (seeding keeps an
explicit `strict`). An existing project's first all-project `cas update` refresh
writes `observe` for each missing key, including `qa.registry.enforce`, and records the changes in the update receipt's
`projects[].phase_documents.docs_upkeep[].changes` array. It preserves TOML
comments and project-specific sections. Retrying the same release keeps the
window; the next newer release promotes only autogenerated observe values.

To keep observing, pin each chosen gate explicitly, even if its value is already
observe:

```bash
cas config set upkeep.codemap observe
cas config set upkeep.product_overview observe
cas config set qa.registry.enforce observe
```

This clears that gate's `upkeep.observe_since` release marker (`registry` for
`qa.registry.enforce`). A manual TOML
editor can pin the value by removing its entry in `[upkeep.observe_since]`.
Explicit `off` and `enforce` choices are preserved by update. Seeding chooses
`enforce` for both gates and clears the adoption markers.

The former `docs/qa/features` / `map unchanged:` close gate is retired. Existing
feature documents and their optional static check remain usable; task park no
longer checks their Touches globs.
