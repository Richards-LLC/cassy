### F1 — High — A refused message sends the user to a control that is not on screen (HUB-J5, stage 5 "A refused message says why")

- **Receipt:** HUB-J5 `J05.png`. The refused bubble reads "Not sent · This device isn't the one in control of the session. Take control from the header, then retry." The conversation header shows only the avatar, "cas-src", "Atlas · Linux · patient-pelican-9 · Live" and "Terminal view". HUB-J5 `final.aria.yml` confirms that the only header button in `main` is "Terminal view". The Take control button (`#lease`) is rendered only in the Terminal view session header (`hub-web/src/main.ts:2479`), and in the command palette (HUB-J3 `J10.png`, "Release control"). The copy comes from `hub-web/src/refusal.ts:26`.
- **User experience:** The refusal now gives a reason and a next step, which is a clear improvement. But the next step points at nothing. A user who reads "Take control from the header" looks at the header and finds no such control. Retry sends the message into the same refusal. The recovery is reachable only if the user guesses Terminal view or Ctrl+K twice. This happens on the core replying journey.
- **Fix:** Put the recovery on the message. Add a "Take control and resend" action beside Edit and Retry, or a "Take control" button that re-enables Retry. If the header must host it, render a Take control button in the conversation header whenever this device observes the session. Then name the place the button actually is. Add a journey assertion that the control the refusal names is visible.
