# Journey evaluation — hub-web/dist 09747d57

**No Blocking finding. The 3.50.0 cut may proceed on this dist.** The new Write access journey (HUB-J20) carries three Normal findings, filed as P2 tasks.

3.50.0 ships four hub-web changes on top of 3.49.0 (dist 9ad79049, evaluated in `2026-10-10-hub-web-9ad79049.md`):

- **Write access (cas-ab04, HUB-J20, new).** The Tasks & progress rail gains "Write access…". On a pairing with factory:manage, it opens a panel that grants a task's agents create or edit access to a folder outside their worktree, after a confirmation, and revokes it again. On any other pairing, the button is disabled.
- **Conversation switching (cas-4646, HUB-J8 step 10).** A tap or click on a conversation row opens the row that was pressed, even when the list re-sorts or rebuilds under the finger.
- **App icon and installed-app safe areas (cas-8951).** A new violet tile mark replaces the flat lavender one in the sidebar, favicon and pairing dialogs. A web app manifest and home-screen icons are added, and the top surfaces add `env(safe-area-inset-top)` for an installed iPhone app.
- **Supervisor answers to terminal questions (cas-5c89).** This is a daemon-side change: the supervisor's answer to a question asked in its terminal is now mirrored into the Cassy Cloud conversation. It changes no hub-web source or dist. Only a visual-QA fixture changed. The protocol double cannot show it (see Not covered).

In this run, all 132 tests pass, with 0 flaky and 0 unexpected. Every `result.json` has empty `page_errors` and `frame_defects`.

### Notes (report only)

- **"create+edit" in the confirmation and the receipt.** The `+` is the CLI's mode syntax. "create and edit files" would read more plainly. The confirmation names the task, the folder and the end condition, so the meaning is recoverable. This is a 1 with no fix needed for the goal.
- **Revoke… is offered before any grant exists** (HUB-J20 J02). The journey does not walk a revoke with nothing to remove, so what the operator reads then is not observable. Revoke's receipt counts the grants it removed (J05).
- **The tap bound.** The catalog's step 10 says a tapped conversation opens "within about 100 ms". The spec asserts at most 150 ms. Every one of the 100 taps in this run met the assertion; individual latencies are not in the receipt.
- **A quiet machine still reads "Live" for a moment.** In HUB-J8's quiet-machine stage, soundwave's conversations open from cache right after the double stops answering. The header says "Live" (J02), because the machine has not yet missed its heartbeats. HUB-J12 shows the measured change to "Reconnecting" once it has.

The screen says "Reconnecting" throughout, and nothing in this dist touches reconnect.

## Not covered

The protocol-double limits are unchanged from `2026-10-06-hub-web-9fade21f.md` § Not covered. For this release's deliveries:

- **cas-ab04, Write access.** The double answers `POST /v1/sessions/<s>/write-grants` the way the hub does. The hub writing `.cas/operator/write-policy.toml` with the device id, noting the task, and posting the operator receipt to the supervisor are proven by the Rust hub tests (catalog HUB-J20 Gaps). A refusal the hub sends for a closed task or an unresolvable folder is not walked by the journey. Its wording is unit-tested in `write-grant.test.ts`. cas-42c0, in progress, changes how a 403 scope refusal reads; it is not in this dist.
- **cas-8951, installed-app safe areas and icons.** A browser tab has no safe-area inset, so the journeys can only show that ordinary tabs are unchanged, which they are. The inset is proven by `e2e/installed-safe-area.spec.ts`: 5 of 5 at 49356ac3f, with Chromium's safe-area override at 47 px top and a 44 px landscape notch. Manifest and icon installability is proven by cas-8951's QA bundle `cas-8951/qa-49356ac3f` (cell M04). Since 49356ac3f, hub-web has changed only `conversation-list.ts` and `main.ts` (cas-4646); `styles.css` is unchanged. No icon was seen on a real home screen.
- **cas-5c89, supervisor answers to terminal questions.** The mirror runs in the daemon (`commander_mirror.rs`). The double replays no daemon, so no journey shows a mirrored answer. Its rendering is an ordinary supervisor message, which HUB-J4 and HUB-J7 cover. The mirror itself is proven by its Rust tests and the `conversation-terminal` visual-QA fixture.
- **cas-4646.** The taps are dispatched as raw CDP mouse and touch input, on the double's update timing. A real phone's touch latency and a real hub's catalog cadence were not measured.

A real hub's reconnect timing and a real-device Glass frame time remain unmeasured.
