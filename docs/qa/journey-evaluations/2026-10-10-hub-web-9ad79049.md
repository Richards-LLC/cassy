# Journey evaluation — hub-web/dist 9ad79049

**No Blocking finding. The 3.49.0 cut may proceed on this dist.**

3.49.0 ships one hub-web change on top of 3.48.2 (dist 6e53168b, evaluated in `2026-10-07-hub-web-6e53168b.md`): the HUB-J18 keyboard-focus fix (cas-3c25, commits a4e2f0a21 and 85add742d). It has two parts:

- **Focus mid-Tab.** A shell rebuild that was waiting for the search box to lose focus used to run in a microtask. For a keyboard Tab, that microtask runs while focus is in transit on `<body>`. The rebuild then replaced the control Tab was moving to, and focus fell to the page. The rebuild now waits one task for focus to settle, and `render()` restores the rebuilt control with its focus ring when the replaced one showed it.
- **Stale palette signature.** Closing the command palette closed its dialog in place without a render, so the recorded shell signature still said "palette open". The next unrelated hub update rebuilt the whole shell under whatever control had focus. Closing the palette now adopts the built shell's closed-palette signature.

Everything else that changed between v3.48.2 and the evaluated commit is Rust, scripts, skills or docs. In this run all 127 tests pass, with 0 flaky. HUB-J18's keyboard stages reach Interrupt and Raw output with a visible ring in all four of its tests.
