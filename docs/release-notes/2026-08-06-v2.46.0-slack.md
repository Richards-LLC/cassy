=== MESSAGE 1 — User thread, top-level ===
Live on production — **User** — Finished work no longer gets told it isn't finished, and a message marked "delivered" now actually means someone saw it.

=== MESSAGE 2 — User thread, reply (to MESSAGE 1 ts) ===
**Was →** work that had already been safely merged could be refused at the finish line and you'd be pointed at rewinding the very branch that held the result. A message could be stamped delivered the instant it was written down, sit unseen for an entire piece of work, and be counted as read just because the other side happened to say something back — so you'd carry on believing a correction had landed when it hadn't. A single notification could multiply into hundreds of copies until the conversation it was in collapsed under them. And a status view could report phantom leftover work on something already done, or a reassuring zero on something it couldn't read at all.

**Now →** completed work closes on the evidence that it actually landed, and if something genuinely is empty you're told exactly what to attach instead of being sent to do branch surgery. Delivery is only claimed when there's a record on the receiving side, being read requires actually being shown, and an urgent interruption isn't considered done until there's proof it woke the other side — retried gently, never in a flood. Repeat notifications collapse into one line with a count. New work starts from the code it actually belongs to instead of whatever happened to be on screen. A shared workspace can't be quietly parked somewhere else and swallow later results. And status views now name what they read, fall back to the shared copy when the local one is gone, and say plainly when there's nothing to read rather than inventing a number.

=== MESSAGE 3 — Dev thread, top-level ===
Live on production — **Dev** — Close guards accept merge receipts instead of demanding branch resets, and delivery/confirmation state is now corroborated per-recipient in the same transaction as the write.

=== MESSAGE 4 — Dev thread, reply (to MESSAGE 3 ts) ===
**Was →** a branch showing only a sync-merge after its work had already been integrated read as "no work" to the close guard, so the success state was indistinguishable from the failure state and the remediation text suggested resetting the branch. Confirmation was inferred from any inbound message from a recipient, regardless of ordering against delivery or whether the message was ever surfaced, which silenced the sender's escalation clock; one acknowledgement shape could delete a never-shown inbox row outright. Delivery was stamped at daemon write time with no receiver-side corroboration. Worker checkouts were based on the dashboard's focused epic rather than the assigned task's epic. Parked notifications were re-injected on the worker path without the once-per-interval contract, producing hundreds of duplicates and forced compaction. The supervisor-owned review gate was enforced on one dispatch path and bypassable on another. Six delivery tests read the ambient config directory and failed on any machine pointing at an alternate profile. Epic status read only local branches, so a cleaned-up merged lane reported phantom unmerged commits and an unreadable branch reported zero.

**Now →** a close carrying a valid receipt for merged work passes, and the empty-close refusal names the receipt path. Confirmation requires a reply that post-dates delivery *and* evidence the message was surfaced; already-acted-on assignments aren't re-served verbatim and genuine redeliveries are labeled. Every delivery writes a per-recipient record in the same transaction, only an explicit ack or a real surfacing hides an inbox row, and an urgent interrupt is retried on a throttle until there's evidence it woke its target. Spawn base resolution follows the task's epic and the spawn report names the branch it chose and why. Identical parked notifications collapse to one entry with a count under the same once-per-interval contract as the supervisor path. A non-isolated worker parked on its own branch in the shared checkout is flagged in status output and steered away by the commit guard. Every review dispatch route applies the same ownership refusal. Delivery test fixtures pin their own config root, with a regression test that deliberately runs under a non-default directory. Epic status rows name the branch they read, fall back to the remote when the local copy is gone, state explicitly when neither exists, and a stale inherited base commit no longer blocks an epic from closing. Worker guides now mandate backgrounding builds, test suites, and CI waits, since a foreground-blocked worker is only reachable by a turn-breaking interrupt.
