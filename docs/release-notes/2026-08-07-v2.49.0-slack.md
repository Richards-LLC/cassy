## Post 1 — User

Live on production — **User**

A message you send now actually gets read, a reset actually resets, and when a command is about to write somewhere other than where you are standing, it says so first.

### Reply to Post 1

- **Was → Now:** a message could be filed away and marked delivered while the session it was sent to never saw it — sometimes for hours → messages waiting for a session are put in front of it at the start of its next turn, and delivery is only counted once that has actually happened. If a wake-up was attempted and nothing surfaced, that is now recorded and reportable instead of invisible.
- **Was → Now:** asking a session to clear its context sent it the four characters `/clear` as ordinary text, which it read as a note and carried on with everything still loaded — while the command cheerfully reported success → the reset is now sent over a real command channel and confirmed by checking that a new session actually started. If it cannot be proven, you get an error naming exactly what was and was not observed, not a false "done". Where the reset is not supported, you are told up front rather than left with a silent no-op.
- **Was → Now:** a review policy you set was accepted, reported back as an unknown setting, and then ignored — the expensive review ran anyway, repeatedly → the setting is real, readable back with `cas config get`, rejects invalid values, and is enforced at the point where the cost is actually incurred.
- **Was → Now:** a fresh working area could be cut from a months-stale copy of a branch while a current one sat right next to it, and work with no parent grouping silently inherited whatever happened to be pinned → the fresher of the two is used and both commits and the gap are named, and unparented work starts from the trunk with the override announced.
- **Was → Now:** an environment setting could quietly override the folder you were standing in, so a "practice run" against a copied database wrote to the live one instead → the behaviour is deliberately unchanged, but the folder that lost is now named out loud, once, along with the one-line way to opt out.
- **Was → Now:** help text pointed at a build flag that had been removed and a mode name the tool rejects → both now describe what the tool actually does.
- **Added:** moving legacy notes into the distilled knowledge library is now a supported, reversible operation — it previews before it writes, records every page it creates, and can undo exactly those pages later without rolling back anything else you have done since.

## Post 2 — Dev

Live on production — **Dev**

Three "success" paths that were reporting outcomes they had never verified — message delivery, context reset, and review-ownership policy — now measure their own post-conditions, and the memory→knowledge migration ships with a ledger-driven rollback that was proven on copies of the real databases.

### Reply to Post 2

- **Was → Now:** the queue had a delivery path and no surfacing path — a row was written to the recipient's inbox file, stamped `delivered`, and nothing anywhere read it back → a turn-start handler drains a recipient's unread rows and injects them into the turn that is starting. Selection and receipt are one transaction, so a caller can never hold content whose receipt failed to persist. The turn-start event is now installed in the generated hooks block; the other twelve events are deliberately untouched.
- **Was → Now:** wake state was a hardcoded constant with no backing column, and the nudge helper returned `Delivered` from its success arm, its deferred arm *and* its error arm → the three states were always computed and are now persisted (fired / failed / not attempted). Status output reports the attempt and calls out the signature of a fired nudge with no surfacing. Migration `m220` adds the receipt source column; the queue's own wake columns stay store-managed alongside their siblings.
- **Was → Now:** context reset enqueued the literal string `/clear` as an ordinary message, which under team routing landed in an inbox and was read as prose → reset is a control row matched ahead of every message-routing path and typed over the same interrupt-and-inject channel urgent traffic uses, so it can no longer reach an inbox. The post-condition is a new transcript that records the command; the confirmed new session id is written back to the agent record, so status and activity resolve the live transcript instead of the dead pre-reset file. Unsupported harnesses are refused before anything is queued.
- **Was → Now:** `code_review.owner` was read at runtime but had no CLI surface, so the policy could not be audited and reported as an unknown key → get/set/list arms plus a registry entry, with an absent section reporting the owning default and `set` rejecting anything outside the two valid values. The dispatch refusal now covers the entry points that actually spend tokens (including the current agent-spawn spelling, added as intercept-only and never auto-approved), the gate is hoisted above every earlier branch, and the close path no longer demands the review artifact from the party the policy says does not produce it. The honest limit is documented: it is a pre-tool hook, so a session on hand-edited settings is advisory again.
- **Was → Now:** base resolution collapsed "provably no parent" and "could not determine" into one `None` and mapped it to the pinned focus, and read the local ref without ever consulting the remote's → a three-state result routes unparented work to trunk (counted as a divergence, so the override is announced) while genuinely unresolved stays on the legacy fallback; and the base ref now compares local against `origin/`, cutting from the remote commit when local is strictly behind and naming both SHAs and the gap, reporting a divergence without overwriting it, and staying silent when local is ahead, equal, or has no remote.
- **Was → Now:** the root-resolution order put the environment override ahead of the working directory with nothing saying so → precedence is byte-for-byte unchanged, and the losing candidate is named once per process on stderr (never stdout, so JSON, hook payloads and stdio framing stay parseable), with no notice when both spellings canonicalize to the same directory.
- **Added:** a memory→knowledge migration tool with preview-by-default, a per-page ledger, and a rollback driven from that ledger rather than a database restore — the database also holds tasks, leases, sessions and receipts, so restoring it would discard more than it recovers. Rollback refuses on divergence instead of guessing, and exiting non-zero on divergence is part of the contract. Exercising it caught a real defect: restored rows were routed to the first database that had the table, so payloads are now stamped with their origin and an unstamped payload is a hard error. Also ships a retrieval-parity harness (fixed query set, read-only channels, capture/replay diff) and the cutover runbook.
