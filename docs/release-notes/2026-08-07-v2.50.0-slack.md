## Post 1 — User

Live on production — **User**

Work that finishes now always announces itself. A hand-off notice that fails to arrive is reported as a failure instead of vanishing, and a session that restarts keeps getting its notices.

### Reply to Post 1

- **Was → Now:** a completed piece of work could sit waiting while the person who needed to act on it was never told — the notice was written, quietly re-sent for a while, then filed away as a stale duplicate, and nothing anywhere said it had failed to arrive → a notice that expires without ever reaching anyone is now recorded as a failure in its own right, kept distinct from the harmless case of withholding a copy nobody needed.
- **Was → Now:** you had to already suspect something was missing to go looking for it → undelivered notices are surfaced where you already look: a banner above the roster, and a warning in the health check. Both read information that was already being written, so past incidents show up too, not just new ones.
- **Was → Now:** when a session restarted, later notices could be addressed to the identity you had already walked away from, chosen essentially at random between the old and the new → notices now go to the session that actually exists. A session that has shut down cannot capture them, no matter how recently it appeared.
- **Was → Now:** a notice waiting on someone who never came back would retry forever with no ending → retries are now bounded — long enough that a merely busy recipient always wins the race, short enough that an absent one produces a recorded failure instead of something that never resolves. Every notice now ends up either delivered or visibly failed.
- **Was → Now:** the log claimed "delivered" for messages that had never been delivered — one of them said so nearly 56,000 times while the message itself was ultimately abandoned → the log now distinguishes "written, waiting for the next turn" from "actually delivered", so it stops contradicting the thing it is describing.
- **Was → Now:** three older storage and search paths still sat alongside the distilled knowledge library that had replaced them → they are gone. Nothing you do changes; what goes away is a second code path claiming the same job, plus a written record of what was retired and what deliberately stays.

## Post 2 — Dev

Live on production — **Dev**

Every lifecycle relay now reaches exactly one terminal state — delivered or visibly failed — instead of being able to expire into silence, retry unboundedly, or be logged as delivered while its row said otherwise.

### Reply to Post 2

- **Was → Now:** an untransported relay was stamped with the same suppressed-idle reason used for benign dedup, so "we withheld a copy nobody needed" and "the recipient was never told" were indistinguishable → a distinct terminal reason marks a relay that expired without transport, emitted with an error-level trace and decided by a pure, unit-testable outcome function. A stale wake-eligible row still terminates rather than re-writing an expired premise every cadence tick — but terminates as a recorded failure. An explicit ack still counts as arrival, so acked relays stay quiet.
- **Was → Now:** the failure signal existed only in columns nobody read → the roster view grows an undelivered-relay banner (rendered even with zero registered agents) and the health command grows a relay check that warns rather than reporting health when it cannot read the queue. Both derive from already-persisted columns, so the signal is retroactive.
- **Was → Now:** recipient resolution broke ties on name then id — lexicographic order on a UUID — so a mid-session restart that left several same-name rows handed later relays to an arbitrary one, often a superseded session whose frozen transcript reads as "tool call in flight" forever and therefore permanently vetoed the wake gate → ties now break on registration recency, after liveness. Liveness still wins outright: a newer but shut-down row cannot capture relays.
- **Was → Now:** the staleness suppressor only fires when a task leaves its state, so a relay parked behind a recipient who never returned had no terminal state and re-nudged indefinitely → the redelivery decision now takes the row's attempt count and stops once it exceeds the retry bound (20 intervals ≈ 20 minutes, far longer than any real turn boundary). Only a genuine (re)delivery burns budget; a cooldown tick is policy, not a failed attempt.
- **Was → Now:** the inbox-write arm logged `stage="delivered"` for wake-deferred rows that kept `transport_delivered_at` NULL and were rewritten every tick → deferred writes now log `stage="inbox_write_pending_turn"`.
- **Was → Now:** the layered store, the markdown-backed store, and the standalone hybrid search path remained after the distilled knowledge library superseded them → all three removed (~2,100 lines), with a decommission survey recording what was retired, what replaced it, and what deliberately stays.
- Note: no schema migration in this release — the new pending-reason state is carried in existing prompt-queue storage, so `cas doctor` still reports schema v220.
