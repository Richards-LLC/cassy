## Post 1 — User (top-level)

Live on production — *User*

Messages between the parts of your setup stopped quietly disappearing. Mail written for a session now actually lands in front of it, and work that dies says so instead of waiting to be discovered.

### Reply (Was → Now)

• *Was → Now:* a message written to a session's inbox could sit there forever, never shown to anyone → mail is surfaced at the start of the next turn, and the path is checked against real traffic rather than a hand-made stand-in.
• *Was → Now:* a helper that died left you to notice on your own, or buried you under repeats of the same death → one death, one notice, delivered where you will actually see it, and it wakes an idle session rather than waiting to be polled.
• *Was → Now:* the retry counter on a stuck message always read zero, so nothing could be triaged before it gave up → retries are counted durably with their reason, and a health check names the messages running out of road while you can still act.
• *Was → Now:* background servers kept a project's database open long after the session that started them was gone → a server notices its launcher disappear and shuts itself down within seconds, releasing what it held.
• *Was → Now:* searching your saved knowledge for several words at once returned nothing unless every word matched → more matches now rank higher instead of everything short of perfect being thrown away.
• Reports now save as one self-contained file that opens correctly anywhere, and the built-in guidance every session loads got substantially shorter — less to read, less to pay for.

## Post 2 — Dev (top-level)

Live on production — *Dev*

Turn-start inbox surfacing was reading a payload key the event never sends, and the real key was bound to an unread field — so it failed silently through a whole release with a green suite. Three features were dead on that same wire; all are now wired to captured payloads, with a rule that payload tests must parse raw events.

### Reply (Was → Now)

• *Was → Now:* the submit event's text key was declared on an unrelated unread field and surfacing sat behind an early return → the key is read where it is actually sent and surfacing moved ahead of the return; either fix alone restores delivery. Corroboration: the attribution table it also writes held zero rows for the life of the database.
• *Was → Now:* the long-output guard read a whole-message field that is never sent (text arrives as streaming fragments), and the already-being-resumed signal was emitted everywhere and read nowhere while five sites could block a stop → both read the wire shape now, so a session can tell it is inside a loop of its own making.
• *Was → Now:* death notices went to a queue nobody reads and re-fired on every re-detection — one incident produced 1,400+ copies → an idempotent dual write keyed on the death itself, carrying a wake signal, visible in the undelivered report if it never lands.
• *Was → Now:* the delivery-attempt counter was wired only to error branches this system never takes while the real retry loop counted in memory → attempts persist with their reason in one transaction; policy cooldowns still cost nothing; historical rows stay at zero rather than being invented.
• *Was → Now:* rows acknowledged at turn start were overstamped as delivered-awaiting-ack, crediting the wrong source and producing two claims that had to be withdrawn → a row now records the acknowledgement it holds and the path that produced it.
• *Was → Now:* the close guard did not recognise a merge commit as evidence the change landed, and socket election could adopt a listener whose process was gone or on an old binary → merge commits count as proof, and election requires a live server on the current binary.
• *Was → Now:* the suite wrote into the live project and global stores (~1,000 fixture rows left behind), a wedged harness could burn ten minutes, and retrieval-parity numbers silently excluded the global tier → isolated temp stores plus a residue-reporting cleaner, a bounded wait, and parity measured across both tiers.
