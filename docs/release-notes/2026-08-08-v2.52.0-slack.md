# v2.52.0 — Slack release notes (#cas-internal)

Status: posted 2026-08-08

Runtime release. Two distinct top-level posts (User + Dev), each with exactly one
threaded reply in Was → Now form. Zero internal ticket IDs; GitHub issue numbers
appear only in the dev reply, which the rubric permits.

## Post 1 — User (top-level)

Live on production — *User*

The notices that say a piece of work changed hands stopped being thrown away before they were ever sent. Over four days, almost every one of them died in silence — including nearly all the "this is ready for you" and "this was sent back" alerts. Now a notice is delivered, receipted, or loudly dead.

### Reply (Was → Now)

• *Was → Now:* 353 of 361 hand-off notices over four days were destroyed before they reached the wire — 34 of 36 "ready for you to merge" and 34 of 36 "this was sent back" among them → the check that was silently killing them can no longer be defeated by a clock, and the worst case is now a duplicate courtesy notice instead of total silence.
• *Was → Now:* a notice pulled because its premise had expired was filed under the same label as ordinary de-duplication, so a four-day outage sat hidden inside a bucket that reads as normal housekeeping → a withdrawal now says a decision was made and names the work that moved on.
• *Was → Now:* a message you had already read, acted on and replied to came back — sometimes in whole bursts → every path that hands a message over now records that it did, so a read message stays read. This matters most for broadcasts, where that record is the only thing that can ever retire one.
• *Was → Now:* mail addressed to a role rather than a person was unreachable from that person's own inbox — 40 of 50 such messages left no trace, and one dismissed under one name resurfaced under the other → both names now resolve to the same recipient, and a receipt is written for every name they answer to.
• *Was → Now:* sending a message quietly wrote a second copy into a folder nothing reads and nothing prunes; it grew without limit and then arrived as a stale flood the next time a similarly named session started → those strays are marked inert on sight, and only in folders that were conjured by that write. A real mailbox is never touched.
• *Was → Now:* one stuck message wrote 16,604 identical log lines in thirty minutes — an eighth of everything logged that day → the line rides the actual retry and names the attempt, so the noise tracks real effort instead of an internal timer.
• *Was → Now:* refreshing everyone against one line of work dragged sessions onto branches they had nothing to do with, grafting on unrelated commits and rewriting ones that had already landed → a session is refreshed only when it actually feeds into that branch, and a skip says which work and which branch. Naming a session by hand is still an override.
• *Was → Now:* updating built-in files reported the summary and file list under whichever destination printed last, so a write to one place was credited to another that was never touched → each destination reports for itself, and every claimed write names where it landed.
• *Was → Now:* a scoped test run could report success having executed nothing at all — three separate runs did exactly that and were all read as green → success now requires that tests actually ran and that more than zero of them passed.

## Post 2 — Dev (top-level)

Live on production — *Dev*

A freshness guard compared a notification timestamp against a task timestamp for exact equality, with the two values read from the clock microseconds apart. It could never pass. 397 relays died on that one line — 353 of 361 over four days, zero exact matches in the discarded rows, closest miss 21.9µs. Freshness is now a state question, not a clock question.

### Reply (Was → Now)

• *Was → Now:* the staleness predicate required `notification.ts == task.updated_at`, two separate clock reads → it asks whether the work is still in the state the notice announces, which no skew can defeat, while keeping the one judgement a timestamp can make soundly. Duplicate courtesy notice on state re-entry is the new worst case. (GH #167)
• *Was → Now:* premise-expired withdrawals shared a disposition label with routine de-duplication, hiding a four-day outage in a bucket that reads as housekeeping → withdrawal is its own decision and records the task that moved on. (GH #167)
• *Was → Now:* "delivered" was computed from a per-recipient receipt ledger that only two of the delivery paths wrote to — the path that actually hands a message to a session wrote none, so a message could be delivered and simultaneously unread by the recipient's own check → every terminal-delivery path writes the receipt. Delivery still is not acknowledgement. (GH #176)
• *Was → Now:* the two readers of that ledger had drifted on alias resolution: 40 of 50 role-addressed messages were never receipted (vs 15 of 59 for the personal name), and retiring under one name left no record under the other → one shared identity resolver, receipts written for every alias. (GH #176)
• *Was → Now:* under a non-default config directory the underlying tool wrote every outgoing message into an unread, unpruned mailbox tree that later replayed as a stale burst → strays are dead-lettered on appearance, scoped strictly to trees created by that write. (GH #176)
• *Was → Now:* the retry announcement was emitted before the guard that decides whether to retry, so a declined retry still logged once per 100ms poll — 16,604 lines, 12.5% of the day's volume, from one message → the log rides the retry itself and carries the attempt number. (GH #166)
• *Was → Now:* the save path re-read the clock instead of returning the instant it persisted, so anything derived from a save was stamped microseconds off the row it described — the root of the notification loss above → a save returns its own persisted timestamp, and the suite's test doubles stopped discarding caller-supplied timestamps, which is what made this class untestable.
• *Was → Now:* commit fingerprints were stored at whatever abbreviated width the VCS chose at that moment, a width that grows with repo size, so fixed-length readers silently skipped a large share of rows → full identifiers stored, abbreviation only at display.
• *Was → Now:* fleet rebase rebased every session regardless of its integration branch, grafting unrelated unmerged commits and rewriting landed ones, which then made the completion check miscount and refuse correct work → the target branch must match the session's own integration branch; skips are explained. Explicit naming still overrides; consenting to rebase over uncommitted work still does not.
• *Was → Now:* the builtin-sync report attributed its summary and file list to whichever destination heading printed last, and two of three destinations never appeared in readable output → per-destination inline reporting, each write naming its directory.
• *Was → Now:* a scoped test invocation could exit 0 having run nothing — wrong crate name, cwd-dependent path, filter matching nothing — and all three read as green → a wrapper requires exit success **and** a harness that genuinely reported **and** a non-zero pass count; the middle condition carries the weight, because the exit code is exactly what lied. (GH #173)
