## Post 1 — User (top-level)

Live on production — *User*

CAS used to remember your project only when you stopped to ask it a search question. Now the most relevant knowledge, code, and change history can meet you at the start of the turn — automatically, briefly, and without turning your prompt into stored memory.

### Reply (Was → Now)

• *Was → Now:* useful project history stayed behind a search command → CAS now checks knowledge, past changes, and current code together and surfaces only the best matches for the work in front of you.
• *Was → Now:* semantic search covered stored knowledge and commit history but not the source tree itself → current code is now indexed and kept fresh automatically, including removal from every index when a file is deleted.
• *Was → Now:* "is this fixed?" could accidentally mix evidence from old and new processes → CAS now separates the period before the fixed binary ran, the mixed-version overlap, and the clean window after every old process stopped, and says when there is not enough evidence yet.
• *Was → Now:* updating a developer install depended on a private, untracked helper → the updater and installer now live in the repository, with explicit build-only, sync-only, no-restart, and dry-run modes.
• *Was → Now:* synced knowledge could cross team boundaries or reappear after deletion → ownership stays scoped to the active account and team, while deletions propagate as deletions.

## Post 2 — Dev (top-level)

Live on production — *Dev*

Ambient recall now fans one bounded query vector across Knowledge, History, and Code; executable epochs make fixed/unfixed verdicts evidence-aware; and release/update paths enforce migration and stale-runtime safety.

### Reply (Was → Now)

• *Was → Now:* semantic context required an explicit search and source code had no vector namespace → one role-aware query fans out across three isolated corpora with latency/corpus caps, lexical fallback, no prompt persistence, and automatic source-tree reconciliation.
• *Was → Now:* exact-symbol history could rank textual mentions above the commit that touched the symbol → mapped symbol hits receive exact priority while lag and provenance coverage remain explicit on every status path.
• *Was → Now:* process evidence was grouped by release date even while old daemons still served the previous executable → daemon heartbeats record binary epochs, classify CLEAN-PRE/MIXED/CLEAN-POST windows, and return sample-bearing three-valued verdicts.
• *Was → Now:* lower migration gaps and false-positive ledger rows could leave a database advertising a schema it did not have → ordered-prefix discovery and audited safe reconciliation converge released databases, while the release guard runs `component_output_test` whenever the migration registry changes.
• *Was → Now:* a source-build update could replace the binary while stale processes kept executing the old inode → tracked `cas-update` snapshots executable hashes and process start times, signals only the frozen identity, verifies turnover, and exposes non-signalling modes for controlled installs.
• *Was → Now:* cloud knowledge sync mixed full snapshots, ambiguous ownership, and no deletion protocol → personal pushes are incremental and repository-attributed, team traffic is scoped, foreign rows are rejected at ingest, and tombstones preserve deletion truth.
