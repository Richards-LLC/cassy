## Post 1 — User (top-level)

Live on production — *User*

CAS 2.54.0 could stop while opening a terminal session on some x86_64 computers.
CAS 2.54.1 is built for the portable x86_64 baseline again. If you installed
2.54.0, upgrade to 2.54.1.

### Reply (Was → Now)

• *Was → Now:* the 2.54.0 Linux download could contain CPU instructions copied
from a newer build machine → 2.54.1 pins the supported CPU baseline and checks
the finished download before it can be published.

• *Was → Now:* an affected machine could exit during terminal startup with no
useful application error → the replacement runs on supported x86_64 machines
without requiring AVX-512.

• *Was → Now:* replacing the broken download in place would erase release
history → 2.54.0 remains untouched and 2.54.1 is a new, traceable replacement.

## Post 2 — Dev (top-level)

Live on production — *Dev*

Ghostty VT builds now map every supported Cargo target to an explicit Zig
baseline, and the x86_64 release gate rejects EVEX/AVX-512 in the bundled
Ghostty archive.

### Reply (Was → Now)

• *Was → Now:* native Cargo builds omitted Zig's `-Dtarget`, allowing host CPU
features into the static Ghostty VT library → native and cross builds both pass
an explicit ABI-preserving target mapping.

• *Was → Now:* an unknown target warned and silently fell back to a host build →
missing and unknown target mappings fail closed with the supported target list.

• *Was → Now:* release validation exercised behavior but did not inspect the
artifact's instruction encoding → a deterministic guard accepts a baseline
fixture, rejects a seeded incident-matching `vcvttsd2usi`, and audits the final
x86_64 executable before packaging.
