# v2.55.4 — Slack runtime-release posts

## User — top-level

**Restarting Commander went from risking a confusing handoff to waiting for the old hub to fully let go. Now a restart either starts one clean replacement or clearly says it could not.**

- A replacement waits for both the old process and its ownership lock to disappear.
- If the handoff times out, Cassy does not start a competing hub.
- Concurrent starts and restarts preserve one owner.

## Dev — top-level

**Commander restart went from cleanup before authoritative ownership to lock-verified handoff. Now stop failures propagate and replacement launch occurs only after the original process and machine lock are gone.**

- The replacement acquires the machine lock before stale-state cleanup or launch.
- Bounded handoff failure is reported rather than masked by a competing process.
- Concurrent start/restart paths preserve the single-owner invariant.
