# v2.55.5 — Slack runtime-release posts

## User — top-level

**A paired browser could be blocked from reading its own refused pairing request. Now a properly paired device gets a clear response while every other invalid request stays locked down.**

- Successful pairing credentials remain available only to the authorized paired device.
- A valid paired browser can now read the generic refusal for its own capability.
- Unpaired devices, wrong origins, and invalid exchanges remain blocked.

## Dev — top-level

**Bound pairing refusals went from omitting the authorized CORS origin to returning it precisely. Now the controller-origin browser can read its allowed success or generic refusal without weakening fail-closed checks.**

- The exact authorized origin is returned only for a bound cross-machine pairing exchange.
- Unbound, mismatched-origin, and otherwise invalid exchanges expose no allow-origin header.
- The correction preserves fail-closed authorization semantics.
