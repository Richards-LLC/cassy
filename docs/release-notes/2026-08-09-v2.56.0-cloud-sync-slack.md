# v2.56.0 — Slack runtime-release drafts

Status: **Draft only — unposted.**

## User — top-level

**Cloud changes could sit on one machine until something else happened. Now they keep moving automatically, and a restored item is protected from an old delete.**

- Your queued updates continue syncing while CAS is running, even during quiet periods.
- CAS warns before a cloud queue becomes unusually large or old.
- A task or note that exists again locally is not removed remotely by a stale earlier delete.

## Dev — top-level

**Daemon cloud draining went from activity-triggered to cadence-driven. Now persisted queue rows are retried on the daemon schedule, with preflight health thresholds and fail-closed delete handling.**

- `cloud.queue_pending_warning` and `cloud.queue_oldest_warning_secs` surface backlog count and age through preflight with safe defaults.
- Personal and team delete paths neutralize a stale tombstone when its co-located task or entry exists, and failed HTTP deletes retain an error-backed retry row.
- Delete routes accept successful responses, treat an already-absent remote row as converged, and preserve skipped upserts for later sync.
