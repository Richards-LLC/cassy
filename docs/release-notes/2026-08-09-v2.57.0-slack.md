## User — top-level post

**Was: remembering the same decision twice could leave duplicates, and background coordination could feel noisy or vague. Now: CAS can safely consolidate an overlapping memory on purpose, gives steadier recent results, and makes sync, recovery, and worker state easier to trust.**

- Was: an overlap needed manual follow-up and a competing edit could quietly win; recent memories could be ordered ambiguously. Now: an explicit one-step merge keeps one surviving memory with a receipt, rejects a stale concurrent edit, and clearly states a stable order for recent results.
- Was: a full sync recovery or malformed cloud record could be harder to diagnose, and a quiet background queue could leave uncertainty. Now: full sync deliberately starts from a clean read point, errors identify the affected record, and the system gives clearer guidance before work is stranded.
- Was: a healthy cloud pull that found nothing new could look like a failure. Now: CAS says when you are up to date, distinguishes personal-only from team sync, and shows the active scope, daemon state, queue health, and last successful pull.
- Was: an old context echo or duplicate worker appearance could make the experience feel less precise. Now: recall filters its own noise, held workers stay quiet, and a restart reconciles to one clear identity.

## Dev — top-level post

**Was: several correctness boundaries were implicit or non-deterministic across memory, cloud pull, and factory control paths. Now: the release makes those boundaries explicit, atomic, and observable.**

- Was: high-overlap memory saves stopped for manual handling, while a later unconditional update could overwrite an intervening write; recent ordering had no documented stable tie-break. Now: explicit autofix performs a conditional atomic merge with a surviving-ID receipt and conflict response, and recent reports `recent_at desc, id desc` ordering semantics.
- Was: a poisoned pull watermark required indirect recovery, malformed entities lost their identity in errors, and inline `#[cfg(test)]` matchers could dilute the production pull-url guard. Now: `cas cloud sync --full` resets recovery state, deserialize errors retain entity IDs, team pull inserts required skills, knowledge attribution schema self-heals, and the guard excludes test-only modules.
- Was: a personal pull rendered zero synced rows without explaining whether it was healthy, and status hid the current sync context. Now: personal pull explicitly reports up-to-date versus no-team/personal-only versus fetched work; status reports active team, daemon liveness, pending/failed queue state, and last successful pull.
- Was: review dispatch, legacy verification, roster reconciliation, and held-worker output could each report a state detached from the durable delivery boundary. Now: review dispatch binds atomically, repository proof is explicit, amendment routing remains pinned, identities deduplicate on startup, and held workers stay silent.
