## User — top-level post

**Was: a few everyday Cassy actions could leave you guessing whether a saved memory, review decision, sync, or handoff had landed cleanly. Now: Cassy keeps those paths safer, clearer, and more dependable—especially when work is busy or interrupted.**

- Was: a rare sync collision could put an existing daily memory at risk, and a failed review could feel stuck. Now: existing memory is preserved safely, and a rejected review returns through a clear correction path.
- Was: an interrupted session or a quiet sync skip could leave too little context to pick up confidently. Now: Cassy leaves a compact handoff before it runs out of room and explains retained sync work instead of making it look lost.
- Was: a workspace or macOS-specific edge could make an otherwise routine workflow less predictable. Now: writes stay inside approved project locations and the supported macOS suite is substantially steadier.

## Dev — top-level post

**Was: several reliability boundaries were implicit across memory identity, verification storage, factory lifecycle, and release execution. Now: v2.58.0 makes those boundaries explicit, recoverable, and tested on the supported macOS path.**

- Was: a remote daily-entry ID collision could overwrite local truth, verification storage could encounter a missing required schema, and a rejected review could leave close status misaligned. Now: collisions are skipped safely, verification storage self-heals on open, and rejected reviews use the sanctioned amendment exit with aligned epic close reporting.
- Was: workspace writes and proof locations depended too much on convention, while sync skips and pre-compaction exits provided incomplete recovery context. Now: sanctioned roots and tmpfs-proof rejection are enforced, durable task artifacts are collected, skip diagnostics are retained, conflict journals preserve reconciliation context, and workers checkpoint before compaction.
- Was: a release could spend platform-build time before discovering invalid inputs, and macOS test behavior still depended on Linux-shaped assumptions. Now: the workflow validates tag/version/changelog/lock inputs in a dedicated verify job before builds, and the macOS suite covers PTY aliases, portable hub fixtures, FSEvents, history cleanup, migration projections, and reminder references.
