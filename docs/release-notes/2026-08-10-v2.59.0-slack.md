---

## User — top-level post

**Was: switching Claude accounts or waiting on cloud updates could feel opaque. Now: Cassy makes account choice clearer and gives stuck cloud work a direct path forward.**

- Was: choosing a Claude account could require manual setup and leave credentials crossing between profiles. Now: launch can guide you to the right account, each profile keeps its sign-in separate, and you can sign into a named profile directly.
- Was: queued cloud work could sit quietly after a failed attempt. Now: Cassy surfaces that state and gives you a clear retry command to move it forward.
- Was: routine factory checks could be slower or unexpectedly affected by local test state. Now: focused checks return faster and test runs start from a cleaner baseline.

---

## Dev — top-level post

**Was: Claude profile selection, cloud-queue recovery, and test-gate behavior depended on implicit state. Now: v2.59.0 makes those paths explicit, isolated, and easier to recover.**

- Was: bare Claude launch did not reliably choose a profile, credentials could leak across profiles, and login was not scoped to a chosen account. Now: Cassy provides the picker flow, profile-specific credential isolation, the `cas claude login <profile>` path, and an account badge in factory status.
- Was: silently pending cloud rows and terminally skipped pushes lacked a direct operator recovery path. Now: pending state is visible, skipped rows reach a terminal failure record, and `cas cloud queue --retry` resubmits failed work.
- Was: workspace write-target parsing and CI fixtures could produce false failures, while routine test gates paid unnecessary setup cost. Now: Bash target parsing accepts valid writes, fixtures isolate their environment, scoped nextest gates reject unscoped runs, and sccache shares Rust build artifacts.
