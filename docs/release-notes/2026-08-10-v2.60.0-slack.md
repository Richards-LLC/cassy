# v2.60.0 — Slack runtime-release threads

Channel: #cas-internal (`C0B44GUKDK2`)

Publish in this order after the annotated `v2.60.0` tag, official release
workflow, and both release-asset digests are verified: user top-level, user
reply, dev top-level, dev reply. This release does not restart an already
running daemon; the next ordinary daemon restart loads the new version.

---

## User — top-level post

**Live on production · User · Was: a stuck update or a quiet failed check could leave you guessing. Now: CAS tells you what needs attention and carries factory work forward with clearer safety signals.**

## User — reply

- Was: one rejected cloud update could look like a generic failure and obscure work that the server already accepted. Now: CAS identifies the rejected records and reasons, while accepted work keeps moving.
- Was: a failed factory check could wait for someone to discover it manually. Now: CAS sends one clear alert with the affected branch, run, job, and available failing test.
- Was: worker activity, waiting work, and release status could appear healthier than they were. Now: CAS preserves live work ownership, avoids unnecessary wake-ups, and shows the running version consistently.

---

## Dev — top-level post

**Live on production · Dev · Was: cloud rejection, CI, merge, and liveness verdicts could depend on incomplete signals. Now: v2.60.0 preserves itemized outcomes and surfaces bounded, evidence-backed operational state.**

## Dev — reply

- Was: cloud push failures collapsed partial rejection into an opaque result and startup pulls could regenerate queued work. Now: personal and team push paths retain itemized rejection details, accept the successful subset, and startup pulls avoid requeueing already-handled updates.
- Was: completed red CI on main or an active lane could remain invisible, and merge output omitted the latest lane verdict. Now: the daemon relays deduplicated red-run evidence, while merge receipts report red, green, or explicit-unknown CI state with a red-run URL.
- Was: shutdown targeting, task-bound merge attribution, background-process liveness, preassignment recovery, and close-gate feedback could drift from the work actually in progress. Now: each path validates and reports the intended target or holder, with bounded diagnostics when it cannot.
- Was: scoped test, hook, migration, workspace, panic-isolation, ambient-recall, and factory-status behavior had edge cases that obscured the real state. Now: the release tightens their validation, isolation, matching, and version display behavior.
- Was: deploying a new release could be mistaken for activating every running process immediately. Now: existing daemons are left untouched; the next ordinary daemon restart loads v2.60.0.
