# v2.61.1 — Tailscale Serve upgrade-path release threads

Channel: #cas-internal (`C0B44GUKDK2`)

Publish in this order after the annotated `v2.61.1` tag, official Release
workflow, and both release-asset digests are verified: user top-level, user
reply, dev top-level, dev reply. This release does not install binaries or
restart a daemon or hub.

---

## User — top-level post

**Live on production · User · Was: upgrading a hub could leave its secure public address unavailable. Now: the upgrade safely restores the hub’s normal public connection.**

## User — reply

Was: an older hub’s saved connection record could not be read after an upgrade, leaving the old public connection in place. Now: CAS recognizes that saved record, removes only the connection it owns, and publishes the upgraded hub normally.

---

## Dev — top-level post

**Live on production · Dev · Was: v2.60.0 Tailscale Serve receipts were rejected after upgrade because they predated executable metadata. Now: v2.61.1 accepts those legacy receipts and performs owned teardown.**

## Dev — reply

Was: receipt deserialization required `executable`, so shutdown could not remove the exact v2.60.0 mapping and the replacement hub could not claim HTTPS 443. Now: the field defaults to an explicit legacy/unknown value; ownership validation and teardown complete, then the upgraded hub republishes its mapping.
