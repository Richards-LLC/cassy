## User thread

**Top-level:**
Live on production — **User** — Code review is now one clear step: the supervisor reads each delivery's actual changes before merging, instead of a fleet of automated reviewers whose findings mostly got dismissed.

**Reply (Was → Now):**
- Was: every delivery triggered a multi-reviewer pass that took minutes, cost a lot of tokens, and mostly produced findings the supervisor dismissed anyway. Now: the supervisor reads the actual diff against the task's goal at merge time, reruns the affected tests, and records one review receipt — the checks that were actually catching problems.
- Was: finished work could sit in a special "waiting for review" state with its own rules. Now: finished-but-unmerged work simply waits for the merge, and older items in the retired state move over automatically.
- Was: a close could demand a machine-readable review report before it was accepted. Now: closes need the same thing reviews actually verify — merged work and passing tests.
- Install: use `cas update` for an existing installation, or download the
  v3.10.0 archive for Linux x86_64 (SHA-256 `b41b197ad895425f2e8ff3235567b2ee76cd93cdfaa5b8d89a4fa410f6af0594`) or macOS ARM64
  (SHA-256 `ab8cce436bacaf6815f985179d7f3e3b43de1345585219154d7197d300dadd7b`) from the GitHub release.

## Dev thread

**Top-level:**
Live on production — **Dev** — Persona pipeline removed end to end; close gate wants merged work + receipts, not a findings envelope; `pending_supervisor_review` retired via m248; `supervisor_override` replaces `bypass_code_review`.

**Reply (Was → Now):**
- Was: cas-code-review skill/workflow (1.2k-line orchestrator), persona references, worker dispatch refusal gate, `[code_review]` config, `ReviewOutcome`/`Finding` types, and envelope validation (REVIEW EXECUTION UNREPORTED et al.) all shipped in the binary. Now: all deleted (−25k lines net across the train); `Skill`/`Workflow` are no longer PreToolUse-intercepted, `Agent` stays intercepted only for the worktree-spawn guard.
- Was: close under supervisor-owned review parked tasks as `pending_supervisor_review` with an approve/requeue flow in verification_store. Now: unmerged work parks as `awaiting_merge` (the merge-state guard), m248 rewrites existing rows, and legacy cloud/proposal strings ingest-map to `awaiting_merge`; the enum variant is gone with a serde alias for old payloads.
- Was: `bypass_code_review=true` covered both real overrides (tmpfs-proof exception, verification-skip) and the review gate. Now: `supervisor_override` (supervisor-only, non-empty reason, decision-note logged) carries the surviving overrides; the old flag is a warned alias for one release.
- Was: the supervisor skill told you to run a Phase 4 full persona pass on the assembled epic. Now: Phase 3's merge-time diff review is the canonical review (diff vs spec, ownership, receipts, touched-module reruns, `verification action=add`), and Phase 4 is the assembled-tree `cargo nextest run -p cas` gate.
- Validation and artifact: `cargo check --workspace --tests`, `cargo nextest run -p cas`, doctests, merge-queue validation of the single integration PR. The published archives are
  `cas-x86_64-unknown-linux-gnu.tar.gz` (SHA-256 `b41b197ad895425f2e8ff3235567b2ee76cd93cdfaa5b8d89a4fa410f6af0594`) and
  `cas-aarch64-apple-darwin.tar.gz` (SHA-256 `ab8cce436bacaf6815f985179d7f3e3b43de1345585219154d7197d300dadd7b`).
