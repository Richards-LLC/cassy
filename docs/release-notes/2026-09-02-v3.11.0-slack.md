## User thread

**Top-level:**
Live on production — **User** — cas update and cas doctor now read like a status report: one line per project, one grouped page of checks, and every warning explains itself.

**Reply (Was → Now):**
- Was: `cas update` printed about 860 lines for 14 projects, most of them "0 things synced" and repeated warnings, and `cas doctor` opened with 160 lines of sync noise before a wall of one-line checks. Now: `cas update` shows a table with one row per project and a closing banner, prints detail only where something warned or failed, and says each warning once. `cas doctor` opens with a header, groups its checks into Store, Indexes, Cloud, Config and Integrations, puts each fix on its own line, and ends with a count and elapsed time. Add `--verbose` to either command for the full transcript.
- Was: cloud push and pull printed nine zero-count lines and one error line per failed row. Now: one line per push and per pull, with only the non-zero counts and failures grouped by cause with a retry hint.
- Install: use `cas update` for an existing installation, or download the
  v3.11.0 archive for Linux x86_64 (SHA-256 `{{LINUX_SHA256}}`) or macOS ARM64
  (SHA-256 `{{MACOS_SHA256}}`) from the GitHub release.
