## User thread

**Top-level:**
Live on production — **User** — Cassy releases now run through one fail-closed checklist that remembers every way a release has failed before, and teaches itself when a new one appears.

**Reply (Was → Now):**
- Was: the release steps and their known pitfalls lived in the supervisor's memory, so the same failures repeated across releases and each cost a retry. Now: a single release procedure with a mechanical gate refuses to proceed until every known failure class is checked, keeps a log of what went wrong before, and requires any agent that hits a new failure to record it and add a check before retrying.
- Install: use `cas update` for an existing installation, or download the
  v3.12.1 archive for Linux x86_64 (SHA-256 `{{LINUX_SHA256}}`) or macOS ARM64
  (SHA-256 `{{MACOS_SHA256}}`) from the GitHub release.

## Dev thread

**Top-level:**
Live on production — **Dev** — cas-cut-release skill (three harness mirrors) + scripts/release-gate.sh with 12 fail-closed checks and a self-learning failure log; release.sh cleans stale BLAKE3 outputs before its audit.

**Reply (Was → Now):**
- Was: release steps were memory-driven; the local gate could not reproduce the merge-queue shard runner (archive, no checkout, no rg); a pre-warm in the tag worktree left duplicate BLAKE3 outputs that failed release.sh's audit; snapshot and version-literal failures surfaced only in the queue. Now: `scripts/release-gate.sh <version>` runs failure-log integrity, version-literal grep, cargo check --workspace --tests, nextest, doctests, an archive-mode run from a home-disk remap outside the checkout with no rg, snapshot portability under a deep TMPDIR and no COLUMNS, root projection and ledger sync, changelog/version alignment, release-script preconditions, procedure guardrails, and clean tree; `--learn` appends a dated entry to all three failure-log mirrors; the gate fails if a logged entry has no check id; `scripts/test-release-gate.sh` covers 13 fixture cases; `release.sh` removes stale blake3-* build and fingerprint dirs before the ISA audit; the skill is registered in builtins.rs and linked from cas-supervisor and docs/RELEASE_SLACK_RUBRIC.md.
- Validation and artifact: this release was cut through the new train itself: `scripts/release-gate.sh 3.12.1` on the prep tree (all rows PASS), scripts/test-release-gate.sh 13/13, builtin_flavor_drift_test 15/15, cargo check clean. The published archives are
  `cas-x86_64-unknown-linux-gnu.tar.gz` (SHA-256 `{{LINUX_SHA256}}`) and
  `cas-aarch64-apple-darwin.tar.gz` (SHA-256 `{{MACOS_SHA256}}`). Linux and
  macOS are both available from CI, regardless of the tagger's host.
