## User thread

**Top-level:**
Live on production — **User** — Cassy now keeps factory work visible through restarts and makes release communication safer across every harness.

**Reply (Was → Now):**
- Was: a supervisor restart could strand live workers or leave confusing
  warnings, and duplicate work was easy to miss. Now: workers stay reachable,
  duplicate task descriptions are called out with meaningful identifiers, and
  completed work is not re-delivered.
- Was: release communication depended on a single posting route and manual
  timing. Now: every harness can use one checked, paced Slack transport with a
  durable receipt and no credentials in project files.
- Install: use `cas update` for an existing installation, or download the
  v3.13.0 archive for Linux x86_64 (SHA-256 `{{LINUX_SHA256}}`) or macOS ARM64
  (SHA-256 `{{MACOS_SHA256}}`) from the GitHub release.

## Dev thread

**Top-level:**
Live on production — **Dev** — Cassy now reconciles factory identity and delivery boundaries while shipping a checked, multi-harness Slack release path.

**Reply (Was → Now):**
- Was: factory restart identity, duplicate detection, merge CI diagnostics,
  and assignment delivery each had a narrow boundary. Now: restart-aware
  registry reconciliation, description/identifier similarity scoring,
  SHA-scoped check-run receipts, and final task-state plus harness-aware brief
  delivery cover those boundaries end to end.
- Was: release notes required a route-specific manual handoff. Now:
  `mecha-cassy` performs authenticated four-tool preflight, ordered
  user/dev threaded posting with one-second pacing, retry handling, and
  POSTED receipts while keeping tokens in environment references only.
- Was: navigation could lag the assembled source tree. Now: the generated code
  map and builtin reference ledger are refreshed with the release inputs.
- Validation and artifact: the assembled tree passes the full `cas` nextest
  and doctest suites, projection and ledger checks, and the release gate. The
  published archives are `cas-x86_64-unknown-linux-gnu.tar.gz` (SHA-256
  `{{LINUX_SHA256}}`) and `cas-aarch64-apple-darwin.tar.gz` (SHA-256
  `{{MACOS_SHA256}}`). Linux and macOS are both available from CI, regardless
  of the tagger's host.
