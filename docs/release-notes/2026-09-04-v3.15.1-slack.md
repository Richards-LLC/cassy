## User thread

**Top-level:**
Live on production — **User** — Cassy v3.15.1: the factory stops wedging on task close, released workers can actually be shut down, and recording a verdict no longer fails on a busy store.

**Reply (Was → Now):**
- Was: closing a task could get stuck forever with "repository proof changed" if the worker had already moved on; shutting down an idle worker by name was refused as "not found" while the same message listed it; recording a verdict under load failed instantly with "database is locked"; tests could read the machine's own project configuration and fail for reasons unrelated to the change. Now: a close verifies against the delivered commits, so moving the branch afterwards is fine and a real drift simply mints a fresh check; shutdown accepts the worker by name or id and tells you if a policy refused it; a verdict waits its turn and lands; tests are isolated from the machine they run on and the release gate neutralizes stray config instead of asking a human to move files.
- Install: use `cas update` for an existing installation, or download the
  v3.15.1 archive for Linux x86_64 (SHA-256 `{{LINUX_SHA256}}`) or macOS ARM64
  (SHA-256 `{{MACOS_SHA256}}`) from the GitHub release.

## Dev thread

**Top-level:**
Live on production — **Dev** — v3.15.1: RepositoryProofBoundary.anchor_commits with a DeliveredContentIntact verdict and fresh-cycle mint on drift; one worker identity lookup for shutdown_workers/worker_status; BEGIN IMMEDIATE with bounded retry for verification writes plus journal_size_limit; TestEnvGuard::temp_home pins CAS_ROOT by default and the release gate gains an ancestor-proxy-config row.

**Reply (Was → Now):**
- Was: verify_repository_proof required whole-boundary equality (HEAD + dirty digest) and close replayed a Pending dispatch without a proof check; the worker_names selector matched name only and parsed only comma-separated strings; verification_tools used unchecked_transaction (DEFERRED) then wrote, hitting SQLITE_BUSY on the snapshot upgrade with no busy-handler call; find_cas_root's worktree branch mapped tests onto the main repo's .cas. Now: anchor_commits (serde default) bound from the commit receipt and an ahead-of-base tip, evaluate_repository_proof → Unchanged | DeliveredContentIntact | Err(bound, current, missing anchors), both digests recorded on the verdict; worker_answers_to shared by both selectors and the known-workers listing, bracketed/quoted elements tolerated, REFUSED vs NOT FOUND split; shared_db::begin_immediate_with_retry (retries only while acquiring the lock), reindex reads before BEGIN, journal_size_limit 64 MiB, 8-writer contention test; CAS_ROOT pinned at <temp HOME>/.cas in temp_home (5,170/5,170 lib green), ancestor-proxy-config gate row neutralizes via CAS_ROOT, test-release-gate.sh defaults CAS_RELEASE_GATE_HOME_DIR to /var/tmp; *.snap.new ignored.
- Validation and artifact: {{VALIDATION_SUMMARY}} The published archives are

  `cas-aarch64-apple-darwin.tar.gz` (SHA-256 `{{MACOS_SHA256}}`). Linux and
