## User thread

**Top-level:**
Live on production — **User** — Cassy v3.15.4: one `cas update` now finishes the job (the refresh runs with the version you just installed), supervisors in different sessions on one machine can finally message each other and get woken, and two hub commands racing no longer stall or fail.

**Reply (Was → Now):**
- Was: after an update the first run reported stale results and you had to run `cas update` again; a supervisor messaging another supervisor in a different session on the same clone saw "enqueued" forever and the recipient never woke; worker_status listed other sessions' supervisors without saying what they were working on; two hub lifecycle commands racing meant a guaranteed ten-second stall and a spurious failure; a release gate on a busy machine aborted because a child `cas init` hit its fixed five-minute watchdog; two release gates for the same version shared one artifacts directory. Now: the post-install refresh runs in the newly installed binary and the receipt says which version did the work (and refuses to claim success if it could not); cross-session supervisor messages route to the recipient's session, wake their pane, and report a real reason when undeliverable; worker_status names each supervisor's current epic across sessions; the hub waiters return as soon as a live hub satisfying the request exists; gate children get a raised, capped init budget; each release run has its own directory and PID and the pipeline waits for checks to actually pass before enqueueing.
- Install: use `cas update` for an existing installation, or download the
  v3.15.4 archive for Linux x86_64 (SHA-256 `{{LINUX_SHA256}}`) or macOS ARM64
  (SHA-256 `{{MACOS_SHA256}}`) from the GitHub release.

## Dev thread

**Top-level:**
Live on production — **Dev** — v3.15.4: --post-swap child runs the refresh with refresh_binary_version + version guard; prompt_queue rows stamped with the recipient's factory_session, registry-verified peer-supervisor wake (sender name preserved), message_status deadline narrative; worker_status supervisor epic column; CAS_INIT_TIMEOUT_SECS (≤3600) carried across sandbox scrubs and exported by the gate; RelaunchIntent for hub stop/start waiters; scripts/release-train.sh gate + pipeline.

**Reply (Was → Now):**
- Was: execute() ran refresh_all_projects in the pre-update image; queue rows carried the sender's factory_session so no daemon selected cross-session rows (abandoned_unknown_target after 15 min) and the sender display name collapsed to the literal "supervisor" so source_is_supervisor never resolved; init watchdog fixed at 300 s with only NO_TIMEOUT as an opt-out and the sandbox scrubbed every CAS_*; hub waiters waited for the machine lock to be FREE while a healthy hub legitimately held it; release wrappers were hand-written per release under a version-keyed artifacts dir. Now: perform_update delegates post-install phases to the installed binary via --post-swap, single JSON receipt, refresh_binary_version verified against the installed version, non-zero exit + "run cas update again" when re-exec fails; row_factory_session() stamps the recipient's session, supervisor_wake_decision(source_is_supervisor) keyed on an agent-store role lookup, peer rows carry the sending supervisor's name, pending_deadline_narrative(); factory_supervisor_overlap::resolve_supervisor_epic; CAS_INIT_TIMEOUT_SECS clamped at 3600 and forwarded through CasSandbox/TestEnvGuard as the sole exemption, gate exports 900 s and names it; running_hub_satisfies_request + wait_for_lock_or_satisfying_hub, StopOutcome::AlreadySatisfied, RelaunchIntent on stop_with_output (None = byte-identical plain stop); release-train.sh (run dir v<version>-<worktree>, recorded PID, --status/--stop, pipeline with bucket==pass checks-wait, bounded re-enqueue, SINCE-at-enqueue, MERGED + landed-main.sha), self-tests 33 + 23.
- Validation and artifact: {{VALIDATION_SUMMARY}} The published archives are
  `cas-x86_64-unknown-linux-gnu.tar.gz` (SHA-256 `{{LINUX_SHA256}}`) and
  `cas-aarch64-apple-darwin.tar.gz` (SHA-256 `{{MACOS_SHA256}}`). Linux and
  macOS are both available from CI, regardless of the tagger's host.
