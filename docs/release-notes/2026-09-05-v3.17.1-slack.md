User top-level

```text
*Live on production — User — Cassy v3.17.1*
Was: updates could unpack bad bytes and concurrent background writes could damage settings. Now: integrity checks and atomic writes protect both.
```

User reply

```text
• *Safer updates* — Was: a downloaded archive was unpacked before its integrity was checked. Now: it must match GitHub's published SHA-256 first, or your existing installation stays untouched.

• *Stable settings* — Was: two background updates could overlap and leave a damaged settings file. Now: updates take turns and replace the file atomically with its existing privacy preserved.

• *Separate Slack conversations* — Was: two nearby Slack threads could collide and share one conversation. Now: channel, thread, and project identify each conversation. Already-live threads start fresh once after the update, then restart resumes the right one.

• *Truthful pull-request status* — Was: a failed pull-request lookup looked exactly like no pull request existed. Now: uncertainty is shown plainly instead of a false answer.

• *Faster repeat builds* — Was: a linked checkout could rebuild after nothing relevant changed. Now: Cassy watches the real Git files and leaves unchanged builds fresh.

• *Verified outside delivery* — Was: completed work delivered outside the source repository could not use its approved production evidence. Now: a matching passed receipt can prove delivery without weakening other checks.

• *Updated design default* — Was: the factory taste lane routed design-quality work to Codex GPT-6 Astra. Now: the factory taste lane routes to Claude Fable 5.1 at medium effort instead of Codex GPT-6 Astra. Explicit Astra and Opus requests still work, and taste fails closed when the Claude account is unavailable.

• *Clearer bug filing* — Was: it was easy to send an operational bug to the wrong issue board. Now: each Cassy distribution names the right project, Cassy, MechaCassy, or Cassy Cloud destination and tells you where to file it.

• *Truthful updates* — Was: a post-swap refresh failure could look skipped. Now: `cas update` reports the failed refresh and preserves the executable version and per-project outcomes so recovery guidance matches what happened.

Install
Update with `cas update`, or download the Linux x86_64 or macOS ARM64 archive from the Cassy v3.17.1 release. SHA-256: Linux `{{LINUX_SHA256}}` · macOS `{{MACOS_SHA256}}`.
```

Dev top-level

```text
*Live on production — Dev — Cassy v3.17.1*
Was: download integrity, concurrent config writes, Slack session identity, and external close evidence had gaps. Now: each boundary is explicit and fail-closed.
```

Dev reply

```text
• *Installer receipt* — Was: `download_and_install` trusted HTTPS and the selected tag but extracted before byte verification. Now: the exact asset digest from the GitHub Release API is required and checked before `tar` or replacement. This is same-authority corruption detection, not independent authentication.

• *Atomic project config* — Was: project alias and canonical-id read/modify/write paths could race and truncate or discard unrelated TOML. Now: both share a cross-process lock, create same-directory temps as 0600 before bytes, sync, preserve prior mode, and rename atomically.

• *Scoped Slack sessions* — Was: the first 16 timestamp bytes formed the session UUID and an in-memory set forgot successful sessions on restart. Now: SHA-256 over `[channel, thread_ts, project]`, durable success state, and a per-key queue prevent collisions and overlapping children. The identity migration starts a fresh child once for already-live threads.

• *Session-state failures* — Was: malformed durable state silently became empty, and a post-success persistence error made the next request look new. Now: corrupt state blocks child launch with an actionable error, while successful establishment remains known in memory before persistence.

• *PR lookup tri-state* — Was: missing `gh`, nonzero lookup, invalid UTF-8, and definite empty output all rendered `PR: none`. Now: URL, none, and unknown are distinct, with fixed redacted reasons and existing session-stop consumers preserved.

• *Precise build inputs* — Was: `build.rs` watched nonexistent linked-worktree paths or broad directories that included Cargo output. Now: it watches per-worktree HEAD/index plus the exact shared ref/packed state. Previously absent optional environment files still need another ordinary trigger or clean rebuild.

• *External verification receipt* — Was: a completed external-production receipt could not satisfy the code-task zero-commit evidence branch. Now: a separate receipt ID requires exact authority, task, parent, active session, gate, completed/pass verdict, and portable evidence. Every other gate remains active.

• *Taste route* — Was: `taste` selected Claude Opus and its routing guidance could drift. Now: registry recipe `claude_fable` selects model `claude-fable-5-1` at medium effort. Astra is explicit-only, the disabled Opus fallback edge remains fail-closed, and taste fails closed when the Claude account is unavailable.

• *Issue routing registry* — Was: bug-filing guidance named no stable component destination. Now: compiled defaults map the project, Cassy, MechaCassy, and Cassy Cloud through `issues.repo`, with `[issues.components]` overrides. Session start, doctor, config get/set, managed guidance, and all harness skill mirrors consume the same registry, and operational bugs are directed to the matching repository first.

• *Post-swap refresh receipts* — Was: `cas update --json` labeled child refresh as skipped even when the refresh ran and failed. Now: `refresh_binary_version` and per-project `refresh_status=refresh_failed` remain in the receipt, while `spawn_failed` and `refresh_failed_no_receipt` are separate outcomes with truthful guidance.

• *Stable gate diagnostics* — Was: the release gate could preserve host-specific `fatal: not a git repository` wording. Now: doctor snapshots normalize that message alongside parent-directory and mount-boundary forms, and the failure is recorded in the release ledger.

Validation
Require the full release gate, protected-main pipeline, exact landed SHA, and published-asset receipts before publication. Published archives: `cas-x86_64-unknown-linux-gnu.tar.gz` (`{{LINUX_SHA256}}`) and `cas-aarch64-apple-darwin.tar.gz` (`{{MACOS_SHA256}}`).
```
