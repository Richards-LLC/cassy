User top-level

```text
*Live on production — User — Cassy v3.18.0*
Was: Commander screens were dark-only and hard to scan. Now: the fleet, attention, transcript, and pairing experience share a clear light-or-dark visual language.
```

User reply

```text
• *A house design language* — Was: Commander used one dark presentation with separate visual treatments. Now: it follows the Petrastella design language in light and dark, with readable type and intentional state colour.

• *Fleet at a glance* — Was: machines appeared as a list of unrelated cards. Now: a verdict and dot plot show the fleet's working state as one composed figure.

• *Attention you can follow* — Was: important events were dense and easy to lose. Now: a readable timeline shows what needs attention, when it happened, and what you can do.

• *Transcript as evidence* — Was: terminal output and activity history competed for attention. Now: the transcript reads like a ledger while terminal detail stays available where it belongs.

• *Pairing with a clear path* — Was: pairing and connection states could look like one opaque process. Now: each surface names the current step, outcome, and recovery path.

• *Choose your appearance* — Was: the interface offered no clear way to choose a comfortable scheme. Now: Appearance is an explicit choice in the command palette, alongside the system default.

Install
Update with `cas update`, or download the Linux x86_64 or macOS ARM64 archive from the Cassy v3.18.0 release. SHA-256: Linux `{{LINUX_SHA256}}` · macOS `{{MACOS_SHA256}}`.
```

Dev top-level

```text
*Live on production — Dev — Cassy v3.18.0*
Was: Commander styling, visual validation, and several release-bound guardrails were separate contracts. Now: generated tokens, strict visual QA, and fail-closed checks share one releaseable path.
```

Dev reply

```text
• *Generated tokens* — Was: token output could drift silently from its source data and consumers. Now: generated light/dark tokens and a drift test keep the source, CSS, and runtime reads aligned.

• *Visual-QA gate* — Was: a source change could pass tests while introducing contrast, clipping, or invisible-text defects. Now: CI and the release gate render light and dark desktop and phone surfaces with strict findings and receipts.

• *Shared allowlists* — Was: visual exceptions could be expressed differently by each check. Now: shared CSS allowlist semantics make intentional exceptions explicit and reviewable.

• *Attention reliability* — Was: a flaky `hub::attention` test could redden an otherwise valid run. Now: the test is stable while preserving the behavior it covers.

• *Workspace guard* — Was: heredoc bodies could be mistaken for filesystem targets. Now: the guard ignores heredoc contents while retaining its real path protections.

• *Fail-closed bug reports* — Was: an unfiled operational report could look handled after a filing failure. Now: `report_cas_bug` stages the report and fails closed until filing succeeds.

• *Rebased delivery anchors* — Was: pre-close could lose a valid delivery after a branch anchor was rebased. Now: a named commit receipt recovers the rebased anchor without weakening merge evidence.

Validation
Require the full release gate, protected-main pipeline, exact landed SHA, and published-asset receipts before publication. Published archives: `cas-x86_64-unknown-linux-gnu.tar.gz` (`{{LINUX_SHA256}}`) and `cas-aarch64-apple-darwin.tar.gz` (`{{MACOS_SHA256}}`).
```
