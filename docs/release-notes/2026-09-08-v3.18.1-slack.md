# Slack draft — Cassy v3.18.1 runtime release

Channel: #cas-internal (C0B44GUKDK2)

Status: DRAFT — source preparation only. Do not post until v3.18.1 is published
and the release gate and published-asset receipts are complete.

User top-level

```text
*Live on production — User — Cassy v3.18.1*
Was: a hub's public connection could become unclear after a restart. Now: Cassy keeps hub access dependable across relaunches and makes connection failures easier to understand.
```

User reply

```text
• *A route that stays put* — Was: restarting a hub could leave its public route pointing at the wrong place or make its state hard to read. Now: the hub remembers its CAS-created public route and reports when that route no longer reaches the live hub.

• *Diagnostics with a clear next step* — Was: a public route returning an error could look like a generic connection failure. Now: Cassy distinguishes a route whose backend is gone and tells you how to restore the route or use another reachable hub URL.

• *Connection states you can trust* — Was: connection and pairing previews could show a different state from the product. Now: Commander’s fixtures use the same connection surfaces as the app, including failure, retry, and pairing recovery states.
```

Dev top-level

```text
*Live on production — Dev — Cassy v3.18.1*
Was: hub transport state and Commander connection fixtures relied on separate assumptions. Now: durable Tailscale Serve ownership, host transport diagnostics, 502-specific recovery, and shared connection rendering are covered by the release path.
```

Dev reply

```text
• *Transport persistence* — Was: a relaunch could lose the lifecycle intent and ownership needed to inspect a CAS-created Tailscale Serve route. Now: the hub persists the requested Serve transport, reuses the owned port, and carries the ownership receipt through status checks.

• *Transport diagnostics* — Was: `cas hub status` could report a process without proving that its public route still targeted the live hub. Now: status exits non-zero when the route target differs from the live hub shim, and `cas doctor --host` includes a `hub transport` row with a remedy.

• *Pairing recovery* — Was: an HTTP 502 during reverse pairing looked like generic unreachable-host output. Now: the error names the route-without-backend condition and preserves the recovery guidance.

• *Fixture fidelity* — Was: visual-QA fixtures hand-built connection and pairing markup separately from the application. Now: they exercise the shared connection surface and open pairing dialogs through the same production path.
```
