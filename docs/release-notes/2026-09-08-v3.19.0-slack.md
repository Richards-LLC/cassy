User reply

```text
*Daily confidence*

• *Clearer health checks* — Was: one warning could cover several different problems. Now: checks separate missing projects, incomplete setup, and unreachable services with the right remedy.

• *History from the right place* — Was: code history could look in the wrong repository. Now: it uses the configured history source or the project's GitHub home.

• *Honest hub status* — Was: a healthy public route could look loopback-only. Now: status shows when the live public route is working.

*Safer recovery*

• *Cloud conflicts* — Was: a project-name mismatch could look like a retryable sync failure. Now: Cassy explains the conflict and what to change.

• *Safe cleanup* — Was: cleanup could drift after its preview. Now: Cassy checks the exact rows and stops if state changes.

• *Accepted changes* — Was: accepted shared changes could disappear from the local task list. Now: they appear as open tasks in the intended project.

• *Known projects* — Was: a missing folder and an uninitialized project could look the same. Now: each gets a precise repair path.

*Reliable work*

• *Messages you can find* — Was: a delivered message could be invisible or repeat. Now: it stays visible until observed and repeated delivery is bounded.

• *Safe urgent requests* — Was: an urgent request could affect the wrong assignment. Now: ownership is checked before the request takes effect.

• *Clean restarts* — Was: clearing a conversation could resume under the wrong identity. Now: the recipient's new session is confirmed before work continues.

• *Predictable parallel builds* — Was: simultaneous builds could compete for the machine. Now: configured limits keep them within a safe budget.

*Trustworthy updates*

• *File uploads you can trust* — Was: a successful byte count did not prove a usable image arrived. Now: uploads are downloaded, hash-checked, decoded, and previewed.

• *Safer installs* — Was: an installer could replace a program without a valid published digest. Now: missing, malformed, or mismatched digests stop replacement.

Install: update with `cas update`, or download the Linux x86_64 archive (`{{LINUX_SHA256}}`) or macOS ARM64 archive (`{{MACOS_SHA256}}`) from the Cassy v3.19.0 release.
```

Dev reply

```text
*Branch and build controls*

• *Close validation* — Was: close and commit guards could inspect the wrong target worktree or stale epic base. Now: both resolve the declared target, and spawns retain the focused epic base.

• *Push safety* — Was: a rejected push existed only as hook stderr. Now: non-factory destinations are refused and recorded in worker activity.

• *Build throttling* — Was: concurrent builders could ignore configured limits. Now: `factory.max_concurrent_builders` and `factory.worker_build_jobs` cap process and Cargo jobs, with the active throttle in spawn output.

• *Release drift* — Was: committed hub-web `dist` output could drift from its source unnoticed. Now: the release gate rejects stale generated assets.

*Delivery and messaging*

• *Parked retries* — Was: a parked delivery anchor could point at a stale session. Now: retries refresh the anchor and preserve actionable upstream Slack errors.

• *Urgent ownership* — Was: an urgent wake could consume work owned by another session. Now: assignment ownership is validated before dispatch.

• *Context reset* — Was: clearing context could leave the recipient under an old identity. Now: the reset runs in the recipient harness and confirms the new transcript.

• *Bounded redelivery* — Was: an unobserved Claude delivery could repeat without a clear cap. Now: attempts and retries stay within a bounded delivery budget.

• *Session routing* — Was: a worker relay could land in a generic supervisor session. Now: relays route to the owning supervisor session.

• *Inbox visibility* — Was: a transport-delivered receipt could hide an unread row. Now: it remains pollable until an observed wake consumes it, and consumption retires exactly one row.

*Cloud synchronization*

• *Conflict diagnostics* — Was: a cloud HTTP 409 could become a generic queue retry. Now: `cas cloud sync` and `cas doctor` name the project conflict, park affected rows, and give the exact remedy.

• *Verified purge* — Was: foreign-row cleanup could delete a different count or re-admit rows after its preview. Now: `cas cloud pull --purge-foreign` applies the verified set exactly and aborts on drift.

• *Proposal materialization* — Was: an accepted cross-project proposal could remain absent locally. Now: `cas cloud pull` creates the open target task from the server-attested destination and prints concrete pull errors.

*Diagnostics and configuration*

• *Epic status* — Was: `mcp__cas__coordination action=epic_status` could spend unbounded work on a large epic. Now: `offset`, `limit`, and `summary` provide bounded pages and a fast ancestry-only view.

• *Known-repository classifier* — Was: `cas doctor` treated missing roots and live roots without a Cassy store alike. Now: `cas doctor --fix` prunes only missing roots and gives safe manual guidance for live roots.

• *History repository* — Was: history indexing reused the bug-intake repository setting. Now: `history.github_repo` is independently configurable through `cas config`, with GitHub-origin fallback.

• *Upstream reachability* — Was: proxy startup exposed only a coarse connection failure. Now: `cas doctor` probes each configured upstream once, shows redacted detail, and boot output records reachable routes.

• *Healthy hub route* — Was: `cas hub status` printed loopback-only for a live CAS-created Tailscale Serve route. Now: it reports the live hub target while retaining distinct unavailable and unrecorded-route states.

• *Portable Codex workers* — Was: Playwright MCP inherited a fixed host home path. Now: Codex derives `HOME` and its profile from the host home.

*MechaCassy and installation*

• *Read preflight* — Was: the skill treated an available transport as proof that posting was safe. Now: it requires the read preflight and documents the approved fallback.

• *Channel operations* — Was: channel resolution, edits, and deletes had incomplete guidance. Now: the skill documents the complete channel contract and safe error handling.

• *Upload integrity* — Was: file size or a success response could stand in for proof. Now: downloaded SHA-256 equality, image decoding, and visible preview are required.

• *Install receipts* — Was: the installer could trust an incomplete asset receipt. Now: extraction and replacement require the selected published asset's valid SHA-256.

Validation: `scripts/release-gate.sh 3.19.0 --only changelog-and-versions,version-literals`; `cargo check -p cas --lib --tests`.

Install: `cas-x86_64-unknown-linux-gnu.tar.gz` (`{{LINUX_SHA256}}`) and `cas-aarch64-apple-darwin.tar.gz` (`{{MACOS_SHA256}}`) are published by CI for Linux and macOS.
```
