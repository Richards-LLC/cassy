User reply

```text
*Quality at the epic level*

• *One walk of the whole feature* — Was: each task was exercised alone, so problems between tasks only surfaced after release. Now: when any task in an epic names a user outcome, Cassy runs one combined 60-minute walk of the assembled build alongside the release checks and records coverage, misses, and any place two tasks contradict each other.

• *Honest epic close* — Was: an epic could close on the strength of its tasks' individual reports. Now: the epic close needs the walk's note and applies the same evidence rules before it reads the close reason.

*Telemetry in QA*

• *Your analytics, your sweep* — Was: nobody looked at production analytics between client emails, and zero events from a reporter looked like a clean run. Now: a project can point Cassy at its own read-only sweep script; new, rising, high-rate, and blackout findings land in the QA ledger as evidence, and a ledger says plainly when no sweep is configured.

*Already live on hosts that updated from main*

• *Recall that keeps arriving* — Was: long Claude Code sessions silently stopped receiving Cassy's recall and factory mail. Now: the same context arrives through the tool path once per prompt, and `cas doctor` reports a silent prompt hook.

• *Faster release checks* — Was: every release check ran the test suite twice. Now: once, with an unchanged release re-checked in under a minute.

Report: the v3.21.0 release report (PDF and HTML) is attached below in this thread.

Install: update with `cas update`, or download the Linux x86_64 archive (`dfcbdf1936dc1c8a8643153ed1cfd53e6ac621fde6f00847d4cbf7de806deed2`) or macOS ARM64 archive (`ebbd648122c72533feb8dd2b65329c4280a5ea0f1fe64e75922413e3925cfb6b`) from the Cassy v3.21.0 release.
```

Dev reply

```text
*Epic flow walk*

• *Supervisor procedure* — Was: the supervisor checklist ran the full suite on the epic branch and closed. Now: after the detached gate launch, one verifier-class evidence agent walks the assembled tip with a combined matrix over every child `demo_statement` (same quotas, 8-cell cap, 60-minute box, cross-child contradiction rule) and writes `~/.cas/artifacts/<epic-id>/LEDGER.md` plus one `Epic flow walk` note; one pass per epic, resumed rather than repeated on gate retries.

• *Verifier gate* — Was: `verification_type=epic` checked subtasks and the close reason. Now: it enumerates child demos first, requires the walk note and ledger on the current tip, and applies the Step 0A REJECT table before reading the close reason.

*Telemetry sweep contract*

• *Config* — Was: no seam for project analytics in QA. Now: `qa.telemetry_sweep` (string, optional, project-relative) round-trips through get/list/set and the config registry.

• *Skill* — Was: ledgers had four evidence labels. Now: the sweep runs read-only as step one with `--reporter <value>` when present; six-field TSV findings (`kind subject count people window sample`) become `eyewitness/telemetry` rows; the header records `sweep: configured — <path>` or `sweep: not configured`; a PostHog HogQL example and known-noise table are documentation only.

*Carried from main since 3.20.0*

• *Turn context delivery* — Was: recall and factory inbox reached a session only through the UserPromptSubmit hook, which Claude Code 2.1.263+ omits in long-lived team sessions. Now: PostToolUse and the MCP response wrapper deliver them once per prompt when that hook is silent, and a doctor row counts misses (PR #772, #763).

• *Ambient ranking* — Was: discovery read the eight most recently updated rows, so same-day exact matches were missed and the semantic step timed out at 400 ms. Now: overlap ranks before recency, prompt terms cap at 16, the semantic deadline is 1500 ms, and commits sort behind guidance (PR #773, #764).

• *Release gate* — Was: the gate ran the workspace suite twice and kept no per-row timings. Now: a single suite execution across the nextest and archive rows, per-row timings, and `--reuse` for unchanged trees (PR #771).

Validation: full release gate green on the exact candidate tip 4d93394e (second run; the first failed one skill-size guardrail test that was fixed on the assembled tree); merge queue validated the synthetic tree (PR #777, run 34356617509). Tag-to-published 163 s; green-to-published 2,402 s.

Install: `cas-x86_64-unknown-linux-gnu.tar.gz` (`dfcbdf1936dc1c8a8643153ed1cfd53e6ac621fde6f00847d4cbf7de806deed2`) and `cas-aarch64-apple-darwin.tar.gz` (`ebbd648122c72533feb8dd2b65329c4280a5ea0f1fe64e75922413e3925cfb6b`) published by CI for Linux and macOS.
```
