## User thread

**Top-level:**

```text
*Live on production — User — Cassy v3.24.0*
Was: routine coordination and recovery could stall or expose details. Now: work completes more safely, predictably, and with clearer recovery.
```

**Reply (Was → Now):**

```text
*Safer coordination*

• *Clear identities* — Was: one exact identifier was required. Now: start, claim, and close accept a name or ID.

• *Supported messages* — Was: coordination could use the wrong transport. Now: messages stay on the supported path.

• *Gate ownership* — Was: only one owner could finish a gate. Now: authorized reviewers can finish it and get a clear ownership warning.

• *Bounded completion* — Was: large completion checks could wait too long. Now: checks finish within a limit and safely show unfinished work.

• *Retryable proof* — Was: a close retry could lose approved evidence. Now: the approved evidence is reused when the proof is still valid.

• *Merged results* — Was: proof could point at an old result after a merge. Now: it follows the result that was actually published.

*Clearer recovery*

• *Credential settings* — Was: variable placeholders could fail silently. Now: values and defaults expand, and missing required settings explain the fix.

• *Hub recovery* — Was: a stuck hub could block a restart. Now: startup is transactional, forced recovery restores service, and health checks explain the remedy.

• *Fresh notices* — Was: old assignment notices could reappear. Now: they disappear once the work has started or finished.

*Protected execution*

• *Profile write-through* — Was: credentials in linked profiles did not reliably follow the profile. Now: configured credentials and linked profile updates stay in sync.

• *Whole-process stopping* — Was: stopping a service could leave its children running. Now: the complete process group is stopped and checked.

• *Accurate proof targets* — Was: test data could point proof at the wrong target. Now: declarations identify the target precisely.

• *Oversized entries* — Was: oversized history entries could remain quarantined. Now: they are shortened, retried, and recorded as recovered.

• *Protected image credentials* — Was: image-service keys could appear in command details. Now: the key is sent through a protected temporary header file.

Install: use `cas update` after publication, or download the v3.24.0 Linux x86_64 archive (SHA-256 `{{LINUX_SHA256}}`) or macOS ARM64 archive (SHA-256 `{{MACOS_SHA256}}`) from the GitHub release.
```

## Dev thread

**Top-level:**

```text
*Live on production — Dev — Cassy v3.24.0*
Was: lifecycle, proof, credential, and process boundaries were loose. Now: bounded contracts, durable evidence, and isolated execution are enforced.
```

**Reply (Was → Now):**

```text
*Lifecycle contracts*

• *Assignee identities (#799)* — Was: lifecycle calls required one identity form. Now: UUID and name resolve to the same assignee. Commit `42ae8311`.

• *Message routing (#793)* — Was: supervisors could use the host SendMessage transport. Now: supervisor coordination uses the CAS message path. Commit `86db4c81`.

• *Gate ownership (#800)* — Was: worker-assigned gates could not be closed by the supervisor. Now: supervisor closure is supported and cross-owner assignment warns. Commit `c34f25e3`.

• *Epic close (#802)* — Was: close evaluated children with unbounded repeated probes. Now: batched probes are bounded and partial evaluation fails closed. Commit `d53e32d0`.

• *Close retry (#755)* — Was: retrying could mint a new dispatch and orphan an approved verdict. Now: superseded dispatches preserve the approved result. Commit `9d7e1b49`.

• *Post-merge proof (#753)* — Was: proof could bind to a stale worker checkout. Now: post-merge verification binds to the published target head. Commit `9d7e1b49`.

*Runtime recovery*

• *Proxy variables (#803)* — Was: proxy configuration treated `${VAR}` as literal text. Now: `${VAR}` and `${VAR:-default}` expand, with `missing_credential_env` for required gaps. Commit `0a16d12e`.

• *Hub startup (#804)* — Was: a lock holder could strand startup between auth, bind, and recording. Now: startup is transactional and `--force` recovers wedged holders with a doctor remedy. Commit `219a033b`.

• *Assignment delivery (#756)* — Was: delivered assignment boilerplate could replay after state changed. Now: direct, queued, MCP, and hook paths revalidate task state. Commit `c43b112e`.

• *Credential profiles (#758)* — Was: isolated processes missed credentials from configured files and linked profiles. Now: credential discovery and symlink write-through are preserved. Commit `87614f4a`.

*Execution and proof*

• *Process groups (#796)* — Was: stopping a registered PID could leave nested watchers alive. Now: each service has a dedicated group and stop verifies no survivors. Commit `fc40166a`.

• *Scoped proof (#778)* — Was: source-path strings could claim integration-test ownership. Now: exact targets and module declarations determine ownership. Commit `67733a3b`.

• *Embedding recovery (#805)* — Was: provider-size failures quarantined units permanently. Now: oversized units are truncated, retried, and marked with a recovery receipt. Commit `d386dc56`.

• *Image credentials (#757)* — Was: the API key appeared in curl arguments. Now: a mode-600 header file carries the key without exposing it in argv. Commit `5dabbdcc`.

Validation: `cargo metadata --locked`, the full release gate, published asset receipt, and release report receipt are required before posting.

Install: `cas-x86_64-unknown-linux-gnu.tar.gz` (SHA-256 `{{LINUX_SHA256}}`) and `cas-aarch64-apple-darwin.tar.gz` (SHA-256 `{{MACOS_SHA256}}`) will be published by CI.
```
