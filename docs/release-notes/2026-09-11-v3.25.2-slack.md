## Dev thread

**Top-level:**

```text
*Live on production — Dev — Cassy v3.25.2*
Was: FactoryConfig took the supervisor model from the global role default regardless of harness, and the hub catalog listed supervisor-less sessions. Now: launch recipes resolve per harness with preflight refusal, and the catalog marks dormant sessions.
```

**Reply (Was → Now):**

```text
*Factory*

• *Per-harness launch recipes (#820)* — Was: `FactoryConfig.supervisor_model/effort` came from `llm.model_for_role("supervisor")` after `resolve_supervisor_spec`, so `cli=codex` still launched with `claude-fable-5-1`. Now: `normalize_spec_for_harness` in `cas-factory` routing repairs an inherited incompatible model/effort to the harness recipe and refuses an explicit one at preflight; the pane wiring reads the resolved spec (cas-cli factory, daemon, cas-mux).

*Hub and Commander*

• *Dormant sessions* — Was: the session catalog and conversation list included sessions with no registered live supervisor. Now: the catalog marks sessions without an active supervisor (liveness evidence, not the session record) as dormant; hub-web hides them by default with a toggle, and a supervisor exit removes the row on the next refresh.

• *hub_clean_home_test (#826)* — Was: `assert_ne!(old_pid, new_pid)` flaked on PID reuse. Now: teardown proves the old process is gone via pid + start time.

Validation: `cargo metadata --locked`, the full release gate, published asset receipt, and release report receipt are required before posting.
```
