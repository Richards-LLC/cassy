## Dev thread

**Top-level:**

```text
*Live on production — Dev — Cassy v3.27.1*
Was: `commander:<label>` targets were queued to nobody and abandoned. → Now: they route to the operator lane; impossible targets are refused.
```

**Only reply:**

```text
• *Reply routing* — Was: message accepted any target string; a `commander:…` reply had no verified-device stamp, so `peek_operator_replies` never selected it and the daemon abandoned it 15 min later. → Now: `commander:<label>` resolves the newest verified Commander row (in_reply_to + device), row-source prefixes and empty targets are refused before enqueue, queue-before-register for plain names is unchanged, and Commander rows are framed with the exact reply command in inbox, hook and daemon renderers.

• *Keyboard viewport* — Was: viewport meta without `interactive-widget`, 100dvh shell scrolled under the soft keyboard. → Now: `interactive-widget=resizes-content`, `--keyboard-viewport-height` from visualViewport as fallback, `followTail()` on composer focus; pebble-qa keyboard receipts at 390x544 on both paths.

• *Hub service restart* — Was: update relaunched a detached `cas hub serve --launched-by update` beside an inactive unit and later left the old binary running. → Now: with cas-hub.service installed, restart goes through `systemctl --user restart`, the outcome records old→new version, the unit keeps `--tailscale-serve`, and status/doctor flag an inactive unit with a detached lock holder; systemctl is injected via `CAS_HUB_SYSTEMCTL` in tests.

• *Assets* — Was: n/a. → Now: `cas-x86_64-unknown-linux-gnu.tar.gz` `{{LINUX_SHA256}}`; `cas-aarch64-apple-darwin.tar.gz` `{{MACOS_SHA256}}`.

Install: `cas update`.
```
