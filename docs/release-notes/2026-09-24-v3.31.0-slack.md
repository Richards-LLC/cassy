## User thread

**Top-level:**

```text
*Live on production — User — Cassy v3.31.0*
Was: messages and controls could mislead you after a disconnect. → Now: Commander keeps the conversation clear, reports failures precisely, and protects your team's data.
```

**Only reply:**

```text
*Commander*

• *Disconnected machines* — Was: an offline session could still look live and offer controls that could not work. → Now: its controls and live row disappear until it reconnects.

• *Messages* — Was: a send could spin on “Sending…” forever, and a refused reply left you without a clear next step. → Now: unconfirmed sends offer Retry, and refusals explain the next action.

• *Keyboard focus* — Was: taking control or receiving a refusal could drop keyboard focus away from the action. → Now: focus stays on the message or its Retry action.

• *Conversation order* — Was: a fast machine clock or a reload could shuffle recent turns. → Now: the conversation keeps the same order across reconnects and reloads.

• *Find your session* — Was: an open session with no other activity could vanish from the list, picker or search. → Now: it stays visible and counted.

• *Project context* — Was: the terminal, picker and search could make similar machine names hard to place. → Now: each leads with its project, while long names stay readable.

• *Phone navigation* — Was: a search jump could leave the keyboard or search panel in the way. → Now: Enter dismisses the keyboard and a jump closes the panel.

• *Small-screen polish* — Was: notices could cover headings, long hints crowded the composer, and actions were small to tap. → Now: notices clear the content, hints shorten, and phone actions have larger targets.

• *Reports* — Was: a report that failed to open gave the same vague error whether the online service failed or your machine did not answer. → Now: the message tells you which happened, and published reports open through a secure link.

• *Fleet summary* — Was: a stray separator appeared before summary text and times. → Now: the summary reads cleanly.

*Your data and updates*

• *Team sync* — Was: syncing a team project could mix in personal changes. → Now: that project syncs only with its team.

• *Memory handoffs* — Was: an older handoff could compete with the current one. → Now: the current handoff is clear, and older ones remain available as history.

• *Violet* — Was: connecting Violet required using older integration names. → Now: Violet has its own integration and issue routing; the older names still work during this release.

• *Mac updates* — Was: the source updater could claim running Cassy programs were current without checking them. → Now: it says verification is unavailable and names what to restart; it also finds existing source checkouts more reliably.

• *Mac releases* — Was: preparing a release on a Mac needed extra command-line workarounds. → Now: the release tools handle the standard Mac commands.

Update with `cas update`. Published Linux x86_64 archive SHA-256: `{{LINUX_SHA256}}`. Published Apple Silicon macOS archive SHA-256: `{{MACOS_SHA256}}`. Download both from the GitHub release after publication checks pass.
```

## Dev thread

**Top-level:**

```text
*Live on production — Dev — Cassy v3.31.0*
Was: runtime and delivery paths hid stale state or crossed boundaries. → Now: scope, verification and recovery paths fail clearly and preserve their owners.
```

**Only reply:**

```text
*Runtime and product*

• *Commander state* — Was: outage paths retained live session rows, active control or ambiguous refusal actions. → Now: one visibility rule hides stale controls, preserves focus, and offers Retry only when it applies.

• *Thread delivery* — Was: clock skew, reloads and missing delivery receipts changed order or left Sending indefinite. → Now: durable turn order is stable and receipt grace ends in Not confirmed with Retry.

• *Navigation* — Was: palette jumps, phone keyboards, long names and notices collided. → Now: jumps clear the palette and keyboard; project-first labels, bounded hints and touch targets keep the route readable.

• *Reports* — Was: Cloud failure and an unreachable machine shared one open error; published artifacts lacked a safe browser route. → Now: errors are distinct and signed team-scoped view URLs open published reports.

• *Team scope* — Was: a team-linked project still did personal push and pull. → Now: its sync stays in team scope and never runs the personal path.

• *Violet* — Was: integration and issue routing used legacy names. → Now: Violet has dedicated commands, settings and routes with one-release aliases.

• *Memory and recall* — Was: handoffs could accumulate as competing current entries and envelope-only terms could pollute recall. → Now: one current handoff remains per project and role, while recall suppresses noise and surfaces domain-matched context.

*Access and delivery*

• *Runtime access* — Was: reading runtime errors and logs required write-capable proxy access. → Now: read-only access exposes those routes while writes remain denied.

• *Database branches* — Was: task SQL could target a shared branch. → Now: a disposable Neon branch can be scoped to one task with credentials held in its checkout.

• *Review rounds* — Was: reset review tasks held a dead claim, and a new delivery tip could leave an old round open. → Now: reset releases the claim for a replacement and a new tip retires the earlier round.

• *Close proof* — Was: an inherited hub diff could demand unrelated visual evidence, and a proof refusal omitted later targets. → Now: close judges the task's own diff and names every required proof target.

• *Spawn briefs* — Was: spawn_workers accepted prompt and silently dropped it. → Now: it rejects that parameter before queueing and names the message route; a normal spawn receipt says no brief was delivered.

• *Assignment paths* — Was: a path mentioned in prose could trigger an output warning for `/`. → Now: the warning requires an output instruction and ignores a bare slash.

• *Task recovery* — Was: blocked tasks could not transfer by name, rebases could lose delivery attribution, and unrelated base failures could be blamed for a new test. → Now: transfer, attribution and integration probes use the actual task and failing test identity.

• *Notifications* — Was: local tags, stale branch runs and old inbox replays could trigger premature or irrelevant alerts. → Now: tag checks use origin, red-run wakes require the current failed job, and the named message arrives first.

• *Evaluation and tests* — Was: midnight recency changed ranking between evaluation modes and fixed sleeps or host probes made test results vary. → Now: both modes share one clock and timing-sensitive fixtures wait on conditions in isolated environments.

• *Mac operations* — Was: Linux procfs checks produced a false verified turnover on macOS, and release scripts needed manual tool shims. → Now: turnover reports unverified with restart targets and source lookup fallbacks, while the release train handles stock macOS tools.

• *Tag handoff* — Was: a guarded release checkout failed late when publishing a tag. → Now: it prepares the local annotated tag and stops before the audit with an explicit publication handoff.

Install: `cas update`. Published `cas-x86_64-unknown-linux-gnu.tar.gz` SHA-256: `{{LINUX_SHA256}}`. Published `cas-aarch64-apple-darwin.tar.gz` SHA-256: `{{MACOS_SHA256}}`.
```
