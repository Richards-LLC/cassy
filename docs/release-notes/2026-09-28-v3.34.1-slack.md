**Only reply:**

```text
• *Session reads off the reactor* — Was: `list_sessions` ran on Tokio workers from the 1 s catalog task and every `/v1/sessions` call, so a stalled SQLite close or open pinned them all. → Now: the read model runs on `spawn_blocking` with single-flight; callers wait at most 20 s and join the running read.

• *Registry churn* — Was: every pass closed and reopened each listed project's agent registry, and a `sqlite3WalClose` could race a `sqlite3BtreeOpen` on the same file. → Now: listed registries stay open across passes and are released when the project leaves the list.

• *shared_db closes* — Was: a connection closed wherever the last caller dropped it, outside any lock, so a close could race an open of the same file. → Now: the pool owns every close, under the same per-database lock opens take, through an idle sweep (60 s TTL, at most 16 idle); the CLI closes idle connections on exit, and update backup and rollback close them before copying cas.db.
```
