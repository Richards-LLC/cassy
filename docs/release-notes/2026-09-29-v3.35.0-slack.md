## Dev thread

**Top-level:**

```text
*Live on production — Dev — Cassy v3.35.0*
Was: the hub could drive sessions but not create them. → Now: `POST /v1/sessions` starts a detached factory daemon under `session:launch`.
```

**Only reply:**

```text
• *Launch endpoint* — Was: `/v1/sessions` was read-only. → Now: `POST /v1/sessions` takes a registry or browse target, a CLI, an optional profile and workers; it is single-flight per project, returns Attach for a running project, and is audited.

• *Survives hub restarts* — Was: a hub child would die with `cas-hub.service` (`KillMode=control-group`). → Now: each session runs as a transient `cas-factory-<session>` user unit under a `cas hub reap-daemon` reaper that writes the exit receipt.

• *Service environment* — Was: a service-started CLI saw an empty PATH and the `main` profile. → Now: `hub::launch_env` probes the login-shell PATH once, sets the account from `[hub.launch_profiles]`, and strips ambient tokens.

• *Targets and profiles* — Was: no project or account catalog. → Now: `GET /v1/projects` lists main repo roots only, `/v1/projects/browse` stays inside `[hub] launch_roots`, and `GET /v1/launch/profiles` reports each CLI on its own.

• *Team-only sync* — Was: every project write was queued for personal and team scope. → Now: `cloud.team_only` routes project rows to the team only and holds personal rows, since the server requires a project identity.

Validation: the full nextest suite (10,326) plus doctests at the assembled head, the 13-journey Commander suite and independent QA. Published `cas-x86_64-unknown-linux-gnu.tar.gz` SHA-256: `{{LINUX_SHA256}}`. Published `cas-aarch64-apple-darwin.tar.gz` SHA-256: `{{MACOS_SHA256}}`. ```
```
