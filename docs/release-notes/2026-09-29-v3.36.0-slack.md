## Dev thread

**Top-level:**

```text
*Live on production — Dev — Cassy v3.36.0*
Was: local stores absorbed foreign rows through registration, enqueue and push. → Now: rows carry `origin_project` and only authored rows sync.
```

**Only reply:**

```text
• *Provenance* — Was: only tasks had `origin_project`, re-stamped with the local project on every migration run. → Now: m260 adds it to entries and rules, backfills once from `sessions.cwd` (else `unknown`), and stores stamp at creation.

• *Authored-only sync* — Was: pushes stamped missing origins with the pushing project. → Now: enqueue and push refuse foreign or `unknown` rows, legacy payloads take the stored origin, and `cas cloud status` counts the skips.

• *Project roots* — Was: `cas update` fan-outs registered containers and store lookup walked past the Git top level. → Now: `is_project_root` requires a Git top level or pinned `canonical_id`, and lookup stops at the repository boundary.

• *Audit* — Was: doctor and purge covered tasks only. → Now: doctor classifies tasks, entries and rules as authored, foreign or unknown; `purge-foreign --include-unknown` and `cas cloud adopt-unknown` act on them.
```
