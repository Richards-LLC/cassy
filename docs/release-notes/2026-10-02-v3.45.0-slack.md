**Top-level:**

*Live on production — User — Cassy v3.45.0*
Was: judgment calls needed a separate service. → Now: Cassy offers recorded advice and clearer limits on when a person must decide.

**Only reply:**

```text
*Decision support*

• *Ask for advice* — Was: decision advice needed a separate service. → Now: your Cassy sign-in gives access to the live service while its private service key stays on the server.

• *Questions and recorded answers* — Was: recommendations had no shared place to ask questions and review answers. → Now: you can ask one question set or a batch and review recorded answers without saving the original input in the decision history.

• *Measured triage results* — Was: there was no measured comparison with reviewed work. → Now: two runs matched 69% then 70% of reviewed decisions, while cases not used to tune the questions slipped from 71% to 70%. Advice remains for a person to review.

• *Guidance on when to trust advice* — Was: there was no shared guidance for interpreting uncertain answers. → Now: shared guidance explains uncertainty, requires review for triage suggestions and forbids destructive decisions based on advice alone.

• *Answers about files* — Was: getting advice about files required copying their content into the conversation. → Now: selected project files can be sent for questions, returning answers while refusing secret paths.

• *Command-risk study* — Was: command-risk advice had no measured baseline. → Now: an offline study compares it with existing checks. It remains research and changes no live decisions.

*Privacy and quality checks*

• *Private sign-in details* — Was: quality-check output could expose sign-in details. → Now: the check hides them in its logs and recordings, and warns when an existing recording is outside that protection.

• *Secret-file protection* — Was: commands could alter private settings despite direct-write protection. → Now: recognized command writes to private settings receive the same protection as direct edits. Reading settings and quoting command text stay allowed.

• *Linked checks run* — Was: starting a visual check through a linked location could report success without doing anything. → Now: it runs, saves a report and explains when it cannot capture anything.

• *Team-only sharing* — Was: the team-only setting could not be enabled, and rejected personal uploads accumulated. → Now: you can enable team-only sharing and clear those rejected uploads while keeping your local work.

*Completing and finding work*

• *Closing work without code changes* — Was: cleanup of old work could prevent completed work from closing. → Now: work that needed no code can close with valid recorded proof.

• *Checks survive combined history* — Was: combining a reviewed change into one commit could lose its accepted quality check. → Now: the check stays valid when the delivered change is proven to match.

• *Live work keeps its place* — Was: a busy machine could make running work look abandoned or reopen work on hold. → Now: running work keeps its assignment, and work on hold keeps its blocker.

• *Log without stopping the check* — Was: creating a build-check log could prevent the check from starting. → Now: the guidance puts logs where they can be written without blocking the check.

• *All relevant checks* — Was: a change to checks could leave some tests out of validation. → Now: those tests are selected, and uncertain selections widen the checks.

• *Lists explain missing work* — Was: work set aside for review disappeared from task lists without explanation. → Now: lists say how many items each filter hides, including when no items remain.

• *Build tools are found early* — Was: a build preview could fail to find a compiler already available in the source checkout. → Now: it finds that tool or names what is missing before the build starts.

• *Large groups finish with an answer* — Was: closing a large group of completed work could time out with an unknown result. → Now: the checks have a shared time budget and clearly record any work still unchecked.

• *Reliable release tools* — Was: simultaneous release checks could interfere while installing build tools. → Now: setup runs one at a time and reports incomplete installations before building.

• *Release checks on a Mac* — Was: release checks could fail because they expected Linux tools. → Now: the Mac checks pass, and Linux-only checks explicitly say why they are skipped there.
```

• *Builtin decision guidance* — Was: there was no shared Jev question-writing or confidence policy. → Now: the cas-jev skill ships across integrations with literal question rules, confidence routing and a reviewed-suggestions-only triage recipe. Jev alone cannot authorize destruction.

• *Questions about files* — Was: file evaluation needed custom reads and prompts. → Now: cas jev files and the MCP files action return answers without file contents, enforce project/ignore boundaries and refuse secret paths before reading.

• *Shadow gate research* — Was: command-risk advice had no fixed comparison corpus. → Now: two runs on 208 cases compare hook/Jev/composite decisions. The held-out default composite detects 60/60 destructive cases versus hook 16/60. This remains shadow-only research with study-authored labels, limited real commands and 71/78 trusted safe passes. No runtime hook or Jev gate behavior changed.

*Authentication and task visibility*

• *Visual QA secret redaction* — Was: teardown logs exposed auth headers/cookies and traces recorded tokens. → Now: logging redacts secrets and owned traces scrub auth/storage. An already-tracing runner continues with one warning and no harness trace (#1076).

• *Credential write parity* — Was: Bash destinations bypassed file_path checks. → Now: PreToolUse denies parsed Bash redirects, tee, cp/mv and Python/Node writes to .env and configured credential files like direct Write. Reads and quoted text are unaffected.

• *Symlink entry points* — Was: visual-qa compared lexical entry paths and silently skipped a symlinked invocation. → Now: both guard sides use realpath, reports are written and no-input/zero-capture runs fail (#1050).

• *Team-only project sync* — Was: cloud.team_only was absent from config accessors and rejected personal rows lingered. → Now: the setting works across enqueue, push/pull, daemon and MCP startup. Cas cloud queue --purge-team-owned removes only matching local rejections.

• *Expired leases on live processes* — Was: heartbeat-only recovery reopened live work and reset Blocked work. → Now: process/PTY evidence protects live assignments and Blocked state. Genuinely dead work still recovers (#1065).

• *Task-list exclusion accounting* — Was: the quarantine wrapper silently removed open rows. → Now: the list reports request-filter, quarantine and foreign counts, explains project/all scope and applies the display limit last (#1090).

*Delivery and validation*

• *Zig in build previews* — Was: fresh preview worktrees could not find the source checkout's Zig. → Now: ZIG, PATH and source/main-checkout fallbacks are exported before Cargo, with preflight required only for ghostty_vt_sys (PR #1091).

• *Bounded nested close proofs* — Was: missing-ref fetches and history scans overran the epic close deadline. → Now: one remaining budget bounds all probes, unfinished children stay unchecked and the decision audit names them (PR #1092).

• *Shared Rust toolchain setup* — Was: simultaneous self-hosted release jobs could corrupt shared stable installs. → Now: setup is locked, existing stable is reused and incomplete installs fail with an idle-pool repair instruction. Hosted jobs are unchanged.

• *Portable Mac release checks* — Was: GNU-only timestamp parsing, native Bash empty-array handling and Git regex boundaries broke the Mac gate. → Now: portable paths pass the Mac cohort/Make wrapper, Linux-only fixtures explicitly skip and Linux runner code stays unchanged.
