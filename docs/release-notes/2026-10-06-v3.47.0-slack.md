# Slack draft — Cassy v3.47.0 runtime release

Channel: #cas-internal (`C0B44GUKDK2`). Transport: Violet hub/bot only.

**Status:** Draft. Do not post until the tagged GitHub workflow publishes both
assets and `release-published-receipt.sh --write-draft` has replaced both
checksum placeholders below.

The four fenced bodies are the exact text to post: the User and Dev top-levels,
each with its only reply. Internal task references and evidence stay outside the
bodies. GitHub PR numbers appear only in the Dev reply.

**Scope check before posting:** the operator inbox has landed and is described
from the merged code; its journey against the deployed cloud has not run, so
the bodies make no claim about it. Everything else described here is on the
release tip, which carries both the Commander and the burn-down work.

## User thread

**Top-level:**

```text
*Live on production — User — Cassy v3.47.0*
Was: with the computer off, Commander went silent. → Now: your conversations wait in an inbox you can read and answer from any browser.
```

**Reply (Was → Now):**

```text
*Messages that always reach you*

• *Your inbox when the machine is off* — Was: with the computer off or asleep, Commander showed nothing and you couldn't reply. → Now: up to 90 days of conversations, kept encrypted by Petra Stella Cloud, stay readable on every browser you sign in, including a new phone.

• *Replies wait for the machine* — Was: a reply needed the machine to be on. → Now: it waits as "Pending machine", is sent once when the machine is back, and shows "Accepted by machine".

• *Sign in with your account* — Was: only browsers paired to the machine could see its conversations. → Now: you approve a browser from your Petra Stella account by matching a code, and a message that can't be verified is held back with a note saying so.

• *Sends never go twice* — Was: two open tabs could both send the same queued message. → Now: each queued message is sent from one tab only, and anything waiting survives a reload without being resent by itself.

• *Retry from any tab* — Was: with two tabs open, a message confirmed in one tab could leave the other offering Retry, and retrying could stall. → Now: a confirmation in either tab settles both, and Retry works from either tab without a second copy.

• *No stale "will go out by itself"* — Was: that line could stay after the message was delivered. → Now: it clears once nothing is waiting, even when another tab sent it.

• *Notices stay resolved* — Was: after a reload, a delivery problem you had already resolved could come back in the conversation as a Blocker. → Now: a resolved notice stays resolved, and "Taking control…" disappears once your message is on its way.

• *Replies show where they are* — Was: Commander counted a reply as delivered before your browser had saved it. → Now: each reply says "Forwarded · not stored on this device" until this device saves it, then "Stored on this device".

• *Your devices, listed* — Was: every re-pair added another copy of the same browser, one computer had 14. → Now: re-pairing refreshes the same entry, and each machine lists its browsers with Revoke and Remove from this browser.

• *Admin by explicit choice* — Was: an invitation could not ask for the right to remove other browsers. → Now: it can request Hub administration, which is never pre-ticked and must be chosen on purpose.

*Clearer conversations*

• *One screen for everything* — Was: Commander had a separate Terminal view that showed wrong status and stale alerts. → Now: Conversations is the only screen, with Interrupt and a read-only Raw output view in the conversation header.

• *Questions show real choices* — Was: every question offered made-up "Yes, go ahead / Hold" buttons. → Now: buttons appear only for choices the question offers; otherwise you type the answer.

• *Each question once* — Was: a "Waiting on you" panel repeated the question and covered the message box. → Now: the question appears once in the conversation, with a small bookmark that jumps to it.

• *Plain status words* — Was: the side panel showed raw codes like "AWAITINGMERGE", star markup in previews and a wrong count. → Now: it says "In progress" or "Awaiting merge", previews read cleanly, and the list shows who is really working on what.

• *Connection problems explained* — Was: "Reconnecting" gave no reason. → Now: Connection details names the cause, what to do, the next retry and the last good connection, and can download a safe report for support.

• *Readable error notes* — Was: on a wide screen an error note squeezed into a narrow strip. → Now: it uses the full row and names what failed.

• *Asked once to start a session* — Was: New session asked you twice to allow starting sessions, under two different names. → Now: one Allow, and the project list opens.

• *Steadier connection state* — Was: a machine that briefly stopped answering could jump to "Reconnecting" after one missed check-in. → Now: it shows "Unsteady" and only reconnects after four missed check-ins.

• *Whole machine names* — Was: a long machine name stayed cut off even on the conversation you had selected, and the phone header clipped it. → Now: the selected or focused conversation shows the full name, and the phone header no longer clips it.

• *Phone search lands where you read* — Was: opening a conversation from search on a phone left you nowhere on the page. → Now: you land on the conversation itself, and the keyboard stays down.

• *Connection card on a sideways phone* — Was: in landscape, a connection problem's card cut off Retry. → Now: the card scrolls, so Retry and Diagnose are always reachable.

• *Hub status after a restart* — Was: after a reboot, `cas hub status` only said whether the hub answered, and a stuck system service could freeze it. → Now: it reports what came back and what to do next, and gives up on a stuck service within half a second.

*Faster, steadier checks*

• *Browser tests in minutes* — Was: every change to Commander ran all of its roughly 80 browser tests three times, about an hour. → Now: each change runs only the screens it can affect, often one, and the full set runs once per release batch.

• *Messages to busy helpers* — Was: a message to a helper that stayed busy for a few minutes could be dropped as undeliverable. → Now: it waits and appears at the helper's next step.

• *Quicker task wrap-up* — Was: finishing a task on a large project could hang for a minute with no answer. → Now: it finishes, or says plainly within 35 seconds that it ran out of time and changed nothing.

• *Release lessons kept* — Was: release problems were fixed by hand and forgotten, and reports said no one had stepped in. → Now: a release can't finish until each problem is recorded as a lesson or an open job, and reports count every manual step.

• *Cleaner disk* — Was: interrupted release checks and an unbounded build cache piled up nearly 40 GB on one computer. → Now: they clean up on every exit, leftovers are swept on the next run and caches stay capped.

• *Release checks protected* — Was: browser tests running alongside a release check could use up the computer's memory and stop the check. → Now: tests share memory safely, several run side by side, quick checks never wait behind them, and the release check goes first.

• *Finished work closes cleanly* — Was: merged work could not be closed once the helper that did it had moved on to something else. → Now: it closes from its merged result, and corrected work from a retired helper can still be reviewed and closed.

• *Build folders reclaimed* — Was: some build folders could never be cleaned up while an unrelated program was running. → Now: Cassy marks the folders it creates, so it can remove them safely later.

• *Release setup checked early* — Was: a release tool setting failed only after the release was already merged. → Now: it is checked before anything lands.

• *Fewer false alarms* — Was: readability checks failed easy-to-read buttons and renamed page parts looked like new problems. → Now: those checks read the real colours and match issues by what they are.

• *No false clipping reports* — Was: layout checks reported text as cut off when it was deliberately shortened with "…" or not drawn at all. → Now: they skip what isn't drawn and still catch real clipping.

*Team sync*

• *Honest sync summaries* — Was: syncing with your team could say "0 pending" while thousands of items were held back. → Now: it counts what is really waiting or refused, shows when your team last synced, and gives the command that fixes a team-only setting mismatch.

• *Stuck items recover* — Was: about 200 task links and a few notes retried and failed forever. → Now: the missing tasks are sent first, and anything that can't sync is set aside with a reason.

Install: run `cas update`, or download the v3.47.0 archive for Linux x86_64 (SHA-256 `2fe19923608e2a122402411caff9253fc68b5fd7a2aaec9beddcd75742eefd9f`) or Apple Silicon macOS (SHA-256 `356b4630c29f328b94113be4b68b7dc45ab41252ecf8ffdce183a3b99c7c69a9`) from the GitHub release.

• *Release effort* — 7 manual interventions were needed to publish this release.
```

## Dev thread

**Top-level:**

```text
*Live on production — Dev — Cassy v3.47.0*
Was: operator turns lived only on the machine and every hub-web delivery ran all journeys. → Now: encrypted cloud inbox, device receipts and impact-selected journeys.
```

**Reply (Was → Now):**

```text
*Commander delivery*

• *Operator inbox* — Was: operator turns existed only in the hub's SQLite, unreachable while the machine was off. → Now: an HPKE/AES-GCM cloud inbox (cas-operator-crypto, byte-identical browser HPKE, cloud-held keys, not E2E) replays 90 days to each approved browser and withholds unverifiable envelopes.

• *Offline commands* — Was: a reply needed a live hub connection. → Now: replies are sealed to the machine command key under a stable command_id, admitted once with the queue row in one transaction (m265), and expire after 24h.

• *Account sign-in and CSP* — Was: no account-level browser enrollment existed. → Now: browsers enroll by device-code approval or `cas hub operator approve <code>`, and connect-src pins exactly the cloud operator API origin.

• *Transactional outbox* — Was: a reply was stamped in a separate write after it was queued. → Now: each operator-visible turn and its immutable operator_delivery_outbox row commit in one transaction (m263), drained every 15s through a PSC-PoP signed transport.

• *Enrollment assertion* — Was: installations were always unenrolled. → Now: POST /v1/auth/account/{challenge,enrollment} verifies the issuer-signed psc-op-enrollment+jwt (one-use 5-minute challenge, aud, ins_jkt == DPoP key, acct == machine principal) before recording Enrolled.

• *Atomic pending sends* — Was: pendingSendStore did whole-namespace localStorage read-modify-write, so tabs raced. → Now: an IndexedDB journal claims each held send per item, scoped to hub, device and session, and never auto-resends.

• *Cross-tab receipts and Retry* — Was: a delivery receipt reached only the tab that sent, and peer captions could cancel a retry. → Now: receipts are shared by client_ref across tabs, explicit Retry reuses the original reference behind an owner fence, and a receipt racing the retry wins.

• *Held-send line* — Was: showHeldSendStatus ran for live sends and nothing cleared its "will go out by itself" fallback. → Now: it shows only for a held send, and settleHeldComposerStatus clears it after a flush, receipt, reconnect or another tab's journal change.

• *No-delivery settlement* — Was: a refused or upstream-unavailable send could only re-hold through History, which the claim fence blocked, so Cancel refused and a late refusal could re-hold a newer Retry. → Now: an authoritative no-delivery settles against the original wire claim (owner, credential and content fenced).

• *Notices out of the journal* — Was: persistDeviceReply ran before the isOperatorNotice route and journal restore hydrated every row, so resolved notices returned after reload. → Now: notices are routed first, never journaled, legacy notice rows are pruned, and the take-control notice clears once control is held.

• *Device reply receipts* — Was: the hub inferred delivery at WebSocket write, before client persistence. → Now: the browser sends OperatorReplyPersisted after storing, the hub records operator_reply_device_receipts (m264), and the caption tracks it.

• *Installation rotation* — Was: AuthStore::exchange_pairing minted a device UUID per re-pair. → Now: a possession-proven re-pair rotates the installation via /v1/auth/pairing/{protocol,commit,abort}, /v1/auth/devices lists them, and hub:admin by explicit consent revokes others.

• *Connection causes* — Was: any fetch failure looked the same and lagged SSE records were skipped. → Now: 18 typed causes in a 64-entry ring, X-Cas-Request-Id for granted origins, viewer_lagged and epoch markers, 10s deadlines and a sanitized diagnostics export.

• *Terminal view removed* — Was: a second Terminal surface with its own fleet model and a 130-event stale Attention feed. → Now: Conversations only, with InterruptPane and a read-only Raw output dialog in the header; about 6,200 lines and 53 KB of JS gone.

• *Conversation polish* — Was: DEFAULT_ASK_OPTIONS invented quick replies, previews leaked Markdown and status rendered raw enums. → Now: options only when declared, one in-thread ask plus bookmark, plain-text previews and roster-joined status labels.

• *Single launch consent* — Was: the grant view's Allow led to a second "Allow "Start new sessions"" confirm sheet. → Now: the first named Allow grants session:launch and opens the project list.

• *Half-open stays Unsteady* — Was: an event-triggered catalog read's TypeError aborted the event stream and skipped the heartbeat gate, so one missed beat became Reconnecting. → Now: failed or timed-out event reads are left to the heartbeat (Reconnecting at beat 4), and only a refused pairing ends the stream.

• *Machine name on focus* — Was: the row's machine name stayed ellipsised on the open or keyboard-focused row. → Now: focused and open rows wrap the whole name clear of the time stamp; resting rows keep the allowlisted ellipsis.

• *Phone host line and focus* — Was: the phone header clipped machine glyphs, and a coarse-pointer search jump left focus on BODY. → Now: the host line has glyph room, and coarse-pointer jumps land on the reading region or back link with the composer unfocused.

• *Landscape connection card* — Was: #pane-grid's overflow: hidden cut Retry and Diagnose off the failure card at 844×390. → Now: the pane scrolls vertically while it holds the card.

• *Hub status* — Was: a hung systemctl blocked `cas hub status` (10.6s measured). → Now: probes are capped at 500ms with a typed unknown state, and status --json adds a read-only runtime_receipt.

*Browser test tiering*

• *Impact selection* — Was: journeys-for-diff treated hub-web/dist as surface-wide, so every delivery selected all 18 journeys (~81 tests, ~20 min, run three times). → Now: dist is ignored and selection follows Touches, imports, main.ts symbols and CSS selectors; a narrow fix selected 1.

• *Tier enforcement* — Was: worker and QA browser runs executed the full suite. → Now: they run only the affected journeys at 4 workers, --full is supervisor-only at assembly, and a PreToolUse guard denies unfiltered Playwright to workers and QA.

• *Receipt gates* — Was: close and QA accepted any hand-picked subset. → Now: they recompute the selection at the tip and require a passing journey-receipt.json for every selected ID, and an epic close needs one full-suite receipt.

*Cloud sync*

• *Sync receipts* — Was: a team-linked sync skipped the personal push, so its receipt read "0 pending, 0 failed/parked" over thousands of team_owned_project rejections, and status showed only the personal last_pull_at. → Now: the receipt refreshes from the queue, status reports the team pull watermark, and status and doctor flag the team_only mismatch with its fix.

• *Orphan dependency repair* — Was: 196 parent-child edges burned retries as orphan_dependency and 3 origin-null memories had no attributable project. → Now: healed edges stage missing own-project endpoint tasks insert-only and wait for them, foreign or deleted endpoints park with a reason, and origin-null memories park as unattributed_origin.

*Release train*

• *Learning loop* — Was: blockers were fixed by hand and never recorded. → Now: receipts refuse until each blocked stage and hand fix maps to a learned gate row or an open task, printing the exact `release-gate.sh --learn` command.

• *Honest interventions* — Was: INTERVENTIONS counted only kind=manual rows and printed 0 since 3.42.0. → Now: it counts resumed blockers, hand fixes and manual rows (3.46.0 replays as 8), in the report and both replies.

• *Publish toolchain preflight* — Was: cargo-zigbuild rejected build.jobs only after the release landed on main (hotfix PR #1132). → Now: a publish-toolchain row loads the real zigbuild config first, and a failed publish deletes its own local tag.

• *Tooling warning* — Was: the off-main tooling warning was buried under git merge-base noise and dead refs. → Now: noise is captured and merged, stale, epic-covered and duplicate refs are skipped.

*Gates and runtime*

• *QA binds the delivered tip* — Was: a park could bind QA two commits behind its tip, and qa_request re-found that stale pass. → Now: an own-lineage advance binds the tip, qa_request rebinds and supersedes, and shared branches never move the anchor.

• *Bounded child close* — Was: a supervisor close on a 450-child epic ran about 60k git processes and timed out at 55s claiming COMMITTED. → Now: a 35s budgeted content gate with a timing log, about 1.3k processes, a typed retryable refusal and IN_PROGRESS on deadline.

• *Busy-recipient mail* — Was: three declined wakes stamped a message abandoned and hid it from hooks. → Now: it parks as awaiting_busy_recipient, stays surfaceable, and the reassign notice waits for 10 minutes of silence.

• *Worker selection* — Was: an explicit --worker-cli claude lost to the stock worker default, and a Claude fallback was routed as Codex over PTY. → Now: explicit flags win, launch specs are recorded per name, and --worker-spec names apply.

• *Retired-worker recovery* — Was: the pre-close hook validated a retired worker's moved-on worktree, and qa_request refused an Open task. → Now: a live supervisor parks and closes a corrected delivery from its pushed receipt against the WorkTarget, and qa_request takes an explicit head on a reopened task.

• *Detached assignee close* — Was: a merged commit_receipt was refused with "expected task worktree branch …, found ``" when the assignee's checkout was detached. → Now: a supervisor receipt that is an ancestor of the WorkTarget closes without override; worker and unmerged paths are unchanged.

• *Snapshot hash approval proof* — Was: the SHA-256 snapshot approval had no public-path test. → Now: an MCP notes→close test refuses a 1,500+ character literal, closes on the exact hash and refuses a same-prefix wrong hash.

• *Canonical proof targets* — Was: close suggestions prescribed --test agent_definition_contract_test and other modules now inside combined targets, which failed with "no test target named". → Now: modules map to their containing Cargo target (integration_contracts and so on), and unknown suites fail closed.

• *Recycle and reset* — Was: recycle_worker demanded force on a clean worker, then rejected force. → Now: a clean recycle keeps name, tasks and worktree, and clear_context errors name clear_context.

• *Visual QA skipped and ellipsised content* — Was: content-visibility: hidden subtrees and ellipsised one-line text were measured as clipped. → Now: checkVisibility() marks skipped content not drawn, the X walk stops at the ellipsising box, and a real visible clip still fails.

• *Visual QA identity and contrast* — Was: findings keyed on full selectors and color(srgb …) was unparsed (2.57:1 reported for 12.08:1). → Now: findings match by rule, state and text, and CSS Color 4 and opaque layers resolve.

• *Host-memory admission* — Was: worker Playwright and Vitest runs admitted nothing, and 125 headless Chromium pushed MemAvailable under the proof reserve, aborting it. → Now: worker-memory.py reserves weighted counting slots behind a proof-priority lease (two browser suites plus tsc under a normal budget, serial at 8 GiB, light commands never queued), waits visibly within CAS_RELEASE_GATE_ASSEMBLY_MEMORY_WAIT_SECS, and hook denies still win.

• *Private fixture pools* — Was: the test-release-gate train-proof fixture ran assembly-proof.py against the real host locks and held intent EX for 8 minutes. → Now: in-process and subprocess fixtures use private admission pools, with no production env bypass.

• *Forked mold RSS* — Was: link RSS receipts measured only the waited process. → Now: they also sample the same link's forked mold workers.

• *Owned worker targets* — Was: seeded worker target/ dirs had no owner record, so retirement refused them whenever an opaque same-uid process existed. → Now: new targets carry checkout, target and lease identity plus PID start and boot provenance before any data; an unignored target/ stays legacy and seeding still succeeds.

• *Scratch cleanup* — Was: aborted proofs leaked about 9.7 GB of scratch and the shared assembly cache reached 29 GB. → Now: owner leases reap on TERM/INT/HUP, dead owners are swept, the cache is capped by CAS_ASSEMBLY_TARGET_MAX_GIB (20) and age, and gc_report shows retained bytes.

• *Parallel links and proof targets* — Was: assembly linked one test binary at a time and proofs shared one CARGO_TARGET_DIR across worktrees. → Now: link slots are admitted from live memory, capped by CAS_RELEASE_GATE_ASSEMBLY_LINK_JOBS, and each worktree proves into its own target.

• *Journey flakes* — Was: reattach backoff grew to 16–30s, CI ran 16 recording browsers and failure traces never uploaded. → Now: reattach is capped at 10s, CI runs 6 workers, and hidden .results traces upload on failure.

• *Journey fixtures and settle* — Was: phone fixtures assumed a desktop layout, and a frozen screenshot settle could outlive its page. → Now: fixtures follow the real phone layout in a responsive four-variant lane, settling is cancelled and drained with the page, and repeat captures are isolated by index.

Published archives: `cas-x86_64-unknown-linux-gnu.tar.gz` (SHA-256 `2fe19923608e2a122402411caff9253fc68b5fd7a2aaec9beddcd75742eefd9f`) and `cas-aarch64-apple-darwin.tar.gz` (SHA-256 `356b4630c29f328b94113be4b68b7dc45ab41252ecf8ffdce183a3b99c7c69a9`), both built by CI regardless of the tagger's host.

• *Release effort* — 7 manual interventions were needed to publish this release.

• *Publication timing* — Tag to published: 197s; within budget (600s); WITHIN_BUDGET=true. INTERVENTIONS=7.
```
