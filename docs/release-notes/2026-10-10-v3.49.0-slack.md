## User thread

**Top-level:**

```text
*Live on production — User — Cassy v3.49.0*
Was: an @Violet mention in Slack waited until Cassy next looked. → Now: it wakes Cassy, and Cassy posts files to Slack by path.
```

**Reply (Was → Now):**

```text
*Slack mentions wake Cassy, files by path, steadier task closes*

• *@Violet mentions wake Cassy* — Was: when someone mentioned @Violet or replied in a thread Violet started, nothing happened until Cassy next checked Slack. → Now: Cassy wakes on it within about 15 seconds and keeps reading that channel every 5 minutes until an hour passes with no one talking. It is on by default but stays quiet until the Slack side starts sending these alerts; `cas config set slack.wake_enabled false` turns it off.

• *Post a file by its path* — Was: sharing a local file in Slack through Cassy meant copying its contents into the message by hand. → Now: `cas violet post --channel <name> --file <path>` posts it, and `cas violet thread` posts a message with its replies and attachments in one go.

• *Share a published report by name* — Was: getting a published Cassy report into Slack meant downloading it and uploading it again. → Now: Cassy sends it straight from its id and checks the file arrived unchanged.

• *Violet's new address* — Was: Violet settings pointed at the old hub address and used the old `MECHA_` key names. → Now: `cas update` and `cas integrate violet` move them to the new address and `VIOLET_` names; the old names keep working for one more release.

• *Several closes at once* — Was: closing a few tasks at the same time could freeze Cassy for most of a minute and then answer "unknown". → Now: closes run side by side, and one that runs long records its result when it finishes.

• *Healthy sessions left running* — Was: on a busy machine Cassy could mistake a session it had just started for a broken one and shut it down. → Now: freshly started sessions are recognised and left alone.

• *Database times in the right zone* — Was: times read from a Neon or Postgres database could come back shifted by your time zone, so 14:34 read as 18:34. → Now: they come back exactly as stored.

• *Keyboard focus stays put in Commander* — Was: in a Commander conversation, a live update could knock keyboard focus off the page while you tabbed to Interrupt. → Now: focus stays on the control you moved to, with its focus ring.

• *Clearer setup checks* — Was: `cas doctor` said to re-run Violet setup when a project settings file was hiding a missing key, which never fixed it. → Now: it names that file and the block to remove.

• *Release effort* — 2 manual interventions were needed to publish this release.
```

## Dev thread

**Top-level:**

```text
*Live on production — Dev — Cassy v3.49.0*
Was: Slack activity reached the supervisor only by polling. → Now: the daemon claims Cloud Slack events every 15 s; opt out with wake_enabled.
```

**Reply (Was → Now):**

```text
*Violet push-wake, `cas violet` CLI, close and factory fixes (PR #1155)*

*Violet*

• *Push-wake, on by default* — Was: an @Violet mention or a reply in a Violet thread surfaced only when someone polled the channel. → Now: a logged-in factory daemon claims the project's `violet.slack_activity/v1` events from Cloud every 15 s, admits each once by `dedupe_key`, acks it and wakes the supervisor with a typed `SlackActivity` envelope; a no-op until the hub emits events. Opt out with `slack.wake_enabled=false`.

• *Channel watch* — Was: after one wake nothing re-read the channel. → Now: each admitted channel is swept with `violet_read` every 5 min, stopping after 1 h without human activity, 3 failed reads or session end; `slack.violet_bot_user_ids` seeds the bot ids sweeps ignore.

• *`cas violet post|thread|read`* — Was: posting a local file meant pasting base64 into `violet_post`. → Now: the CLI reads, hashes and encodes files from disk, sends up to 1 MiB inline and streams larger sets via `file_external` begin, upload, complete; `thread` is one `kind:"thread"` call with ordered `--reply`/`--reply-file`, and hub error codes pass through with a non-zero exit.

• *Artifact post* — Was: a published artifact had to be downloaded and re-uploaded by hand. → Now: `artifact action=post` resolves it through Cloud, verifies size and SHA-256, uploads through Violet and saves the permalink on the record; every failure is named.

• *violet-hub address and VIOLET names* — Was: managed registrations kept the former hostname and `MECHA_*` names. → Now: update/sync rewrite proxy files to `violet-hub.vercel.app` and `VIOLET_*` in place, `cas integrate violet` renames credential keys (0600, values never printed), and lookup falls back to `MECHA_*` for one release.

• *Skill contract* — Was: the violet skill described the pre-2026-10-09 `violet_post` and `violet_read` shapes. → Now: it documents `files[]`, `file_external`, `kind=thread`, the 100,000-byte read default and `file_id`/`message_id`/`thread_id` scopes, the attachments read route and the human-handoff rule.

*Close and QA gates*

• *No-code close* — Was: a no-code task without its own commits was judged on the worker lane's other-task commits, so it read as stranded or parked. → Now: it closes on its `external_ref`, foreign anchors are ignored, and a lane is foreign only when every unmerged commit names another task.

• *Batch-squash receipts* — Was: a `commit_receipt` naming a multi-task squash charged every sibling's paths to the closing task. → Now: QA judges the delivery anchor's own paths when the squash carries all of them.

• *Fresher verification target* — Was: `resolve_target_branch_ref` bound a local target ~1000 commits behind origin. → Now: it binds `origin/<target>` when local is a strict ancestor; equal, ahead or diverged local still wins.

• *Close off the async runtime* — Was: synchronous close work pinned a tokio worker, so parallel closes serialised and timed out as UNKNOWN at 55 s. → Now: close runs on the blocking pool with the caller's prefix and receipt scope; a late close answers IN_PROGRESS and appends `CLOSE_OUTCOME`, and an exact receipt replay returns the persisted boundary.

• *Snapshot and visual QA* — Was: a shared change needed one approval note per snapshot line, a translated finding read as new, and placeholder-hidden loading text was flagged invisible. → Now: `file-sha256:<digest>` approves a whole file, pure translations pair, rejections always record, and a marker-hidden painted placeholder is exempt.

*Factory and runtime*

• *Delivery watchdog* — Was: PTY echo of injected text grew pane output, so a swallowed message read as delivered. → Now: the watchdog reads the recipient's transcript for a turn start, nudges once and then flags `nudge_failed`.

• *MCP start-up* — Was: a pre-`initialize` `server/discover` probe made `cas serve` exit, and on macOS the dead child pid got a healthy worker killed; a failed start-up hung on stdin. → Now: the probe gets -32601, a live fingerprinted harness parent keeps the worker alive, and failed start-up exits within 2 s.

• *Launch canary floor* — Was: the canary floor was stamped after `finish_worker_spawn`, 0.8–19 s late, so fresh canaries were rejected and healthy workers killed. → Now: the floor is taken before the PTY starts.

• *Codex model preflight* — Was: a Codex worker could spawn on a model its ChatGPT account cannot run and look busy. → Now: spawn refuses it from `models_cache.json`, and a provider model refusal is fatal, relayed as a blocker and shown as stalled.

• *Task-store locks* — Was: every store open took the write lock and sync loaded the task under it, a lock inversion that stalled 31.6 s. → Now: opens write only when repair is needed, the sync queue has a busy timeout, and the task loads before the lock.

• *Postgres UTC* — Was: `mcp-server-neon` serialised naive timestamps in the host zone with a Z suffix. → Now: Neon and `server-postgres` stdio children run with `TZ=UTC` unless their env sets `TZ`.

• *Commander focus* — Was: a deferred render's microtask flush ran mid-Tab and a closed palette left a stale shell signature, so a hub update rebuilt the shell and focus fell to body. → Now: the flush waits a task, the palette adopts the closed signature and focus returns with its ring.

• *Doctor* — Was: a missing upstream credential got generic integrate advice even when a project `proxy.toml` block shadowed it, and a bad `violet_post` schema went unnoticed. → Now: doctor names the shadowing block, flags a `violet_post` schema with a top-level `anyOf` or missing kinds, and states bearer readiness.

Published archives: `cas-x86_64-unknown-linux-gnu.tar.gz` (SHA-256 `8116fa0f0120c44540cacc393c40caa9eb1931ac8b6b3ccb234e44b656782c16`) and `cas-aarch64-apple-darwin.tar.gz` (SHA-256 `aae369899a4b4ee4a3698228a58bb0d6820c750450fbd6573aac2c281ed0ee46`), both built by CI regardless of the tagger's host.

```
