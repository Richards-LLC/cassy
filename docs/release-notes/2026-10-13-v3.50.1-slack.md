## Dev thread

**Top-level:**

```text
*Live on production — Dev — Cassy v3.50.1*
Was: write roots lived in write-policy.toml behind a TTY plus typed-ALLOW gate. → Now: `[factory] write_roots` in .cas/config.toml, hook-gated.
```

**Reply (Was → Now):**

```text
*Project write roots in config.toml (GH #1182)*

• *Config key* — Was: 3.50.0 stored project roots in `.cas/operator/write-policy.toml`, invisible to `cas config list`. → Now: `[factory] write_roots = [...]` in the project's `.cas/config.toml`, registered and shown by `config get`/`list`, read by PreToolUse from the owning project's cas root (also for isolated worktrees).

• *Operator set path* — Was: `cas config set factory.write_roots` required no agent env markers, no agent ancestor, a TTY and a typed `ALLOW`, so the operator's `! cas …` from a pane was refused. → Now: it refuses only a `cas-worker-*` or `cas-server-*` cgroup and writes config.toml directly.

• *Set-time validation* — Was: entries were `path[:modes]`, canonicalized, refusing `/`, `$HOME` and `.cas/operator`. → Now: plain paths, each allowing create, edit and delete. Paths are canonicalized; `..` components, `/`, `$HOME` and its ancestors, the project root, and anything containing or inside `.cas/` are refused. The hook re-checks each entry and skips unsafe ones.

• *Hook is the agent gate* — Was: agents were kept out by the separate policy file. → Now: PreToolUse refuses agent `cas config set factory.write_roots`, and agent writes, in-place edits, renames and deletes of `.cas/config.toml`, `.cas/config.yaml` and `.cas/operator/` (file tools, NotebookEdit, apply_patch, redirections, tee, cp, mv, `sed -i`, `perl -i`, rm). No root admits any project's `.cas/config.*` or `.cas/operator/`.

• *Other write paths* — Was: `Config::set` refused the key because roots were not in config.toml. → Now: it still refuses it, so MCP, the config TUI and reset cannot widen roots, and `cas config import` keeps the current value.

• *Compatibility* — Was: roots and grants shared write-policy.toml. → Now: legacy roots are unioned in the hook and migrated on the next set (an empty value clears both). Per-task grants (`cas config grant-write`, Commander) stay in the operator file, unchanged. With no roots configured, the workspace contract is unchanged except for the config-file refusal.

• *CLI output* — Was: `cas config set --help` printed 337- and 486-column lines. → Now: help, set/get output and refusals wrap at 78 columns in ASCII.

Published archives: `cas-x86_64-unknown-linux-gnu.tar.gz` (SHA-256 `8c30d63da5cef10c50f68e34e7e1fc3fc6ba52442beb5619f22640b900871f34`) and `cas-aarch64-apple-darwin.tar.gz` (SHA-256 `b4fec4c3c179e9fd073691b7413858017307e1d033682527441cc62f6de3fe60`), both built by CI regardless of the tagger's host.
```
