## Dev thread

**Top-level:**

```text
*Live on production — Dev — Cassy v3.56.0*
Was: external reminder probes and gated Teams inboxes blocked the daemon loop and message delivery. → Now: probes run off-loop and Teams members own their inboxes.
```

**Reply (Was → Now):**

```text
• *Daemon loop* — Was: `branch_contained_in`, `tag_exists` and `ci_completed` reminder probes ran `git fetch` and `gh` on the daemon loop, delaying other work. → Now: they run off-loop, fetch each ref once per pass, and back off or expire stale reminders.

• *Teams inbox* — Was: a Claude Teams member's messages stayed gated. → Now: the `<name>@<session>` member owns its inbox, messages surface at tool boundaries and turn start, and confirmation needs a transport receipt.

• *Startup validation* — Was: delayed startup could time out before the CAS server was ready, and version drift failed during setup. → Now: the wait window is honored, known mismatches are caught before launch with a fix named, and `spawn_brief` arrives once.

• *Delivery receipts* — Was: waivers could follow the wrong branch, receipts could include a later merge's files, and merge status could be reported too early. → Now: waivers use the delivery branch, and each receipt checks its own first-parent diff.

• *Lifecycle* — Was: `shutdown_workers` and `clear_context` could fail silently when the store was busy. → Now: shutdown works under contention, and a failed reset records why.

• *Tool validation* — Was: `remind` refusals listed one missing field, verification rejected `issues` arrays, and broadcasts lacked replacement and later-delivery controls. → Now: refusals list every missing field, arrays work, and `supersede_key`, `sticky`, and `video/webm` artifact uploads are supported within the 3,600 B schema cap.

• *Publication timing* — PR opened 3:55:48 → merged 4:11:27 (15m 39s) → published 4:18:22 (6m 55s) → installed 4:19:49 (1m 27s). PR to install: 24m 01s (25m rounded). Times ET. Budget comparison unavailable because no separate limit was recorded.
```
