## User thread

**Top-level:**

```text
*Live on production — User — Cassy v3.57.0*
Was: upgrades could break Slack sign-in. → Now: upgrades keep Slack (Violet) working.
```

**Reply (Was → Now):**

```text
*Accounts and messages*

• *Violet upgrades* — Was: an update could leave Slack unable to sign in. → Now: existing accounts are repaired and checked during updates.

• *Profile upgrades* — Was: old credentials could break sign-in after an update. → Now: every profile migrates and launches with its saved credentials.

• *Messages to teammates* — Was: a message could be repeated or lost. → Now: it appears once, with the full body preserved.

• *Supervisor replies* — Was: replies and requests could sit unseen. → Now: peer replies and asks wake supervisors; FYIs stay quiet.

• *Safer connected tools* — Was: background work could run commands under your account. → Now: operator-authenticated commands and matching tools are refused.

• *Issue tracking* — Was: an unset repository could hide a project's issue tracker. → Now: the GitHub origin supplies it, and checks show the source.

• *Shipped issue links* — Was: fixed issues could stay open without a clear trail. → Now: new tasks suggest links, release closure warns, and checks list them.

• *Short send receipts* — Was: every send repeated a long status. → Now: success is brief; delivery problems include the detail.

• *Safer message delivery* — Was: a direct message could skip recipient and rate checks. → Now: every message follows the same delivery rules.

• *Safer stops* — Was: stopping by name could interrupt unrelated work. → Now: stops are limited to the command you started.

*Fewer interruptions*

• *Smoother screens* — Was: hidden views could keep updating while typing. → Now: visible views stay responsive and typing appears first.

• *Long-running work* — Was: long commands triggered repeated quiet warnings. → Now: active work stays quiet and old warnings become one notice.

• *Shutdown summary* — Was: stopping several background jobs produced a critical alert for each one. → Now: one clear summary reports the outcome.

• *Fresh start details* — Was: a relaunch could show output from the previous run. → Now: notices describe only the current run.

*Builds and reliability*

• *Focused terminal checks* — Was: work with no terminal output could be blocked by a terminal receipt. → Now: only changes that draw terminal output need one; other work uses its real-build proof.

• *Reclaimed build space* — Was: old build data could crowd the disk. → Now: safe cleanup frees stale data under pressure and flags unclear results.

• *Memory-limited builds* — Was: simultaneous builds could compete for host memory. → Now: each build stays within its configured memory limit.

• *Runtime settings* — Was: some supported settings were not configurable. → Now: all runtime settings are readable and changeable.

• *Slow-work indicator* — Was: a delay gave no clue what had stalled. → Now: the slow or stuck step is visible.

• *Release reports* — Was: changes under descriptive headings could count as zero. → Now: reports count every change correctly.

• *Boolean settings* — Was: the text values `true` and `false` were rejected. → Now: either spelling works.

• *Flexible scratch paths* — Was: paths containing variables were refused. → Now: they are accepted.

• *Chosen destinations* — Was: an explicit destination could route work somewhere else. → Now: work stays with the destination you choose.

Install: `cas update` for an existing installation, or download the v3.57.0 archive for Linux x86_64 (SHA-256 `{{LINUX_SHA256}}`) or macOS ARM64 (SHA-256 `{{MACOS_SHA256}}`) from the GitHub release.
```

## Dev thread

**Top-level:**

```text
*Live on production — Dev — Cassy v3.57.0*
Was: stale credentials and unbounded delivery paths could break upgrades or bury useful status. → Now: migration and runtime controls enforce the same contracts.
```

**Reply (Was → Now):**

```text
*Upgrade and messaging*

• *Violet migration* — Was: updates left old profile keys. → Now: all Claude/Codex profiles migrate, `tools/list` is verified, and empty bearers are refused.

• *Compact receipts* — Was: success returned a ~540-character block. → Now: success is one line; failures keep detail in the receipt and `message_status`.

• *Message policy* — Was: direct `SendMessage` skipped target, session, rate and origin checks. → Now: it directs callers to the validated path.

• *Owned command control* — Was: pattern stops could interrupt another command. → Now: the hook blocks name-based kills but allows PID-scoped stops.

• *Memory isolation* — Was: parallel compiles could exceed available memory. → Now: each compile has its own configurable memory limit.

• *Runtime controls* — Was: supported settings lacked typed command-line access. → Now: all runtime settings can be read and updated consistently.

• *Slow-step indicator* — Was: slow work hid its stuck step. → Now: named budgets and the TUI identify slow or stuck steps.

• *Activity-aware nudges* — Was: open calls triggered repeated stall nudges. → Now: task activity suppresses false stalls and replaces stale nudges.

• *Shutdown receipts* — Was: shutdown alerted critically for every command. → Now: one non-critical summary reports outcomes; unexpected deaths still alert.

• *Recycle diagnostics* — Was: a same-name relaunch could quote prior output. → Now: old session output is cleared before the new session starts.

*Reports and API inputs*

• *Release report parsing* — Was: summaries under `Fixed`/`Changed` were not counted. → Now: descriptive sections count; presentation headings are ignored.

• *Boolean decoding* — Was: MCP rejected string booleans. → Now: `true`/`false` work; invalid values still fail.

*Rendering, disk use and paths*

• *Render scheduler* — Was: redraws could delay typing. → Now: focused/unfocused/off-screen panes cap at 15/5/0 fps;
  typing draws first; the spawn spinner caps at 10 fps.

• *Memory-limited systemd builds* — Was: systemd-run expanded `$VAR` in embedded test scripts on systemd 254+, breaking checks. → Now: `--expand-environment=no` sends them to Bash and Python unchanged.

• *Terminal-QA scope* — Was: backend and mux input/PTY/resize changes could require a terminal receipt. → Now: only CLI drawing paths and cas-mux render.rs, pane/style.rs, and pane/snapshot.rs require receipts; no-surface tasks and mux input/PTY/resize use the real-build interaction ledger.

• *Disk-cache reclaim* — Was: stale worker build caches could consume disk under pressure and blur uncertain results.
  → Now: GC safely reclaims stale caches and reports `indeterminate` separately.

• *Scratch-path variables* — Was: paths containing `$VAR` were refused. → Now: variable paths are accepted.

• *Explicit epic targets* — Was: an explicit `epic/` target could use the task lane. → Now: it selects that epic's lane.

• *Reliable unread alerts* — Was: acted-on messages could still trigger unread alarms. → Now: only evidence tied to that message clears its alarm.

• *Reliable activity alerts* — Was: unrelated activity could hide a real stall. → Now: only evidence tied to that work row suppresses its alarm.

• *Faster release checks* — Was: a large release needed repeated child checks. → Now: one bounded check verifies every released child.

• *Quieter optional integrations* — Was: an unset optional key logged as an error every session. → Now: missing keys log quietly; real failures remain errors.

• *Private launch credentials* — Was: launches could miss migrated profile credentials. → Now: every profile migrates, launches load private credentials, and empty tokens are never sent.

Install: `cas update` or Linux x86_64/macOS ARM64 archives. SHA-256: Linux `{{LINUX_SHA256}}`; macOS ARM64 `{{MACOS_SHA256}}`.
```
