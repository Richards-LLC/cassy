```text
*Acknowledged delivery*

• *Receipt verdict* — Was: a pane handoff looked like completion. → Now: `message_status` leads with RECEIVED or PENDING from recipient evidence, and names ended deliveries without a receipt.

• *Abandoned messages* — Was: an item could still report Delivered after wake checks were declined; the sender saw no cause and a successor lacked the message. → Now: it reports Undelivered, names the reason and carries content to the next live session.

• *Idle wake cadence* — Was: the normal watchdog waited 120 seconds and retried once. → Now: it checks after 30 seconds, then nudges every 60 seconds up to five times while no turn has started.

• *Wake bursts* — Was: several messages could repeat wake work, and an optional batch failure could interrupt delivery. → Now: directed wakes are debounced, share bounded deadlines and still deliver when batching fails.

• *Escalation* — Was: unread messages could wait hours before escalation. → Now: priority and normal thresholds both default to 300 seconds, notifying the sender and operator.

• *Caller identity* — Was: response fallback could drain a parent's mail for a child call. → Now: caller identity is checked before mail is surfaced or consumed.

• *Correct message context* — Was: a message mentioning older work could be treated as a stale delivery. → Now: it is tied to the intended context, and a truly closed target gets an explicit refusal.

• *Violet reconnects* — Was: command-line and background delivery classified proxy outages differently. → Now: both use the shared MCP reconnect mapping and bounded retry policy.

• *Peer succession* — Was: messages for an ended or signed-out recipient could stall or look stale. → Now: they reach a verified successor when available, or return a clear refusal with bounded recovery details.

*Cloud and command safety*

• *Cleanup ownership* — Was: global task ownership and concurrent checkpoints could go unverified. → Now: project and global stores are checked read-only, with bounded retries and uncertain ownership refused.

• *Credential path resolution* — Was: a command could reach saved credentials with relative paths after changing directories. → Now: directory changes and recursive path operands are checked before access.

• *Local queue preview* — Was: a dry-run migration could trigger Cloud credential preflight. → Now: the read-only plan loads no credentials; applying it still requires authentication.

• *Queue diagnostics* — Was: held personal rows counted even when they could not migrate, and generic retry advice obscured the cause. → Now: counts cover migratable rows and held-only queues point to the migration remedy.

• *Stable migration plans* — Was: duplicate personal rows could make preview differ from apply. → Now: both use one deduplicated eligibility plan without discarding original rows.

• *Transient sync recovery* — Was: a temporary network failure could leave personal sync work parked. → Now: bounded retries re-arm it without duplicating the queued work.

• *Lossless task notes* — Was: NUL rejection advice blocked recovery and an interim repair stripped text. → Now: stored notes and queued payloads stay exact; rows remain parked until Cloud can round-trip NUL losslessly.

*Replies and review flow*

• *Managed-thread files* — Was: a local-file reply lacked automatic reply-intent fields and could be refused as external. → Now: the caller's intent supplies thread and claim checks for a normal file reply, with the same request id for a safe retry.

• *Replaced drafts* — Was: a newer message from the same task could be reported as a dropped delivery after a sync changed its draft. → Now: its own replacement is recognized as a superseding update.

• *Actionable notifications* — Was: already handled events or activity that still needed a review could trigger another prompt. → Now: notices follow current state and appear only when they still need action.

• *Cross-project proposals* — Was: aliases could make an accepted task's target mismatch or leave ownership dependent on notes. → Now: registered project identity is resolved consistently and a local acceptance record grounds the receipt.

• *Accepted proposal history* — Was: accepted work could disappear from its board or be pruned from untrusted notes. → Now: it stays visible and its acceptance record controls retention.

• *Delivery accounting* — Was: shared or reassigned branches could make completed deliveries look stranded. → Now: close checks each delivery's own branch, including earlier owners' remaining commits.

• *Named task handoff* — Was: a caller-supplied assignment tag or a busy session could start the wrong task. → Now: untrusted tags are discarded and each start binds to its named task.

• *Planning scope* — Was: a plan could hide overlapping work or a local outage, or include work outside a peer's scope. → Now: warnings remain visible and plans stay within the requested scope.

• *Lifecycle-safe rework* — Was: an older sync event could reopen work after a newer delivery decision. → Now: rework follows the latest task lifecycle action.

• *Merge alert completion* — Was: a terminal fallback or delayed native alert could lose an unfinished merge notice. → Now: alert work is rechecked against the current inbox and completion is retained through fallback.

• *Generated skill history* — Was: a close check could run an unsupported generator or compare stale generated references. → Now: it uses the supported scoped generator and rebuilds each output from merged history.

• *Task delivery range* — Was: target-branch syncs could make a task's own delivery look like extra work. → Now: delivery checks skip target-sync merges and follow that task's branch tip.

• *Shared contact authority* — Was: named-contact posts could proceed without a shared contact check, or leave the outcome unclear on timeout. → Now: authority is reserved before sending, retries keep one request identity and local uncertainty is visible.

*Proof, splits and setup*

• *Portable proof* — Was: evidence and its task context could stay on one machine or branch. → Now: synced notes carry proof artifacts, and parked reviews recover only for the owning machine and session.

• *ARTIFACT_PROOF field refusals* — Was: selected evidence fields could accept caller-supplied markers. → Now: close/cancel/reopen/request_changes/QA reasons, transfer notes, stranded override, spawn_brief and worktree_merge reason refuse them.

• *Fair work splits* — Was: a split needed both sides at once, and expired claims could strand child work. → Now: either side can initiate, decisions are recorded, and a live successor can cancel an orphaned split.

• *Parked checkout adoption* — Was: a receiving session could lose commits from a parked source checkout. → Now: adoption preserves its history and reconciles the linked checkout before work resumes.

• *Viktor opt-out* — Was: a saved opt-out could be ignored by later prompts, and an explicit re-add could remain disabled. → Now: opt-out persists and an explicit add enables Viktor again.

*Developer and release tooling*

• *Elegant tests* — Was: test-first required a new file, and one verifier verdict could create a project rule. → Now: a changed test case in an existing file qualifies, while reusable lessons stay candidates until separate tasks repeat them.

• *Release reports* — Was: empty issue captions could count outside the report ledger, and a closing folio could create a footer-only page. → Now: counts stay scoped to that ledger and the final page keeps its content.

• *Commander-branded reports* — Was: report pages did not follow the Cassy hub's visual system. → Now: shared colors, type, mark, Was→Now cards and example captures carry through HTML and print.

• *Installed hub binary* — Was: update could restart a stale launchd or systemd executable, with no repair guidance. → Now: it checks the service definition before restart and points to `cas hub service install` when they differ.

• *Startup readiness* — Was: service install reported not running just after activation. → Now: it reports `starting` until the runtime is ready.

• *Hub status phases* — Was: status could lose the startup phase or give drift advice outside the affected service. → Now: it retains the phase and scopes repair guidance to the detected drift.

• *Codex version probe* — Was: suffixes and abbreviated versions confused model-cache checks. → Now: versions compare consistently, and an on-demand probe fits the existing five-second account deadline.

• *Linux isolation design* — Was: changing HOME alone left absolute credential paths visible. → Now: the Linux prototype recommends a mount boundary and explicit tool/auth grants; production enforcement and macOS support remain pending.

• *SOW delivery reports* — Was: client delivery meant hand-assembling requirements, feedback rounds and screenshots. → Now: a built-in workflow tracks each outcome and round, pairs real captures and prepares a branded report and PM handoff.

• *SOW report hygiene* — Was: ambiguous client terms or a sign-in redirect could pass as report evidence. → Now: client identifiers and standards are bounded, and login success is checked before capture.

• *Viktor import cleanup* — Was: case and import variants could create duplicate or mismatched accounts. → Now: identities are normalized before cleanup.

• *Actionable login check* — Was: a login preflight could overflow a narrow terminal. → Now: its explanation wraps and keeps the next action visible.

• *Readable SOW captures* — Was: report evidence could be cramped on phones or lose full-width print flow. → Now: client identifiers are preserved and captures fit phone and print layouts.
```
