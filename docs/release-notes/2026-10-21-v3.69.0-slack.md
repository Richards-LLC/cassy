## User thread

Top-level:

```text
*Live on production — User — Cassy v3.69.0*
Was: helper sessions could read your saved Neon and Vercel sign-ins with a crafty command. → Now: on Linux they cannot see them at all.
```

Reply:

```text
*Your sign-ins stay private*

• *Neon and Vercel sign-ins hidden* — Was: a helper session Cassy started for you could read your saved Neon or Vercel sign-in files through a script or a chained command that the safety check could not follow. → Now: on Linux those files are hidden from helper sessions entirely, and pushing code still works; on a Mac the safety check remains the protection.

*Clearer messages*

• *Sharing warning during updates* — Was: when an update found network sharing switched off, the reason ran together with the heading and broke mid-sentence. → Now: the heading stands on its own line with the reason neatly beneath it.

• *Errors your scripts can read* — Was: when a settings or hub command asked for machine-readable output was refused, the error came back as styled text only. → Now: the refusal comes back in the same machine-readable form, with the same message.

• *Status marks on plain terminals* — Was: on a terminal without Unicode support, status lines showed symbols it could not draw. → Now: they show plain words such as [OK] and [WARN].

Install: use `cas update` after publication. Linux x86_64 SHA-256 `{{LINUX_SHA256}}` · macOS ARM64 SHA-256 `{{MACOS_SHA256}}` from <https://github.com/Richards-LLC/cassy/releases/tag/v3.69.0|the GitHub release>.
```

## Dev thread

Top-level:

```text
*Live on production — Dev — Cassy v3.69.0*
Was: workers shared the operator's HOME, so Neon and Vercel stores were one interpreter call away. → Now: Linux workers spawn with them masked.
```

Reply:

```text
*Credential-store isolation*

• *Masked stores* — Was: the PreToolUse guard could not stop interpreter one-liners, piped shells or variable indirection from reading the Neon and Vercel CLI stores. → Now: on Linux, `Pty::spawn` starts workers in a bubblewrap user+mount namespace that covers each non-empty store with an empty read-only tmpfs; host filesystem, PIDs, env and cwd are unchanged, and the guard stays as defense in depth.

• *Fail-closed spawn* — Was: no isolation backend existed, so a host without one exposed the stores silently. → Now: a store with no usable `bwrap` or unprivileged user namespaces refuses the spawn with a remedy; `CAS_WORKER_STORE_ISOLATION=off` in the daemon env opts out, and macOS has no backend yet and warns.

• *ssh inside the namespace* — Was: root-owned ssh config drop-ins appear owned by `nobody` inside a user namespace. → Now: workers get a user-owned copy of the drop-ins, following symlinks, so ssh and `git push` keep their config.

*Output*

• *Serve warning layout* — Was: `cas update` printed "Tailscale Serve inactive: <cause>" as one run, wrapped at the findings cause column. → Now: the label takes its own line and the cause wraps beneath it at a continuation indent.

• *JSON refusals* — Was: `cas --json config` and `cas --json hub` refusals took the styled stderr error path and left stdout empty. → Now: they print one `{"status":"error","message":…}` document on stdout, with `CasError` exit codes unchanged.

• *ASCII status fallback* — Was: `StatusLine` drew its glyph whenever output was styled, even on a non-UTF-8 locale. → Now: it checks `Formatter::glyphs()` and falls back to the coloured `[OK]`/`[WARN]`/`[ERROR]`/`[INFO]` tags.

• *Recovery content unwrap* — Was: the abandonment-recovery batch called `unwrap()` on a notice's recovery content. → Now: it uses `if let`; behaviour is unchanged because that batch only holds notices with content.
```
