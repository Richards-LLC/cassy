## User thread

Top-level:

```text
*Live on production — User — Cassy v3.70.0*
Was: you picked by hand what to re-check after a change. → Now: Cassy shows what a change touches and keeps your project docs current.
```

Reply:

```text
*Checks that follow your change*

• *Re-checks chosen for you* — Was: after a change, someone had to guess which parts of the product to walk through again.
→ Now: Cassy reads what the change touched and lists the user journeys it affects, the proof each one needs and any files no journey covers.

• *One list of your user journeys* — Was: the paths people take through your product lived only in loose notes, with nothing checking them against the code.
→ Now: one list records each journey with its files and tests; Cassy can draft it from your project and flags broken links and gaps.

• *Docs kept current* — Was: work could finish while leaving the code map or product overview out of date, or add a new journey nobody listed.
→ Now: Cassy refuses to hand that work over until the document is updated or a written reason says why it did not need to change.

• *Warnings first for existing projects* — Was: a new rule like this would start refusing work the day it shipped.
→ Now: projects you already have get one release of warnings only; refusals start with the next release, and new projects get them from day one.

• *A check after each release* — Was: nothing confirmed a release still worked once it went out.
→ Now: a project can name a safe, read-only check that Cassy runs a few times in the half hour after release; release notes wait for a clean result.

*Fixes*

• *Hub settings reach your machine* — Was: changing a hub setting from inside a project saved it to that project, so the hub on your machine never saw it.
→ Now: hub settings always save to your machine's own settings, from any folder.

• *Release notes checked before posting* — Was: a release note with a very long line passed the pre-post check and was then refused by Slack.
→ Now: the check catches lines over 300 characters first, and no longer misreads a two-line item followed by a heading.

Install: use `cas update` after publication. ## Dev thread

Top-level:

```text
*Live on production — Dev — Cassy v3.70.0*
Was: QA scope was hand-picked and docs drifted silently. → Now: `cas qa impact` maps diffs to journeys and park enforces registry, CODEMAP and overview upkeep.
```

Reply:

```text
*Adaptive QA*

• *Journey registry* — Was: journeys lived in prose QA docs with no machine-checkable owners.
→ Now: a v1 YAML journey registry lists owners, specs and surfaces; `cas qa journeys --check` validates it, `--seed` drafts one and keeps curated entries, and `cas doctor` shows its counts.

• *Journey impact* — Was: QA selection had no tool behind it.
→ Now: `cas qa impact [BASE..HEAD | --files | --stdin | --task]` emits text, Markdown or JSON v1 with journeys, `evidence_required` and unowned files; exit 2 for usage, 3 for read errors.

• *Impact on parked deliveries* — Was: QA dispatch and ledgers knew nothing of the journeys a delivery touched.
→ Now: park stores a Cassy-managed `qa_impact` snapshot; an approved `qa_record` needs a PASS, FAIL, NOT A ROUTE or NOT EXERCISED row for each live journey.

• *Upkeep gates at park* — Was: a delivery could orphan registry globs, add unowned surface files, or move directories without touching CODEMAP or PRODUCT_OVERVIEW.
→ Now: G1–G3 (registry) and G5/G6 (CODEMAP, overview) refuse at park unless the delivery updates the document or records a decision escape.

• *Staged adoption* — Was: a new gate applied to every project at once.
→ Now: `cas init` and `--seed` select `enforce`; an existing project's first `cas update` writes `observe` for `upkeep.*` and `qa.registry.enforce`, promoted on the next release unless pinned.

• *Post-release check* — Was: no signal after a release landed.
→ Now: `[qa.post_release]` runs a read-only command under `cas serve` at about +0/+15/+30 min; pending or failed receipts hold release-note posts and epic close. Unconfigured projects are unaffected.

• *Retired features gate* — Was: close checked `docs/qa/features` Touches globs with a `map unchanged:` escape. → Now: that gate is gone; the registry gates replace it.

*Fixes*

• *Host-scoped hub config* — Was: `cas config get|set|reset hub.*` followed project discovery, so a value set in a project never reached the hub.
→ Now: those keys and `list --section hub` resolve to the machine's own Cassy config before discovery; `CAS_ROOT` and `--store` no longer redirect them.

• *Announce lint line limit* — Was: `release-train-announce.py` passed lines the Violet hub refuses as `long_line`.
→ Now: `--validate` and `--lint` refuse any line over 300 visible characters, counting `<url|label>` as its label.

• *Announce lint bullet span* — Was: a two-line bullet followed by a bold section heading counted as three lines. → Now: a bullet ends at a blank line, the next bullet or a heading line.

Published Oct 21, 7:01 AM CT; 2328s (about 39 minutes) from merge-queue green to published release, over the 600s budget because no merge-queue prebuild existed and the release built from scratch; about 8 hours from release PR opened.
```
