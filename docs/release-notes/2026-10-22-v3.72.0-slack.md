# Slack draft — Cassy v3.72.0 runtime release

Channel: #cas-internal (C0B44GUKDK2)

**Status:** Posted 22 October 2026 · 5:11 AM CT (6:11 AM ET); receipts below.

## User thread

**Top-level:**

```text
*Live on production — User — Cassy v3.72.0*
Was: parallel sessions could collide, lose messages or misreport finished work. → Now: Cassy coordinates them and reports what really happened.
```

**Reply (Was → Now):**

```text
*Shared work stays coordinated*

• *Task ownership* — Was: overlapping sessions could clear a task's claim at the wrong time.
→ Now: claims stay protected while another session takes over or restarts the task.

• *Shared files* — Was: two sessions on one project could edit the same file without either knowing.
→ Now: the edit still goes ahead, and Cassy says who else holds the file, on which machine and for which task.

• *Handing work over* — Was: handing a task to someone else could leave it locked until a timer ran out.
→ Now: release, reset, transfer and handing back free the task at once.

*Merges and reviews report what actually happened*

• *Merge results* — Was: a slow merge could report an unknown outcome even though it had finished.
→ Now: a finished merge always says so, and the rest of the close is recorded on the task when it completes.

• *Branches in one place* — Was: merging into a branch that existed only online, or only on your machine, could fail with a confusing error.
→ Now: both cases merge cleanly, and an unreachable server is reported as not pushed.

• *Build results* — Was: a reminder could fire before the build checks had really finished, or never fire when they were cancelled.
→ Now: it fires once the checks are actually done.

• *Follow-on work* — Was: follow-up work planned on top of unreleased changes could not start.
→ Now: it builds on the unreleased changes and warns when it falls behind them.

• *Fewer repeat test runs* — Was: changing only a doc after a passing test run forced the tests to run again.
→ Now: a doc-only change keeps the earlier test proof.

*Messages reach the right person*

• *Questions are kept* — Was: a question could be silently dropped when other messages arrived at the same time.
→ Now: every message is kept and shown once, oldest first.

• *Reminders* — Was: a reminder could appear to come from the wrong person, or stay pending forever.
→ Now: reminders keep their real sender and expire when they no longer apply.

• *Picking up after a reset* — Was: resuming a session after a reset could forget answers it had already received.
→ Now: the resume summary includes those answers.

• *Session handover* — Was: when a coordinating session ended, its open tasks and pending questions were lost.
→ Now: they are handed to the next session, with a short preview at startup.

*Builds and disk space*

• *Urgent builds first* — Was: an urgent build waited behind routine ones.
→ Now: builds start in priority order, and nobody can jump the queue by raising their own priority.

• *Disk space* — Was: review copies of the project piled up on disk and were never cleaned up.
→ Now: they are reused, then cleaned up after their task, with unsaved changes kept.

• *Cleanup reports* — Was: the cleanup report overflowed the screen and called real changes a preview.
→ Now: it fits the screen, explains each cleanup step and can be run from the command line.

*Smoother everyday commands*

• *Restarting the hub* — Was: two restarts at once could both report failure while a hub was left running.
→ Now: each restart reports what really happened and leaves one healthy hub.

• *Settings* — Was: some listed settings were refused as unknown, and resetting one wrote the default back.
→ Now: every listed setting works, and reset removes your override.

• *Plain terminals* — Was: setup, help and prompts printed symbols that plain terminals cannot show.
→ Now: they fall back to plain characters and fit narrow windows.

• *Copy-paste fixes* — Was: some suggested git commands could be changed by the shell when pasted.
→ Now: suggested commands are quoted so they run exactly as shown.

Upgrade from 3.71: after installing 3.72, restart every MCP server, hub and coding session on the host. Updating the binary and restarting only the hub are insufficient.
Install: use `cas update`, or download the Linux x86_64 archive (SHA-256 `fe387afb098fccc3499763f92a8942e745a9f7484f2b79e0fbae8d23484fde9c`) or macOS ARM64 archive (SHA-256 `1e04d966999848dbdf1debab851fc7fc0374acf8363d35050696998f24f2d197`).
```

## Dev thread

**Top-level:**

```text
*Live on production — Dev — Cassy v3.72.0*
Was: claims, merges and messages could race or report UNKNOWN. → Now: fenced claims, cross-session file leases and committed merge receipts.
```

**Reply (Was → Now):**

```text
*Claims and file leases*

• *Claim fences* — Was: 3.71 took no per-task fence; only unreleased development builds deleted settled fence files.
→ Now: 3.72 retains those files and releases their OS locks. Pending, synchronous and manual-claim releases all go through the fence.

• *Cross-session file leases* — Was: Edit/Write in two factory sessions on one repo never saw each other.
→ Now: edits claim the repo path as a Cloud `File` claim, and a held file gets a holder/machine/task advisory. Codex `apply_patch` edits are claimed too.

• *Lease lifecycle* — Was: release, reset, force-transfer and a blocked yield left file or task leases until expiry.
→ Now: they free them and name the real holder. Cloud claim release runs off the caller on park, close and cancel.

*Merges*

• *worktree_merge receipts* — Was: a merge past the 55 s MCP budget answered `Mutation outcome: UNKNOWN`.
→ Now: COMMITTED once published, with merge and push state. The background close writes its outcome and task status to a note.

• *Merge targets* — Was: origin-only targets failed `not something we can merge`, and local-only re-merges hit `CONTAINMENT COULD NOT BE VERIFIED`.
→ Now: origin-only targets are materialized, origin confirms local-only, one fetch is reused and a no-op skips the sync.

• *Parked delivery pinning* — Was: a merge could take the worker's unpushed local HEAD and treat an HTTP 422 CI lookup as advisory.
→ Now: guards and git operations pin the reviewed SHA, and drift or missing remote commits are refused.

• *ci_completed* — Was: it fired while a check-run was still in progress, and never fired when every check-run was cancelled.
→ Now: it settles exactly when merge admission would see CI finished.

• *Stacked epics* — Was: a successor epic created during an unreleased one was cut from main.
→ Now: it stacks on its open predecessor, and `epic_status` warns about lag, cross-host local-only lanes and attributed supersessions.

• *Superseded merge alerts* — Was: fallback delivery paths kept the stale MERGE REQUIRED text for a superseded tip.
→ Now: they deliver the Superseded body, without stale ref-disagreement or push-required lines.

*Close and park gates*

• *Proof inputs* — Was: a doc-only change after a receipt forced FOCUSED PROOF REQUIRED, and inputs were read from the checkout HEAD.
→ Now: doc-only ranges rebind, while embedded crate files and manifests are read from the delivered tree.

• *Delivery anchors* — Was: re-closes, amended anchors and reused lanes were refused or misattributed.
→ Now: approved receipts survive a re-claim, amended anchors rebind and delivery binds to the task's start base.

• *Concurrent close writes* — Was: the terminal close write could revert a concurrent `proof_scope_fix` or a note appended mid-close.
→ Now: both survive, and an audited no-delivery declaration closes genuinely empty work.

• *Gate order with the new checks* — Was: 3.71 had no parked-delivery or no-delivery checks to order against its QA and merge gates.
→ Now: a backend-only squash closes without a QA round, a pending QA round refuses both merge paths first, and start resolves an origin-only epic base.

• *Priority guard* — Was: 3.71 had no guard on a worker raising its own task's priority.
→ Now: the guard runs only for a real priority change, after the proof-scope check, so a locked delivery scope is refused as such.

*Messaging*

• *Folded worker actions* — Was: a worker's question could be dropped as superseded by a control-policy message.
→ Now: coalesced actions carry every body once, oldest first, and `message_status` answers local ids.

• *Reminders and resume briefs* — Was: reminders were misattributed or never expired, and recycle/clear briefs dropped received answers.
→ Now: issuers are kept, orphans expire, and briefs include capped received history.

• *Supervisor handoff* — Was: session end lost owned tasks, live workers, parked PRs and pending asks.
→ Now: the handoff keeps lease evidence and is bound to the successor's registration epoch.

• *SessionStart handoff pointer* — Was: SessionStart compaction could drop the handoff stub when other guidance grew.
→ Now: the compact pointer (id, title and get command) is kept for every role within the unchanged budget.

*Builds, gc and the hub*

• *Build admission* — Was: P0 builds queued behind P2 at the cap, and verifier subagents built outside it.
→ Now: priority-ordered admission refuses self-promotion, and `cas factory verifier-test` runs verifiers in the capped lane.

• *Capacity waits* — Was: every capacity refusal toggled the task to blocked and paged the supervisor.
→ Now: a bounded wait keeps the lease and status, one notice past the bound wakes an idle supervisor, and fruitless admission GC cools down.

• *Scratch and gc* — Was: review scratch checkouts were never reclaimed, and `gc_report` overflowed the terminal.
→ Now: task-owned checkouts are collected, and `cas factory gc report|cleanup` shows a bounded summary with full and JSON views.

• *gc durable-artifact counts* — Was: 3.71's gc report printed raw, unbounded status lines.
→ Now: the bounded summary keeps the durable-artifact counts on their own row, ahead of long paths, within 80 columns.

• *Hub restarts* — Was: concurrent `cas hub restart` calls could both report `status:error`, lose the hub's process record or leave an empty cgroup.
→ Now: outcomes are attributed to the peer, and cleanup holds the machine lock.

• *Config and locale* — Was: registered keys were refused, editor resets wrote defaults and `LC_ALL=C` printed Unicode.
→ Now: the keys work and `notifications.webhook_url` is operator-only. Resets remove the key, and output falls back to ASCII.

*Other*

• *Rule observation* — Was: `rule action=observe` failed with `database is locked` under load, losing rule candidates.
→ Now: observation writes retry under contention.

• *Quoted git remedies* — Was: printed git remedies left `{ } , !` unquoted for bash to expand.
→ Now: remedies are quoted atomically, synced branch names are sanitized, and doctor's JSON keeps standalone git advice.

• *MCP schema size* — Was: 3.71's `tools/list` sat near its 59,000-byte budget.
→ Now: 3.72 adds `no_delivery`, gc `full`, `record_test_receipt` and `recover_branch` within it, with tightened descriptions and no rule dropped.

3.71 → 3.72 rollout: after installing 3.72, restart every `cas serve`, hub and worker session on the host, including harness-owned MCP servers and pinned sessions.
A running 3.71 process takes no per-task fence and can race 3.72 on the same task. `cas update` can restart the managed hub but does not restart or verify every other session. Retire unreleased development builds too.

Windows limitation: claim fencing is unverified; the exclusive whole-file lock can reject the generation recheck through a second handle. Restarting does not fix this. Local-lease fallback does not prove cross-process exclusion. No Windows asset is published.
Release timing: 20.6 min from release start to main (5:35 → 5:55 AM ET), 10.8 min from main to published (6:06 AM ET), installed on soundwave within a minute.
Published assets: the Linux x86_64 archive (SHA-256 `fe387afb098fccc3499763f92a8942e745a9f7484f2b79e0fbae8d23484fde9c`) and the macOS ARM64 archive (SHA-256 `1e04d966999848dbdf1debab851fc7fc0374acf8363d35050696998f24f2d197`).
```

## Publication handoff

Preserve the restart notice in both replies. Released 3.71 never deleted
claim-fence files; only unreleased v57 development builds did. Every old
process must still be restarted, because 3.71 takes no fence at all, and
`cas update` does not certify that the rollout is complete.

Validation, the release report and the posting receipts remain the release
owner's responsibility. The release train adds the measured publication timing
to the Dev reply.
