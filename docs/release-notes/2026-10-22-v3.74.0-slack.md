## User thread

Top-level:

```text
*Live on production — User — Cassy v3.74.0*
Was: uploads, sync and checks could give misleading answers. → Now: Cassy reports completion clearly and explains what still needs attention.
```

Reply (Was → Now):

```text
*Everyday commands*

• *Artifact uploads* — Was: Some file uploads failed or looked delivered when they were only saved locally.
→ Now: Uploads use the required settings and clearly distinguish local saves from completed delivery.

• *Complete checksums* — Was: A saved file's checksum was shortened with an ellipsis.
→ Now: The receipt shows the complete checksum for comparison.

• *Completion contention* — Was: A brief database lock after upload could require publishing the same proof again.
→ Now: Completion retries the local save and clearly reports when it still cannot finish.

• *Clean error output* — Was: Redirected error output could contain stray color codes.
→ Now: Errors follow the output stream you actually read or save.

• *Visible unsafe paths* — Was: An invisible character in a folder or branch could distort an error or its suggested command.
→ Now: Unsafe characters stay visible and unsafe copyable remedies are withheld.

• *Multiline Git details* — Was: Several lines of Git detail could collapse into text showing a literal backslash-n.
→ Now: The details keep their line breaks and unsafe characters remain visible.

• *Finished notifications* — Was: A notification command could exit before sending its webhook.
→ Now: It waits for a bounded result and says whether delivery was confirmed.

• *Account-aware login checks* — Was: A login check could inspect the wrong account or trust an overly long cached result.
→ Now: It checks the selected account and gives a clear retry time after login.

• *Old launcher files* — Was: Old startup files could accumulate after a process ended.
→ Now: Known files from dead starts are cleaned up while live and unrecognized files stay.

• *Update connections* — Was: An old inactive connection or a removed project folder could block an update.
→ Now: Updates pass inactive connections, including those with missing project folders, and name how to stop a connection still held.

• *Cloud receipts* — Was: Sync could say nothing was new while a completion disagreement remained, or repeat the same warning.
→ Now: The disagreement stays visible until resolved and appears once in a combined summary.

• *Readable sync warnings* — Was: A sync warning and its recovery hint could spill beyond a normal terminal.
→ Now: The shorter summary keeps the cause and recovery hint readable.

• *Plain-locale sync* — Was: Plain-text terminals showed unsuitable symbols or lost the reason an update sync was incomplete.
→ Now: Summaries fit the locale and retain the cause and recovery command.

• *Readable diagnosis* — Was: A diagnosis footer could run beyond a normal terminal width.
→ Now: The short recovery hint stays readable on an 80-column screen.

*Quality checks*

• *Declared QA safety* — Was: A project using test data could receive instructions to check live systems.
→ Now: QA instructions follow the declared setting and refuse listed credentials or destinations at startup.

• *Plan coverage first* — Was: You could not record a planned test or a new journey before its traffic was measured.
→ Now: Those plans are allowed and clearly listed as work still owed.

• *Unwritten tests stay clear* — Was: A planned test could look runnable or keep its planned label after it was written.
→ Now: Unwritten tests are named clearly and outdated labels get a warning.

• *Consistent journey status* — Was: One status screen mixed counts from different versions and could headline DRIFT or UNKNOWN.
→ Now: It labels each source and headlines the current working copy's problems or debt.

• *CODEMAP freshness* — Was: Different checks could disagree about whether the code map was stale.
→ Now: QA impact uses the same freshness calculation as the other status commands.

• *Shared ownership hints* — Was: A supposedly shared owner group used by only one journey had no warning.
→ Now: The check names it as a cleanup hint without failing validation.

• *Failures inside the promise* — Was: A promised fix that still failed could be dismissed because an older build failed too.
→ Now: Review guidance keeps failures inside that promise in scope and calls out tests that sidestep their own check.

• *Verification rejection policy* — Was: A serious finding or a reproduced silent failure could be approved with a warning.
→ Now: The shipped review instructions require rejection for those cases.

*Delivery and recovery*

• *Find the right repository* — Was: A slow unrelated folder could make Cassy reject a valid project.
→ Now: It checks the current project first and distinguishes an incomplete search from a real mismatch.

• *Recorded delivery branches* — Was: A valid delivery could be refused because its branch used a shortened name.
→ Now: Recorded ownership selects the intended branch and ambiguous alternatives are refused.

• *Approved replacement branches* — Was: An approved replacement delivery branch could leave Cassy checking the old reference.
→ Now: Authorized replacement records the prior branch and keeps the normal delivery checks.

• *Recover old start references* — Was: An earlier branch reference could block closing work that was already integrated.
→ Now: A validated delivery receipt can retire that stale reference with an audit trail.

• *Clearer start recovery* — Was: A start refusal could omit unsaved new files or suggest switching branches too late.
→ Now: Recovery advice names untracked files and says when to switch branches.

• *Less false overlap* — Was: Repeated safety instructions could make unrelated tasks look like duplicates.
→ Now: Overlap checks discount shared instructions while retaining the real task scope.

• *Accurate merge receipts* — Was: A merge record could hide whether checks passed or were overridden.
→ Now: The record distinguishes passed, unconfirmed and overridden checks.

• *Keep approved QA evidence* — Was: Equivalent integrated changes could lose their already-approved QA evidence.
→ Now: A complete diff comparison lets that evidence carry across safely.

• *Current ownership repairs* — Was: An ownership fix added after delivery could be ignored at close.
→ Now: Closing integrated work reads the current target's ownership declarations.

• *Net evidence changes* — Was: A document-only result could be refused because an earlier code edit was later undone.
→ Now: Ordinary evidence-only checks judge the final delivered difference.

• *Readable reference proof* — Was: A failed optional history read could block otherwise available delivery proof.
→ Now: The normal line comparison still runs when that optional read is unavailable.

• *Observation errors* — Was: A busy save could look like a bad request, and missing suggestions had no explanation.
→ Now: Busy saves report a server error and failed suggestion reads leave a warning.

• *Old reminder cleanup* — Was: Due reminders with no end date could remain forever after their sessions ended, with repeated cleanup notices.
→ Now: Those orphaned reminders expire and unchanged reminder counts no longer repeat on every scan.

• *Cleanup wording* — Was: A cleanup preview sounded completely read-only and a work-in-progress note ran into its summary.
→ Now: Help explains the limited preview and the notice has its own spacing.

*Build and release tools*

• *Durable review ownership* — Was: A power loss just after creating a review copy could leave it unrecognized for cleanup.
→ Now: Its ownership file is made durable before creation succeeds.

• *Nested check isolation* — Was: A check launched inside another test could accidentally reuse its launcher and fail.
→ Now: Nested checks use their intended launcher.

• *Progress lines from other projects* — Was: A normal progress message from another project could be flagged as cut-off text.
→ Now: Complete progress sentences such as Installing dependencies... pass the terminal check.

• *Mounted sibling tests* — Was: A test mounted by a differently named source file could be reported as missing coverage.
→ Now: Explicitly mounted sibling tests count toward the source file they exercise.

• *Warm review builds* — Was: A review check could rebuild dependencies already compiled for the same work.
→ Now: Eligible reviews reuse safely available build output and the matching build settings.

• *Prebuild lookup fairness* — Was: One unavailable release build could hide another usable build or end the search too soon.
→ Now: The search checks other builds and retries within its time limit.

Install: run `cas update` or choose the Linux x86_64 or macOS ARM64 download from the release.
```

## Dev thread

Top-level:

```text
*Live on production — Dev — Cassy v3.74.0*
Was: valid delivery evidence could be lost in retries and rewrites. → Now: completion, attribution and QA checks preserve the proven result.
```

Reply (Was → Now):

```text
*Everyday commands*

• *Artifact uploads* — Was: Signed PUTs could duplicate Content-Type and failed uploads printed success.
→ Now: Cloud-required headers win and CLI/MCP receipts report local-only until commit.

• *Complete checksums* — Was: Human publish receipts shortened SHA-256 with a Unicode ellipsis.
→ Now: The full ASCII digest is printed in every locale.

• *Completion contention* — Was: A lock after Cloud complete stranded an uploaded row.
→ Now: Only mark_committed retries with the shared wait budget, without replaying remote requests or proof attachment.

• *Clean error output* — Was: Diagnostic sinks selected color from stdout even when writing stderr.
→ Now: Top-level and affected command errors use stderr terminal detection.

• *Visible unsafe paths* — Was: Hook paths, conflict lists and Git refusals could contain raw controls or invisible Unicode.
→ Now: Diagnostic labels consistently escape unsafe characters without changing filesystem paths.

• *Multiline Git details* — Was: Whole-message escaping flattened multi-line Git details into literal backslash-n text.
→ Now: Merge refusal rendering escapes each row separately and preserves newline structure.

• *Finished notifications* — Was: A detached webhook thread could die at process exit and curl failures looked successful.
→ Now: The hook waits up to eleven seconds and reports the sender result.

• *Account-aware login checks* — Was: SSH keychain checks used the legacy service and writable cache TTLs could extend freshness.
→ Now: The account selector chooses the service and each cached state's TTL is capped.

• *Old launcher files* — Was: Stale launcher cleanup was a no-op.
→ Now: Launch removes recognized pid/go/error files only for a dead, valid PID.

• *Update connections* — Was: Dead GUI socket paths or unresolved project roots could block binding reconciliation.
→ Now: Dead sessions with unresolved roots reach endpoint inactivity checks, unrelated projects are skipped, and held or unknown endpoints still block.

• *Cloud receipts* — Was: A skipped remote terminal transition disappeared after the cursor advanced, and combined pulls duplicated it.
→ Now: Durable guard reporting survives empty pulls, matching diagnostics deduplicate and totals include both scopes.

• *Readable sync warnings* — Was: Guarded pull receipts could exceed eighty columns.
→ Now: Redundant no-rows text is omitted when errors already explain the guarded result.

• *Plain-locale sync* — Was: Push/pull separators were hard-coded and update parsing recognized only middle dots.
→ Now: Receipts use the shared separator and update findings parse both forms.

• *Readable diagnosis* — Was: The missing-backend footer exceeded eighty columns.
→ Now: It gives a shorter fix-and-rerun instruction.

*Quality checks*

• *Declared QA safety* — Was: Impact text assumed staging regardless of project policy.
→ Now: Registry safety drives evidence instructions, while preflight checks declared credential names and configured origins.

• *Plan coverage first* — Was: Unwritten specs and absent traffic shares always failed registry validation.
→ Now: Explicit planned specs and snapshot-less shares are debt, while ordinary missing coverage remains a problem.

• *Unwritten tests stay clear* — Was: Impact exposed a planned path as automated coverage.
→ Now: Planned paths are omitted from runnable impact specs, status lists them and stale markers warn.

• *Consistent journey status* — Was: Journey status combined measured-ref upkeep with working-tree counts.
→ Now: The headline uses registry validation, sources are labelled and integration upkeep appears separately.

• *CODEMAP freshness* — Was: QA impact separately counted files added in the CODEMAP commit as drift.
→ Now: It uses the shared measured freshness source.

• *Shared ownership hints* — Was: Single-consumer owner groups were not flagged.
→ Now: Registry validation adds named curation debt, separate from problems.

• *Failures inside the promise* — Was: Some QA guidance excluded every defect shared with base.
→ Now: Purpose, criteria, demo and edited invariants define scope, and guidance rates invariant-evading tests at least Normal.

• *Verification rejection policy* — Was: Verification instructions allowed high-impact findings to become warning-only follow-ups.
→ Now: The policy requires rejection for high/critical findings or realistic reproduced silent failures.

*Delivery and recovery*

• *Find the right repository* — Was: Known-root scanning could time out before reaching a matching checkout.
→ Now: Direct caller evidence wins, healthy matches survive incomplete scans and an absent known-repos table is an empty registry.

• *Recorded delivery branches* — Was: Merge lookup inferred ownership from one branch spelling.
→ Now: Recorded task authority selects the parked source and QA uses that resolved source.

• *Approved replacement branches* — Was: There was no supported way to replace an obsolete recorded delivery branch.
→ Now: MCP task action=rebind_branch requires an active, authorized reviewer, an existing clean branch and a reason, records the old tip, and moves no refs.

• *Recover old start references* — Was: Close could reject a valid integrated receipt before reaching its validation.
→ Now: Narrow stale-start recovery validates repository, owner, attribution and integration before retiring the old boundary.

• *Clearer start recovery* — Was: The equal-dirty path repeated attribution scans and stash advice omitted untracked files.
→ Now: One cached result is reused and the refusal explicitly says switch before start.

• *Less false overlap* — Was: Sibling overlap scored repeated common safety paragraphs as scope.
→ Now: Only epic-declared or all-sibling shared multiline blocks are discounted when distinct scope remains.

• *Accurate merge receipts* — Was: Merge records conflated green, advisory and override admission.
→ Now: Admission is stored and displayed separately, and override merges remain ineligible for automatic close.

• *Keep approved QA evidence* — Was: A clean rewrite broke the QA bundle citation's binding.
→ Now: Validated passed bundles carry only across identical aggregate delivery diffs, preserving the full safety-check range.

• *Current ownership repairs* — Was: Ownership checks read only the older receipt's registry.
→ Now: Landed deliveries consult the target-tip registry for ownership.

• *Net evidence changes* — Was: Evidence-only validation rejected reverted intermediate code paths.
→ Now: Ordinary deliveries measure base-to-tip paths, while workflow-only proof still checks every commit.

• *Readable reference proof* — Was: Optional reference-history read failures aborted line proof.
→ Now: Unavailable batch or blob reads fall back, while invalid history data still errors.

• *Observation errors* — Was: Busy observations mapped to INVALID_PARAMS and candidate reads silently defaulted empty.
→ Now: SQLite busy becomes INTERNAL_ERROR and candidate read failures are logged.

• *Old reminder cleanup* — Was: No-TTL due time reminders were counted but not expired, and TTL notices repeated each scan.
→ Now: Dead-session cleanup expires due no-TTL reminders and each scanner logs TTL-bound orphan counts only when they change.

• *Cleanup wording* — Was: GC dry-run help promised no changes while baseline maintenance still ran.
→ Now: Help states destructive cleanup is previewed, and WIP notes get a blank line.

*Build and release tools*

• *Durable review ownership* — Was: Owner payloads were synced but the renamed directory entry was not.
→ Now: Owner publication syncs the containing directory after rename.

• *Nested check isolation* — Was: Nested checks and lease-free managed tests could inherit CARGO_TARGET host runners.
→ Now: Those commands clear the inherited runner instead of invoking an outer lease wrapper.

• *Progress lines from other projects* — Was: The literal-progress exception recognized only Reconfiguring Cassy...
→ Now: Both shipped scripts accept the documented complete-sentence pattern, retaining cut-word and column-gap failures.

• *Mounted sibling tests* — Was: Sibling test proof recognized only conventional parent filenames.
→ Now: Cached AST mount discovery finds alternate parent names for _tests.rs files while comments and lookalikes remain uncovered.

• *Warm review builds* — Was: Review checkouts could start cold or invalidate reused artifacts because inherited Cargo flags were missing.
→ Now: Eligible targets reuse a quiescent assigned target with mirrored flags. One Linux comparison: 144.9 s/20 workspace units versus 253.1 s/661 cold, with zero registry crates rebuilt.

• *Prebuild lookup fairness* — Was: One artifacts query could consume the lookup deadline and killed requests looked like ordinary failures.
→ Now: Each run gets bounded retries, later polls recover query failures and exit 137 is labelled timeout.

Published archives: Linux x86_64 SHA-256 `146c3584cab1f9b32513e95aaf3fa388f6eed8711afa9ef424dbbbfd3b1e93f3`; macOS ARM64 SHA-256 `853c4c301d69b735931060fcc1236a1e2726151e05cd782c006a259b3ab3671b`.
```
