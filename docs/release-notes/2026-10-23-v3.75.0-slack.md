## User thread

Top-level:

```text
*Live on production — User — Cassy v3.75.0*
Was: leftovers and strict checks could stall updates, merges and releases. → Now: Cassy cleans up safely and names the next step.
```

Reply (Was → Now):

```text
*Everyday commands*

• *Dead session cleanup* — Was: Records left by sessions that ended abruptly piled up and were rechecked for every project.
→ Now: An update checks them once and safely removes the ones nothing still uses.

• *Ignored signals stay ignored* — Was: A Cassy screen started with nohup could still close when its terminal hung up.
→ Now: Signals you chose to ignore stay ignored, and the background check wakes less often.

• *Successful pulls stay successful* — Was: A finished sync could be reported as failed because a later warning lookup failed.
→ Now: The sync is reported as successful and the lookup problem is listed.

• *Codex readiness paths* — Was: Codex trust messages could print a folder path whose hidden characters disguised it.
→ Now: Hidden characters in those paths are shown visibly.

*Delivery and recovery*

• *Rebased fix-forward merges* — Was: A rebased follow-up delivery could be refused and pointed at a branch that did not exist.
→ Now: The rebased work merges directly and suggestions name only real branches.

• *Recorded branch remedies* — Was: Some delivery branch names were refused with no next step, or made every task look ambiguous.
→ Now: The refusal names the fix, the task's own branch wins and interrupted merges resume.

• *Blocked delivery rebinding* — Was: A delivery blocked after review could be moved to a new branch before anyone asked for changes.
→ Now: Cassy asks for a change request first and keeps the existing evidence.

• *Same-branch parked closes* — Was: Starting new work on the same branch name could block closing finished, merged work.
→ Now: A validated merge receipt closes it, and merged work is no longer called never pushed.

*Build and release tools*

• *Review build seeding* — Was: A review build could change files in the build it borrowed from, and cleanup overstated the space it would free.
→ Now: Changing build files are copied, interrupted setups are recovered and cleanup reports real savings.

• *Tests mounted beside a folder* — Was: A test included by a file next to its folder counted as missing coverage.
→ Now: It counts, and a test included by two files names both instead of choosing silently.

• *Report links on other default branches* — Was: Release report links assumed a branch called main and could be dead.
→ Now: The links use the repository's default branch.

• *Release PDF assets table* — Was: The printed report could leave the downloads table heading alone at the bottom of a page.
→ Now: The heading stays with its first row, and the PDF check catches a stranded heading.

• *Prompt prebuild refusals* — Was: A permanent permission error could make a release wait half an hour for a ready-made build.
→ Now: It stops at once with a clear reason, while temporary errors still retry.

• *Version placeholders in drafts* — Was: A release draft using the supported version placeholder failed its pre-publication check.
→ Now: The draft passes before release, and posting still refuses unfilled placeholders.

• *Project progress words* — Was: Terminal checks flagged normal progress lines such as Building project... as cut off.
→ Now: Projects can list their own progress words, and the single-character ellipsis works too.

Install: run `cas update` or choose the Linux x86_64 or macOS ARM64 download from the release.

```

## Dev thread

Top-level:

```text
*Live on production — Dev — Cassy v3.75.0*
Was: stale anchors, dead runtime records and shared seed inodes forced manual recovery. → Now: merges, closes, update reaping and review seeding follow recorded evidence.
```

Reply (Was → Now):

```text
*Everyday commands*

• *Dead session cleanup* — Was: Stale session cleanup ran only in tests, and binding checks spawned a thread and runtime per socket probe per project.
→ Now: One inventory per cas update reaps owned, unchanged dead records with refused or missing GUI probes, and writer churn asks for a rerun.

• *Ignored signals stay ignored* — Was: The client signal guard replaced an inherited SIG_IGN, and its watcher polled every 20 ms.
→ Now: Signals whose prior disposition is SIG_IGN keep it, the watcher polls at 100 ms and the second-signal re-raise is documented.

• *Successful pulls stay successful* — Was: A post-apply guard-report read error turned an applied pull with an advanced cursor into a failure.
→ Now: The error is appended to the pull's errors, and LocalWins, non-superseding and owner-wins skips are documented exclusions.

• *Codex readiness paths* — Was: The codex_trust not-trusted and failed-to-parse readiness messages interpolated raw paths.
→ Now: They use visible_hook_path, and one shared unsafe-character predicate serves hook labels and CLI remedies.

*Delivery and recovery*

• *Rebased fix-forward merges* — Was: worktree_merge checked the stale pre-rebase anchor and suggested a branch with a doubled task suffix.
→ Now: Equivalent remote rebases rebind before the merge-source gate, and suggestions name only existing local or origin refs.

• *Recorded branch remedies* — Was: Non-pattern recorded branches had no remedy, an unsuffixed branch made every task ambiguous and resume stopped at 0 candidates.
→ Now: Refusals name request_changes or rebind_branch, per-task refs outrank unsuffixed ones and receipt-backed resume runs first.

• *Blocked delivery rebinding* — Was: rebind_branch accepted a Blocked task with a parked delivery without request_changes.
→ Now: It refuses while a parked branch or anchor exists, and the merge-source helper is a plain bool check.

• *Same-branch parked closes* — Was: Reusing a branch name made close refuse DELIVERY BRANCH UNRESOLVED, and a merged per-task ref read as never pushed.
→ Now: A validated integrated commit_receipt closes and audits the old base, and target-contained parked refs count as integrated.

*Build and release tools*

• *Review build seeding* — Was: Seeding hardlinked build-script outputs, could orphan .target-seed-in-progress and counted hardlinked bytes at full size.
→ Now: build/ outputs are copied, orphan stages are recovered and an inode counts once only when all its links are in the deletion scope.

• *Tests mounted beside a folder* — Was: The proof-scope sibling matcher searched only the test's own directory and silently chose the first of competing parents.
→ Now: The adjacent directory-named .rs file is a candidate, and an alias mounted by two parents is refused naming both files.

• *Report links on other default branches* — Was: Report Markdown source and print-edition links hardcoded blob/main.
→ Now: They use the detected repository default branch.

• *Release PDF assets table* — Was: The assets table header could separate from its row at a page end.
→ Now: The template keeps header and first row together, and check-pdf.py reports orphaned_assets_headers.

• *Prompt prebuild refusals* — Was: A definite 4xx artifacts-query failure waited the full 1800 s prebuild window.
→ Now: 401, 403 and 404 decline at once, while rate limits, 408, 5xx, network errors and exits 124/137 retry, and a final run-list failure names its cause.

• *Version placeholders in drafts* — Was: Announcement lint rejected the supported version placeholder, failing pre-push fast rows.
→ Now: Prepublication lint accepts it, while strict validation and posting still reject unresolved tokens before any write.

• *Project progress words* — Was: The terminal-qa progress exemption allowed five fixed nouns and only ASCII dots.
→ Now: Repeatable --progress-noun flags or progressNouns declare whole nouns, and U+2026 is accepted under the same grammar.

Published archives: Linux x86_64 SHA-256 `54079f746e39bd5f6a5dc235d4627cf930b60ff6e9ba0b75b136c1ff8fc8e051`; macOS ARM64 SHA-256 `8c218f3c0b94bed729039cf37768a25a3ff135005f15240c2a9a488091f4e54a`.

Publication timing: Merge-queue green to published 897 seconds, over the measured 600-second budget (WITHIN_BUDGET=false).

Release timer: PR opened to merged 21m19s; merged to published 14m47s.

Release: <https://github.com/Richards-LLC/cassy/releases/tag/v3.75.0|Cassy v3.75.0>
```
