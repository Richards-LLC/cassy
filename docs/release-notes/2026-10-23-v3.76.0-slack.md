## User thread

Top-level:

```text
*Live on production — User — Cassy v3.76.0*
Was: finished work could get stuck in refusal loops or forced repeat checks. → Now: Cassy recognizes merged work and keeps valid proof.
```

Reply (Was → Now):

```text
*Everyday screens and commands*

• *Terminal sizes across viewers* — Was: Taking over a shared screen by typing kept the old size, and a narrow second terminal showed nothing.
→ Now: The screen follows whoever is typing, and a narrow terminal gets its compact view.

• *Document status in worktrees* — Was: Map and overview status checks read the main checkout, so documents updated in another checkout looked missing or stale.
→ Now: They read the checkout you run them from.

• *Detached checkout guard* — Was: Stepping through history with bisect and a detached checkout was refused as if it were a commit.
→ Now: It runs, and commits on a detached checkout are still refused, including a disguised file-restore form.

• *Priority refusal wording* — Was: Changing a task's priority without a signed-in session gave an unrelated message about receipts.
→ Now: The message says the priority change was refused and why.

*Delivery and recovery*

• *Own branch per task* — Was: Starting a task could reuse another task's branch and mix up its merge and close.
→ Now: Cassy refuses and prints the exact commands that create the task's own branch.

• *Squash re-close after a rejection* — Was: Re-closing squash-merged work after a review rejection looped between two refusals that each pointed at the other.
→ Now: The squash receipt closes it, and staging uses the remote branch instead of a stale local copy.

• *Adopting already merged work* — Was: Picking up merged work after a restart needed a manual branch reset.
→ Now: It is adopted directly, and a checkout carrying unrelated unmerged work is refused before anything changes.

• *Proof survives documentation commits* — Was: A docs-only or checklist-only commit after browser checks forced a full browser rerun.
→ Now: The existing proof is reused and noted, while product changes, or checklist edits that change which checks apply, still need a rerun.

• *Review checkout durability* — Was: A power loss right after a review copy was created could drop it and leave stale records.
→ Now: The new copy is saved to disk before work continues.

*Build and release tools*

• *macOS slow-call checks* — Was: On macOS, process lookups slipped past the check for slow calls in Cassy's background service.
→ Now: They are caught on macOS as they already were on Linux.

• *Release report sign-in* — Was: Posting a release report failed when the Slack token was set up only in Codex, or under a name other tools accept.
→ Now: Codex's setup is read, every accepted name works, and a refusal names the file and the fix.

• *Durable report links* — Was: A release report could link to a temporary branch or an unchecked hand-typed address that later broke.
→ Now: Only main or the release tag is accepted, checked before the report is uploaded.

Install: run `cas update` or choose the Linux x86_64 or macOS ARM64 download from the release.

Published SHA-256: Linux `{{LINUX_SHA256}}`; macOS `{{MACOS_SHA256}}`.
```

## Dev thread

Top-level:

```text
*Live on production — Dev — Cassy v3.76.0*
Was: squash re-closes looped, adoption needed resets and doc commits staled QA traces. → Now: close, park and adopt_branch accept recorded evidence.
```

Reply (Was → Now):

```text
*Everyday commands*

• *Terminal sizes across viewers* — Was: Typing took input ownership without a resize, and non-owner Resize events were dropped, so narrow viewers never got a compact target.
→ Now: An ownership change feeds the recorded size through the debounced resize path, every client's size is kept and the full layout follows the owner.

• *Worktree document status* — Was: cas codemap status, overview status and the close drift checks resolved CODEMAP and PRODUCT_OVERVIEW from the CAS_ROOT parent checkout.
→ Now: They read the calling checkout when level with or ahead of its target; behind or divergent checkouts keep the target snapshot.

• *Detached checkout guard* — Was: The worker commit guard treated checkout as a history write, refusing bisect plus checkout --detach, and matched --detach after a -- separator.
→ Now: Isolated detached checkout skips the branch check, option scanning stops at --, and detached commits stay refused.

• *Priority refusal wording* — Was: An unregistered priority update returned "Receipt submission requires an already registered authenticated Cassy session".
→ Now: It returns TASK PRIORITY UPDATE REJECTED with the registration reason, and blocked→open+P0 and closed→open+P0 rows are tested.

*Delivery and recovery*

• *Own branch per task* — Was: task start reset and reused factory/<worker>-cas-<old> for a different task, breaking worktree_merge and close attribution.
→ Now: Start refuses with the exact fetch, switch and push remedy unless rebind_branch recorded that branch, and cas-worker requires whole-module proof.

• *Squash re-close after a rejection* — Was: After a verifier rejection, PARK REFUSED named the source tip, MERGE REQUIRED named the squash, and merged_into resolved stale local refs.
→ Now: PARK recognizes target-reachable exact squash equivalence without moving source anchors, and merged_into prefers origin/<branch>.

• *Adopting already merged work* — Was: transfer adopt_branch refused a receiver HEAD descending from the delivery tip ("cannot fast-forward"), forcing git reset --hard.
→ Now: HEAD is kept when it contains the tip and is target-contained; unintegrated descendants refuse before assignment, lease or HEAD change.

• *Proof survives documentation commits* — Was: Any commit after the QA trace tip, even journeys.yaml bug metadata or a ledger row, made close demand a browser replay.
→ Now: Non-product diffs with unchanged qa_impact selection rebind the trace with an A/B/paths note; selection, status or invariant changes refuse by name.

• *Review checkout durability* — Was: Fresh review checkout creation did not fsync the scratch-store parent directory.
→ Now: The parent is synced after owner publication and before git worktree add, and a sync failure propagates.

*Build and release tools*

• *macOS lane checks* — Was: read_pid_starttime called libproc without a lane-guard note, so Proc enforcement never fired on macOS and flv2_no_blocking_call_on_lanes failed.
→ Now: It notes BlockingKind::Proc before the syscall, and the test uses a real macOS PID fingerprint.

• *Release report credentials* — Was: release-report-post.py read only .claude.json and refused Codex selector names outside VIOLET_SLACK_TOKEN_*.
→ Now: It reads bearer_token_env_var and env_http_headers from CODEX_HOME/config.toml, accepts CLI-valid names and fails closed on conflicts naming VIOLET_SLACK_TOKEN_ENV.

• *Durable report links* — Was: Generated refs could point at a delivery branch, and a manual CAS_RELEASE_TRAIN_REPORT_HTML_URL skipped the ref check.
→ Now: Both must name main or the release tag without . or .. segments, refused before the PDF upload.

Published archives: Linux x86_64 SHA-256 `{{LINUX_SHA256}}`; macOS ARM64 SHA-256 `{{MACOS_SHA256}}`.

Release: <https://github.com/Richards-LLC/cassy/releases/tag/v3.76.0|Cassy v3.76.0>
```
