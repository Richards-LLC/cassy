## User thread

Top-level:

```text
*Live on production — User — Cassy v3.77.0*
Was: a second task, a rewritten branch or an abandoned review could stall finished work. → Now: Cassy recognizes the work and keeps it moving.
```

Reply (Was → Now):

```text
*Starting and delivering work*

• *Adding help from an out-of-date copy* — Was: Asking for another assistant while your copy had drifted from the shared one said "queued", then failed out of sight.
→ Now: It is refused at once with the command that fixes the copy, and any later start failure is reported straight away.

• *A second task while the first waits* — Was: Starting a new task while earlier work waited to merge could move that work's branch and suggest a push that would overwrite it.
→ Now: The new task gets its own branch, the waiting work stays put, and its backup copy can be saved.

• *Moving work onto a corrected base* — Was: After work moved onto a corrected starting point, Cassy said the branch held nothing to deliver, forcing a redo.
→ Now: It recognizes the task's own commits and records where the work used to be, while empty or unrelated branches are still refused.

• *Closing again after bringing in the latest changes* — Was: Closing again after merging in the latest shared changes reviewed the old version, then blamed history that was fine.
→ Now: The new version is the one reviewed and merged.

• *Restarting on a recovery branch* — Was: Restarting a task on its own recovery branch could be refused as if it belonged to a different task.
→ Now: It is recognized as the task's own.

*Reviews and reminders*

• *Abandoned reviews* — Was: When a reviewer let go of a review or shut down, the review stayed locked to them until its deadline.
→ Now: It is freed at once for someone else, and a reviewer who is still active keeps it.

• *Reused review proof* — Was: An edit raising how much evidence a check needs could still let older proof count.
→ Now: Older proof is reused only when every requirement is unchanged, and Cassy names what changed.

• *Timed reminders during background work* — Was: A timed reminder could sit unseen for up to two minutes while a background job kept the screen busy.
→ Now: It is delivered as soon as the current turn has ended.

Install: run `cas update` or choose the Linux x86_64 or macOS ARM64 download from the release.

Published SHA-256: Linux `{{LINUX_SHA256}}`; macOS `{{MACOS_SHA256}}`.
```

## Dev thread

Top-level:

```text
*Live on production — Dev — Cassy v3.77.0*
Was: spawn queued doomed requests, rebind and re-park refused legitimate history, and QA claims outlived reviewers. → Now: each is checked, attributed or released.
```

Reply (Was → Now):

```text
*Spawn and start*

• *Spawn base preflight* — Was: spawn_workers answered "Queued … NOT YET CONFIRMED" for a base diverged from origin, and the provision failure arrived as a Normal row at the next turn.
→ Now: A diverged base is refused synchronously with the rebase --autostash remedy, and provision/register failures are Critical blocker notices that wake an idle supervisor.

• *Second task beside a parked delivery* — Was: task start reset factory/<worker> under a parked delivery, close pointed at that branch's push, and the push guard refused the per-task archive ref.
→ Now: Start leaves the parked branch alone, close measures the task branch with start-base checks, and the hook admits a same-name archive ref but not HEAD:<other-task>.

• *Recovery-suffix branches* — Was: factory/<w>-<task>-reviewed parsed as owned by a task named <task>-reviewed, so a restart after the rebind record cleared was refused.
→ Now: An owner equal to the task ID or prefixed by "<task-id>-" is the task's own, and foreign per-task branches still refuse.

*Delivery recovery*

• *rebind_branch after rewritten history* — Was: rebind_branch refused rewritten anchors, resets onto origin/<target> and distinct per-task branches with "replacement has no unmerged task delivery".
→ Now: It attributes commits via the validated common root, derives the base from the target even on the same branch, audits the old start/base/anchor/tip, and still refuses empty or foreign ranges.

• *Re-park at a target-sync tip* — Was: close with commit_receipt=C kept the obsolete anchor B and dispatched QA for B, and a later close claimed the start base was not an ancestor of C.
→ Now: An attributable fast-forward target-sync tip advances the anchor, supersedes B's QA round and dispatches C's, and rewrites that drop B refuse truthfully.

*QA*

• *QA pass claims* — Was: Releasing the QA task or shutting down the reviewer left the pass claimed until its deadline, blocking replacement starts and qa_request.
→ Now: Release and lease-absent recovery return the pass to Pending, shutdown/unregister clear claims by session ID or name, and stale claimants can be replaced.

• *QA trace rebind coverage* — Was: The non-product rebind check compared journey status and invariants only, so a registry edit raising evidence_required reused an old trace.
→ Now: It also compares kind, evidence_required and the registry safety policy, and the refusal names the journeys and whether the policy changed.

*Wake delivery*

• *Self-reminders during background tasks* — Was: A Claude supervisor's fired self-reminder needed 2 s of PTY silence, so background-task repaints parked it for 120 s until an unrelated turn.
→ Now: Once the transcript records the turn ended, the reminder injects once without the silence bar, and the composer, readiness and in-flight vetoes stay.

Published archives: Linux x86_64 SHA-256 `{{LINUX_SHA256}}`; macOS ARM64 SHA-256 `{{MACOS_SHA256}}`.

```
