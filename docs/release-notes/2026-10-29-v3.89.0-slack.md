Top-level:


Reply (Was → Now):

```text
*Team you can trust*

• *Team stays visible* — Was: Team could flicker or disappear during refresh and restarts.
→ Now: Current sessions stay listed through refresh and replacement, and genuinely ended sessions leave the list.

• *Current assignments agree* — Was: Team could show no task beside a session that was actively working.
→ Now: The current task is selected from the same status update as the work it describes.

• *Latest waiting work wins* — Was: Team could show older waiting work after a newer task reached review.
→ Now: Active work takes priority, followed by the latest waiting delivery rather than old bookkeeping.

• *Reported models appear* — Was: Team could omit a model even when the session had a recorded choice.
→ Now: Team shows the recorded model when available and keeps missing information as Not reported.

• *Delivery progress stays visible* — Was: Progress for the current release could disappear after its last active task reached review.
→ Now: Team keeps that release ahead of historical work so recorded delivery steps remain available.


*Read, send and copy*

• *Paths send as messages* — Was: A message starting with a slash could be swallowed as a command.
→ Now: Pasted paths and unknown slash text send normally. Only supported command names open command handling.

• *CSV copy protects cells* — Was: Copied CSV could let a cell starting with a formula sign run as a spreadsheet formula.
→ Now: Formula-leading cells are protected in CSV, while Copy Markdown keeps the original text.

• *Copy feedback clears* — Was: A copied-table confirmation could stay visible indefinitely.
→ Now: Copy feedback clears after its short confirmation period.


*Conversation controls*

• *Current activity wins* — Was: A slower status response could replace newer activity with an older phase.
→ Now: Late responses cannot overwrite a newer phase, and slow reads still keep publishing progress.

• *Cancelled shortening expires* — Was: A cancelled context-shortening step could leave its clock growing forever.
→ Now: An unmatched shortening phase expires instead of claiming endless activity.

• *Accounts is easy to find* — Was: The Accounts button could look like an empty square, with settings pressed against the edge.
→ Now: A visible Accounts icon and label, with inset controls, keep the header understandable on desktop and phone.

• *Codex Clear confirms* — Was: Clear could finish in Codex while its command card stayed unconfirmed.
→ Now: The card confirms when Codex's fresh native welcome screen is observed.

• *Questions get one reply* — Was: A question could receive both a chat answer and a separate duplicate.
→ Now: Claude and Codex answer once in chat, including after a restart, without a separate duplicate.


*Accounts and activity*

• *Reset times use Eastern hours* — Was: Usage reset times could appear in 24-hour form or the wrong local date.
→ Now: Account choices and usage views use labelled Eastern 12-hour times, including the correct date around midnight.

• *Recent work is recognized* — Was: A recently active session could be called stalled while its saved history was being found.
→ Now: Recent work or outgoing activity can establish progress during that lookup. A heartbeat alone still does not prove work.


*Reliable completion*

• *Ready means finished* — Was: An unfinished checkpoint could look ready to accept just because its checks passed.
→ Now: Readiness also requires recorded completion, and accepting unfinished work shows a warning.

• *Restart notes survive* — Was: A restart note could be discarded before the replacement session opened.
→ Now: The same pending note remains for the replacement, while genuinely ended sessions keep their shutdown safeguards.

• *Claude restarts keep the project* — Was: A restart without a separate checkout could stop Claude and then fail to open its replacement.
→ Now: Checks happen before stopping, and the project location is retained. A refused restart leaves the current session running.

• *Check lookup explains failures* — Was: Missing check results could produce the same vague source error.
→ Now: Git discovery and GitHub lookup failures are distinguished instead of being reported as one generic problem.

• *Reviewed work recovers after restart* — Was: A restart could lose the link to reviewed work and prevent completion.
→ Now: The original reviewed version can be recovered, without accepting later changes that were not reviewed.


*Releases and updates*

• *Automatic updates on macOS* — Was: Automatic published updates were available only on Linux.
→ Now: macOS can check each minute and install published releases, recording success only after the installed version matches.

• *Release and browser versions agree* — Was: A new release could carry an older embedded Commander build.
→ Now: Release preparation rebuilds Commander for the new version and refuses a failed build before recording the release.

• *Removed browser files stay removed* — Was: A removed browser file could stop a release update from being rebuilt.
→ Now: Removed generated files are handled during rebuilding, while ordinary source conflicts still require review.

• *Rebuilds use matching dependencies* — Was: Rebuilding merged changes could reuse incompatible installed packages.
→ Now: Rebuilds install the matching locked dependencies first and retain an explanatory log if generation fails.

• *Generated reports upload correctly* — Was: A generated release report could be rejected because its title followed a short introductory block.
→ Now: Generated reports are recognized even when introductory details appear before their title.


*Evidence checks*

• *Evidence grammar agrees* — Was: Valid zero counts could be rejected, while an unrun check could omit its reason.
→ Now: Evidence checks accept zero-count labels and require a reason for anything not exercised.

• *Evidence setup stays in its project* — Was: An alternate project path could point evidence setup at the wrong storage location.
→ Now: Setup refuses a mismatched storage alias before creating its folder.

• *Instructions match the checks* — Was: Example instructions could ask for an unrun result that their own checker rejected.
→ Now: The examples and instructions include the required reason for checks that were not run.


*Sharing evidence*

• *Large uploads report their limits* — Was: An evidence upload could report success even when it could not be restored elsewhere.
→ Now: Oversized evidence is clearly marked as not portable, while its saved description remains available.

• *Shared evidence includes its parts* — Was: A shared evidence archive could omit material needed to read part of the result.
→ Now: Shared archives retain the material the evidence checks actually read, including referenced parts.

• *First restores can run together* — Was: Two first-time restores of the same evidence could interfere with each other.
→ Now: Concurrent first restores both succeed, while altered cached evidence is still rejected.

*Known limits*

• *Revoked sends can offer the wrong action* — Was: Revoking access during a pending send could leave a misleading recovery action.
→ Now: This can still offer Take control instead of Re-pair. The failed message remains editable.

• *The larger refresh is still ahead* — Was: The wider visual refresh and conversation-header model and effort display were planned separately.
→ Now: They remain planned for 3.90.
```
