```text
• *One consistent look* — Was: Accounts, the left nav and the conversation header used older, mismatched shapes.
→ Now: One shape scale with shared card, pill and avatar rules, provider logos as avatars, and Accounts grouped by machine with Default and Recommended badges. It fits a phone.

→ Now: The stopped count appears only when something stopped, and ended sessions no longer count as live.

• *Load earlier keeps your place* — Was: Loading earlier history could drop you far below where you were reading.
→ Now: Your reading position is kept.

• *Revoked access offers Re-pair* — Was: Revoking a device's access during a send could offer Take control.
→ Now: Commander offers Re-pair, or re-pairing with Send messages.


*A team that keeps moving*

• *Shutdowns no longer stall messages* — Was: Cleaning up a finished session could hold up message delivery for over an hour.
→ Now: Cleanup runs in the background, warns once if it is slow, and finishes on the next start if interrupted.

• *Disk space comes back* — Was: Finished sessions' files could pile up when the team was idle.
→ Now: An idle team reclaims them on its regular check.


*Smoother delivery*

• *Corrected work closes* — Was: After a refused push was fixed, completion could read the old version.
→ Now: Completion uses the corrected push.

• *Faster proof checks* — Was: Proof checks could take several seconds per file and sometimes hang.
→ Now: One combined search brings them back under a second.

• *Every change gets a changelog line* — Was: Release notes could miss most of a release's changes.
→ Now: Product changes need a titled changelog entry before they are handed in.
```

## Dev thread

Top-level:

```text
*Live on production — Dev — Cassy v3.90.0*
Was: cleanup ran on the daemon control loop and changelogs drifted. → Now: off-loop cleanup, a design-system Commander and a park changelog gate.
```

Reply (Was → Now):

```text
*Commander*

• *Design-system refresh* — Was: Accounts, nav and header each used their own shapes and radii.
→ Now: One shape scale with shared card, pill and avatar rules in the design system; provider marks as avatars; Accounts grouped by machine.

• *Model and effort in status* — Was: The session catalog had no reported model or effort.
→ Now: Panes record both in the catalog and status; the model chooser no longer treats old history as confirmation after a failed selection.

• *Refused sends keep their cause* — Was: A revoked pairing during a pending send surfaced as a generic control conflict.
→ Now: The hub keeps the pairing or message-permission cause, so Commander offers Re-pair.


*Factory daemon*

• *Cleanup off the control loop* — Was: Worktree cleanup and target retirement ran on the daemon control loop, stalling delivery for over an hour.
→ Now: Cleanup is queued off-loop, a long cleanup warns once, and exit waits a bounded time and saves unfinished work for the next start.

• *Dead-worker shutdown frees the store* — Was: Retiring a dead worker's target ran inline on the store write lane without reserving its name.
→ Now: Retirement runs off that lane and the name stays reserved until cleanup finishes.

• *Held and idle cleanups complete* — Was: Held retirements replayed on every start, and staged cleanups ran only when a spawn or another cleanup was pending.
→ Now: Held retirements complete their record, and an idle daemon adopts staged cleanups on every tick with idempotent staging.


*Delivery gates*

• *Changelog gate* — Was: Nothing required a CHANGELOG entry, so [Unreleased] held 3 entries for about 30 merges.
→ Now: Park requires a titled [Unreleased] entry or a reasoned note for product-source deliveries, only in repos with a CHANGELOG; the fast row validates existing entries, passes on an empty post-cut section and refuses template placeholders.

• *Exception approvals checked* — Was: Park trusted fast-row exception files without checking the approver.
→ Now: The approver must be a live registered supervisor with a complete approved scope.

• *Proof-surface checker* — Was: One ripgrep per symbol, up to 7 s per file, and a possible hang on a bundled ripgrep.
→ Now: One alternation `git grep` with color off, about 0.3 s per file, and committed surfaces resolved through Git.

• *Close uses the corrected push* — Was: Close could read a stale delivery tip after a refused push.
→ Now: Close honors the explicitly pushed tip, and older evidence ledgers close through a covering review.


*Tests and tooling*

• *Steadier tests* — Was: Tests depended on timing, entropy, shared environment and elapsed waits.
→ Now: Deterministic clocks, collision-free fixture identities, one guard for environment and stores, observed async fixtures, exclusive port and socket ownership, and a real-hub /exit journey.


*Known limits*

• *Fast-row PASS receipts are still trusted* — Was: Park trusts fast-row PASS receipts written by the same user.
→ Now: Still true in this release; a stronger check is tracked separately.

Update with `cas update`, or choose <https://github.com/Richards-LLC/cassy/releases/tag/v3.90.0|the Linux x86_64 or macOS ARM64 downloads>.
```
