## User thread

Top-level:

```text
*Live on production — User — Cassy v3.91.0*
Was: urgent fixes waited on every check. → Now: a rapid response mode and task lists that keep work moving.
```

Reply (Was → Now):

```text
*Faster when it matters*

• *Rapid response mode* — Was: Every fix ran the full set of checks and reviews, even during an urgent outage.
→ Now: The operator can open a time-boxed window, at most 12 hours, for one project board. Checks scale down while a safety floor stays on, and every skipped check is caught up when the window closes.

• *Safety floor stays on* — Was: Speeding up meant choosing which protections to drop.
→ Now: Build, changed-test and secret checks still refuse. A change with a secret-shaped line, or one Cassy cannot read, keeps every check, and database changes wait for the operator's review.

• *Work keeps moving* — Was: A helper finished one task and could wait a long time for the next assignment.
→ Now: Each helper takes an ordered list of tasks and starts the next one on its own. The list can be reordered or cleared at any time.


*Safer deliveries*

• *Finished work cannot be rewritten* — Was: Work already handed in could be overwritten.
→ Now: Overwrites are refused with a clear "merge, don't rebase" message, and recovery merges are accepted.

• *Required checks cannot be skipped* — Was: A push could skip the required checks with a skip flag or a settings trick.
→ Now: Those pushes are refused, while ordinary pushes work as before.

• *Checks run where they cannot be faked* — Was: The finish line trusted a local "checks passed" note that anyone on the machine could write.
→ Now: The shared build server decides, and the local note is only an early warning.
```

## Dev thread

Top-level:

```text
*Live on production — Dev — Cassy v3.91.0*
Was: every gate always ran and park trusted local receipts. → Now: an operator rapid response window, ordered task queues and CI-only fast-row proof.
```

Reply (Was → Now):

```text
*Delivery process*

• *Rapid response mode* — Was: Per-task QA, close verification and batch receipts always gated a fix.
→ Now: `cas qa rapid-response enable <epic> --for <duration>` opens an operator-only window of at most 12 hours; per-task QA is skipped, verification is sampled one in four and fixes close without a batch receipt.

• *Floor and back-fill* — Was: No record existed of checks skipped under pressure.
→ Now: Build, touched-test and diff secret checks still refuse; an unreadable diff, a secret-shaped line or a migration keeps every gate, and migrations need operator review. Each skip is logged in an operator-only ledger, and window close files one back-fill task.

• *CI-only fast-row proof* — Was: Park required a local PASS receipt or an exception file written by the same user as the worker.
→ Now: CI runs the no-build fast rows once per lane and is the only proof; the exception writer, validator and reader are removed.


*Factory workflow*

• *Ordered worker queues* — Was: One assignment at a time per worker.
→ Now: spawn and assignment accept an ordered task list; close or park starts the next eligible task on its own target branch. Stale entries are skipped with notes, and a returned delivery can resume while its successor is held.

• *Close before handoff* — Was: A close could report "status unchanged" after writing Closed when the next task's start passed the deadline.
→ Now: The close commits first; an interrupted handoff is recovered from the durable queue.

• *One start lock per worker* — Was: A manual start could race a queue assignment and run two tasks in one checkout.
→ Now: Every start holds the worker's start lock; unqueued starts wait for it and queued starts refuse a busy lock.

• *Anchor rewrite refusal* — Was: A forced push could replace a parked delivery.
→ Now: The worker pre-push hook refuses non-fast-forward rewrites of a published factory tip, and re-park accepts the recovery merge that restores the anchor.

• *Hook bypass guard* — Was: `--no-verify`, `core.hooksPath` changes and `GIT_CONFIG_*` exports could skip pre-push.
→ Now: The worker and reviewer guard refuses each form, including `git config unset` and nested shells; inherited `GIT_CONFIG_GLOBAL` no longer blocks a plain push.


*Documented late (shipped in v3.90.0)*

• *Two-tab kept messages* — Was: A message kept in one of two tabs during an outage could stay unsent until reload.
→ Now: Each kept message is sent once after reconnect.

Update with `cas update`, or choose <https://github.com/Richards-LLC/cassy/releases/tag/v3.91.0|the Linux x86_64 or macOS ARM64 downloads>.
Published SHA-256: Linux `{{LINUX_SHA256}}`; macOS `{{MACOS_SHA256}}`.
```
