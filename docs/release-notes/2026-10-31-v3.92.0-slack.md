## User thread

Top-level:

```text
*Live on production — User — Cassy v3.92.0*
Was: Commander reshuffled projects and secrets went through chat. → Now: a steady project list, a secure secret card and calmer commands.
```

Reply (Was → Now):

```text
*Commander at a glance*

• *Projects stay in place* — Was: Project cards and the sessions inside them reordered by recent activity, so a project open on two machines flickered as they traded places.
→ Now: Cards sort by project name and sessions by name, then machine. Activity never moves them, and the Most recent mark stays where it stands.

• *See which sessions need an update* — Was: Nothing showed which Cassy version each connected session was running.
→ Now: Each online session shows a quiet version badge, and an upgrade arrow marks one running an older Cassy than its machine has installed, with a hint to reconnect.

• *12-hour times everywhere* — Was: Message bubbles, dividers, the Team trail and Attention showed 24-hour times such as "19:15".
→ Now: Every Commander time uses your timezone in 12-hour form, such as "7:15 PM" or "Sep 30, 5:49 PM".

• *Team shows the whole team* — Was: Team needed scrolling to see everyone, opened with a plain heading, and some lines, states and the empty progress bar were hard to read.
→ Now: Four people fit without scrolling on laptop and phone, the heading says what is happening ("3 working, 1 waiting. 1 needs you."), each state has its own color, and contrast holds in light, dark and high-contrast modes.


*Commands*

• *A refused command keeps one row* — Was: Each resend of a refused slash command added another row and another Attention item, and the rows stayed.
→ Now: One row says why it was refused and how many times you tried, clears once the command is accepted, and no longer raises Attention.

• *Commands wait for the reply to finish* — Was: A command such as Status or Exit could be typed into a reply still in progress, and Codex can pause mid-reply long enough to look finished.
→ Now: Commander waits until the reply has really ended, Codex pauses included.

• *Commands keep working all day* — Was: After 256 slash commands in one run, every further command was refused until Cassy's background service restarted.
→ Now: Finished commands are forgotten after 10 minutes, so commands keep working, and a repeat within that window still never runs twice.

• *Codex no longer updates itself by accident* — Was: When a newer Codex was out, starting a Codex session showed an "Update now" prompt that was accepted automatically, reinstalled Codex machine-wide and ended the session.
→ Now: That prompt never appears, and the session starts normally.

• *Codex startup text stays out of your chat* — Was: A new Codex conversation showed Codex's own startup context and Cassy's startup prompt as messages you sent, and the sidebar read "You: Message from director".
→ Now: That startup text is recognized and never shown as yours. A message you type that pastes such text after your own words still arrives.


*In the conversation*

• *Secrets stay out of chat* — Was: When Cassy needed an API key it asked in chat, and the key you pasted back became part of the conversation and its history.
→ Now: An "Asking for a secret" card offers a hidden field, Save securely and Decline. The key goes to a private file on the machine, never into chat, and can delete itself after use or after 1 or 24 hours.

• *Image viewer* — Was: Screenshots in a conversation were small cards you could not inspect in place.
→ Now: Image cards open a viewer with zoom, pan and a gallery for that turn, by touch, mouse or keyboard. Closing it puts you back where you were reading.

• *Changed files per turn* — Was: Seeing which files a turn changed meant reading every step.
→ Now: Show work lists each turn's changed files with added and removed line counts when known. Open a file for its diff, and it stays open on this device.

• *Readable thinking* — Was: The model's published reasoning was a long block that was hard to skim.
→ Now: It shows a folded summary preview with formatted detail and an exact raw-text fallback, and opening or updating it keeps your place.

• *Emoji picker* — Was: Adding an emoji meant leaving the draft for the system picker or pasting one in.
→ Now: A searchable, keyboard-friendly emoji tray sits beside the mic, with recent picks, and inserts at your cursor.

Update with `cas update`, or choose <https://github.com/Richards-LLC/cassy/releases/tag/v3.92.0|the Linux x86_64 or macOS ARM64 downloads>.
```

## Dev thread

Top-level:

```text
*Live on production — Dev — Cassy v3.92.0*
Was: flakes ejected releases and findings spawned endless work. → Now: queue flake quarantine, risk-tiered verification, independent QA authors and a release-pinned hub.
```

Reply (Was → Now):

```text
*Merge queue and verification*

• *Flake rerun and quarantine* — Was: One flaky Rust test or journey spec ejected the release from the merge queue.
→ Now: The queue reruns a failure once on the same tree, keeping both attempts. A fail-then-pass files a deduplicated P1 issue, and a second independent flake quarantines that test through a `flaky-quarantine` issue label until its fix issue closes.

• *Risk-tiered verification and QA* — Was: Every delivery got the same verifier, and its non-blocking improvements became new tasks with verifiers of their own.
→ Now: Close records a tier. Tier 0 (docs, tests) gets no independent verifier and walks no journeys, tier 1 gets one verifier, and tier 2 (guard, CI, release, close gate) adds an adversarial probe, also required in batch QA ledgers.

• *Review spawn threshold* — Was: Nothing in the tools stopped a review finding from becoming a task.
→ Now: `task create` refuses a follow-up from a finding without `repro` and `affected`. P0/P1 bugs an operator or supervisor observed directly stay exempt, and QA's automatic follow-ups need the same two fields.

• *Loop-gain breaker* — Was: Nothing showed when an epic's reviews generated more work than they closed.
→ Now: With at least 5 completed reviews, 0.5 or more follow-ups per review over the epic's last 10 sends the supervisor one notice, and `epic_status` shows the ratio.


*QA*

• *Independent QA author* — Was: A batch receipt accepted a ledger walked by the worker that delivered the task.
→ Now: `batch_receipt` requires `ledger_author` and refuses anyone in a tier 1 or 2 task's implementation lineage, and close rechecks it. Only the operator-only `cas qa author-override <task> --note "<why>"` admits a lineage author.

• *Cross-machine batch receipts* — Was: A receipt lived only on the machine that recorded it, so the delivering machine's close waited for it forever.
→ Now: The receipt syncs with each listed task, either machine's close accepts it, and `verification show id=qab-…` prints it.

• *Batch QA overdue alarm* — Was: Merged tasks could wait hours for a batch QA round with nothing flagging it.
→ Now: After 60 minutes with no receipt and no round started, every supervisor on the epic, on both machines, gets one notice an hour. A round counts when "batch QA round" appears anywhere in its title.

• *QA candidates from source web assets* — Was: An isolated QA candidate compiled Cassy without rebuilding Commander, and real-hub QA could serve a stylesheet from external dist.
→ Now: The candidate builds production web assets from source first, records source and served digests, and fails publication on a mismatch. External-dist overrides are refused.


*Factory*

• *Role-scoped skill catalog* — Was: Every worker and Codex verifier loaded the full native skill listing at launch, 12,000 to 18,000 characters.
→ Now: Workers list six role skills in under 2,500 characters on Claude, Codex, Grok and OpenCode, and Codex verifiers list none. Every skill still expands by name, and `skill action=list_all` serves the shipped catalog.

• *Supervisor-only restart* — Was: Any supervisor exit shut the factory down and stopped every worker.
→ Now: `factory action=restart_supervisor` starts a fresh supervisor session with the boot harness, model and effort while workers keep their tasks, panes and leases. A plain exit or crash still shuts the factory down.

• *Release-pinned hub with CPU priority* — Was: A live hub hotfix could run any binary, including a slow debug QA build, and host CPU weights were a manual merge.
→ Now: The pin accepts only an audited Release Prebuild artifact and refuses agent roles. Its `install` step (with `--dry-run`) sets hub CPUWeight 1000 over agent 40 and builds 25. The operator applies it once per host.

• *Park and close gates* — Was: A helper-branch commit could hijack a delivery anchor and loop park, a merged predecessor's changelog entry did not count, and released-trunk sync merges read as foreign.
→ Now: Only the task's own branches move its anchor, close credits entries from the task's attributed commits, and only `origin/main` history counts as released, so sync merges pass.

• *Cancelled lane runs* — Was: A docs push that cancelled the code commit's lane run left `worktree_merge` refusing with "CI PENDING" forever.
→ Now: Once the tip's run is green, cancelled jobs are set aside. A passed code check admits the merge, and a docs-only tip needs the docs-only override.


*Guards*

• *Shell guard hardening* — Was: The workspace and operator-command guard read some shell forms loosely and refused some harmless ones.
→ Now: It parses heredoc terminators, coproc and function bodies, `case` arms, redirects at command position, `{fd}` descriptors, arithmetic and backtick unescaping. Unresolved forms fail closed, and quoted data stays allowed.


*Commander and Codex*

• *Secret requests* — Was: Credentials were requested in chat and landed in transcripts.
→ Now: `coordination action=message target=operator kind=secret` shows a masked card. The value goes to `POST /v1/sessions/{session}/secrets/{id}` (factory:manage only) and a mode-600 file under `secrets.destination`. The requester gets the path, never the value.

• *Turn-aware supervisor commands* — Was: Commander could type a slash command into a running turn, and the daemon refused all commands after 256 receipts.
→ Now: Claude's `·` spinner counts as busy, Codex is busy from turn start to turn end in its session file, a 2-second quiet window applies, and finished receipts expire after 10 minutes.

• *Codex launch input* — Was: The "Update now" dialog's first Enter ran a global npm install, and `<environment_context>` and startup prompts mirrored as operator messages.
→ Now: Factory Codex launches with `check_for_update_on_startup=false`, and launch context, repository instructions and pane deliveries are matched as machine input on the whole message.

Known behaviour: a supervisor command sent within 2 s of a reply waits up to 3 s and may log a transient "daemon lane wedged" line. Nothing is killed.
```
