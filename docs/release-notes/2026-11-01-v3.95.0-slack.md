# Slack draft — Cassy v3.95.0 runtime release

Channel: #cas-internal (`C0B44GUKDK2`).

Status: Draft. Checksums are filled after publication.

## User thread

Top-level:

```text
*Live on production — User — Cassy v3.95.0*
Was: an unreviewed task could look approved. → Now: anything not clearly approved stays unapproved.
```

Reply (Was → Now):

```text
*Reviews you can trust*

• *Unclear reviews never count as approval* — Was: A review record that was incomplete, or written by a newer Cassy, could be read as approved and let work close without a real review.
→ Now: Anything that is not clearly approved is treated as not approved, so work waits for a real review.

• *Questions stay open* — Was: When a reviewer needed a decision, it had to fail the review and start over.
→ Now: The reviewer asks, the answer goes on the same review, and nothing is redone.

• *Honest review counts* — Was: Reviews that had only been requested showed up as errors, so the numbers looked far worse than they were.
→ Now: They show as waiting until a verdict arrives.
```

## Dev thread

Top-level:

```text
*Live on production — Dev — Cassy v3.95.0*
Was: unknown or missing verification status could deserialize as Approved. → Now: fail-closed status parsing and a supervisor-call verdict.
```

Reply (Was → Now):

```text
*Verification*

• *Fail-closed status* — Was: 3.94.0 mapped unknown stored statuses to Approved, and synced JSON with no status defaulted to Approved. → Now: Unknown and missing statuses parse as Error everywhere, so close refuses them.

• *Mixed-version safety* — Was: New statuses would read as Approved on older binaries sharing a store during rollout. → Now: `pending` and `supervisor_call` are stored as `error` plus a `status_detail` column that older binaries ignore.
  Proven by running released 3.94.0 against a store this release wrote.

• *Supervisor-call verdict* — Was: A reviewer question resolved its dispatch as error and forced a re-dispatch. → Now: `supervisor_call` keeps the dispatch open for one answer; final verdicts stay single-use.

• *Pending dispatches* — Was: Dispatch-request placeholder rows were counted as error verdicts (39 of 42 "errors" since 10/30). → Now: They are `pending` and excluded from verdict and ledger counts.


*Removed*

• *Last Jev residue* — Was: A config shim still warned about and rewrote `[jev]` sections. → Now: Removed; old configs with `[jev]` still load silently.

Update with `cas update`, or choose <https://github.com/Richards-LLC/cassy/releases/tag/v3.95.0|the Linux x86_64 or macOS ARM64 downloads>.
Published SHA-256: Linux `{{LINUX_SHA256}}`; macOS `{{MACOS_SHA256}}`.
```
