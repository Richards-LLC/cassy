## User thread

Top-level:

```text
*Live on production — User — Cassy v3.97.0*
Was: Commander could hide or misformat parts of an answer. → Now: diagrams, tables, diffs and status updates show properly, and task-launched sessions start.
```

Reply (Was → Now):

```text
*Answers in Commander*

• *Answers use the whole display* — Was: Answers stayed with bold, bullets and links, so richer formatting went unused.
→ Now: A flow comes as a diagram, bad news as a callout, commands as colored code and comparisons as a table.

• *Flowcharts show start to finish* — Was: A tall diagram was cut off mid-shape with no cue.
→ Now: The whole diagram shows on phone and desktop, and Expand appears only on its source view.

• *No dead Wrap button* — Was: Wrap on a rendered diagram did nothing and took header room on a phone.
→ Now: Wrap appears only on the diagram's source view, where it has lines to wrap.

• *Short status updates keep their formatting* — Was: A status of 140 characters or fewer showed callouts and bold as raw symbols.
→ Now: Callouts, headings and lists read as a full message, and bold, code and links render.

• *Hand-written diffs show color* — Was: A before/after diff without a line-position header rendered in one color.
→ Now: Added and removed lines are tinted, and a block with no changed line stays plain code.

• *Tables read as tables* — Was: A table sat in a dark code-style box with blank headers and floating Copy buttons.
→ Now: Tables have ruled rows in the message's own font, aligned numbers and compact Copy buttons at the bottom.

• *Stopped sessions look stopped* — Was: A stopped session on an online machine showed the same green dot as a live one.
→ Now: It shows the gray disconnected dot, and a live idle session stays green.

*Sessions and alerts*

• *Sessions started with a task start* — Was: A Claude session launched with a task could exit at once with "Invalid MCP configuration".
→ Now: It starts, and a launch that does fail clears its prompt and frees the task.

• *Replacements get their task* — Was: A new session reusing an old name could receive nothing while its task counted as delivered.
→ Now: Each launch receives its task once, together with its startup instructions.

• *Fewer needless alerts* — Was: Finished-work notices, an hourly test reminder and repeated blocked alerts interrupted people.
→ Now: Finished work waits for the next turn, the reminder is gone and each blockage alerts once.

• *Requirements up front* — Was: A task's finish requirements appeared one refusal at a time.
→ Now: They are listed when the task starts, and a refused finish reports every problem in one reply.

*Test builds*

• *Test builds on request* — Was: Each test build needed a person to start it and pass back the result.
→ Now: A build can be requested for an exact revision, and the requester receives its path, version and hash or the exact error.

• *Earlier test builds stay* — Was: A new build replaced the old one, so a binary cited as evidence could disappear.
→ Now: Each revision keeps its own folder, and asking for it again reuses it without a rebuild.

• *Requested builds stay contained* — Was: A requested build could use stored sign-ins, and a hung one could hold the machine.
→ Now: Stored sign-ins are hidden, and a build stops after 30 minutes with an error.

• *Known limit on some Linux machines* — Was: Test builds always started by hand.
→ Now: Requests work, but some Linux machines refuse them within seconds with a permissions error, so those still build by hand. A fix is planned for the next release.

Update with `cas update`, or choose <https://github.com/Richards-LLC/cassy/releases/tag/v3.97.0|the Linux x86_64 or macOS ARM64 downloads>.
```

## Dev thread

Top-level:

```text
*Live on production — Dev — Cassy v3.97.0*
Was: queued candidates, launch assignments and blocker wakes could strand work. → Now: isolated builds, one assignment turn and one alert per blocker keep it moving.
```

Reply (Was → Now):

```text
*Candidates*

• *Typed candidate requests* — Was: Each QA candidate took a supervisor turn and a message back, and a request could go stale in the hand-off.
→ Now: `factory action=candidate_request` builds a reachable revision from a default-branch checkout, one per machine, and reports path, version, hash and log.

• *Bubblewrap isolation and bounds* — Was: Queued builds inherited daemon credentials and the supervisor role, and a hang could hold the machine lock.
→ Now: Credential stores are masked, only build environment variables pass, and the process tree stops after 30 minutes.

• *Queue resilience* — Was: Preparation could appear dead or replace a newer request.
→ Now: Preparation keeps heartbeating, and admission notices preserve newer requests.

• *Per-revision retention* — Was: Each build overwrote `<task>/candidate`, so a ledger's cited binary could disappear.
→ Now: Revisions live in `<task>/candidates/<revision>/`, `candidate` points at the newest, and a published revision is reused without a compile.

• *Known limitation: namespace refusal* — Was: Candidates were built by hand on every host.
→ Now: On some Linux hosts, bubblewrap refuses queued builds in the daemon's launch context ("No permissions to create a new namespace"). The requester gets that error within seconds, and the candidate is built by hand until the fix planned for the next release.

*Launch and assignment*

• *Variadic flag handling* — Was: A spawn prompt following `--mcp-config` was read as a config path, so Claude exited with "Invalid MCP configuration".
→ Now: `--` ends the options for Claude and Grok, confirmed against Claude 2.1.312 and Grok 1.0.70.

• *Failed launch cleanup* — Was: A launch that failed before using its assignment kept the prompt for the next same-name launch.
→ Now: The prompt is cleared and the task released at the failure point.

• *Launch-scoped assignment rows* — Was: A predecessor's received row blocked a new one, so a same-name replacement got nothing.
→ Now: Each launch frees received rows, and a pending row carries its assignment once.

• *One startup turn* — Was: Startup, brief and assignment could arrive separately, and queued successors could be lost after automatic start.
→ Now: They arrive together, successors survive delivery, and ready and status messages name the current task.

*Wakes and alerts*

• *Merged delivery facts* — Was: Merge-close and lane-parked notices woke workers, and queued READY TO MERGE alerts could fire after the merge.
→ Now: They stay in the next-turn digest, while new deliveries, verifier findings and blockers keep action wakes.

• *One blocker episode* — Was: Blocked and idle signals could repeat an alert, including during owned verification waits.
→ Now: Both share one durable lifecycle queue, stay quiet during those waits and escalate once after the deadline.

• *Verification wake routing* — Was: Approved verdicts and expired dispatches could wake the wrong owner.
→ Now: Close retries stay with the assignee, and an expired dispatch sends one supervisor wake.

• *Background job state* — Was: Native background jobs could look finished, or stay busy when completion arrived as a queued-command attachment.
→ Now: A job holds busy state until its completion notice, in either form.

• *Hourly QA notice removed* — Was: The daemon prompted a QA round for each hour merged work waited.
→ Now: The notice is gone, and one queued by an older daemon wakes nobody.

*Close and closeout*

• *Close gate preflight* — Was: Requirements surfaced one refusal per attempt.
→ Now: Start context lists what close will check, and a refused park reports proof, upkeep, ledger, QA evidence, unpushed tip, changelog and scope together.

• *Earlier failures stay visible* — Was: A later metadata, checkout, receipt or verification failure could hide collected proof refusals.
→ Now: Close reports them together, and refused attempts skip speculative delivery-anchor advancement.

• *One closeout order* — Was: The guides described an hourly candidate and QA cycle, with each failure starting another round.
→ Now: They name one review with the queue precheck, one batch fix, a fix-diff re-review and one QA round before enqueue.

• *Interim queue precheck* — Was: The guides had no runnable precheck ahead of the hosted one.
→ Now: They name a clean-checkout diagnostic with both npm installs, Playwright and Chromium, workspace nextest and CI-tier tests.

*Commander rendering*

• *Reply contract* — Was: Operator replies were limited to bold, bullets, lists, inline code and links.
→ Now: The contract, pane guidance and Commander pointer steer to diagrams, callouts, language-tagged blocks and tables, with a worked example.

• *Diagram bounds and Wrap* — Was: Diagrams over 288 px clipped silently, and Wrap was a no-op on the rendered view.
→ Now: Rendered diagrams show whole at phone and desktop widths, and Expand and Wrap are source-view only.

• *Short status routing* — Was: The status box showed Markdown literally at 140 characters or fewer.
→ Now: Callouts, headings and lists promote to a full message at any length, and inline Markdown renders in the box.

• *Hunkless diff fences* — Was: A `diff` fence without an `@@` line rendered as one color with no Source control.
→ Now: Changed lines are tinted without line numbers, and a fence with no changed line stays plain code.

• *Table styling* — Was: Tables used a dark panel, monospace numbers and no row rules.
→ Now: Ruled rows use the bubble font and right-aligned tabular figures, with Copy Markdown and Copy CSV on the closing rule.

• *Stopped-session dot* — Was: A stopped session on an online machine used the idle or needs-you dot.
→ Now: It uses the gray disconnected dot, and live idle stays green.
```
