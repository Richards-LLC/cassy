## User thread

Top-level:

```text
*Live on production — User — Cassy v3.98.0*
Was: closing a release took many separate checks. → Now: one verdict closes finished work, test builds run on request, session dots show three states.
```

Reply (Was → Now):

```text
*Releases*

• *One review per release* — Was: Each finished piece of work in a release got its own separate review.
→ Now: One verdict for the whole release closes the work it covers, with no per-item reminders while it waits.

• *Check a commit in one command* — Was: Checking a commit before release needed a full local build and browser setup.
→ Now: `cas release precheck <commit>` runs the same checks on hosted CI and reports the result.

• *Merges finish themselves* — Was: A merge refused because tests were still running had to be retried by hand.
→ Now: It completes on its own when the tests pass, and a failure sends one clear notice.

*Test builds*

• *Test builds on request work on Linux* — Was: Some Linux machines refused every requested test build within seconds.
→ Now: Requested builds run inside their sandbox and return the finished build, about two minutes on our main machine.

• *Clear refusals* — Was: A machine that could not build reported "queued" and then failed later.
→ Now: It refuses at the request and says why.

• *No leftover disk use* — Was: A stopped build could leave up to 20 GB behind.
→ Now: The next build clears whatever a stopped build left, and leaves a running build alone.

*Commander*

• *Session dots show three states* — Was: An idle session looked unlike a working one, and a stopped one could look alive.
→ Now: Green means working, muted green means idle, and gray means disconnected.

• *Dismissed sessions come back* — Was: A dismissed session could be unreachable, and a restore on another device did not show on the first.
→ Now: Dismissed sessions stay reachable, and a restore shows on every browser.

*Fewer interruptions*

• *Busy work is not called stalled* — Was: A long build or test run could be reported as stalled while it was working.
→ Now: Work running in the background counts as busy, and only work that has truly stopped is reported as stalled.

• *Answers reach the person who asked* — Was: A reply to a question between machines could sit unread until something else happened.
→ Now: The answer brings the person who asked back to it, and plain notices do not interrupt.

• *Quieter idle time* — Was: Idle sessions produced empty status updates and repeated reminders.
→ Now: Empty updates and repeat reminders are gone.

Update with `cas update`, or choose <https://github.com/Richards-LLC/cassy/releases/tag/v3.98.0|the Linux x86_64 or macOS ARM64 downloads>.

Full report (PDF): <https://github.com/Richards-LLC/cassy/blob/4f405717aaaba5d6aee8918a1c84aea04bbecf88/docs/release-reports/v3.98.0.pdf|open the PDF>.
```

## Dev thread

Top-level:

```text
*Live on production — Dev — Cassy v3.98.0*
Was: per-delivery verifiers, local prechecks and manual merge retries. → Now: one release verdict, hosted `cas release precheck`, CI-gated merge retry and Linux candidate builds.
```

Reply (Was → Now):

```text
*Closeout*

• *One verifier per release* — Was: With `qa.mode=batch`, each merged delivery dispatched its own verifier (9 on 3.96, 1.57M fresh tokens).
→ Now: `verification action=batch_receipt verification_type=release` records one verdict that closes the covered Tier 1 deliveries, including unassigned ones.

• *No waiting-delivery nags* — Was: Each Tier 1 delivery waiting for the verdict woke the supervisor as a blocked close.
→ Now: Deliveries wait quietly for the verdict, and unreadable worker holds suppress only assignment prompts.

• *Hosted queue precheck* — Was: Prechecks needed a local build, both npm installs and Playwright.
→ Now: `cas release precheck <sha>` pushes a precheck ref and runs the queue suite on hosted CI. Python runs isolated, run discovery is bounded, failures are reported honestly and refs are cleaned up.

• *CI-gated merge retry* — Was: A merge refused for pending CI needed a supervisor retry.
→ Now: The authorized merge persists and runs when CI turns green. A terminal non-green result sends one notice.

• *Docs pushes keep code covered* — Was: A docs-only follow-up push cancelled the code CI run and forced an override.
→ Now: Each push is compared with its delivery fork, so the code run's coverage is kept.

*Candidates*

• *Sandbox no longer nests itself* — Was: Queued builds ran `/proc/self/exe` inside bwrap, which resolved to bwrap and failed with "No permissions to create a new namespace".
→ Now: The builder execs the real binary. Measured on soundwave: request to receipt in 133 s under the daemon's sandbox.

• *Early refusal and self-probe* — Was: Hosts without a usable sandbox accepted requests and failed later.
→ Now: The daemon probes the sandbox at startup, and requests are refused at admission with the reason.

• *Killed builds clean up* — Was: A timed-out or interrupted build left its checkout and target behind.
→ Now: A normal exit removes the checkout and target. A kill cannot unwind, so the next build removes what it left and leaves a running build alone.

*Runtime*

• *MCP merge stack budget* — Was: On dev-profile builds, a supervisor merge or closing verdict overflowed the 2 MiB tokio worker stack (about 2.03 MB of frames), losing the reply and the close.
→ Now: The heavy merge and close futures are boxed (782 KB measured), and a test holds the path under a 1 MiB budget.

• *Process-tree liveness* — Was: Liveness read only the harness pid's CPU, so a busy background child read Stalled after 120 s.
→ Now: CPU is summed over descendants when user work exists, and the root's CPU is used for inference without children.

• *Peer reply wakes* — Was: Untyped replies to actionable peer messages did not wake the idle asker.
→ Now: Replies and explicit answers wake the asker once, and FYI receipts stay quiet.

• *Cross-device restore* — Was: A restore on another device left the dismissing browser hiding the session.
→ Now: The restore is reconciled on every browser.

• *Three-state session dots* — Was: Live idle and live working looked different in the wrong way, and stopped sessions could read as alive.
→ Now: The `--state-ok`, `--state-idle` and `--state-off` tokens map working, idle and disconnected.

• *Bounded waits and quieter turns* — Was: Approved verdicts could block forever, and delay reminders could poll inboxes.
→ Now: Verification and background waits have deadlines, polling reminders are refused, and content-free idle bubbles are omitted.

Full report (HTML): <https://github.com/Richards-LLC/cassy/blob/4f405717aaaba5d6aee8918a1c84aea04bbecf88/docs/release-reports/v3.98.0.html|open the report>.

```
