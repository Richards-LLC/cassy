## User thread

Top-level:

```text
*Live on production — User — Cassy v3.99.0*
Was: important work got buried in session lists. → Now: Team puts blocked and stalled work first, with a direct next step.
```

Reply (Was → Now):

```text
*Find the next action*

• *Team shows what needs you* — Was: finding blocked or stalled work meant scanning similar session labels.
→ Now: Team puts those items first, shows their task titles and offers a direct attention shortcut.

• *Quieter active conversations* — Was: ordinary notices could interrupt Codex while it was working.
→ Now: those notices wait, stay readable and leave your own messages free to steer the conversation.

• *Accurate pending updates* — Was: an update could refer to a newer code version than the one it originally described.
→ Now: it keeps the original version and disappears when that work has already merged.

*Keep work moving*

• *Optional fresh conversations* — Was: each queued task inherited the conversation before it.
→ Now: you can choose a fresh conversation between tasks without losing the checkout or settings. This choice stays off by default.

• *Real conversation capacity* — Was: long output or lifetime token totals could make a conversation seem fuller than it was.
→ Now: notices use its measured capacity and say when that measurement is unavailable.

• *More private startup instructions* — Was: long instructions appeared in process listings and could match an unrelated cleanup search.
→ Now: startup reads a private file, keeping those instructions out of the command line.

• *Finished work stays recoverable* — Was: completed work could stay open after its controlling session ended.
→ Now: the next session finds it with its remaining review requirements and a clear completion action.

*Understand the cost*

• *Count rejected merges* — Was: a release could report no queue failures even after being sent back for repair.
→ Now: history restores each distinct failure once, including its failed check and a link to the run.

• *See each turn's cost* — Was: the report could not connect each resumed conversation to measured actions and cost.
→ Now: it records what resumed the turn, successful actions, tokens, time and turns with no measured action.

• *Keep reports flowing* — Was: one unsupported turn record could hold up other report updates.
→ Now: it stays saved for a later retry while other records continue to sync.

*Checks and current limits*

• *More reliable release checks* — Was: parallel checks could claim the same briefly available port and fail at startup.
→ Now: the service chooses its port when it starts, removing that race.

• *Compatible browser checks* — Was: recording and repair instructions lacked the newer options.
→ Now: newer recording options and bounded repair guidance are documented while valid Playwright 1.63 captures remain supported.

• *Clear coverage limits* — Was: a missing activity record could be mistaken for no activity.
→ Now: missing usage is disclosed, and OpenCode turn costs remain explicitly outside the report's coverage.
```

## Dev thread

Top-level:

```text
*Live on production — Dev — Cassy v3.99.0*
Was: activity costs were incomplete and interruptions obscured progress. → Now: typed turn records, recovered queue failures and gated notices make the cost visible.
```

Reply (Was → Now):

```text
*Conversation behavior*

• *Attention-first Team* — Was: blocked tasks and stalled sessions competed with routine merge waits and identical state labels.
→ Now: named attention shortcuts, task titles and a stronger count put reported trouble first.

• *Ordinary Codex input waits* — Was: standard, unattributed and oversized nonoperator messages could enter a busy turn.
→ Now: they obey the wake gate before PTY delivery; verified operator input can still steer the active turn.

• *Stable pending notices* — Was: delayed delivery decisions could drift to a later source tip or outlive their merge.
→ Now: each notice retains its original delivery tip, reports supersession and withdraws after the merge.

• *Configurable context boundaries* — Was: queued tasks always reused the existing conversation.
→ Now: explicit opt-in enables generation-fenced restarts with the same name, worktree and launch recipe; the default remains false.

• *Measured occupancy* — Was: context pressure could be inferred from total billing tokens or output volume.
→ Now: MCP notices use the latest native input count and reported model window, suppress repeats and label unavailable capacity unknown.

• *Private launch briefs* — Was: assignment text in argv was visible locally and could match a process-search pattern mentioned in that text.
→ Now: a private worktree file supplies the brief through startup and resume; teardown removes it.

*Accounting and recovery*

• *Typed turn records* — Was: release reports lacked per-turn wake channels, successful actions and no-op costs.
→ Now: incremental Claude, Codex and Grok collection records those facts with measured tokens and duration, independently of conversation mirroring.

• *Correct first wakes* — Was: launch context could hide the first Codex wake, and indirect message delivery could lose its source.
→ Now: launch context is excluded, authenticated message origins are retained and isolated-checkout rollouts resolve correctly.

• *Honest no-op time* — Was: routine prose could look productive and an unfinished turn could leak its duration into the next.
→ Now: typed successful actions determine no-op status, new turns reset timing and appended rows avoid full replay.

• *Historical queue failures* — Was: consumed relay history was omitted and immutable zero snapshots hid recovered failures.
→ Now: backfill preserves historical timestamps, titles and run links, then reports each failed run once even alongside legacy queue-exit keys.

• *Independent sync progress* — Was: a rejected Turn could stall other quality events.
→ Now: a separate pending cursor and capability cooldown retain Turns for retry while unrelated records continue pushing and pulling.

• *Cross-session completion* — Was: merged items could remain open after the controlling session ended.
→ Now: eligible deliveries retain their close action across sessions, and exact recorded release verdicts clear covered expired review debt.

• *Review holds stay visible* — Was: higher-tier deliveries or one unreadable review row could disappear from recovery.
→ Now: all review tiers keep their current hold and next action; bad rows are reported without hiding the rest or skipping required probes.

*QA and current limits*

• *Port allocation at startup* — Was: a sampled free port could be taken before a Linux service test used it.
→ Now: the service binds port zero itself, removing the sample-to-bind gap.

• *Browser guidance without a forced upgrade* — Was: recording and automated repair guidance omitted newer controls.
→ Now: optional 1.64 recording/style controls, CLI-first checks and bounded locator repairs are documented; the supported floor stays ^1.63.

• *Explicit measurement gaps* — Was: unsupported activity could be confused with a measured zero.
→ Now: missing usage is disclosed. OpenCode turns are not collected yet, and automatic task-boundary restarts remain opt-in.

Validation: release workflow passed, fresh Linux/macOS downloads match published digests, and the manual post-release check is clean.
```
