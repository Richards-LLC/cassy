## User thread

Top-level:

```text
*Live on production — User — Cassy v4.0.0*
Was: work was reviewed after it merged. → Now: it's checked against its plan first, small fixes ship in minutes, Commander is steadier, two machines cooperate.
```

Reply (Was → Now):

```text
*Checked before it ships*

• *Reviewed before merging* — Was: a change was reviewed only after it had already merged.
→ Now: each change is reviewed first; a pass ships exactly what was reviewed, and a fail holds back only that change.

• *Checked against the plan* — Was: a change could pass its own narrow brief while missing parts of the plan or its measured goals.
→ Now: review names every missing piece or missed target, and a miss holds only the work that depends on it.

• *Room for the AI's judgment* — Was: a plan could not mark decisions that should stay with the AI model.
→ Now: a plan can, and review flags hard-coded word lists or patterns that would take over that judgment.

• *Rules keep their reasons* — Was: rules could lose who asked for them and why, and a retired rule left its code behind.
→ Now: rules keep the requester's exact words, scope and review date, and changing one lists every spot to clean up.

• *Project hold* — Was: during a full stop, ready work and merge prompts stayed active.
→ Now: the operator can hold a project with a reason, and new work and merges wait until the hold is lifted.

*Fast fixes*

• *Small fixes in minutes* — Was: a small screen fix waited for the full test run before it could merge.
→ Now: projects that opt in merge small fixes once unit tests and type checks pass; the full checks follow within 30 minutes.

• *Automatic revert* — Was: a fix that failed its follow-up checks needed someone to notice it and undo it.
→ Now: the check is retried once, then Commander asks Revert or Fix forward and reverts on its own after fifteen minutes.

*Commander*

• *Answers arrive once* — Was: long sessions could show an answer twice, or show a progress note instead of the answer.
→ Now: each answer appears once, and it is the real answer.

• *Messages get through* — Was: a typed-then-erased terminal draft could hold Commander messages back (one case waited 107 seconds).
→ Now: messages arrive at once, a held message says why, and earlier messages are answered first.

• *Usage at a glance* — Was: seeing a Claude or Codex account's usage meant switching to that account.
→ Now: Accounts and New session check five-hour and weekly usage in place, with Eastern reset times.

• *Safer, steadier screens* — Was: the hosted Commander site had no content security policy, and the Most recent badge shifted rows.
→ Now: the site connects only to Tailscale machines or a local hub, and the badge and phone timeline stay put.

• *Keyboard-friendly confirmations* — Was: confirmation prompts were two full-width bars you couldn't reach from the keyboard.
→ Now: compact buttons, arrow keys and Enter to choose, Esc to cancel, and ending a session starts on Cancel.

*Two machines*

• *Two machines, one team* — Was: notices about work from the other build machine could be handled twice, and shared files lacked a working fetch command.
→ Now: each machine handles its own work, notices arrive once, and shared files print a command that works.

*Everyday fixes*

• *"Ready" always gets through* — Was: a "ready, please merge" message for a follow-up fix could be filed as a duplicate, so work sat idle overnight.
→ Now: only true duplicates are folded away, and a message left unread for ten minutes raises one alarm.

• *Memory and video* — Was: Cassy couldn't save notes to a project's own memory, and screen recordings uploaded as plain files.
→ Now: each project's memory can be saved to with no setup, and WebM and MP4 recordings upload as video.

Update with `cas update`, or choose <https://github.com/Richards-LLC/cassy/releases/tag/v4.0.0|the Linux x86_64 or macOS ARM64 downloads>.
```

## Dev thread

Top-level:

```text
*Live on production — Dev — Cassy v4.0.0*
Was: verification ran after merge. → Now: candidates are verified pre-merge with plan-fit, plan-target and model-boundary gates, and frontend hotfixes merge on unit tests.
```

Reply (Was → Now):

```text
*Pre-merge verification*

• *Candidate review before publish* — Was: required verification ran after a merge had already published.
→ Now: the verifier reviews an immutable candidate; PASS publishes that exact tree and closes with the approval, FAIL holds only that delivery.

• *Approvals survive sibling merges* — Was: a target advance discarded a pre-merge approval, and an unrelated merge voided a verdict as "no longer reachable".
→ Now: one reviewed-file rule keeps approvals across unrelated, append-only and generated updates; changed reviewed content still needs review.

• *PLAN-FIT* — Was: a narrower task card could pass while planned fields or outcome targets were missed.
→ Now: verifiers report `PLAN-FIT`, name each omission, reject known misses and ask for a scope decision or an authorized plan revision.

• *Plan-target gates* — Was: phases had no measured outcome gate and evaluation claims needed no run evidence.
→ Now: gates carry measured targets and receipts bound to a real run log; a miss holds dependent starts, closes and merge prompts, and exceptions expire with the measurements.

• *Model boundaries* — Was: plans could not reserve interpretation for the model.
→ Now: an optional plan boundary flags added literal collections, regexes and exact-string assertions; the verifier names blocking sites and honors approved exceptions.

*Rules and governance*

• *Rule provenance* — Was: attributed rules could lose their wording, and a saved version stored the previous text.
→ Now: rules keep verbatim words and scope, attributed hard rules need a review date, and each version snapshots the persisted result in the same transaction.

• *Rule traceability* — Was: retiring or narrowing a rule left its cited code and tests behind.
→ Now: code cites rules, close checks declared sites, `cas rules refs <id>` lists references, and scope changes file one cleanup chore listing each `path:line`.

• *Policy hygiene* — Was: superseded memories stayed in session context, and non-operator rule writes could create encoding chores.
→ Now: superseded or expired memories leave context, drift reports compare rule sources with peer snapshots, and encoding chores are operator-only.

• *Governance stops* — Was: repeated stakeholder defects kept staffing fixes, and a full stop left dispatch and merges actionable.
→ Now: five stakeholder P0/P1 bugs in 48 hours pause new starts for a design review, and operator-only project holds stop dispatch and merges.

*Hotfix fast lane*

• *Fast-lane opt-in* — Was: every frontend hotfix waited for hermetic e2e, the production build and the journey walk before merging.
→ Now: eligible deliveries (configured paths, at most 10 files and 300 lines, Tier 1) merge on unit tests and typecheck; the rest is a post-merge receipt due in 30 minutes.

• *Post-merge failure handling* — Was: a failed post-merge check had no defined recovery path.
→ Now: it reruns once; a hotfix-caused failure asks Commander Revert or Fix-forward and opens the revert PR after fifteen minutes, surviving restarts.

• *Concurrent hotfix PRs and conflict repair* — Was: a branch holding an earlier PR refused new work, and a queue-dropped conflict waited for request_changes.
→ Now: new work starts on a fresh `factory/<worker>-<task>` branch, and the assigned worker can resume a truly conflicted park.

*Commander*

• *Mirror and message delivery* — Was: transcripts past the 4 MiB window re-keyed turns, progress lines posed as answers and erased drafts held messages.
→ Now: reads start at turn boundaries and wait for final text, erased drafts count as empty, and real holds are labelled.

• *Claude launch, usage and layout (#1465, #1467, #1464)* — Was: launches could pick an incompatible Claude, usage needed an account switch and the Most recent badge shifted rows.
→ Now: native Claude 2.1.280+ is verified, API failures show on the first turn, usage rereads in place and the badge keeps its slot.

• *Hosted CSP* — Was: hub.petrastella.io sent no Content-Security-Policy.
→ Now: sources are limited to `*.ts.net` tailnets on any port (an opt-in flag; the named-tailnet list remains) or a loopback hub, with `Referrer-Policy: no-referrer`, and deploys verify the live policy.

• *Confirm sheet* — Was: slash-command confirmations stacked full-width buttons with no keyboard control.
→ Now: an `alertdialog` with roving focus (arrows, Enter/Space, Esc, Tab trapped), Cancel focused first for session-ending commands, and ↑/↓ in the suggestion list.

*Two machines*

• *Cross-machine handoffs* — Was: watchers could act on another machine's deliveries and repeat notices, and peer artifact pointers had no fetch path.
→ Now: ejections route by recorded session, deliveries stay with their owning machine, occurrences stay stable and artifacts print a scoped fetch command.

*Reliability*

• *Delivery plumbing (#1474, #1470, #1469)* — Was: queued PRs conflicted on the changelog, spawn names could collide and detached runs finished silently.
→ Now: deliveries write `changelog.d/` fragments, spawns reserve names against refs and explain account refusals, and completions wake their owner once.

• *Worker-ready wakes* — Was: a ready naming a new tip on a task whose old anchor had merged was classified as a digest and never woke the supervisor.
→ Now: only an exact-tip duplicate (7–40 hex prefix of the merged anchor) digests; unread worker→supervisor rows escalate once after about ten minutes, and the stop hook warns when no wake covers a worker.

• *Memory roots and media types* — Was: agents couldn't write Claude auto-memory, and `.mp4` uploaded as `application/octet-stream`.
→ Now: the active Claude config's `projects/<slug>/memory` is a built-in write root (own project, symlink-safe, first write creates it), and WebM, MP4 and M4V upload as video.

• *Evidence and smaller fixes (#1471, #1466)* — Was: QA impact dropped unowned files, verifier time went unmeasured and QA refused preview-deployment walks.
→ Now: impact keeps those files, verdicts record measured duration, and `qa.deployed_origins` accepts per-deployment patterns.
```
