## User thread

Top-level:

```text
*Live on production — User — Cassy v4.0.2*
Was: repeat alerts piled up and /finish from Commander was refused. → Now: one alert per change, and /finish waits its turn.
```

Reply (Was → Now):

```text
*Quieter, smoother sessions*

• */finish from Commander* — Was: sending /finish while the screen was still redrawing was refused as "busy", and no reply ever showed.
→ Now: it waits for the turn to end, runs once, and the reply appears in Commander.

• *No more alert floods* — Was: one idle session could trigger 20+ identical alerts in five minutes.
→ Now: one alert per task and state, remembered across restarts.

• *Fewer empty wake-ups* — Was: sessions were woken for events that needed nothing from them.
→ Now: those arrive quietly, and every turn records who caused it.

• *Pairing a device* — Was: pairing through the Tailscale relay port looked successful, but Commander then couldn't connect.
→ Now: the pair command refuses that port and names the right one.
```

## Dev thread

Top-level:

```text
*Live on production — Dev — Cassy v4.0.2*
Was: closes needed hand-run proofs and merges needed manual PR steps. → Now: the queue run is the proof; merges open their own PR.
```

Reply (Was → Now):

```text
• *Queue run is proof (#1490)* — Was: workers could not run `--proof`, so every direct-to-main close needed a supervisor-run scoped proof.
→ Now: a passed merge_group run at the landed tree satisfies the scoped-proof gate; epic-targeted deliveries still need the scoped proof.

• *Approvals survive target moves (#1489)* — Was: a pre-merge approval was discarded when only the target ref moved, and queue-built landings were refused at close.
→ Now: an approval carries over when the candidate tree is unchanged, candidates build from the fetched origin target, and divergence is reported before dispatch.

• *Protected main (#1494)* — Was: a refused direct push could leave an unpushed merge on local main, and the supervisor ran five commands to open the PR.
→ Now: refusals restore local main safely, and confirmed merge queues take the PR route directly with head-pinned auto-merge.

• *Auto-retry follows the tip (#1497)* — Was: the retry watched a superseded commit's cancelled CI and stopped.
→ Now: it follows the tip's live run; a moved lane still stops it.

• *Release changelog (#1492)* — Was: fragments in the same area produced duplicate headings and failed markdownlint, and promoted fragments read as dropped work at close.
→ Now: one heading per section; a fragment promoted by a `release: vX.Y.Z` commit is accepted only for its own task (or an epic's children).

• *Wakes and alerts (#1488, #1493)* — Was: idle-wake dedupe kept only the last signal in memory, and many daemon wakes were no-ops or unattributed.
→ Now: dedupe keys on worker, task and gate state and persists; no-op wakes are suppressed and every turn has a role.

• *Commander /finish (#1486)* — Was: the 3-second settle check counted footer repaints as activity and refused before storing the command.
→ Now: /finish queues until a native turn completes, and the reply mirrors to Commander.

• *Session start and pairing (#1498, #1495)* — Was: session start carried trimmed memory lists nobody opened, and `cas hub pair` accepted the Tailscale shim origin.
→ Now: session start carries a one-line pull pointer, and pairing refuses non-hub origins.

Validation: the merge queue checks the final release tree.
```
