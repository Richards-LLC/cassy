```text

• *Questions stay open* — Was: work could move ahead while a question was unanswered. → Now: the related merge waits for an answer or an explicit exception.

• *Stalled work gets noticed* — Was: ongoing work could stay silent indefinitely. → Now: a long pause prompts attention, then alerts you if progress still stops.

• *Timed reminders work* — Was: some reminder text was refused. → Now: a plain timed reminder is accepted as a backstop.

• *Fewer empty alerts* — Was: routine success messages interrupted useful work. → Now: alerts focus on a failure, a risk or a next action.

• *Unsaved work stays safe* — Was: closing a session could strand unpublished changes. → Now: changes are retained with a recovery reference before removal.

• *Finish waits* — Was: an exit could overtake work that had not been saved. → Now: Finish waits for it to be saved or names what still needs attention.

• *New versions between jobs* — Was: fresh work could start on an older installed build. → Now: the next queued job can pick up the installed release safely.

• *Version labels match reality* — Was: an already installed update could still be offered. → Now: Commander distinguishes the running version from the installed one.

• *Routine decisions keep moving* — Was: settled decisions could wait for another go-ahead. → Now: written standards guide routine choices, with policy questions left to you.

• *Problems get reported sooner* — Was: a workaround could hide a product defect. → Now: defects are reported with evidence and a suggested fix.

• *Shorter instructions* — Was: repeated instructions obscured the goal. → Now: the guidance focuses on complete, simple work and fewer unnecessary steps.

• *Simpler changes pass review* — Was: extra machinery could pass without earning its cost. → Now: review asks whether a smaller change solves the whole problem.

• *Release effort is visible* — Was: release delay and added complexity were hard to compare. → Now: the ledger reports both, or explains missing measurements.

• *Completed merges publish correctly* — Was: a regenerated file could prevent an otherwise valid merge from being published. → Now: that extra step keeps the original merge evidence.

• *Source changes wait for the right build* — Was: a source-only change could be held for an outdated generated page. → Now: the release preparation checks the finished page.

• *Queue messages stay accurate* — Was: queue notices named a check that no longer ran there. → Now: they describe the check actually required.
```

## Dev reply

```text
*Messaging and delivery*

• *Open-question merge hold* — Was: an unanswered peer question could be bypassed. → Now: the named task or PR is held until an answer or a recorded override.

• *Status does not settle an ask* — Was: a typed status reply could release the hold. → Now: only an answer or an untyped reply settles it.

• *Progress watchdog* — Was: liveness could disguise a stalled release. → Now: a progress-based watchdog wakes once after 45 minutes and alerts after another 45.

• *Time backstops* — Was: polling-shaped reminder text was rejected. → Now: plain delay reminders are accepted while event waits remain preferred.

• *Actionable notices* — Was: routine spawn and shutdown success generated interruptions. → Now: informational outcomes stay in the audit and actionable warnings remain visible.

• *One queue-exit notice* — Was: a later failure report could repeat an ejection notice. → Now: both observations belong to the same queue exit.

• *Mirror expiry* — Was: aged transcript mirrors could remain pending. → Now: completed copies expire after 24 hours without dropping operator input or independent delivery snapshots.

*State and preservation*

• *Evidence-qualified status* — Was: cached refs and intermediate writes sounded complete. → Now: publication uses a live origin check and other words identify the observed boundary.

• *Recovery before removal* — Was: shutdown could leave unpublished work stranded. → Now: rescue refs preserve commits and dirty files before destructive cleanup.

• *Finish waits for publication* — Was: shutdown could overtake dirty or unpublished work. → Now: Finish waits up to ten minutes and names any retained work.

• *Between-task version refresh* — Was: queued work could reuse an old MCP process. → Now: it is recycled between tasks after installation, preserving mid-task execution.

• *Running versus installed* — Was: Commander conflated the hub, installed binary and latest release. → Now: reconnect refreshes hub state and labels each version separately.

• *Regenerated-artifact landing* — Was: a post-merge regeneration commit hid the reviewed landing. → Now: publication verifies the merge beneath permitted generated changes.

*Instructions, review and release tooling*

• *Routine decision authority* — Was: settled implementation choices could wait for operator approval. → Now: resident instructions apply written standards and reserve policy decisions for the operator.

• *Immediate defect evidence* — Was: local workarounds could leave defects unreported. → Now: role guidance requires an immediate evidence-backed report and source-fix routing.

• *Smaller resident instructions* — Was: role prompts repeated mechanical gates. → Now: shorter shared guidance preserves ownership, delivery and evidence obligations.

• *Simplicity review* — Was: overbuilding and unearned waits could pass review. → Now: a concrete smaller sufficient solution is a reason to return a change.

• *Speed and complexity metrics* — Was: the ledger lacked comparable release costs. → Now: it reports commit-to-main, main-to-publication and source/config/check deltas with explicit unknowns.

• *Generated bundle timing* — Was: source-only changes required an immediately regenerated bundle. → Now: release-version or bundle changes enforce equality against the final build.

• *Queue check descriptions* — Was: notices and fixtures still named the removed macOS queue check. → Now: they describe Fast Validation, retaining macOS packaging in publication.
```
