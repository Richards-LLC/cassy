## User thread

Top-level:

```text
*Live on production — User — Cassy v4.0.5*
Was: Grok replies missing, reloads needed a keyboard, 74 conflicting rules. → Now: Grok shows up, Reload Cassy works anywhere, one answer per rule.
```

Reply (Was → Now):

```text
*Clearer, closer, less babysitting*

• *Grok in Commander* — Was: replies from Grok sessions never appeared in Commander.
→ Now: they appear like Claude and Codex replies, linked to your question; automatic pings and cancelled turns stay out.

• *Reload Cassy from anywhere* — Was: moving a session onto a new Cassy needed `/mcp` typed at its keyboard.
→ Now: Commander's Reload Cassy does it from any device, and confirms only when the new version is running. Claude Code sessions are supported; Codex and Grok say so plainly.

• *One answer per rule* — Was: Cassy's instructions to its sessions disagreed in 74 places.
→ Now: each question has one answer everywhere, and a test stops contradictions from coming back.

• *Merged work closes* — Was: work that landed through the merge queue often could not close without a manual override.
→ Now: it closes on its own once it lands.

• *Builds use the free machine* — Was: new work waited on a full machine while the other sat idle.
→ Now: overflow goes to your other machine, with its full brief.

• *Fewer repeat reviews* — Was: approved work was reviewed again when main moved, and read-only investigations were reviewed twice.
→ Now: one review sticks unless the work itself changes.

• *Requested changes get seen* — Was: a request for changes could go unseen while work moved on.
→ Now: the next task waits until the requested changes are read.

• *Idle sessions take work* — Was: a clean, idle session could be refused as "behind main".
→ Now: it is accepted; only one in the middle of a task is refused.

• *Disk stays clean* — Was: build caches from idle sessions and finished reviews filled the SSD three times in one day and stalled work.
→ Now: Cassy frees them on its own after each delivery and every 15 minutes, and never touches work in use.

• *Deployed work closes itself* — Was: tasks stayed "awaiting merge" after their work was live; one project had 52.
→ Now: a deploy that contains the work records it automatically.

Update with `cas update`, or choose <https://github.com/Richards-LLC/cassy/releases/tag/v4.0.5|the Linux x86_64 or macOS ARM64 downloads>.
```

## Dev thread

Top-level:

```text
*Live on production — Dev — Cassy v4.0.5*
Was: 74 instruction contradictions; queue-landed closes refused; Grok ignored by the mirror. → Now: one canon plus parity test; landing-commit check; Grok mirrored.
```

Reply (Was → Now):

```text
• *Instruction canon (#1546)* — Was: 30 supervisor, 19 worker and 25 verifier/QA contradictions across skills, launch contracts, assignment text and refusal strings.
→ Now: one close owner and one park-relay signal; a parity test fails if any surface regrows an old answer.

• *Queue-landed close (#1538)* — Was: the synthetic premerge candidate was checked against the current tip of main, so later edits or a release deleting the changelog fragment refused the close.
→ Now: the reviewed patch is checked at its first landing commit; source ancestry is still checked against the target.

• *Grok mirror (#1544)* — Was: completed_turns skipped Grok and rejected integer-second timestamps.
→ Now: ACP turns are parsed natively; `syntheticPrompt` rows never bind, same-prompt image chunks keep the binding, cancelled turns emit nothing.

• *Reload Cassy (#1545)* — Was: no remote path to reconnect a supervisor's MCP.
→ Now: a supervisor command sends `/mcp reconnect cas` once and confirms from the replacement serve PID and version; proven on Claude Code 2.1.311, 2.1.316 and 2.1.318.

• *Build routing (#1539)* — Was: spawn admission refused locally even when the operator's other machine had free builder slots.
→ Now: a refused spawn routes to a fresh own-account peer; routes expire after 15 min and are rate-limited to one per peer per 90 s.

• *Review binding (#1540, #1530)* — Was: a dispatch bound to an unpublished local merge, and no-delivery closes bound to a moving epic tip, so reviews re-dispatched.
→ Now: review targets bind to the fetched origin ref, and measured no-delivery closes pin to the reviewed commit.

• *Late verdicts (#1531)* — Was: a verdict recorded just after the dispatch deadline was discarded.
→ Now: it is honoured while the verifier's 30-minute capability is valid; expired capabilities are still refused.

• *Send-back alarm (#1532)* — Was: request_changes could sit unread while the worker's next queued task started.
→ Now: the queued start waits until the correction notice is read.

• *Disk GC (#1528)* — Was: per-worker Cargo targets (15–40 GB each) and pre-merge review copies were never reclaimed; the disk hit the 85% build watermark three times on Nov 5.
→ Now: targets are trimmed at park and reclaimed when idle, and a review copy's target is freed once its verdict resolves; live builds and source checkouts are never touched.

• *Deploy receipts (#1522)* — Was: a staging or main deploy that contained a task's delivery left it AwaitingMerge (52 tasks in one project).
→ Now: the deploy records the batch receipt automatically.

• *Assignment (#1541)* — Was: an Open queued task counted as active work, so an idle worker behind main was refused.
→ Now: only InProgress and Blocked work refuses.

Validation: the merge queue checks the final release tree.
```
