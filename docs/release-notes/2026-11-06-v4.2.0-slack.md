# Slack draft — Cassy v4.2.0 runtime release

Channel: #cas-internal (`C0B44GUKDK2`).

Status: Prepared for review. Post only after the release cut, published-asset
verification, installation and post-release checks are ready. The release
command resolves the version token. Published-asset verification fills the
checksum tokens; no local-build digest substitutes for that proof.

No screenshot pair applies: this release tree carries no recorded before/after
capture pairs.

## User thread

Top-level:

```text
*Live on production — User — Cassy v4.2.0*
Was: every review and every merge waited on a person. → Now: reviews start on their own and fixes land in order.
```

Reply (Was → Now):

```text
*Less waiting, more shipping*

• *Reviews start themselves* — Was: every finished change waited for someone to start its review by hand.
→ Now: the review starts on its own, an approval goes straight on, and only problems ask for attention.

• *Fixes land in order* — Was: an approved fix often had to be redone because another fix landed a moment earlier.
→ Now: one command lands all waiting fixes in order and sends back only the one that truly conflicts.

• *Project tabs in Commander* — Was: progress was hidden in a panel and showed one workstream at most.
→ Now: tabs above the conversation show every live workstream on both machines, with progress and who is working.

• *Reload Cassy from the card* — Was: typing /mcp opened a menu and did nothing.
→ Now: Reload Cassy is always in the commands menu, a button appears on any card that needs a reload, and /mcp works too.

• *Commands work when a session is idle* — Was: Exit and Reload were refused right after a turn ended.
→ Now: they work as soon as the turn is done, and local commands no longer clutter the chat.

• *Visible problems first* — Was: theoretical findings from reading code got fixed before failures people could see.
→ Now: problems on the main user journeys go first, and code-read findings wait in the backlog.

• *Readable words* — Was: words like disk-limit and ask-me were blacked out as if they were secrets.
→ Now: only real key-shaped secrets are hidden.

• *Updates keep going* — Was: cas update could stop the whole sync over a file it had written itself.
→ Now: it recognises its own files and skips only a file you really changed.

• *Leftover work is visible* — Was: unsaved work in stopped sessions was invisible to the next one.
→ Now: startup and cleanup reports list it with how to recover it.

Update with `cas update`, or choose <https://github.com/Richards-LLC/cassy/releases/tag/v4.2.0|the Linux x86_64 or macOS ARM64 downloads>.

macOS ARM64 SHA-256: `{{MACOS_SHA256}}`
```

## Dev thread

Top-level:

```text
*Live on production — Dev — Cassy v4.2.0*
Was: hand-launched verifiers, re-merges on every train move, 55 s merge timeouts. → Now: auto-verify, train_merge, early receipts.
```

Reply (Was → Now):

```text
• *Automatic candidate review* — Was: each pre-merge dispatch needed a hand-launched verifier.
→ Now: the daemon starts the sealed task-verifier child; approval continues the merge quietly, findings or failures wake the supervisor.

• *train_merge* — Was: approved deliveries conflicted whenever the train moved and were re-merged by hand.
→ Now: `factory action=train_merge` lands parked deliveries in order through the same pre-merge gate, carries unchanged patch-ids, returns conflicts to their worker and holds single merges while it runs.

• *Early merge and close receipts* — Was: most merges and closes hit the 55 s MCP deadline.
→ Now: work runs off the response threads and answers right after the commit, with phase timings in notes.

• *Release train guards* — Was: a cut train still took merges and new tasks; main could move around the train.
→ Now: a cut train refuses merges even after landing, new work opens the next train, and trunk merges are refused while a train is open (hotfix via `release.sh --hotfix`).

• *Gate fixes* — Was: retired-worker Tier 2 closes skipped review; release imports could be granted by quoted text; a close proved the wrong tip after a generated follow-up.
→ Now: a supervisor-owned verifier opens; only the authenticated supervisor handler grants imports; the final pushed tip is proved.

• *Peer coordination* — Was: untyped peer messages and PR-only asks gated merges wrongly; GitHub sources could not be handed to a peer.
→ Now: only open asks naming the task or its PR hold a merge, and `release_claim` hands a source over.

• *Two-axis triage* — Was: findings were prioritised by hand.
→ Now: severity × reach on declared main journeys sets priority (migration m296); code-read findings go to the backlog.

• *Commander* — Was: one hidden release bar; /mcp did nothing; idle supervisors refused commands; peer replays reloaded every conversation.
→ Now: live epic tabs, Reload Cassy in the commands menu plus a card button on version skew, native turn completion for commands, and replay status limited to changed sessions.

• *Factory hygiene* — Was: delivery alerts fired on both machines; stall nudges fired during registered test runs; big worktree listings timed out; capped tests wrote into the RAM-backed /tmp.
→ Now: alerts stay on their owning machine, registered runs count as activity, command output is drained while running, and test temp files use a short scratch root.

• *Release audit* — Was: late deliveries on epics merged into the release source were missed.
→ Now: declared constituent epics are checked and the included task IDs are listed for the receipt.

Validation: the merge queue checks the final release tree.
Published archives: Linux x86_64 and macOS ARM64, available from <https://github.com/Richards-LLC/cassy/releases/tag/v4.2.0|the GitHub release>.
Linux x86_64 SHA-256: `{{LINUX_SHA256}}`
macOS ARM64 SHA-256: `{{MACOS_SHA256}}`
```
