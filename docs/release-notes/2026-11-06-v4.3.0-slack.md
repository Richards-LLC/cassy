## User thread

Top-level:

```text
*Live on production — User — Cassy v4.3.0*
Was: installing an update meant restarting your live sessions. → Now: updates swap in underneath, and sessions keep running.
```

Reply (Was → Now):

```text
*Updates without restarts*

• *Sessions survive updates* — Was: a new version needed every running session stopped and started again.
→ Now: the background service swaps itself for the new version in place, keeping every pane, its history and its input.

• *Connections survive updates* — Was: an update cut the coding tool's connection to Cassy mid-task.
→ Now: the connection checks the new version first and switches over at a quiet moment.

• *Progress where you look for it* — Was: a strip above the conversation listed every project's work, with blank tabs.
→ Now: the right-hand panel shows only this project, with open, in progress and merged counts for each piece of work.

• *Pictures in replies* — Was: screenshots in a reply showed up as file paths.
→ Now: they appear inline in Commander, from this project's own files only.

• *Messages are not lost* — Was: a Slack message waiting for a busy session vanished if that session ended.
→ Now: the next session for the project picks it up and says where to reply.

• *Clearer warnings* — Was: the note that someone on another machine already holds a task could get pushed out of view.
→ Now: that note always shows.

• *Updates tidy up after themselves* — Was: cas update left its own file changes staged, which blocked later merges.
→ Now: it commits its own changes in one step.

• *Reports and searches* — Was: PDF reports failed with no reason given, and an apostrophe broke task search.
→ Now: report errors say what is missing, and natural-language search works.

Update with `cas update`, or choose <https://github.com/Richards-LLC/cassy/releases/tag/v4.3.0|the Linux x86_64 or macOS ARM64 downloads>.
```

## Dev thread

Top-level:

```text
*Live on production — Dev — Cassy v4.3.0*
Was: updates needed a daemon kill; train reds hid until the cut. → Now: in-place re-exec and a full suite per train merge.
```

Reply (Was → Now):

```text
• *In-place daemon re-exec* — Was: installing a release required `cas factory kill` and a relaunch.
→ Now: the daemon re-execs the installed binary with the same PID and an inherited-fd pane handoff; older daemons report relaunch required after one bounded wait.

• *Stable MCP front* — Was: an update replaced the MCP server under live tool calls.
→ Now: a stdio front prepares and checks the replacement backend, switches at an idle boundary and waits for in-flight tool work.

• *Train-tip full suite* — Was: lane CI skipped broad Rust, so reds piled up until the cut.
→ Now: every train merge runs the queue's full suite on the newest tip, a red names the merge range, train_merge holds until green and release.sh needs a green receipt.

• *Peer and machine coordination* — Was: any later peer message cleared a merge hold, and workers could not message across machines.
→ Now: only a linked answer clears a hold, and workers on one account and epic message each other directly.

• *Gate and close fixes* — Was: a shared-lane tip could count as another task's delivery; approved dispatches left tasks in progress; QA receipts never released deliveries.
→ Now: ownership must be positive, the supervisor owns recovery, and receipts close deliveries with the release verdict, under one canonical sentence each.

• *Auto-review launch* — Was: the automatic reviewer started Codex without credentials and exited.
→ Now: it uses account-aware launch and reports the child's stderr when it stops.

• *Commander* — Was: an epic strip above the chat and no inline images.
→ Now: project-scoped Live epics in the right rail with a segmented split, and artifact images served through a scoped ticket.

• *Hygiene* — Was: changelog fragments written in merges, sync residue, unbounded PDF errors and stale draft rules all needed hand work.
→ Now: they are handled at the source, including draft rules retiring after 30 days.

Validation: the merge queue checks the final release tree.
```
