## User thread

```text
*Live on production — User — Cassy v4.4.0*
```

Reply (Was → Now):

```text
*Stuck work freed, cleaner releases*

• *Stuck tasks free themselves* — Was: after the last update, some projects filed new work under a "release train" that never reached GitHub, so finished work could not close.

→ Now: only the failed work re-runs, and those setup problems are fixed.
```

## Dev thread

Top-level:

```text
*Live on production — Dev — Cassy v4.4.0*
Was: release trains defaulted on for every project. → Now: opt-in via factory.release_train, with self-healing for projects already caught.
```

Reply (Was → Now):

```text
• *Opt-in release trains* — Was: `factory.release_train` defaulted to true, so PR-to-staging projects opened train epics with no origin branch and closes refused "target branch missing" (GH #1613).
→ Now: the default is false. In trains-off projects, close and the daemon's train scan detach unfinished tasks from uncut trains, retarget them to the integration branch with a decision note, and cancel emptied trains. An unreadable config never retires a train.

• *Cut notice gated on green* — Was: `release_cut_ready` fired on merged-delivery counts alone, including on a red train tip (GH #1635).
→ Now: the ready and max-age notices wait for a green full-set verdict at the current tip.

• *Finding priority replies* — Was: a create or update on a finding listed priority as updated when severity × reach overrode it (GH #1636).
→ Now: priority stays derived, and the reply says so and names the deciding labels.

• *Shared train and queue graph* — Was: train pushes and the merge queue ran different checks, and one script failure repeated the whole queue graph.
→ Now: one check graph with tree-bound full-set receipts, per-job reuse and a single in-run retry per failed step.

• *CI repairs* — Was: script suites inherited the caller's FULL_SET and BASE_SHA, Visual QA wrote a tracked report, a step shared by two jobs collided on its receipt, and bad quarantine metadata aborted test shards.
→ Now: each of these is fixed, and a red full set still records its FAIL receipt.

• *Close after release progress* — Was: shipped deliveries could not close once a later sibling changed the landing tree.
→ Now: batch receipts accept the reviewed tree or patch at its landing.

Validation: the merge queue checks the final release tree.
```
