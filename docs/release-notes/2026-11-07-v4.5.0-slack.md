# Slack draft — Cassy v4.5.0 runtime release

Channel: #cas-internal (`C0B44GUKDK2`).

Status: Prepared for review. Post only after the published-asset receipt.

## User thread

Top-level:

```text
*Live on production — User — Cassy v4.5.0*
Was: releases could keep taking new work while shipping. → Now: one freeze holds the release still, and Commander's left nav is compact.
```

Reply (Was → Now):

```text
*Release freeze, a compact Commander, steadier two-machine work*

• *Freeze a release* — Was: new work could still land in a release while it was being shipped.
→ Now: one action freezes the release on both machines. Only fixes for a failing release get in, new work waits for the next release, and Commander shows when the freeze started and a measured finish time.

• *Compact left nav in Commander* — Was: a long list with a tagline and two-line sessions.
→ Now: "Needs you" comes first and quotes each waiting question. Each project is one card with its machines, a small release bar and one status line, and each session is one line. On a phone, End session keeps its own space.

• *Two machines work together better* — Was: one machine couldn't finish work parked on the other, and one answer from the other machine didn't release every question it covered.
→ Now: both work, and one machine can search the other's session history without opening a shell there.

• *Fewer false alarms* — Was: `cas update` could warn that the tailnet link was down while it was working, and a release turning green woke no one.
→ Now: the update waits for the link to settle, and the first green run after a red one sends a single "ready" notice.

• *Faster updates on busy machines* — Was: a machine with many projects kept every session on the old version for about five minutes during an update.
→ Now: each session switches to the new version as soon as its own project is updated.

Update with `cas update`, or choose <https://github.com/Richards-LLC/cassy/releases/tag/v4.5.0|the Linux x86_64 or macOS ARM64 downloads>.
```

## Dev thread

Top-level:

```text
*Live on production — Dev — Cassy v4.5.0*
Was: no release freeze, and peer-machine merges needed overrides. → Now: train_freeze gates merge, staffing and retry, and peer deliveries merge from origin.
```

Reply (Was → Now):

```text
• *Release freeze* — Was: nothing kept a release train still between the cut and publication.
→ Now: `factory action=train_freeze` (or Commander's Freeze for release) refuses merge, staffing, assignment and CI retry on the train on both machines. Red-tip repairs still land, new tasks go to the next train, and publication or an operator lift ends it.

• *Peer-machine merges* — Was: the train owner couldn't worktree_merge a delivery parked on the other machine, and the peer-ask guard held merges when the answer was linked to a sibling ask (GH #1634).
→ Now: a delivery still active locally is refused with "merge on <machine>"; once synced, it merges from origin at its recorded anchor. A linked answer clears earlier asks to the same peer about the same tasks.

• *Pre-merge review* — Was: merge refusals said to spawn a verifier while the automatic verifier held the dispatch, so dispatches ran twice and the losing run paged a false recovery (GH #1637).
→ Now: there is one verifier per dispatch, and a settled dispatch raises no notice.

• *Batch receipts for PR-merged tasks* — Was: batch_receipt refused tasks merged through a GitHub PR with "no resolvable delivery anchor" (GH #1641).
→ Now: it resolves the task's own commit on the target, and a reused worker lane is never treated as the task's delivery.

• *Measured estimates* — Was: ETAs were guesses.
→ Now: ledger `estimate` and `estimate_outcome` kinds give p50/p90 from closed-task, lease and check-run history, and `cas ledger report` shows the hit rate.

• *Install and factory* — Was: install-on-publish units were never refreshed, sessions re-execed only after every project updated, spawn failed on a store-wait miss during upgrade (GH #1640), and macOS reexec printed os error 22.
→ Now: `cas update` refreshes the units, each session re-execs after its own project, spawn retries the binding once, and reexec prints its receipt.

• *Smaller fixes* — Timed-out closes keep their refusal detail. Peer receipts say what is actually known. GC tolerates exited PIDs (ESRCH). First-run Claude startup retries Enter once. The test-shape guard accepts receipt filenames.

Validation: the merge queue checks the final release tree.
Published archives: Linux x86_64 and macOS ARM64, available from <https://github.com/Richards-LLC/cassy/releases/tag/v4.5.0|the GitHub release>.
Linux x86_64 SHA-256: `{{LINUX_SHA256}}`
macOS ARM64 SHA-256: `{{MACOS_SHA256}}`
```
