# Slack draft — Cassy v4.11.0 runtime release

Channel: #cas-internal (`C0B44GUKDK2`).

Status: Prepared for review. Post only after the published-asset receipt.

## User thread

Top-level:

```text
*Live on production — User — Cassy v4.11.0*
Was: shipped work was closed by hand after each release. → Now: it closes on its own, and Commander shows when history fails to load.
```

Reply (Was → Now):

```text
*Fewer manual steps, fewer silent gaps*

• *Releases close themselves* — Was: after a release, each shipped task had to be closed by hand because changelog and map files had moved.
→ Now: closing follows the release history, so shipped work closes without overrides.

• *You can lift a release freeze* — Was: Lift freeze asked for an unrelated fleet-control permission, and turning it on didn't help.
→ Now: your normal pairing can freeze or lift a release from the release card.

• *Missing history shows up* — Was: when Commander asked for a conversation's history and got no answer, the gap stayed silent.
→ Now: after 15 seconds you see an error with a Retry button, for each page separately.

• *Undelivered decisions are noticed* — Was: a decision meant for you could expire without anyone knowing it never reached a device.
→ Now: Cassy notices the miss, and delivery keeps retrying.

• *Approvals from your other machine are acted on* — Was: a landing approval from your other machine could sit quietly for a while.
→ Now: it's picked up right away.

• *Parallel fixes merge cleanly* — Was: two fixes that each added a QA entry collided and had to be redone.
→ Now: separate entries merge on their own; edits to the same entry still ask for a person.

• *Easier debugging and publishing* — Was: a helper that failed to start vanished without a trace, and reports inside a helper's folder could not be published.
→ Now: failed starts keep their boot output, and those reports publish directly with secrets still protected.

Update with `cas update`, or choose <https://github.com/Richards-LLC/cassy/releases/tag/v4.11.0|the Linux x86_64 or macOS ARM64 downloads>.

```

## Dev thread

Top-level:

```text
*Live on production — Dev — Cassy v4.11.0*
Was: post-release close refused promoted changelog fragments and regenerated CODEMAP lines. → Now: close walks the release history and records the promoting commit.
```

Reply (Was → Now):

```text
• *Release close* — Was: closes after a release hit DELIVERY CONTENT DROPPED for `changelog.d/<id>.md` and CODEMAP lines rewritten during integration.
→ Now: close follows the full history to the promoting release commit and the final regenerated blob, with no reviewed-drop override.

• *Peer approvals* — Was: an admitted peer premerge approval was refused after later plan bookkeeping changed the digest, and published landing approvals were treated as quiet receipts.
→ Now: the approval survives when task, delivery SHA, target and landed tree still match, and published landings wake idle supervisors.

• *Release freeze scope* — Was: `lift_train_freeze` required factory-operate, which the pairing toggle could not grant.
→ Now: freeze and lift use machine-read pairing scope; revoked and preview credentials still cannot lift.

• *Commander history* — Was: an unanswered history request left a silent partial transcript, and one late reply could clear another page's timeout.
→ Now: each request tracks its own 15-second deadline, error and Retry; older-page cursors retry independently.

• *Operator delivery* — Was: an expiring transcript mirror copy with no receiving device produced no signal.
→ Now: the current supervisor is notified, including decisions carried in status replies; durable delivery keeps retrying.

• *Merging and publishing* — Was: the QA journey registry conflicted on every pair of additive deliveries, and `artifact publish` refused files in registered worktrees under `.cas`.
→ Now: a registered merge driver unions disjoint bug families and keeps the newer date, and nested registered checkouts publish while Git internals, sockets and credentials stay refused.

• *Boot diagnostics* — Was: a missing SessionStart canary lost the startup output with the pane.
→ Now: bounded, redacted boot output is retained and findable by worker or spawn request.

Validation: one release review of every delivery (one finding fixed before the cut), one batch QA round on the exact release candidate, and the merge queue on the final release tree.
Published archives: Linux x86_64 and macOS ARM64, available from <https://github.com/Richards-LLC/cassy/releases/tag/v4.11.0|the GitHub release>.
Linux x86_64 SHA-256: `{{LINUX_SHA256}}`
macOS ARM64 SHA-256: `{{MACOS_SHA256}}`
```
