# Slack draft — Cassy v4.13.0 runtime release

Channel: #cas-internal (`C0B44GUKDK2`).

Status: Prepared for review. Post only after the published-asset receipt.

## User thread

Top-level:

```text
*Live on production — User — Cassy v4.13.0*
Was: one bad message kept Commander stuck on "Reconnecting". → Now: it reports the error and stays connected.
```

Reply (Was → Now):

```text
*Steadier Commander, calmer updates*

• *Commander stays connected* — Was: if Commander failed while drawing one message from a machine, it dropped that machine's connection, got the same message again on reconnect, and showed "Reconnecting" in a loop.
→ Now: it reports the error and keeps the connection; the hub log also says why any connection closed.

• *One-row conversation headers* — Was: actions sat stacked above the name, and the live state was trailing "· Live" text.
→ Now: name and actions share one row, live state is a pill beside the project title, and phones get a compact header with an overflow menu.

• *Numbers type normally* — Was: digits, `#` and `*` in the reply box showed as wide emoji-style characters, so "4.13" looked odd.
→ Now: they use the normal font; emoji still show in colour.

• *Plain links open* — Was: a bare `https://` address in a message or work row was plain text.
→ Now: it opens in a new tab, and trailing punctuation stays outside the link.

• *Matching assistant mark* — Was: an empty conversation showed the machine's letter while the header showed the Claude mark.
→ Now: both show the same mark.

• *Tidier Accounts* — Was: removing an account used a browser pop-up, the default account offered Set default, and usage could show a reset time already past.
→ Now: removal confirms inside the card you clicked, the default shows only its badge, and a stale reset reads as unknown.

• *Easier on a phone* — Was: New session tabs and buttons were small, action sheets didn't say what they acted on, and Paired machines filters ran off the edge.
→ Now: full-size touch targets, sheets name their target, and filters wrap.

• *Task titles first* — Was: work cards and chips led with an ID.
→ Now: they lead with the task title and show each session's name.

• *Hub stays the way you left it* — Was: `cas update` restarted a hub you had stopped, and `cas hub restart` with a bad address stopped the hub before refusing.
→ Now: a stopped hub stays stopped, and a bad address is refused while the hub keeps running.

• *Updates don't hang* — Was: an automatic update could hang for hours on a stuck release notice.
→ Now: notices are time-bounded and newer versions install first.

Update with `cas update`, or choose <https://github.com/Richards-LLC/cassy/releases/tag/v4.13.0|the Linux x86_64 or macOS ARM64 downloads>.
```

## Dev thread

Top-level:

```text
*Live on production — Dev — Cassy v4.13.0*
Was: a frame error tore down the machine socket and replayed forever. → Now: the hub keeps the socket and logs every close reason.
```

Reply (Was → Now):

```text
• *Violet message contract* — Was: posts had no request identity, so an uncertain write after a transport close needed a session restart.
→ Now: Cassy sends request IDs and reconciles by them only when the connected hub advertises both; older hubs get unchanged posts, and reconnect never resends an uncertain write.

• *Verification and merges* — Was: a stale peer approval blocked a repaired delivery, and merge conflicts surfaced as an unnamed pre-merge failure.
→ Now: a fresh exact-delivery approval from the same source replaces the stale one (both kept), and conflicts report CONTENT CONFLICT with paths and return to the assigned worker.

• *CI watchdog and train reruns* — Was: the queued-run watchdog aged reruns from the first attempt and cancelled them, and rerunning failed Rust shards dropped earlier green shards.
→ Now: each attempt ages from its own start, earlier green shards are kept, and a red run with no receipt holds merges explicitly.

• *Factory liveness* — Was: refused closes paged as stalls, quiet child processes looked idle, and an intentional early shutdown read as a boot failure.
→ Now: the refusal code and next action show without a page, child CPU and log writes count as progress, and deliberate shutdowns record as stopped.

• *Supervisor identity and inboxes* — Was: a new harness session could register a second supervisor identity, and drained inboxes kept waking.
→ Now: the session rebinds to its live supervisor, and read or acknowledged notifications stop waking.

• *Cloud sync* — Was: mutation timeouts had no correlation ID, and personal backlog after team linking was invisible and stranded.
→ Now: mutations carry `X-Cassy-Attempt-Id` across retries, status shows the personal backlog, linked projects recover eligible personal copies, and retained dependency failures retry by ID.

• *Workers* — Was: workers could not ask for a fresh context, handoff notes could ride into deliveries, and supervisor notes were lost when a worker started from an old snapshot.
→ Now: a typed respawn request recycles with recipe and bindings kept, handoff files are refused at park, and supervisor notes survive the start.

• *Memory and release reports* — Was: editing memory tags could restamp another machine's handoff, and generated release reports failed their own quality check.
→ Now: handoff provenance is retained, and reports pass the gate without a hand edit.

• *QA ledgers* — Was: re-running ledger init on a resumed task failed with "File exists".
→ Now: it keeps the existing ledger byte for byte and refuses only one that doesn't validate.

Close-at-release is not in this release; it ships whole in v4.14.0.
One Commander reading-position journey is quarantined on the CI Linux runner (a 17px jump at reconnect that does not reproduce elsewhere); the fix is tracked for the next release.
Validation: one release review of all 67 deliveries, one batch QA round on the exact release candidate, and the merge queue on the final release tree.
```
