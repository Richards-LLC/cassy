# Slack draft — Cassy v4.16.0 runtime release

Status: Prepared for review. Post only after the published-asset receipt.

## User thread

Top-level:

```text
*Live on production — User — Cassy v4.16.0*
Was: a release could ship 40 fixes and close none of them. → Now: every shipped task with an approval closes on its own.
```

Reply (Was → Now):

```text
*Releases that actually finish their work*

• *Shipped work closes* — Was: one release-wide check held every task, so the last two releases closed 0 of 58 and 0 of 40.
→ Now: each shipped task closes on its own approval; a task with no review stays open and is listed by name.

• *A cut that would close nothing is refused* — Was: you found out after publishing that nothing closed.
→ Now: before anything is pushed, the cut previews what will close and refuses if the answer is zero.

• *Updates close out with the new version* — Was: the old binary did the cleanup for the new release, so the release's own fixes never applied to it.
→ Now: the new version installs first, then cleans up; an older cleanup is replayed once by a newer version.

• *Train checks finish* — Was: every merge cancelled the train's running check, so a full check almost never completed.
→ Now: the running check finishes and only the newest waiting push runs after it.

• *Fewer stuck moments* — Was: Commander replies could stick at "selected", a release notice retried forever, and after a reboot, unfinished work couldn't be picked back up.
→ Now: replies recover after a disconnect, notices stop after ten tries, and unfinished work resumes after a reboot.
```

## Dev thread

Top-level:

```text
*Live on production — Dev — Cassy v4.16.0*
Was: one whole-release check held every member. → Now: each approved member in the published ancestry closes.
```

Reply (Was → Now):

```text
• *Per-member close* — Was: duplicate whole-release gates refused the release when any member lacked proof, and approvals bound by peer pre-merge attestations were ignored (head_commit only).
→ Now: one evaluator closes each member whose recorded approval binds an anchor in the published ancestry; REVIEW_MISSING members stay open as named residuals; source_sha/anchor_commits attestations count.

• *Cut preview* — Was: no closeout signal before publishing.
→ Now: `scripts/release.sh` runs `cas release preview` on the exact Linux prebuild (or one candidate) before push, refuses members > 0 with would_close == 0, records per-reason counts and build seconds in the cut receipt; standalone hotfixes with no members skip it.

• *Reconciler version* — Was: a pre-install binary reconciled the new release.
→ Now: install verifies the new binary before closeout, receipts stamp the reconciling version, and an older stamp is replayed once.

• *Release batch receipts* — Was: `batch_receipt verification_type=release` required the published SHA inside each member's historical epic ref.
→ Now: it checks each member's delivery ancestry against the published SHA.

• *Train CI* — Was: `cancel-in-progress` on train refs cancelled every in-flight run; apt installs of gcc/mold and Playwright `--with-deps` made every hosted train run depend on Ubuntu mirrors (seven runs red during today's Canonical DNS outage).
→ Now: train refs keep one running and one pending run; one shared linker step skips apt when tools are present and fetches checksum-pinned mold 2.40.4 from GitHub otherwise; Playwright installs system packages only when `ldd` finds a missing library.

• *Factory* — Was: transfers after a reboot refused "no prior assignee", recycle kept the old lease, `bash script.sh > log` was refused as a nested shell, filing a task to the supervisor ran worker freshness checks, worktree_merge could time out opening a verifier.
→ Now: each of those paths works.

Validation: the merge queue proves the final release tree.
```
