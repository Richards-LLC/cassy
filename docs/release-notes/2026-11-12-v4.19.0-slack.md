# Slack draft — Cassy v4.19.0 runtime release

Channel: #cas-internal (`C0B44GUKDK2`).

Status: Prepared for review. Post only after the published-asset receipt.

## User thread

Top-level:

```text
*Live on production — User — Cassy v4.19.0*
Was: task updates could take minutes to reach your other machine. → Now: they sync on their own steady schedule.
```

Reply (Was → Now):

```text
*Two machines, one picture*

• *Updates arrive on time* — Was: long background chores on one machine could hold back task updates for the other.
→ Now: task updates sync on their own schedule, and a machine already syncing skips extra cloud calls.

• *Merges no longer stall on a busy build* — Was: two submissions for the same delivery could leave one waiting with nothing to show.
→ Now: they share one build, and a slow build gives a clear "still building" answer and a notice when it is ready.

• *Clearer update blockers* — Was: a refused update did not say which job was in the way.
→ Now: it names the blocking jobs and explains the safe way to recover.

• *Release reports post even without a message link* — Was: a report upload could fail when Slack returned no link for the message.
→ Now: the upload is recorded and the missing link is marked unavailable.

• *Release cuts work from any checkout* — Was: cutting a release from a separate working copy could treat this project's own work as foreign and refuse.
→ Now: the working copy inherits the project's identity and the cut sees its own work.

• *Fixes resume cleanly* — Was: a returned fix that carried already-released work could not restart.
→ Now: it restarts, while unreleased work from elsewhere is still refused.
```

## Dev thread

Top-level:

```text
*Live on production — Dev — Cassy v4.19.0*
Was: entity sync waited behind indexing and telemetry. → Now: it runs on its own timer and checks the lease before cloud calls.
```

Reply (Was → Now):

```text
• *Entity sync* — Was: the daemon awaited full sync in the same select as index and maintenance work, and held a store-wide lease through quality-event batches.
→ Now: entity pull has an independent timer; knowledge and quality serialize their own cursors; background sync takes the store lease before discovery and registration.

• *Pre-merge candidates* — Was: candidate preparation ran inline against a 55 s budget, and a duplicate concurrent receipt got an immediate Pending(None).
→ Now: one coalesced background build with a 20 s response wait; same-key receipts share the in-flight result.

• *Reexec* — Was: a refused in-place update hid which work blocked it.
→ Now: daemon and app guards share one named-blocker diagnostic (worker, occurrence, elapsed, job kind) pointing to a full factory restart.

• *Resume guard* — Was: resuming a release-sync lane refused commits imported from a released tag.
→ Now: commits reachable from origin's trunk are excluded before attribution; local tags grant nothing.

• *Linked-worktree identity* — Was: repo_identities read only <checkout>/.cas, so a .cas-free linked worktree held release members as ForeignScope (GH #1827).
→ Now: it falls back to the main worktree's pin via the git common dir; an explicit local pin still wins, and empty-checkpoint attribution still needs a local pin.

• *Merge-source grants* — Was: a grant on a blocked first-park task failed on the syncing store.
→ Now: it uses the store's guarded update.

• *Receipts and relays* — Was: capped runs mixed guard output into the selected test log, and late lifecycle relays showed queue age.
→ Now: the selected run has its own log path in the receipt, and relays report age from the original transition.

• *Release tooling* — Was: the version-literals fast row flagged fictional versions in skill exemplars, and report posts failed on a null message permalink.
→ Now: exemplars are excluded, and a null PDF message permalink is recorded as unavailable while the file permalink stays required.
```
