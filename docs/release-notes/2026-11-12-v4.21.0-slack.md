# Slack draft — Cassy v4.21.0 runtime release

Status: Prepared for review. Post only after the published-asset receipt.

## User thread

Top-level:

```text
*Live on production — User — Cassy v4.21.0*
Was: nobody graded how releases went. → Now: the ledger report scores each release and shows its evidence.
```

Reply (Was → Now):

```text
*Releases you can measure, checks you can trust*

• *Release scorecards* — Was: the ledger report listed reviews, verdicts and notices, and nobody graded them.
→ Now: it scores five rubrics per release, cites the evidence for each score, and tracks how long a release sat ready without being cut.

• *Pushes test what they touch* — Was: a push proved only the tests its author chose to name.
→ Now: CI runs the delivery's own tests first, then the tests around it, and says whether a failure was caused by the change or was already there.

• *One identity per delivery* — Was: moving work between trains could drop its approval or attach it to the wrong cycle.
→ Now: every delivery records its cycle, approvals stay attached across moves, and one project resolver serves every check.

• *Fewer repeated checks* — Was: a merge asked GitHub about its target up to four times, and some checks ran again at park.
→ Now: one read per merge, and each check runs once, in CI.

• *Clearer refusals* — Was: many refusals were free text.
→ Now: every check has a stable code, and refusals name the fix.

Update with `cas update`, or choose <https://github.com/Richards-LLC/cassy/releases/tag/v4.21.0|the Linux x86_64 or macOS ARM64 downloads>.
```

## Dev thread

Top-level:

```text
*Live on production — Dev — Cassy v4.21.0*
Was: deliveries proved only worker-named tests. → Now: lane CI runs the impact set, own tests first, and attributes failures to the delivery or its base.
```

Reply (Was → Now):

```text
• *Lane impact tests* — Was: a factory push proved only named tests.
→ Now: lane CI selects the impact set from the recorded start base, runs own tests then the ring, and keeps the lane red unless every unsuccessful outcome (FAIL, TIMEOUT, signals, LEAK-FAIL) is inherited from the base.

• *Scorers* — Was: the ledger report had no grading.
→ Now: `cas ledger report` scores review rounds, verdict provenance, interventions and release-held time, with cited hits; the friction ledger counts review rounds by cycle and wakes by notice kind.

• *Delivery identity* — Was: target moves invalidated approvals, and parks recorded no cycle.
→ Now: approvals carry their cycle and registry version, every park records its cycle, rebinds are counted once, and selector stamping shares the repo-identity resolver, including linked worktrees without local config.

• *Release inputs* — Was: release proof was assembled by hand.
→ Now: cuts derive inputs and report proof from recorded external references; previews can replay a relocated store outside Git.

• *Gate registry* — Was: refusals were free text.
→ Now: each factory check has a stable code; uncoded caller-authority refusals are ratcheted; test-shape lint accepts registered gate tokens and recorded CLI arguments.

• *Merge path* — Was: up to 4 origin reads per merge and test-shape lint at park.
→ Now: one fetch under the target lock, and lint runs only in CI.

• *Release close* — Was: a cycle-less no-code report delivery could not be approved after cycle tracking.
→ Now: it closes at release again.

• *Worker guidance* — Was: a refused checkout or a follow-up task's foreign-named commit had no remedy.
→ Now: refusals name the checkout fix, and a follow-up lane can adopt the named commit.

Validation: the merge queue proves the final release tree.
```
