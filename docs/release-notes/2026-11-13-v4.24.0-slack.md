# Slack draft — Cassy v4.24.0 runtime release

Channel: #cas-internal (`C0B44GUKDK2`).

Status: Prepared for review. Post only after the published-asset receipt.

## User thread

Top-level:

```text
*Live on production — User — Cassy v4.24.0*
Was: every merge restarted the full test suite and Commander dropped commands sent while the supervisor was busy. → Now: the suite runs once per release, and Commander shows the supervisor working and holds your commands.
```

Reply (Was → Now):

```text
*Faster releases, a calmer Commander*

• *One full test run per release* — Was: each merge into a release started the whole test suite and cancelled the one already running. → Now: it runs once, when the release is frozen, and that run is what ships.

• *No extra run on the release commit* — Was: the release commit triggered the full suite again. → Now: the release reuses the run it already passed.

• *Commands wait their turn* — Was: a command such as /mcp sent from Commander mid-reply showed "Not sent". → Now: it shows Queued and runs as soon as the reply ends.

• *See when the supervisor is working* — Was: Commander gave no reliable sign that the supervisor was busy. → Now: it shows busy or idle, the current step, how long the turn has run and the last activity.

• *Replies stop stalling* — Was: correct supervisor replies were held back and retried. → Now: they go through when every fact matches what was checked.

• *Flaky and wording-only tests are found* — Was: no tool listed tests that rely on timing guesses or pin exact text. → Now: the test audit lists them with their history, so they can be fixed or removed.

• *Moving work to the next release is one step* — Was: moving parked work to the next release left it stuck under the old one. → Now: it moves in one update.

Update with `cas update`, or choose <https://github.com/Richards-LLC/cassy/releases/tag/v4.24.0|the Linux x86_64 or macOS ARM64 downloads>.
```

## Dev thread

Top-level:

```text
*Live on production — Dev — Cassy v4.24.0*
Was: the full train suite ran on every train push and again on the release commit. → Now: one workflow_dispatch run at the frozen tip is the cut's only full-suite receipt.
```

Reply (Was → Now):

```text
• *Freeze-only train suite* — Was: full-validation.yml ran on every release-train push with a cancel-in-progress group. → Now: no push trigger; freezing dispatches one run at the frozen tip, release.sh consumes its green receipt and a red raises train_ci_red.

• *Release-commit push skips train CI* — Was: the prepared release push started a train workflow. → Now: it starts none; cut retries resolve the source proof through Train-CI-Head. Admission, merge-queue validation and Release Prebuild are unchanged.

• *Commander slash-command queue* — Was: a slash command during an open native turn was refused after three tries. → Now: it is queued durably and typed once at the turn boundary; drafts and open dialogs still refuse.

• *Live supervisor activity* — Was: busy/idle was inferred loosely. → Now: native turn boundaries drive it; stale status (over fifteen seconds) or a stopped daemon shows unknown.

• *Stop-hook evidence* — Was: operator-claim evidence required tool-use IDs that Claude Code never shows. → Now: numbers and SHAs match successful same-turn results directly.

• *cas-test-audit* — Was: no audit covered flake-prone patterns. → Now: Rust and JS/Playwright detectors for timing guesses, teardown and port races, shared state, order and unseeded randomness, plus bounded thirty-day CI/issue history.

• *Retarget moves the parent* — Was: setting a parked task's target to the next train left its parent on the frozen train (G-06 on re-park). → Now: the same update moves the parent epic.
```
