## User thread

Top-level:

```text
*Live on production — User — Cassy v4.30.0*
Was: approved work landing over newer work was held for review again. → Now: it keeps its approval.
```

Reply (Was → Now):

```text
*Fewer stuck merges and reruns*

• *Approved work stays approved* — Was: a queue landing over newer train work held the merge with an empty error. → Now: reconciliation keeps the approval; a real change to the same files is still refused.

• *Moving work between trains* — Was: unfinished work moved to a new train could keep pointing at the old one. → Now: unchanged work follows the move with an audit, and changed work asks you first.

• *Restarted sessions keep their history* — Was: a replacement session's close could drop the earlier session's changes and release note. → Now: both are kept.

• *Releases ship again* — Was: a release could refuse to ship because it wrongly counted already-shipped work as reverted. → Now: each delivery is judged by its own changes, so finished work ships and truly reverted work is still held.

• *Journey runs clean up after themselves* — Was: a cancelled journey run left its server holding the port, so the next run failed. → Now: the server exits with its runner.
```

## Dev thread

Top-level:

```text
*Live on production — Dev — Cassy v4.30.0*
Was: reconcile after a queue landing failed with an empty merge-base error. → Now: it keeps the approval.
```

Reply (Was → Now):

```text
• *Release revert judgement* — Was: closeout judged shipped members per commit, so a self-restored path read as reverted and the cut refused. → Now: own-only paths are judged by net range; a main-reverted delivery re-merged by a train sync stays reverted.

• *Queue-landing reconcile* — Was: a landing over newer target work re-held the delivery for review with an empty merge-base error. → Now: the approval is kept; a target edit to delivered files is still refused.

• *Epic retarget* — Was: retargeting left no-delivery lanes' recorded start on the old train. → Now: unchanged lanes rebind with an audit; changed or mismatched sources need explicit supervisor recovery.

• *Adopted deliveries* — Was: closing a replacement worker's delivery lost a predecessor imported by merge. → Now: its source changes and release note stay in the proof scope after a restart.

• *ci_completed workflow names* — Was: a name shared by several workflows, such as "CI", was refused as ambiguous. → Now: it binds to the workflow that ran for the commit, or the refusal lists each candidate's path and ID.

• *Lane impact attribution* — Was: a one-off failure at the delivery was blamed on it. → Now: it reruns once; only a repeat is attributed. Both still fail the lane.

• *Shared journey stability* — Was: journeys built from a shared callback could not declare their runtime identities. → Now: they can; the capped check validates them against native discovery before five retry-free passes.

• *Journey server* — Was: a killed Playwright runner left the snapshot server listening (EADDRINUSE). → Now: the server exits with its runner.

• *CI bubblewrap* — Was: every Linux job installed bubblewrap through the shared Rust setup. → Now: only jobs that run verifier sandbox tests install it, once.

• *Journey timing* — Was: HUB-J9, HUB-J22 and the machine-socket and launch-sheet journeys could act before the session socket or accounts were ready. → Now: they wait for the observed state.

Validation: the frozen train ran its full suite once, and the merge queue proves the final release tree.
```
