# Slack draft — Cassy v4.33.0 runtime release

Channel: #cas-internal (`C0B44GUKDK2`).

Status: Prepared for review. Post only after the published-asset receipt.

## User thread

Top-level:

```text
*Live on production — User — Cassy v4.33.0*
Was: merges and reviews often stalled until someone stepped in. → Now: twenty fixes keep them moving on their own, plus a credential-guard security fix.
```

Reply (Was → Now):

```text
*Smoother merges, safer guard, fewer stuck tests*

• *Credential guard* — Was: two kinds of shell command could read a protected credential file by changing folder first. → Now: each command is checked against the folder it actually runs in, with no new blocks on everyday work.

• *Merges keep moving* — Was: one stale delivery on a cancelled train could freeze every merge, and train merges never started their reviewer. → Now: the stale delivery is skipped and the reviewer starts by itself.

• *Reviewers start reliably* — Was: a busy database or a Codex reviewer's settings could stop a review before it began, with a misleading error. → Now: the real cause is named and the reviewer can reach Cassy.

• *Two machines agree* — Was: an approval or a session's handoff on one machine could be missing or wrong on the other. → Now: approvals count on both machines, and each session starts with its own task, not someone else's notes.

• *Test checks that fit the work* — Was: JavaScript and node:test checks ran from the wrong folder or refused to run, and a lost CI runner just said "cancelled". → Now: they run from the right config, and a lost runner is reported by name.

• *Commander* — Was: scrolling up could fail to load older history, and Undo could lose focus on a phone. → Now: both work.

• *Accounting reports* — Was: journal entries were loosely formatted. → Now: balanced grids with real account names and numbers, checked before they render.
```

## Dev thread

Top-level:

```text
*Live on production — Dev — Cassy v4.33.0*
Was: train merges, verifier launch and cross-machine proof could stall. → Now: all three resume on their own.
```

Reply (Was → Now):

```text
• *Credential guard (GH1961)* — Was: two cwd classes allowed a credential read. → Now: per-statement effective cwd. Paired replay of 97,765 commands vs v4.32.0: 242/242 must-deny rows still deny, 0 deny→allow; an argument-substitution fail-open found in review was fixed before merge.

• *Train merge* — Was: one parked task on a deleted train branch aborted `resume_pending` on every pass, and resume ran without a daemon so verifiers never auto-launched. → Now: unfetchable targets are skipped and reported; Pending dispatches launch during resume.

• *Verifier launch* — Was: store contention read as "live registered supervisor required", and Codex verifiers were refused MCP under `approval: never`. → Now: `verifier_factory_store_busy` retries, and the cas MCP server is pre-approved for Codex verifiers.

• *Verifier handoff* — Was: dispatches created by a retired supervisor could not launch after handoff. → Now: the successor adopts and launches them.

• *Cross-machine* — Was: pre-merge approvals were machine-local (REVIEW_MISSING on the other machine's cut) and worker SessionStart injected the role-wide handoff. → Now: approvals travel with the task, and worker startup omits other workers' handoffs.

• *Stability proof* — Was: supervisors could not record a peer machine's 5-pass run, and node:test files could not supply stability proof. → Now: `record_test_receipt repeat_log_paths` and `worker-check -- node --test`.

• *JS runner root* — Was: the capped runner started at the nearest package manifest. → Now: it runs from the Jest, Vitest or Playwright config root.

• *Delivery identity* — Was: recorded cycle anchors could read as foreign commits at start, close and rebind. → Now: they count as the task's own; unrecorded foreign work is still refused.

• *Lane CI* — Was: an empty base ref broke first-push attribution, and a hung hosted runner surfaced as "cancelled" after 55 min. → Now: first pushes attribute correctly, and a dependent job reports the lost run with its plan and budget.

• *Cloud sync* — Was: task/memory pushes could fall back to timestamp writes after a rejected base. → Now: guarded revisions are kept until reconciliation.

• *Instructions* — Was: builtin instructions recommended commands that no longer exist. → Now: the sweep removes stale commands and duplicate rules.

Validation: each delivery passed its independent pre-merge review, and supervisor test runs covered every CI/test-runner change. The frozen train ran its full suite once, a batch QA walk covered the Commander and instruction changes, and the merge queue proves the release tree.
Published archives: Linux x86_64 and macOS ARM64, available from <https://github.com/Richards-LLC/cassy/releases/tag/v4.33.0|the GitHub release>.
```
