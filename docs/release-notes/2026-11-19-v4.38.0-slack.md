# Slack draft — Cassy v4.38.0 runtime release

Channel: #cas-internal (`C0B44GUKDK2`).

Status: Prepared for review. Post only after the published-asset receipt.

## User thread

Top-level:

```text
*Live on production — User — Cassy v4.38.0*
Was: finished work waited minutes to be checked. → Now: checks take seconds and releases close out cleanly.
```

Reply (Was → Now):

```text
*Faster hand-offs, cleaner releases, fewer false alarms*

• *Finished work is checked in seconds* — Was: handing in a large piece of work could take up to twenty minutes before Cassy finished checking it, and sometimes looked lost. → Now: the same check takes well under a minute, and its result is always recorded, even if a program crashes mid-way.

• *Reviews start when they should* — Was: on a busy machine, the automatic reviewer could wait so long for its turn that it gave up. → Now: it no longer waits behind other work, and when something does hold it up, Cassy says exactly what.

• *Releases finish the job* — Was: closing a release could time out and leave issues open, or wrongly hold back work that a later change had replaced. → Now: issues close with retries, replaced work closes once it is reviewed, and a slow step says how long it took and why.

• *Fewer false alarms* — Was: Cassy sometimes warned about a page at night for work that was waiting on the operator, or said a message never arrived when it had. → Now: work waiting on the operator goes to the morning summary, and delivered messages stay delivered.

• *Clearer answers* — Was: a session could say "merged" or "green" without checking. → Now: those words need real proof in the same turn. Hub status also now says why remote access failed.

• *Tests that test behaviour* — Was: hundreds of tests checked exact wording. → Now: they check what the product does, so wording can change without breaking them.

• *Also* — a stalled check on macOS is fixed, tests share one rule for timing, and file-name searches inside compound commands are no longer blocked.

Update with `cas update`, or choose <https://github.com/Richards-LLC/cassy/releases/tag/v4.38.0|the Linux x86_64 or macOS ARM64 downloads>.
Linux x86_64 SHA-256: `{{LINUX_SHA256}}`
macOS ARM64 SHA-256: `{{MACOS_SHA256}}`
```

## Dev thread

Top-level:

```text
*Live on production — Dev — Cassy v4.38.0*
Was: 16–20 min close gates and starved verifier launches. → Now: request-scoped inventory, launch off the input loop, durable close outcomes.
```

Reply (Was → Now):

```text
• *Close-gate discovery* — Was: changed-test discovery rebuilt a full Rust inventory per changed file (42 builds, 513 s on one delivery). → Now: one inventory per close request and compiled patterns once (5 builds, about 25 s), same tests selected.

• *Durable close outcomes* — Was: a close past the 55 s MCP budget could lose its CLOSE_OUTCOME if the watcher was cancelled. → Now: backend retirement waits for the outcome; lost continuations record a failure and wake the supervisor.

• *Verifier launch* — Was: LaunchVerifier ran on the GUI client-input path under a 50 ms store budget and starved for 765 s. → Now: it runs on the external job lane; holders name operation and site.

• *Launch retries* — Was: dropped daemon launches spent attempts and a handoff mismatch read as a parse error. → Now: drops count as contention, and VerifierHandoffNotActive is typed and permanent.

• *Release closeout* — Was: one 6 s deadline for every gh issue close, and superseded lines held as RELEASE_MEMBER_REVERTED. → Now: bounded parallel closes with next-pass recovery, and reviewed drops accepted at closeout and tag time.

• *Installer notices* — Was: an adapter killed at its deadline logged only "pending". → Now: the log names the phase and the deadline.

• *Completion claims* — Was: "merged" or "green" matched any successful tool result. → Now: H-47 needs ancestry, CI or task proof from the same turn.

• *Guards* — Was: operator holds paged at night, and Python source edits naming credentials were denied. → Now: holds route to the morning summary; the H-09 literal case is allowed and real reads stay denied.

• *CI* — Was: the journey-catalog row failed on a spent anonymous GitHub API quota, and pre-push refusals had no log path. → Now: the installer uses the token or the releases redirect and prints HTTP status; refusals name rows and log paths.

• *Board and delivery* — Was: an epic targeting main read as shipped before its branch reached main; the watchdog re-sent delivered notices as UNDELIVERED. → Now: shipping is judged from the delivery branch; resumed blockers stay resolved.

• *Also* — wave 2 of the wording-pin sweep finished, the macOS step watchdog walks the process table portably, prebuild fallbacks run per platform, the agent-doc budget check is pinned, a reviewed replacement verifier can claim a never-started dispatch, and recycled workers start their kept task.
```
