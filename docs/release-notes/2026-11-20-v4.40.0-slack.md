# Slack draft — Cassy v4.40.0 runtime release

Channel: #cas-internal (`C0B44GUKDK2`).

Status: Prepared for review. Post only after the published-asset receipt.

## User thread

Top-level:

```text
*Live on production — User — Cassy v4.40.0*
Was: an update could leave helpers deaf to every message. → Now: helpers keep hearing you through an update, and one machine runs the whole release.
```

Reply (Was → Now):

```text
*Helpers that stay reachable, and one owner for each release*

• *Messages get through after an update* — Was: once Cassy updated itself, Codex helpers stopped receiving messages, even urgent ones, until someone restarted them by hand. → Now: helpers that were already running keep getting their messages; only a helper that just started waits for its tools.

• *Restarting a helper keeps its work* — Was: a helper with saved but unshared work could not be restarted, so the only way out was a forced stop. → Now: the restart goes ahead and keeps its branch and saved work.

• *One machine owns the release* — Was: two machines each ran the release and passed approvals back and forth for every merge. → Now: the second machine just runs helpers, and the owning machine reviews, merges and closes everything.

• *Standby in Commander* — Was: a paused session looked the same as a live one. → Now: Commander shows a Standby badge, and one Resume button brings the session and its helpers back.

• *Focus follows the release* — Was: after a release or a handoff, the board could lose track of which release you were working on. → Now: focus stays on the active release and moves to the next one when a release ships.

• *Busy helpers don't look idle* — Was: a helper running a long build or test looked idle, so it got interrupted for nothing. → Now: it shows as working until its build finishes.

• *Also* — merges catch duplicate check IDs before they land, carried work keeps its correct starting point, failures inherited from earlier code no longer block new work, and restarts wait for a helper's own build.

Update with `cas update`, or choose <https://github.com/Richards-LLC/cassy/releases/tag/v4.40.0|the Linux x86_64 or macOS ARM64 downloads>.
Linux x86_64 SHA-256: `{{LINUX_SHA256}}`
macOS ARM64 SHA-256: `{{MACOS_SHA256}}`
```

## Dev thread

Top-level:

```text
*Live on production — Dev — Cassy v4.40.0*
Was: live-exec left Codex workers held forever; peer supervisors relayed merge authority. → Now: Codex wakes survive live-exec; a single train owner with --worker-host peers.
```

Reply (Was → Now):

```text
• *Codex wake after live-exec* — Was: after a daemon live-exec, tools_listed was false with no record, so every running Codex worker's messages sat held as "tools not listed yet". → Now: spawn and recycle write an explicit awaiting record and the gate holds only on it (GH #2185).

• *Wake receipts* — Was: a pane write to a Codex worker recorded nudge_not_attempted. → Now: a completed pane write records nudge_fired.

• *Recycle with local commits* — Was: recycle_worker and clear_context refused a clean worktree with unpushed commits. → Now: recycle proceeds and keeps the worktree, branch and commits; uncommitted files still refuse.

• *Single train owner* — Was: peer supervisors relayed approvals, merge intents and verdicts across machines. → Now: `cas factory --worker-host <train>` runs workers under the owner, which alone verifies, merges, waives QA and closes.

• *Remote admission* — Was: peer approval relays granted authority. → Now: portable artifact and test-receipt claims are checked before remote admission; receiver-side expired-claim protection stays.

• *Focus pin* — Was: a published-but-close-held merge returned before focus recovery, and a peer's focus_epic could take the owner's Cloud claim. → Now: merges and retargets restore the pin, the cut moves it to the successor, and peer pins stay local (GH #2173, #2174).

• *Liveness* — Was: a finished turn read as waiting_for_input while the worker's own child build advanced. → Now: an advancing owned child reads as executing.

• *Merge safety* — Was: an automatic CI-retry merge could land a duplicate gate ID on a moved train tip. → Now: manual and CI-retry merges check the combined registry and refuse with G-160 (GH #2167).

• *Carry-over and web proof* — Was: inherited files could read as dropped (G-56), and base-identical web failures blocked park. → Now: carry-overs prove their own diff, and identical base failures are attributed instead.

• *Also* — recycle waits on the worker's own build lease (GH #2176); repair spawns accept class_audit; worker-check --cas-root drops the CAS_ROOT notice (GH #1918); flaky HUB-J25 390-dark case deleted.
```
