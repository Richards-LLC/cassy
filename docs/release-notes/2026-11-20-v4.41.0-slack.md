# Slack draft — Cassy v4.41.0 runtime release

Channel: #cas-internal (`C0B44GUKDK2`).

Status: Prepared for review. Post only after the published-asset receipt.

## User thread

Top-level:

```text
*Live on production — User — Cassy v4.41.0*
Was: Commander went gray, sends failed and GitHub ran dry. → Now: conversations stay Live, sends arrive, GitHub stays in budget.
```

Reply (Was → Now):

```text
*Steadier Commander and a quieter GitHub footprint*

• *Conversations stay Live* — Was: every conversation could turn gray "Last known" while the footer said Connected, and rows flipped between Live and not Live. → Now: rows, machine chips and sends follow one rule, so a conversation that still answers reads Live.

• *Messages to a busy machine get through* — Was: a send could fail with "couldn't take the message" when the other machine was busy. → Now: it waits and goes out in order. In a 30-minute check, 50 of 50 test sends arrived first try.

• *GitHub stays in budget* — Was: finished work in projects without a "CI" workflow checked GitHub every 30 seconds forever and used up the hourly limit. → Now: Cassy checks only work that hasn't landed. About 2,900 calls an hour dropped to 0.

• *Cancelled CI re-runs itself* — Was: when a CI job hit its time limit, the automatic merge just stopped. → Now: Cassy re-runs it once and merges when it turns green.

• *One /finish* — Was: /finish showed twice in the command list and an old copy sat beside it. → Now: Cassy ships one shorter /finish in every coding tool and removes the old copy.

Update with `cas update`, or choose <https://github.com/Richards-LLC/cassy/releases/tag/v4.41.0|the Linux x86_64 or macOS ARM64 downloads>.
```

## Dev thread

Top-level:

```text
*Live on production — Dev — Cassy v4.41.0*
Was: hardcoded "CI" delivery watches drained REST, event-stream state split Commander's reachability. → Now: defined, unlanded workflows only; one reachability rule plus contention retry.
```

Reply (Was → Now):

```text
• *Delivery CI watches* — Was: `arm_task` armed `ci_completed` for workflow "CI" on every parked delivery (ttl 0, 30 s cadence), re-armed even after landing. → Now: none for a contained commit or an undefined workflow; `runs_for_sha` ~2,900/h → 0/h.

• *Rate-limit filing* — Was: `report_cas_bug` under backoff blamed the credential. → Now: it names the backoff.

• *Commander reachability* — Was: rows, chips and `sessionIsUp` read the raw event-stream phase while the footer and header counted a responding attach, so recoveries painted everything "Last known" and held sends expired. → Now: one rule; the footer's state can lift a row but never lower it.

• *Send under store contention* — Was: a WebSocket send that lost the 2 s store grant was refused for good. → Now: it is deferred and retried in order through the real enqueue path.

• *Cancelled lane runs* — Was: a run that hit lane.yml's 45-minute job timeout read as cancelled and the armed merge stopped. → Now: one `actions/runs/<id>/rerun`; the intent survives while only the original cancellation is visible, and a cancelled rerun stops with one notice.

• *finish* — Was: the user-level and project skill copies both appeared in pickers, and the legacy seed (hash eeeede16) remained in Codex, OpenCode and Grok. → Now: user-level only, the project copy is pruned on sync, the exact legacy seed is removed, and edited copies and exclusions are honoured.
```
