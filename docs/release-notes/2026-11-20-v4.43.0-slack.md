# Slack draft — Cassy v4.43.0 runtime release

Channel: #cas-internal (`C0B44GUKDK2`).

Status: Prepared for review. Post only after the published-asset receipt.

## User thread

Top-level:

```text
*Live on production — User — Cassy v4.43.0*
Was: Cassy's database grew without limit and slowed every write. → Now: old records are cleaned up and opening tasks is instant.
```

Reply (Was → Now):

```text
*Smaller databases, faster writes*

• *Conflict log stays small* — Was: every sync conflict kept another full copy forever; one project reached 22 GB. → Now: each task keeps its ten most recent copies.

• *Old records are cleaned up* — Was: ended sessions and delivered messages were kept forever. → Now: the regular cleanup removes them once nothing needs them; pending ones are always kept.

• *Opening tasks is fast* — Was: each time Cassy opened its task list it read every task in full, up to 2 seconds while everything else waited. → Now: a few milliseconds.

• *Reviews close cleanly* — Was: a manual review on another machine could attach to the wrong commit, so the task could never close. → Now: it attaches to the task's own work.

• *Slow writes are named* — Was: when writes waited minutes, nothing said what held them up. → Now: anything holding the writer over a second is logged by name.

Update with `cas update`, or choose <https://github.com/Richards-LLC/cassy/releases/tag/v4.43.0|the Linux x86_64 or macOS ARM64 downloads>.
Linux x86_64 SHA-256: `{{LINUX_SHA256}}`
macOS ARM64 SHA-256: `{{MACOS_SHA256}}`
```

## Dev thread

Top-level:

```text
*Live on production — Dev — Cassy v4.43.0*
Was: unbounded sync_conflicts, per-open TaskStore::init full scans, verdicts bound to the caller's HEAD. → Now: retention, cached init, delivery-bound verdicts.
```

Reply (Was → Now):

```text
• *Retention* — Was: `sync_conflicts`, `agent_session_ends` and the operator delivery outbox grew without bound. → Now: 10 conflict rows per entity plus the newest per strategy; superseded session ends and completed outbox rows pruned by the retention pass.

• *TaskStore::init* — Was: DDL plus a delivery-cycle check filtering `status` row by row on every uncached open (141 ms warm, 1.8 s cold on a large store). → Now: DDL once per (file, schema_version); the check uses `idx_tasks_status` (4-7 ms).

• *StoreWorker WARN* — Was: writer holders were invisible. → Now: jobs holding the writer 1 s or longer log label, elapsed_ms and queue depth.

• *Supervisor-direct verdicts* — Was: `verification action=add` bound the supervisor's checkout HEAD, so G-65 refused close. → Now: it binds the dispatch's delivery head.
```
