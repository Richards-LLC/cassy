# Slack draft — Cassy v4.45.0 runtime release

Channel: #cas-internal (`C0B44GUKDK2`).

Status: Prepared for review. Post only after the published-asset receipt.

## User thread

Top-level:

```text
*Live on production — User — Cassy v4.45.0*
Was: a busy workspace could hold Commander messages for ten minutes and refuse its own upgrade. → Now: messages keep moving and upgrades load.
```

Reply (Was → Now):

```text
*A busy workspace keeps moving*

• *Messages no longer pile up* — Was: one slow background read let about twenty copies queue behind it in ten minutes, and Commander messages waited behind them. → Now: only the newest copy waits.

• *In-place upgrades load on a busy workspace* — Was: a backed-up workspace refused to load the new version that would fix it. → Now: replaceable background reads no longer block the upgrade.

• *Approved work merges again* — Was: the release merge queue could stay stuck for 15 minutes or more after a review was approved, and refused new entries. → Now: a stuck queue recovers by itself and accepts new work while a review is pending.

• *Coordinating sessions stay reachable* — Was: a coordinating session could sit in a long build or test run while your messages waited. → Now: long commands must run in the background, so messages get through.

• *Fewer stuck closes* — Was: work taken over from a stopped session, approved reviews, and JavaScript changes could be refused at close. → Now: each closes on its own proof.

• *Faster writes* — Was: a background check held the workspace's database for up to 8 seconds at a time. → Now: it reads without holding it.

Update with `cas update`, or choose <https://github.com/Richards-LLC/cassy/releases/tag/v4.45.0|the Linux x86_64 or macOS ARM64 downloads>.
```

## Dev thread

Top-level:

```text
*Live on production — Dev — Cassy v4.45.0*
Was: unbounded daemon read backlogs, an unbounded train advancement lock. → Now: Latest-coalesced reads, leased advancement, and the H-49 foreground guard.
```

Reply (Was → Now):

```text
• *Daemon read coalescing* — Was: delivery reads and liveness probes queued one copy per 30 s behind a slow running one. → Now: a new `Criticality::Latest` keeps at most one waiting instance per key.

• *Reexec flush* — Was: any queued or running job refused `cas factory reexec`. → Now: Refresh and Latest jobs, running or queued, are abandoned and rerun; reexec waits only for durable work.

• *Train advancement lease* — Was: the train driver held an unbounded lock, so appends and resume returned G-113 indefinitely. → Now: a 120 s renewed lease with reclaim records; appends never need the driver.

• *H-49 supervisor foreground guard* — Was: none. → Now: long foreground Bash (cargo, release scripts, npm/pnpm test or build, sleep loops, ssh waits, timeouts over 60 s) is refused in the supervisor pane; verifiers and subagents are exempt.

• *Close fixes* — Was: pre-assigned successors kept the dead worker's source branch; review-only no-delivery closes measured a missing supervisor branch; G-61 suggested jest on a source path. → Now: the source rebinds; no-delivery proves an empty source; G-61 uses `jest --findRelatedTests`.

• *Progress watchdog* — Was: task scans and git ran on the store writer, up to 8 s. → Now: reads run on the External lane; only writes take the writer.
```
