## User thread

Top-level:

```text
*Live on production — User — Cassy v4.50.0*
Was: closes could take 21 minutes to say no, and busy sessions were killed as failed. → Now: answers in seconds, and busy sessions stay.
```

Reply (Was → Now):

```text
*Faster answers, sessions that survive, half the GitHub traffic*

• *A close that will be refused says so in seconds* — Was: handing in a big Commander change could take 21 minutes just to say what proof was missing.
→ Now: the same answer comes back in about 10 seconds.

• *Busy sessions aren't killed as failed* — Was: a session that started with big reads could be removed 5 minutes in as "failed during boot", even while it was visibly working.
→ Now: any work since launch counts, so a working session stays. A truly silent one is still cleaned up.

• *Half the GitHub traffic* — Was: Cassy's CI checks used about 4,600 of the 5,000 GitHub calls an hour, so merges sometimes couldn't check CI at all.
→ Now: one shared answer per poll and cached results bring it to about 2,600 an hour.

• *Commander is easier to use with a screen reader* — Was: several live areas and controls had no name.
→ Now: each one announces itself, and four journey tests deleted as flaky are back and steady.

• *Evidence and proof that just work* — Was: a proof log cited in a sentence could be refused over a trailing ")." or "!", uncited raw files were uploaded at hand-in, and a slow moment could refuse every close from a healthy checkout.
→ Now: citations read the way people write them, only cited evidence uploads, and each close re-reads its own checkout.

Update with `cas update`, or choose <https://github.com/Richards-LLC/cassy/releases/tag/v4.50.0|the Linux x86_64 or macOS ARM64 downloads>.
```

## Dev thread

Top-level:

```text
*Live on production — Dev — Cassy v4.50.0*
Was: 21-min G-61 refusals, a 256 KB boot-watchdog window, ~4,600/h GitHub burn. → Now: 10 s refusals, launch-bound turns, ~2,600/h.
```

Reply (Was → Now):

```text
*What changed under the hood*

*Close proof*

• *Refusal latency* — Was: building G-61 run commands ran `playwright --list` once per config per file (~1,013 processes), again per widened scope, and re-read package imports each time (GH #2331).
→ Now: per park each config lists once, imports are read once per package, and an unloadable config lists nothing: 464 s → 10 s on the same delivery, with the same refusal.

• *Helpers and guards* — Was: a Playwright helper widened to its whole package, and a node:test-only helper could be prescribed as Playwright on workflow YAML (GH #2146, #2200).
→ Now: helpers are proven through each importing spec under its own config, and guard helpers through `node --test`.

• *Evidence publication* — Was: uncited nested files were uploaded at close, and prose punctuation broke citations (GH #2155, #2203, #2212).
→ Now: only declared evidence publishes, citations resolve the way the ledger gate reads them, and backticked or punctuation-ending names are taken literally.

• *Healthy-checkout closes* — Was: one timed-out own-checkout probe was cached 30 s and refused the rest of a batch with G-38 (GH #1941).
→ Now: each close re-reads its own checkout with the full budget.

*Factory*

• *Boot watchdog* — Was: first-prompt detection read only the last 256 KB of the transcript, so large early records hid the first turn (GH #2338).
→ Now: any turn start, output or end since this launch counts.

• *GitHub REST burn* — Was: ~4,600 of 5,000 core calls an hour went to standing CI polls.
→ Now: one recent-runs listing per poll, no per-SHA call for commits it already covers, and shared check-run answers (60 s pending, 600 s completed), about 2,600/h projected. Admission reads stay fresh.

• *Delivery-wake check* — Was: `DELIVERY_WAKE_MISSING` fired before a fresh park armed its wakes (GH #2332).
→ Now: it waits 60 s after the delivery last changed.

*Commander*

• *Accessible names and journeys* — Was: unnamed live regions, class-based selectors, and four journeys deleted as flakes.
→ Now: named regions, role/name/test-id selectors, and HUB-J4/J9/J14/J17 back with settled waits.

Validation: the frozen train suite and the merge queue proved the final release tree. Archives: <https://github.com/Richards-LLC/cassy/releases/tag/v4.50.0|GitHub release v4.50.0>.
Checksums: Linux x86_64 `f14f7159…cd1c`, macOS ARM64 `39f00545…176f` (full SHA-256 on the GitHub release).
```
