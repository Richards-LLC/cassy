## User thread

Top-level:

```text
*Live on production — User — Cassy v4.51.0*
Was: some finished work could never be handed in. → Now: every change gets a proof it can pass, and landed merges speak up.
```

Reply (Was → Now):

```text
*Hand-ins that can finish, merges you hear about*

• *Vue components can be handed in* — Was: finishing a change to a Vue component asked for a test command that crashed on that project, so the work could never be handed in.
→ Now: the component is proven through the tests that use it, or through its package's own test run, and only commands that can actually run are asked for.

• *Tagged browser tests count* — Was: a browser test marked with a tag (such as "staging") was never found by the stability check, so the change couldn't be handed in.
→ Now: tagged and untagged tests are both found, and look-alike names are still kept apart.

• *You hear when an approved merge lands* — Was: when the reviewer approved held work, Cassy merged it and said nothing, so the next step waited until someone asked (one release waited 30 minutes).
→ Now: the session that owns the work gets one message saying the merge landed, so the next step starts at once.

• *Better guidance for browser tests* — Was: the browser-test guide had one shared sign-in and no advice for background jobs.
→ Now: it covers background jobs, separate sign-ins per kind of user, and keeping paid or staging-only tests switched off unless asked for.

Update with `cas update`, or choose <https://github.com/Richards-LLC/cassy/releases/tag/v4.51.0|the Linux x86_64 or macOS ARM64 downloads>.

```

## Dev thread

Top-level:

```text
*Live on production — Dev — Cassy v4.51.0*
Was: impossible `vitest related` on .vue, tag-blind Playwright grep, silent auto-merges. → Now: runnable G-61 prescriptions, tag-aware selection, one merge_outcome wake per approval.
```

Reply (Was → Now):

```text
*What changed under the hood*

*Worker check*

• *.vue proof* — Was: park prescribed `vitest related --run <file>.vue` even when vitest had no Vue plugin, so the transform crashed and no receipt or override could close the delivery (GH #2352).
→ Now: a component vitest cannot load proves through its importing specs or its package's vitest run, and park prescribes only runnable commands.

• *Tagged Playwright tests* — Was: the stability run's title pattern had to end the line, but Playwright greps the title plus tags, so `test('t', { tag: ['@staging'] }, fn)` returned "No tests found" (GH #2349).
→ Now: trailing `@tag` words are allowed after the title, and a title that only shares a prefix is still excluded.

*Pre-merge verification*

• *Auto-continued merges wake their supervisor* — Was: `approved()` ran the held merge directly, outside the supervisor-call merge-receipt wrapper, and pre-marked its only queue row delivered, so nothing woke the owner (GH #2365).
→ Now: a landed approval enqueues one `merge_outcome` notice keyed to its dispatch, and train-queue merges still defer to the train's own outcome.

*Tests and skills*

• *Stale replay removed* — Was: a #2265 replay still asserted `vitest related` for .vue after #2352, so every lane selecting it failed and paid about 12 minutes of base attribution.
→ Now: the superseded case is gone, and the #2352 regression owns the .vue contract.

• *Playwright authoring skill* — Was: one shared storage state, opt-out live smoke, no async-job or `.mjs` guidance.
→ Now: async jobs are graded on server status, per-persona projects are routed by tag, paid and staging-only specs are gated by env in config, and `.mjs` helpers load as native ESM.

Validation: the frozen train suite and the merge queue proved the final release tree. Archives: <https://github.com/Richards-LLC/cassy/releases/tag/v4.51.0|GitHub release v4.51.0>.
Checksums: Linux x86_64 `e4ea39ed…08ab`, macOS ARM64 `6ab3027e…99ba` (full SHA-256 on the GitHub release).
```
