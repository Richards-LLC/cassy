# Slack draft — Cassy v4.52.0 runtime release

Status: Prepared for review. Post only after the published-asset receipt.

## User thread

Top-level:

```text
*Live on production — User — Cassy v4.52.0*
Was: GitHub lockouts, delayed ready messages, double builds. → Now: GitHub stays reachable, ready messages arrive at once, checks finish sooner.
```

Reply (Was → Now):

```text
*Faster handoffs, faster checks, an optional home gateway*

• *Ready messages arrive at once* — Was: after six routine updates in an hour, a "ready" or "please merge" message could sit for minutes behind a rate cap while people waited on it.
→ Now: ready and merge messages always get through right away, like blockers already did.

• *Checks finish minutes sooner* — Was: in half of all checks, Cassy built the code twice, losing three to six minutes each time.
→ Now: the second build is gone, cut from 302 seconds to under one second, and the same tests still run.

• *No more GitHub lockouts* — Was: Cassy checked GitHub once a minute for every parked change (111 of them), tripping GitHub's limits all day, so issue filing and releases stalled.
→ Now: one combined check per repository per poll, with spread-out caching, so GitHub stays reachable.

• *Optional home gateway* — Was: every session used its own account directly.
→ Now: a project can opt in to route session traffic through a private home gateway on this machine or the private network. It is off unless switched on, and nothing changes for anyone who leaves it off.

Update with `cas update`, or choose <https://github.com/Richards-LLC/cassy/releases/tag/v4.52.0|the Linux x86_64 or macOS ARM64 downloads>.
Checksums: Linux x86_64 `e73b2f2c…e448`, macOS ARM64 `2631a7eb…5d55` (full SHA-256 on the GitHub release).
```

## Dev thread

Top-level:

```text
*Live on production — Dev — Cassy v4.52.0*
Was: capped ready/merge wakes, a 190–375 s post-test rebuild, direct-only transport. → Now: uncapped handoff wakes, a sub-second inventory, opt-in gateway overlay.
```

Reply (Was → Now):

```text
*What changed under the hood*

*Coordination*

• *Handoff wakes* — Was: the six-per-hour worker wake cap exempted only blockers, so `ready` and `merge_request` messages could be held for minutes.
→ Now: ready and merge handoffs are waking kinds alongside blockers, and status/progress wakes keep the cap.

*Lane CI*

• *No second compile* — Was: a Python check imported a helper and wrote `scripts/__pycache__`, which `build.rs` watches recursively, so the ring-inventory `nextest list` rebuilt cas (189–375 s in 5 of 10 runs).
→ Now: lane child processes never write bytecode, so the post-test build takes 302 s → 0.59 s on a matched run, with all 11,533 test identities preserved.

*GitHub budget*

• *Batched PR reads* — Was: ci_watch ran one uncached `gh pr list` per parked delivery every 60 s (111 → ~110 calls/min), tripping secondary limits and the shared 120 s backoff.
→ Now: one batched PR read per repo per poll (≤150 branches each), matched locally, with jittered run-cache expiry; open/merge wakes unchanged.

*Factory*

• *Opt-in home gateway* — Was: workers could only reach providers directly.
→ Now: opt-in `[factory.gateway]` (byte-identical when off) overlays a private endpoint and 0600 key file on the native account; a pre-launch probe falls back to direct, and requests carry a `cassy/<worker>` User-Agent.

Validation: the frozen train suite and the merge queue proved the final release tree. Archives: <https://github.com/Richards-LLC/cassy/releases/tag/v4.52.0|GitHub release v4.52.0>.
Checksums: Linux x86_64 `e73b2f2c…e448`, macOS ARM64 `2631a7eb…5d55` (full SHA-256 on the GitHub release).
```
