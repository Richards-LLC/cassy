# Slack draft — Cassy v4.53.0 runtime release

Channel: #cas-internal (`C0B44GUKDK2`).

Status: Prepared for review. Post only after the published-asset receipt.

## User thread

Top-level:

```text
*Live on production — User — Cassy v4.53.0*
Was: finished work could stall, and quota differed per machine. → Now: work closes cleanly, and each account shows one number everywhere.
```

Reply (Was → Now):

```text
*Cleaner closes, one quota per account, reload from Commander*

• *One number per account on every machine* — Was: each machine measured its own accounts, so the same login showed different quota on the desktop and the laptop.
→ Now: Accounts and New Session read the home hub, so one login shows one number on every machine. A reading the hub doesn't have is shown muted and labelled, never as the shared number.

• *Home gateway in New Session* — Was: sending a session's helpers through the home gateway was a config edit.
→ Now: New Session offers Direct or Home gateway, says which helpers it moves, and the session keeps that choice while it runs.

• *Reload Cassy from Commander* — Was: picking up a new Cassy build meant restarting the session by hand.
→ Now: Reload Cassy (or `/reload-cassy`) waits for a quiet moment, reloads Claude in place or restarts Codex after you confirm, and the version badge shows what's loaded.

• *Finished work stops getting stuck* — Was: handed-over or retargeted work could be refused at close as someone else's, an operations-only workstream couldn't close at all, and a test that couldn't be run blocked the close.
→ Now: work keeps its identity through hand-offs and retargets, operations-only workstreams close normally, and when a focused test can't run Cassy runs the whole package instead of refusing.

Update with `cas update`, or choose <https://github.com/Richards-LLC/cassy/releases/tag/v4.53.0|the Linux x86_64 or macOS ARM64 downloads>.
Checksums: <filled at cut>
```

## Dev thread

Top-level:

```text
*Live on production — Dev — Cassy v4.53.0*
Was: G-42/G-61/G-41 refusals on legitimate deliveries and per-machine quota. → Now: one audited start writer, package-suite fallback, ops-only epic close, hub-matched quota.
```

Reply (Was → Now):

```text
*What changed under the hood*

*Close gates*

• *Delivery identity* — Was: start, adoption, retarget and rebind each wrote the task's start boundary, so prior-train history read as foreign work (G-42) after a hand-off or retarget.
→ Now: every write goes through one audited `rebind_start` that keeps the replaced target in `prior_work_targets`; real-path replays cover retarget, adoption and rebind, and a plain branch is still refused.

• *G-61 never refuses an unrunnable proof* — Was: a zero-test focused selection or an unconstructible command failed park.
→ Now: zero selection is told apart from a real failure, the owning package or crate runs once, and that receipt satisfies park; Rust commands come from Cargo's harness inventory; real failures still refuse.

• *Evidence selection* — Was: prose like "epic target <sha>" became a required file, fetched copies were republished, and retries appended evidence summaries.
→ Now: only cited files are required, `art-` copies are never republished, and a re-park replaces the summary (retained-history guard updated).

• *Ops-only epics* — Was: an epic with no source delta failed structural lint (G-41) and no_delivery/evidence_only refuse epics (G-23).
→ Now: an approved operations-only epic closes through ordinary gates with an audit note; source deliveries keep strict lint.

*Commander*

• *Hub quota* — Was: Accounts read each machine's own usage.
→ Now: Claude matches the hub by email and Codex by rollout `creator_account_id` ↔ hub `chatgpt_account_id`; a dashboard-only machine reads inventory without routing.

• *Reload Cassy* — Was: no in-app reload.
→ Now: `/mcp` and `/reload-cassy` queue for idle, reconnect Claude or confirm-and-restart Codex, and a reload invalidates the hub's cached version so badges update at once.
```
