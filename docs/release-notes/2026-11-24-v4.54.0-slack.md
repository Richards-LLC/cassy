# Slack draft — Cassy v4.54.0 runtime release

Channel: #cas-internal (`C0B44GUKDK2`).

Status: Prepared for review. Post only after the published-asset receipt.

## User thread

Top-level:

```text
*Live on production — User — Cassy v4.54.0*
Was: coding stalled when Codex hit its weekly limit. → Now: newer models with a Claude fallback, per-task cost, faster reviews.
```

Reply (Was → Now):

```text
*Newer models, real costs, fewer review rounds*

*The big four*

• *Newer models, and coding never stalls on Codex limits* — Was: everyday coding ran a retired GPT model and stopped whenever every Codex login hit its weekly limit.
→ Now: it runs GPT-6.2 Sol and falls back to Claude Sonnet 5.5; the hardest work runs on Claude Fable 5.2.

• *What each task cost* — Was: the release report only totalled spend by who started the work, so cost per task meant digging through raw logs.
→ Now: `cas scorecard` shows spend per task and per model and effort, with every measurement's health listed first.

• *Fewer comments, less noise* — Was: finished work kept whatever comments were written along the way, and nothing reviewed them.
→ Now: a new no-comments pass removes comments that only restate the code before review; help text and tool descriptions are never touched.

• *Reviews in fewer rounds* — Was: a review stopped at its first problem, and leftover dead code or missing docs each cost another 15–20 minute round.
→ Now: one review lists every problem, and Cassy catches dead code, missing docs and quietly narrowed work in seconds, before review starts.

*Commander*

• *Reload Cassy sees a same-version rebuild* — Was: reloading onto a hotfix build with the same version number answered Already current and did nothing.
→ Now: a different build at the same version reloads, and a second reload says Already current.

• *Reload status stays true* — Was: a reload that went on to finish could show "message was not sent. Retry" while Cassy reconnected.
→ Now: it keeps showing its waiting or restarting status, then the real outcome.

• *Codex quota stays fresh* — Was: with no Codex work for a few hours, Accounts showed Codex limits from hours ago.
→ Now: Cassy reads the 15-minute background check too and shows the newer number.

*Steadier work*

• *Approved research closes itself* — Was: an approved research task with no code could stay blocked until someone repeated the close by hand.
→ Now: it closes itself, and anything still holding it names the exact reason.

• *Restarts don't get stuck* — Was: a busy background queue could pile up hundreds of copies of one check, so a quick restart was refused.
→ Now: a newer copy replaces the waiting one, and restarts go through.

• *Mentioning another task's file no longer blocks merges* — Was: citing another task's saved file in a plan blocked every merge under it.
→ Now: the file is matched to its own task and merges go through.

• *Test runs wait their turn* — Was: a test run that met a busy machine quit and asked to be retried two minutes later.
→ Now: it waits in line and reports once when done.

*JavaScript tests*

• *Tests switched off by design don't block finished work* — Was: a test that only runs when a setting is on failed the five-run stability check every time.
→ Now: it's recorded as inactive, never counted as passing, and real failures still fail.

• *Jest runs from the right folder* — Was: a Jest config kept in a subfolder ran from there, so file paths in tests broke before any check ran.
→ Now: Jest runs from the package that owns the config.

*Mac*

• *Login items are off-limits* — Was: Cassy's Mac sandbox could be configured to allow writing into the folder macOS runs at login.
→ Now: that folder is always blocked.
```

## Dev thread

Top-level:

```text
*Live on production — Dev — Cassy v4.54.0*
Was: deprecated gpt-6.1-sol lanes, no Claude fallback, one finding per verifier round. → Now: GPT-6.2 Sol/Fable 5.2 lanes and park-time gates.
```

Reply (Was → Now):

```text
*What changed under the hood*

*Models and spend*

• *Lane registry* — Was: `standard` = gpt-6.1-sol (deprecated) → gpt-6-sol, Codex-only; `heavy`/`taste` = Opus 5.5; recipes still named Fable 5.1.
→ Now: `standard` = GPT-6.2 Sol xhigh → high → Sonnet 5.5 high; `light` = 6.2 Sol low → Luna 6 → Opus 5.5 low; `heavy`/`taste` = Fable 5.2 high → Opus 5.5.

• *Codex lanes behind the hub gateway* — Was: `spawn_workers lane=standard` refused every Codex recipe when workers routed through the hub, looking for a local Codex login file.
→ Now: a hub-routed recipe is checked against the hub's model listing; direct starts still use the account catalogue.

• *`cas scorecard`* — Was: `cas ledger report` totalled tokens by wake source.
→ Now: each turn records harness, model, effort, cached input and held task; the report adds spend per task and per harness/model/effort, sensor health first (OK/EMPTY/BROKEN), and foreign-project wakes attributed to their emitter. `cas ledger report` still works.

*Park and verification*

• *Dead-code sweep (G-169)* — Was: a refactor that orphaned a helper parked clean and lost one verifier round per symbol.
→ Now: park diffs the delivery with no build or model call and lists every TS/JS function, method, export or type, Rust `pub` item and CSS class whose last reference the delivery removed.

• *AC checklist at park* — Was: a worker could park a narrower slice than its brief.
→ Now: park requires an acceptance-criteria checklist artifact with a row per AC and supervisor decision; a NOT MET or NARROWED row needs a supervisor decision note.

• *Doc fragments at park (G-167, G-168)* — Was: a missing product-overview fragment or bug family cost a verifier round.
→ Now: park lists both at once, with `no overview:` and `no bug family:` decision-note escapes.

• *One verdict, every finding* — Was: the verifier stopped at the first completeness failure.
→ Now: every phase runs on every review and one verdict returns all findings.

• *Auto-verified no-code closes* — Was: an approved no-code close by the automatic verifier was refused because the verifier, not the train owner, ran it.
→ Now: Cassy closes it for the owning supervisor and saves any real gate's code on the task.

• *Epic artifact citations* — Was: any `art-` id in an epic's text was treated as the epic's own, refusing child merges.
→ Now: each id resolves to its owning task; an unowned mention reaches the verifier as missing context.

• *`cas-no-comments`* — Was: nothing reviewed delivery comments.
→ Now: a builtin skill and a worker pre-park pass delete comments outside a keep list; clap and schemars `///` doc text is never deleted.

*Runtime and Commander*

• *Reload by build hash* — Was: `/reload-cassy` compared versions only.
→ Now: the build hash is recorded beside the version; a same-version rebuild reloads and counts only once the supervisor runs the installed build. Reload status survives the reconnect.

• *Reexec vs. reconcile reads (GH #2327)* — Was: the worker-task-queue reconcile read resubmitted every 30 s as durable work (452 after 3.8 h), so `cas factory reexec` refused.
→ Now: a resubmit replaces the waiting one and reexec abandons it.

• *Codex quota freshness* — Was: hub quota came only from proxied requests.
→ Now: the hub's 15-minute inspection runs are read too; the newer read wins.

• *Capped runs queue* — Was: a backgrounded capped run at a full builder cap exited and woke its worker to retry in 120 s.
→ Now: it waits in its own session, keeps its priority and wakes once with the result.

*Test proof and CI*

• *Environment-gated Jest cases (GH #2223)* — Was: `(env ? it : it.skip)`, `skipIf` and `runIf` cases failed 5/5 stability when skipped by design.
→ Now: recorded as inactive on a `stability: INACTIVE` line, never as passing; an all-inactive run is refused with the env to set.

• *Capped Jest working directory (GH #2196)* — Was: Jest ran from the config's folder.
→ Now: it runs from the nearest ancestor of the config that holds the package manifest.

• *Case-file suite selection* — Was: an edit under an integration case directory widened to every integration suite.
→ Now: it runs the suite that compiles it via `#[path]` or `mod` first.

• *Class-audit hint* — Was: the park hint always suggested `--lib`.
→ Now: it names the registering target, such as `--test integration_factory`.

• *macOS sandbox* — Was: listing the macOS LaunchAgents folder in `write_roots` made it writable.
→ Now: the worker profile always denies it.
```
