# Slack draft — Cassy v4.55.0 runtime release

Channel: #cas-internal (`C0B44GUKDK2`).

Status: Prepared for review. Post only after the published-asset receipt.

## User thread

Top-level:

```text
*Live on production — User — Cassy v4.55.0*
Was: every Mac update made macOS ask for folder access again. → Now: allow once, and it sticks across updates.
```

Reply (Was → Now):

```text
*Mac permissions that stick, and steadier reviews*

*Mac*

• *Privacy permissions survive updates* — Was: each Cassy update on a Mac looked like a brand-new app to macOS, so it asked again for access to Desktop and other protected folders.
→ Now: Cassy signs itself with the same local identity on every install and update, so each permission is asked for once and then kept. No password prompt, and if signing ever fails, Cassy warns and keeps working.

*Commander*

• *Reload Cassy appears for a same-version rebuild* — Was: after a rebuild that kept the same version number, Commander hid the Reload Cassy button, so the session stayed on the old build.
→ Now: the button appears whenever the installed build differs from the one the session is running, even at the same version.

*Steadier work*

• *A stuck review no longer blocks merges* — Was: if an automatic reviewer froze partway through, every merge retry for that work was refused until someone cleared it by hand.
→ Now: once the review is overdue and shows no sign of life, the next merge retry starts a fresh reviewer on the same work.

• *Slack replies that never arrived can be resent* — Was: when Cassy couldn't confirm a Slack reply and Slack had no record of it, Cassy said not to retry, so the reply was lost or posted twice by hand.
→ Now: Cassy says to resend it, and the resend uses the same request, so it can't post twice.
```

## Dev thread

Top-level:

```text
*Live on production — Dev — Cassy v4.55.0*
Was: ad-hoc linker signatures reset TCC on every macOS update. → Now: a stable local code-signing identity (dev.cassy.cas).
```

Reply (Was → Now):

```text
*What changed under the hood*

*Install and update*

• *Stable macOS code signing* — Was: installs were linker-signed ad hoc, so each build had a new code identity and TCC treated every update as a new client.
→ Now: every install route signs with one local identity (`dev.cassy.cas`, dedicated keychain, no login password), so the designated requirement and TCC grants carry over.

• *Signing coverage and fallback* — Was: no signing on any route.
→ Now: installer, native updater, refresh-only, both source installs and `cas-update` sign; an interrupted first setup recovers; a failure warns and keeps a byte-identical ad-hoc binary. Linux unchanged.

• *Live macOS proof* — Was: grants reset on every update.
→ Now: two builds with the same leaf and requirement and distinct CDHashes, and zero TCC prompts after the update.

*Commander*

• *Reload by build identity* — Was: the Reload Cassy action was hidden when installed and loaded builds reported the same version.
→ Now: it compares build identity, so a same-version rebuild offers Reload, and reload availability survives an unreachable supervisor.

*Verification*

• *Stalled verifier claims* — Was: a verifier thread that stopped inside a live host process left its expired dispatch Claimed, and every merge retry was refused with "finish this exact verdict".
→ Now: past the deadline, the owning supervisor's retry releases a Claimed dispatch with no fresh verifier heartbeat and no active verifier lane, then starts a replacement on the same dispatch. The daemon verifier records its machine stamp.

*Violet*

• *Retryable lookup miss (GH #1968)* — Was: an uncertain post whose outcome lookup found no record returned `not_posted` with `retryable: false`, so callers opened a second reply intent.
→ Now: `not_posted` with reason `request_not_found` is retryable with the same request ID and arguments, and the proxy reports only what the lookup shows.

*Test hygiene*

• *Fewer flaky and duplicate tests* — Was: the reconcile suite had a scheduler-dependent relay test, and the Codex lane test probed shared capability keys twice.
→ Now: the flaky test is removed (existing job-runtime tests keep the coverage), and each auth scenario is probed once.
```
