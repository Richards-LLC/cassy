# Slack draft — Cassy v4.56.0 runtime release

Channel: #cas-internal (`C0B44GUKDK2`).

Status: Prepared for review. Post only after the published-asset receipt.

## User thread

Top-level:

```text
*Live on production — User — Cassy v4.56.0*
Was: work failing review could loop through patches and hold a release. → Now: two rejections trigger a whole-flow review first.
```

Reply (Was → Now):

```text
*Fewer stuck releases, a steadier Commander*

*Reviews*

• *Repeated rejections get a whole-flow look* — Was: a piece of work could be rejected, patched narrowly and rejected again, round after round, while the release waited on it.
→ Now: after two rejections Cassy requires a review of the whole flow before another fix, and lets the release go ahead without that work unless someone records why it should stay.

• *Written reports always get an independent review* — Was: a research or demo report saved as a document could be closed with nobody else checking it.
→ Now: every such report needs an approved review of exactly what was published, and editing or republishing it asks for a fresh one.

• *"Test first" means a real failing test* — Was: a task meant to start from a failing test could be submitted with only a passing run.
→ Now: Cassy needs proof the test failed before the fix.

*Commander*

• *Reload Cassy confirmation stays open* — Was: the confirmation could disappear before you clicked it when the session list refreshed.
→ Now: it stays until you choose. Commander clears your typed command after sending it, or keeps it and shows who controls the pane if the request is refused.

*Two machines*

• *Replacing a stalled session reaches the other machine right away* — Was: when one machine replaced a stalled session, the machine running the release only found out after some later edit.
→ Now: the handover reaches it immediately.

• *Clearer reply errors between machines* — Was: replying to the wrong message ID said the other machine didn't exist.
→ Now: it names the invalid reply ID.

*Install*

• *Readable update warnings* — Was: `cas-update` warnings were faint on light terminals, still styled with `NO_COLOR`, and could run past 80 columns.
→ Now: stronger contrast, `NO_COLOR` turns styling off, and the install path sits on its own line.
```

## Dev thread

Top-level:

```text
*Live on production — Dev — Cassy v4.56.0*
Was: unbounded reject-and-repair rounds on a train. → Now: two all-time rejections require a linked whole-flow review and detach by default.
```

Reply (Was → Now):

```text
*What changed under the hood*

*Verification*

• *Whole-flow review after two rejections* — Was: unbounded narrow repair rounds; the task kept the train waiting.
→ Now: after two all-time verifier rejections, repair, assignment and start require a linked whole-flow review, and the task detaches from its train unless a supervisor records a reasoned keep. Detachment preserves the recorded source branch; the daemon recovers missed notices.

• *No-code reports are always reviewed* — Was: a no-code spike whose report landed as repo docs was classed docs-only, and light depth, rapid-response, a containing release tag, `supervisor_override` or `task update status=closed` each skipped review.
→ Now: one gate runs before every exemption; approval binds the proof reference and each artifact id and SHA-256 (m302), is rechecked at final write and merge admission, and retires on edit, republish or revoke (G-68 on unreadable state).

*Park*

• *Test-first evidence* — Was: a passing run alone parked a test-first task.
→ Now: park needs a capped failing test at the start base, a committed red checkpoint, or a capped `cargo check --tests` failure at the start base. Red-first coverage is restored without shelling out to real Cargo, and the env-dependent test that failed on CI rings is gone.

*Coordination*

• *Peer reset replication* — Was: a peer's stale-worker replacement didn't sync to the train owner until a later task edit.
→ Now: the reset is recorded in the form Cloud sync recognizes, so the reassignment and rebound branch arrive immediately.

• *Peer reply IDs* — Was: a local supervisor-notice id as `in_reply_to` reported "peer does not exist".
→ Now: the error names the invalid reply ID.

*Commander*

• *Reload confirmation* — Was: session-list updates interrupted a pressed confirmation and could drop a reload waiting for pane control.
→ Now: both survive updates; the command draft clears on send or stays with the pane-control owner shown on refusal.

*CLI*

• *`cas-update` output* — Was: low-contrast markers, styling under `NO_COLOR`, an install target past 80 columns.
→ Now: stronger markers, `NO_COLOR` respected, target on its own indented line.

*Docs*

• *v4.55.0 release report* — Was: no standalone report.
→ Now: HTML and PDF report for v4.55.0 in docs/release-reports.
```
