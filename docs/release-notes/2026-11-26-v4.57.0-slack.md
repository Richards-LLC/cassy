# Slack draft — Cassy v4.57.0 runtime release

Channel: #cas-internal (`C0B44GUKDK2`).

Status: Prepared for review. Post only after the published-asset receipt.

## User thread

Top-level:

```text
*Live on production — User — Cassy v4.57.0*
Was: since 4.54, automatic reviews rejected most work. → Now: reviews are back to their old model and stop at the first real gap.
```

Reply (Was → Now):

```text
*Lighter reviews, and report tasks close again*

*Reviews*

• *Reviews run on their own model* — Was: since 4.54, automatic reviews used the same model as coding sessions, and only 10–27% of deliveries passed (36–67% before); each review took about 6 minutes.
→ Now: reviews are pinned to the model they used before 4.54, so a new coding model no longer changes how strict reviews are.

• *Reviews stop at the first real gap again* — Was: since 4.54, a review that already found a missing piece kept going through every quality check and listed every finding, so rejections got longer and slower (about 3 minutes per review became 6–8).
→ Now: a review that finds a missing piece rejects on it straight away; quality checks run only once the work is complete.

• *Reports no longer get stuck after an update* — Was: if a session was still running the previous version's tools, every attempt to close a report, QA walk or research task opened a review that was cancelled seconds later, over and over, with no hint why.
→ Now: Cassy stops and tells you to reconnect that session's tools. After reconnecting, the review runs and the task closes. A report that changed after review still asks for a fresh review.
```

## Dev thread

Top-level:

```text
*Live on production — Dev — Cassy v4.57.0*
Was: the verifier borrowed the standard lane (gpt-6.2-sol/xhigh). → Now: pinned to gpt-6.1-sol/high; phase gating restored.
```

Reply (Was → Now):

```text
*What changed under the hood*

*Verification*

• *Verifier model pinned* — Was: the verifier resolved `lanes.standard`, so the 4.54 move to gpt-6.2-sol/xhigh hit every review (494/494 runs on 6.1 before, 527/527 on 6.2 after); approval 36–67% → 10–27%.
→ Now: the automatic verifier uses the `codex_sol_6_1` recipe (gpt-6.1-sol/high) directly; worker lanes are unchanged.

• *Verifier phase gating restored* — Was: 4.54's run-every-phase change made Phase 2 Quality run even when Phase 1 Completeness failed, and told the verifier to list every blocking finding; median review time doubled.
→ Now: reverted to the 4.53 instructions for both the Claude and Codex verifier, and the missing-ledger and parser failures reject and stop again.

• *Mixed-version no-code reviews* — Was: a 4.55 MCP created report-review dispatches without the proof reference or artifact digests, and the 4.56 daemon retired each one as verifier_dispatch_proof_drift right after launch.
→ Now: a proofless report dispatch fails closed with a stable code that names the MCP reconnect; a 4.56 MCP close of the same task records the proof and its approval closes the task.

• *Retirement handling* — Was: report-proof codes sat in the factory request retry classifier, and retry guidance was built even when retirement failed.
→ Now: those codes are handled only in the asynchronous retirement path, and guidance is built only after a successful retirement. Edit, republish and revoke still retire a stale review.
```
