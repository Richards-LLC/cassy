## What you can do now

### Clearer work requests
#### Name the outcome before work begins

Was: user-facing work could start without an observable outcome.

Now: configured labels require a demo statement, repeated in worker briefs. Epics, unlabeled work and supervisor overrides are exempt.

### Honest QA
#### Explore within a useful decision window

Was: exploratory QA lacked a clear stopping point.

Now: `cas-qa-craft` supplies a matrix, adjacent-risk checks, evidence labels and a 30-minute box.

#### Keep the evidence behind the result

Was: close prose could hide what was actually exercised.

Now: `LEDGER.md` records verdicts, captures and honest `NOT EXERCISED` results; verification checks that evidence before the close reason.

#### Recall the relevant lesson

Was: recall missed same-day lessons while semantic search timed out.

Now: recent, deeply matching memories outrank old shallow rule matches; semantic search has bounded deadlines.

### Release clarity
#### Open a report you can inspect

Was: release reporting needed a bespoke source-to-PDF path.

Now: `cas-release-report` provides the renderer, brief, template and PDF recipe; the v3.19.0 exemplar demonstrates them, and the announcement draft links the report.

#### Leave the CPU free while waiting

Was: an idle code watcher could keep a core busy.

Now: `cas serve` waits for filesystem events without spinning.

## Under the hood

### Task and QA contracts
#### A configurable creation gate

Was: public-surface labels did not require a demo statement.

Now: `qa.user_facing_labels` defaults to `ui`, `hub`, `cli-ux`, `commander` and `frontend`; creation requires a statement, except for epics, unlabeled tasks and deliberate supervisor overrides.

#### An exploration ledger with evidence labels

Was: QA prose blurred inference, fixtures and actual-build observations.

Now: `cas-qa-craft` caps eight cells, adds three unmentioned conditions and an adjacent surface, labels evidence and marks unrun cells `NOT EXERCISED` after 30 minutes.

#### Evidence mode precedes capture judgment

Was: verifiers could judge close prose before its supporting evidence.

Now: the evidence-mode REJECT table runs before captures open; each capture judgment accompanies its row and close reason.

### Release controls
#### One reusable report renderer

Was: each release needed bespoke source, design and PDF production.

Now: `cas-release-report` supplies the renderer, template, brief, token mapping and A4/Letter recipe, with continuous flow and fidelity checks.

#### An exemplar carried into preparation

Was: the repository lacked a complete release-report example.

Now: preparation carries forward the v3.19.0 Markdown, brief, HTML, PDF and QA receipt.

#### An explicit publication handoff

Was: announcements could omit report artifacts or publication proof.

Now: step 13 requires the report after publication, before authorized Slack posts. Drafts link source/HTML/PDF; the rubric retains four ordered posting receipts.

### Runtime efficiency
#### A watcher that blocks when idle

Was: the code watcher's idle path could spin without a filesystem change.

Now: the idle path waits for events. This report records the shipped fix for #754; it does not claim a new CPU benchmark.

### Ambient recall quality
#### Bound search and remove ranking noise

Was: a 30-second connect timeout sat outside the 400-millisecond semantic budget; old shallow rule matches outranked recent exact-overlap memories, unrelated task titles padded prompts, and tool triggers included hex IDs and durations.

Now: connect and request deadlines are bounded, decision traces include timings, recency and overlap depth affect fusion, strong prompts avoid unrelated padding, and dictionary-like trigger terms filter noisy IDs and durations.
