What you can do now

02 / 06
01

Daily confidence

Clearer health checks

Wasone warning could cover several different problems.

Nowchecks separate missing projects, incomplete setup, and unreachable services with the right remedy.

History from the right place

Wascode history could look in the wrong repository.

Nowit uses the configured history source or the project's GitHub home.

Honest hub status

Wasa healthy public route could look loopback-only.

Nowstatus shows when the live public route is working.

02

Safer recovery

Cloud conflicts

Wasa project-name mismatch could look like a retryable sync failure.

NowCassy explains the conflict and what to change.

Safe cleanup

Wascleanup could drift after its preview.

NowCassy checks the exact rows and stops if state changes.

Accepted changes

Wasaccepted shared changes could disappear from the local task list.

Nowthey appear as open tasks in the intended project.

Known projects

Wasa missing folder and an uninitialized project could look the same.

Noweach gets a precise repair path.

03

Reliable work

Messages you can find

Wasa delivered message could be invisible or repeat.

Nowit stays visible until observed and repeated delivery is bounded.

Safe urgent requests

Wasan urgent request could affect the wrong assignment.

Nowownership is checked before the request takes effect.

Clean restarts

Wasclearing a conversation could resume under the wrong identity.

Nowthe recipient's new session is confirmed before work continues.

Predictable parallel builds

Wassimultaneous builds could compete for the machine.

Nowconfigured limits keep them within a safe budget.

04

Trustworthy updates

File uploads you can trust

Wasa successful byte count did not prove a usable image arrived.

Nowuploads are downloaded, hash-checked, decoded, and previewed.

Safer installs

Wasa temporary GitHub hiccup could make the installer give up with no explanation.

Nowit retries with credentials and tells you exactly what the release service returned.

Under the hood

03 / 06
01

Branch and build controls

Close validation

Wasclose and commit guards could inspect the wrong target worktree or stale epic base.

Nowboth resolve the declared target, and spawns retain the focused epic base.

Push safety

Wasa rejected push existed only as hook stderr.

Nownon-factory destinations are refused and recorded in worker activity.

Build throttling

Wasconcurrent builders could ignore configured limits.

Nowfactory.max_concurrent_builders and factory.worker_build_jobs cap process and Cargo jobs, with the active throttle in spawn output.

Release drift

Wascommitted hub-web dist output could drift from its source unnoticed.

Nowthe release gate rejects stale generated assets.

02

Delivery and messaging

Parked retries

Wasa parked delivery anchor could point at a stale session.

Nowretries refresh the anchor and preserve actionable upstream Slack errors.

Urgent ownership

Wasan urgent wake could consume work owned by another session.

Nowassignment ownership is validated before dispatch.

Context reset

Wasclearing context could leave the recipient under an old identity.

Nowthe reset runs in the recipient harness and confirms the new transcript.

Bounded redelivery

Wasan unobserved Claude delivery could repeat without a clear cap.

Nowattempts and retries stay within a bounded delivery budget.

Session routing

Wasa worker relay could land in a generic supervisor session.

Nowrelays route to the owning supervisor session.

Inbox visibility

Wasa transport-delivered receipt could hide an unread row.

Nowit remains pollable until an observed wake consumes it, and consumption retires exactly one row.

03

Cloud synchronization

Conflict diagnostics

Wasa cloud HTTP 409 could become a generic queue retry.

Nowcas cloud sync and cas doctor name the project conflict, park affected rows, and give the exact remedy.

Verified purge

Wasforeign-row cleanup could delete a different count or re-admit rows after its preview.

Nowcas cloud purge-foreign applies the verified set exactly and aborts on drift.

Proposal materialization

Wasan accepted cross-project proposal could remain absent locally.

Nowcas cloud pull creates the open target task from the server-attested destination and prints concrete pull errors.

04

Diagnostics and configuration

Epic status

Wasmcp__cas__coordination action=epic_status could spend unbounded work on a large epic.

Nowoffset, limit, and summary provide bounded pages and a fast ancestry-only view.

Known-repository classifier

Wascas doctor treated missing roots and live roots without a Cassy store alike.

Nowcas doctor --fix prunes only missing roots and gives safe manual guidance for live roots.

History repository

Washistory indexing reused the bug-intake repository setting.

Nowhistory.github_repo is independently configurable through cas config, with GitHub-origin fallback.

Upstream reachability

Wasproxy startup exposed only a coarse connection failure.

Nowcas doctor probes each configured upstream once, shows redacted detail, and boot output records reachable routes.

Healthy hub route

Wascas hub status printed loopback-only for a live CAS-created Tailscale Serve route.

Nowit reports the live hub target while retaining distinct unavailable and unrecorded-route states.

Portable Codex workers

WasPlaywright MCP inherited a fixed host home path.

NowCodex derives HOME and its profile from the host home.

05

MechaCassy and installation

Read preflight

Wasthe skill treated an available transport as proof that posting was safe.

Nowit requires the read preflight and documents the approved fallback.

Channel operations

Waschannel resolution, edits, and deletes had incomplete guidance.

Nowthe skill documents the complete channel contract and safe error handling.

Upload integrity

Wasfile size or a success response could stand in for proof.

Nowdownloaded SHA-256 equality, image decoding, and visible preview are required.

Install receipts

Wasa temporary GitHub hiccup could make the installer give up with no explanation.

Nowit retries with credentials and tells you exactly what the release service returned.
