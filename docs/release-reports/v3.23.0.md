## What you can do now

### Reply (Was → Now):

#### Message limits

Was: oversized messages and notes could crowd out useful context.

Now: clear limits reject overlong content before queueing and point to an artifact remedy.

#### Return format

Was: handoffs varied and could repeat setup.

Now: every handoff uses six predictable fields and stays quiet unless context is running low.

#### Focused updates

Was: long status messages hid decisions and proof.

Now: concise updates put the decision first while detailed evidence stays available.

#### Startup context

Was: delivered startup context could appear again later.

Now: it arrives once per session, with a short source marker and newest task notes first.

#### Reliable reports

Was: release reports could count a pull request as an issue.

Now: pull requests and issues are distinguished correctly.


## Under the hood

### Reply (Was → Now):

#### Traffic caps

Was: coordination bodies and notes had no shared size budget.

Now: 1,200-character messages, 2,500-character escalations, and 1,500-character notes are enforced before queueing. Commit `6438dbd3`.

#### Return contract

Was: launch responses varied and consumed context with narration.

Now: every launch carries six required return fields and silent execution, with headroom only below 20 percent. Commits `789be31f` and `5c33d2d2`.

#### Pane budget

Was: supervisor output mixed decisions with long evidence recaps.

Now: concise pane responses foreground the decision and keep evidence in notes or artifacts. Commit `095c3b14`.

#### Delivery provenance

Was: startup and fallback paths could replay delivered mail and expose a long provenance header.

Now: startup claims and enqueue are idempotent, delivered mail is excluded from tool-result fallback, task details show the newest five notes, claim files are pruned, and provenance is one line. Commits `987ea4c8` and `aac77a6d`.

#### Close-gate safety

Was: trunk reachability, merge recovery, and epic refresh could rely on local state.

Now: origin reachability, worktree-scoped history changes, and published-parent checks fail closed. PR #806.

#### Release-report references

Was: pull-request references could be counted as issues.

Now: issue extraction distinguishes pull requests from issues. PR #801.
