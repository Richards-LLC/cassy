## What you can do now

### Releases that do not wait

#### Combined as you go

Was: finished pieces were only combined at release time, and every clash surfaced then.

Now: every finished piece is combined with everything else the moment it lands, and clashes are reported to the person who owns them right away.

#### Proof that covers the change

Was: a change could pass its own checks and still break a neighbour.

Now: a change cannot be handed in until the checks that exercise it have run.

#### Small fixes move fast

Was: a one-line fix waited on the same long check as a big change.

Now: small, verified fixes are admitted immediately.

#### Fix rounds in parallel

Was: each failure was written up and fixed one after another.

Now: failures are grouped and handed out at once.

#### One short gate

Was: the final release check redid work already proven.

Now: proven results are reused and only what changed is rechecked.


## Under the hood

### Integration

#### Rolling integration branch

Was: epics were merged one by one at release time.

Now: each epic merge re-merges main plus every open epic into `integration/<project>`, runs the workspace sweep detached, and posts conflict pairs/files or failing targets to the owning supervisors and as epic notes.

#### Proof surface mapping

Was: `check-scoped-test-surface.sh` mapped files to tests that mention them; `--lib`-only proofs passed.

Now: changed modules require the integration binaries that exercise them plus class guardrails (skills → builtin_*, tests/ → archive portability, hooks → hook_schema); close refuses with the exact command.

#### Fast merge admission

Was: every lane waited 10–25 min on Scoped Validation.

Now: `release-train.sh --check-lane` accepts a supervisor `--proof` receipt on the exact tip for small deltas, and a `Scoped Validation (fast)` tier compiles plus mapped targets; the policy is pinned by `test-ci-test-tiers.sh`.

#### Sweep → tasks

Was: sweep logs were read by hand into one task per round.

Now: failures group by binary + panic site into `sweep-tasks.json`; `coordination action=sweep_tasks` previews and accepts, creating tasks and spawning workers idempotently.

#### Gate reuse from sweep receipts

Was: the gate reran nextest/archive rows already proven by the assembly sweep.

Now: the integration sweep writes row-cache-v2 receipts; `--gate --reuse` accepts them for the exact tip with matching checkout, inputs, environment and toolchain under 24 h, and logs the source SHA.

### Release gate

#### version-literals

Was: the row walked every file with `find`, including gitignored build caches.

Now: tracked files only in a git checkout, with a self-test scenario.
