What you can do now

02 / 06
01

Launching

Right model for the account

Waschoosing a Codex profile could open Codex on a Claude model and fail immediately.

Nowthe pane opens on a model the chosen harness supports, and a deliberately wrong choice is refused up front with a clear message.

02

Commander

Live sessions only

Wasthe conversation list included sessions with no supervisor and no workers.

Nowonly sessions with an active supervisor appear; dormant ones sit behind an off-by-default toggle.

Steadier checks

Wasone hub check could fail at random on a busy machine.

Nowit proves the old process is gone instead of comparing process numbers.

Under the hood

03 / 06
01

Factory

Per-harness launch recipes (#820)

WasFactoryConfig.supervisor_model/effort came from llm.model_for_role("supervisor") after resolve_supervisor_spec, so cli=codex still launched with claude-fable-5-1.

Nownormalize_spec_for_harness in cas-factory routing repairs an inherited incompatible model/effort to the harness recipe and refuses an explicit one at preflight; the pane wiring reads the resolved spec (cas-cli factory, daemon, cas-mux).

02

Hub and Commander

Dormant sessions

Wasthe session catalog and conversation list included sessions with no registered live supervisor.

Nowthe catalog marks sessions without an active supervisor (liveness evidence, not the session record) as dormant; hub-web hides them by default with a toggle, and a supervisor exit removes the row on the next refresh.

hub_clean_home_test (#826)

Wasassert_ne!(old_pid, new_pid) flaked on PID reuse.

Nowteardown proves the old process is gone via pid + start time.
