## What you can do now

### Launching

#### Right model for the account

Was: choosing a Codex profile could open Codex on a Claude model and fail immediately.

Now: the pane opens on a model the chosen harness supports, and a deliberately wrong choice is refused up front with a clear message.

### Commander

#### Live sessions only

Was: the conversation list included sessions with no supervisor and no workers.

Now: only sessions with an active supervisor appear; dormant ones sit behind an off-by-default toggle.

#### Steadier checks

Was: one hub check could fail at random on a busy machine.

Now: it proves the old process is gone instead of comparing process numbers.


## Under the hood

### Factory

#### Per-harness launch recipes (#820)

Was: `FactoryConfig.supervisor_model/effort` came from `llm.model_for_role("supervisor")` after `resolve_supervisor_spec`, so `cli=codex` still launched with `claude-fable-5-1`.

Now: `normalize_spec_for_harness` in `cas-factory` routing repairs an inherited incompatible model/effort to the harness recipe and refuses an explicit one at preflight; the pane wiring reads the resolved spec (cas-cli factory, daemon, cas-mux).

### Hub and Commander

#### Dormant sessions

Was: the session catalog and conversation list included sessions with no registered live supervisor.

Now: the catalog marks sessions without an active supervisor (liveness evidence, not the session record) as dormant; hub-web hides them by default with a toggle, and a supervisor exit removes the row on the next refresh.

#### hub_clean_home_test (#826)

Was: `assert_ne!(old_pid, new_pid)` flaked on PID reuse.

Now: teardown proves the old process is gone via pid + start time.
