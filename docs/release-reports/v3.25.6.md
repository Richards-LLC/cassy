## What you can do now

### Keep skills tidy

#### Understand expected Codex copies

Was: expected Codex skill copies could look like conflicting duplicates.

Now: `cas doctor` distinguishes intentional Codex twins from stale Cassy-managed copies and explains which cleanup is safe.

#### Preserve skills you own

Was: stale managed entries and user-created skill directories could receive the same cleanup advice.

Now: remedies reflect ownership; uncertain or user-owned content is left alone.

### See work accurately

#### Trust worker status

Was: an active Codex worker could appear dead, and a real exit could lose its result.

Now: status uses process identity and the Git worktree root, and shows available exit details with a bounded terminal excerpt.

### Clean up with confidence

#### Keep unrelated workspace data safe

Was: a directory name or Git relationship could make a user-created target look disposable.

Now: Cassy rechecks durable ownership before reclamation and preserves active, recent, replaced, or uncertain targets.

## Under the hood

### Delivery and proof

#### Close and platform evidence

Was: ambiguous pass notes or stale branches could satisfy a release check.

Now: bounded typed proof, delivered-content identity, and target-branch reachability must agree, including after request changes and across repositories.

#### Process and repository identity

Was: a live Codex process could be classified as dead, worktree paths could resolve differently, and EOF could hide a later exit code.

Now: validated process evidence and Git toplevel resolution are used; nonblocking reads retain eventual exit status and bounded PTY-tail evidence without inventing missing details.

### Safer execution and cleanup

#### Credential isolation

Was: factory launches could inherit protected machine-global operator values.

Now: protected names are removed unless an explicit task-scoped or project-scoped grant authorizes them; provider authentication remains available.

#### Owned-target reclamation

Was: branch naming and repository membership could be mistaken for Cassy ownership.

Now: discovery uses durable ownership evidence and cleanup revalidates it, refusing uncertain or replaced targets.

### Complete receipts and durable updates

#### PDF integrity

Was: an upload acknowledgement could stand in for proof of the stored document.

Now: size, SHA-256, PDF decoding, and page-count checks must match; the authenticated hub-read fallback is bounded from the user-thread root.

#### Concurrent notes and observations

Was: concurrent note appends could overwrite one another and hook observations could lose their originating session.

Now: appends are serialized and outcomes remain bound to their harness session.
