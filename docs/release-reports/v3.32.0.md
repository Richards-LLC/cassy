## What you can do now

### Everyday use

#### Suggested commands

Was: help text could offer a command Cassy rejects. →

Now: every suggested command is checked against what Cassy accepts.

#### Startup guidance

Was: session startup text could exceed its size limit and arrive as a preview. →

Now: it fits in full for every role.

#### Closing tasks

Was: close checks could judge an older version of your change. →

Now: they check the version you just delivered.

#### Command names

Was: messaging and team control shared one tool. →

Now: team control has its own tool; the old names still work this release.

### Your installation

#### Updates

Was: `cas update` left some skill files at their first version and kept retired ones. →

Now: it refreshes every file, keeps your edits, removes the rest.

#### Grok, OpenCode and Codex

Was: Grok and OpenCode could load skills with commands they cannot run. →

Now: each gets a copy that works for it.

#### Instruction files

Was: `CLAUDE.md` repeated the shared project instructions and grew past its limit. →

Now: the shared file leads and `CLAUDE.md` imports it.

#### Project boundaries

Was: rules and notes from one project could land in another. →

Now: Cassy refuses them and keeps them out of sync.

#### Release notes skill

Was: it was called `release-notes`. →

Now: it is `cas-release-notes`, so it no longer clashes with a Grok command.


## Under the hood

### Prompts and tools

#### Call-shape lint

Was: suggested calls could omit `summary`, `remind_message` or `dispatch_id`. →

Now: a test checks every call in skills and runtime templates.

#### Tool split

Was: `coordination` shipped 61 params to every session. →

Now: `factory` holds fleet, worktree, server, db, loop and queue; old names alias for one release.

#### SessionStart

Was: worker and supervisor payloads hit 11.8–13.2 KB, past the hook cap. →

Now: at most 9,216 B for every role, pinned by a test.

#### MCP schema

Was: one description passed the 2 KB cut and 16% of tools/list was boilerplate. →

Now: descriptions ≤2,048 chars, action enums, no nullable noise.

#### Worker prompts

Was: Claude workers in a Codex session got `mcp__cs__` names. →

Now: prefixes resolve per recipient and one renderer builds every contract.

#### Close gates

Was: gates keyed off stale heads, so one sibling merge voided other dispatches. →

Now: they use the current tip; platform proof defers to assembly.

### Catalog, install and store

#### One skill tree

Was: Claude, Codex and Grok catalogs were hand-kept twins. →

Now: bare tool names; Grok and OpenCode get project copies, Codex no `.md` agents.

#### Install sync

Was: non-SKILL.md files never refreshed after first install. →

Now: every file refreshes, removed files prune, and `cas doctor` reports parity.

#### Store guard

Was: another project's rules and pages could be written, pulled or pushed here. →

Now: writes are refused and sync keeps them out.

#### Verifier and Stop jobs

Was: task-verifier was 27.7 KB and session-learn parsed skill text. →

Now: 9.3 KB, a dedicated classifier, and `rule action=promote`.

#### Operator-data lint

Was: shipped skills carried real names and ids. →

Now: a lint keeps them synthetic.

#### Instruction files

Was: repo `CLAUDE.md` duplicated `AGENTS.md`. →

Now: `AGENTS.md` is canonical and `CLAUDE.md` imports it with Claude-only lines.
