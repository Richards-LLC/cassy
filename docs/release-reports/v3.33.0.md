## What you can do now

### Everyday use

#### Why questions

Was: asking why code was built a certain way got a plausible guess. →

Now: the `cas-why` skill answers from recorded history, rates each claim Documented, Inferred or Unknown, and lists where it looked.

#### Claims of done

Was: "done" could mean tested or merely assumed. →

Now: every claim is VERIFIED, NOT VERIFIED or INCONCLUSIVE, with proof scaled to the risk of the change.

#### Verification kit

Was: every QA pass rediscovered how to launch and drive your app. →

Now: `cas-qa-craft` writes a launch recipe and a feature map your project keeps in `docs/qa/`.

#### Feature map upkeep

Was: a feature map went stale without anyone noticing. →

Now: a static check and an opt-in close check name the stale file; `map unchanged: <reason>` accepts a change as is.

#### Automatic learning

Was: session learning reread whole transcripts at every stop. →

Now: by default it waits for 10 turns and 2 hours, then reads only what is new.

#### Lessons become checks

Was: every recurring lesson ended as a written rule. →

Now: lessons a check could enforce are tagged, and promoting one opens a task to build that check.

### Search

#### Search types

Was: the search tool's help left out `spec` and `artifact`. →

Now: it lists every type it accepts.


## Under the hood

### Verification and QA

#### Claim verdicts

Was: verify-before-claim and task-verifier had no shared verdict. →

Now: VERIFIED / NOT VERIFIED / INCONCLUSIVE per claim, a four-rung blast-radius ladder, same-command baseline/treatment.

#### Verification kit

Was: no reusable launch and drive recipe per project. →

Now: `cas-qa-craft` generates `docs/qa/verify.md` and `docs/qa/features/`; `check-feature-map.mjs` checks headings, Touches globs and the index.

#### Feature-map close gate

Was: nothing tied a diff to its feature doc. →

Now: opt-in on `docs/qa/features/`; a touched glob without its feature file refuses unless a `map unchanged: <reason>` decision note exists.

### Merges and closes

#### Red lane CI

Was: `worktree_merge` treated CI as advisory, so a red lane merged. →

Now: red refuses with the run URL; `supervisor_override=true` needs a reason and is logged; pending never waits.

#### Repeat refusals

Was: the same close gate could refuse the same patch loop again and again. →

Now: repeatable refusals end with a premise-note stop; the merge-required handoff omits it.

#### Failure policy

Was: retries and close reasons were free-form. →

Now: retry by failure mode with a two-retry cap, four required brief fields, PASS/ISSUES close reasons, patch-id re-verify.

### Learning and skills

#### Session-learn cadence

Was: every Stop reread the whole transcript. →

Now: `memory.session_learn_min_turns` (10) and `memory.session_learn_min_minutes` (120) gate runs; a path+mtime index mines only the delta.

#### Enforcement ladder

Was: every lesson ended as a prose rule. →

Now: reviewers tag `enforceable:<lint|hook|gate|type>`; promoting one with two or more sources files a single encode chore.

#### Text pins

Was: rewording a skill sentence could fail a release gate. →

Now: tests assert call shapes, files and links; literal substring probes 1,026 → 809.

#### Vocabulary lint

Was: stock AI phrasing could ship in builtin text. →

Now: a word-list lint covers every builtin, with a reasoned allowlist.

#### cas-why

Was: no workflow for "why was it built this way". →

Now: blame, history provenance, tasks and memories feed tiered claims and a coverage map that keeps null results.

#### Cleanup

Was: `search` `doc_type` help omitted `spec`/`artifact`; hub-web and slack-bridge carried dead scripts and exports. →

Now: both fixed; hub dist is byte-identical.
