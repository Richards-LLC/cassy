## What you can do now

### Only reply (user)

#### Start from Commander

Was: to start a session on another computer you had to SSH in and run a wrapper. →

Now: New session picks the machine, project and account, then starts it there.

#### Keeps running

Was: a remote session lived in a terminal you had to keep open. →

Now: it keeps running after you close the browser, and when the machine's hub restarts.

#### Every account listed

Was: a remote start used whichever account that machine happened to pick. →

Now: every Claude and Codex account on it is listed, logged-out ones show their login command.

#### Your permission

Was: any paired phone or browser could only watch and type. →

Now: starting sessions is a separate permission you grant to each device on purpose.

#### Team-only projects

Was: a team project also kept personal copies of every task and memory. →

Now: a project can opt in to syncing only with its team.


## Under the hood

### Only reply (dev)

#### Launch endpoint

Was: `/v1/sessions` was read-only. →

Now: `POST /v1/sessions` takes a registry or browse target, a CLI, an optional profile and workers; it is single-flight per project, returns Attach for a running project, and is audited.

#### Survives hub restarts

Was: a hub child would die with `cas-hub.service` (`KillMode=control-group`). →

Now: each session runs as a transient `cas-factory-<session>` user unit under a `cas hub reap-daemon` reaper that writes the exit receipt.

#### Service environment

Was: a service-started CLI saw an empty PATH and the `main` profile. →

Now: `hub::launch_env` probes the login-shell PATH once, sets the account from `[hub.launch_profiles]`, and strips ambient tokens.

#### Targets and profiles

Was: no project or account catalog. →

Now: `GET /v1/projects` lists main repo roots only, `/v1/projects/browse` stays inside `[hub] launch_roots`, and `GET /v1/launch/profiles` reports each CLI on its own.

#### Team-only sync

Was: every project write was queued for personal and team scope. →

Now: `cloud.team_only` routes project rows to the team only and holds personal rows, since the server requires a project identity.
