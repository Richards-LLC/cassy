## What you can do now

### Only reply (user)

#### Tests while building

Was: new tests first ran hours later, at release time. →

Now: each change runs the tests it affects before it is handed off.

#### Earlier checks

Was: some cheap checks only ran just before a release. →

Now: they run every time a change is merged.

#### Clearer change summaries

Was: a change arrived as a list of commit messages. →

Now: it shows a short picture of what changed, before-and-after proof, and how risky it is to undo.

#### Lessons that stick

Was: the same kind of mistake could come back release after release. →

Now: a mechanical mistake turns into an automatic check the first time it happens.

#### Finished means shipped

Was: work could be called done while still waiting to be released. →

Now: a release is complete only when the installed version provably contains every change.


## Under the hood

### Only reply (dev)

#### Targeted tests

Was: workers could run only `cargo check`. →

Now: `cargo nextest run -p <crate> -E 'test(name)'` through the capped O_CLOEXEC runner, with zero-match failure and clean-commit receipts.

#### Two-axis review

Was: one task-verifier verdict mixed spec and standards. →

Now: separate Spec and Standards reviewers commit to side refs and cross-check each other, supervisor-only and in shadow mode; `CODING_STANDARDS.md` feeds Standards.

#### Merge-time gate rows

Was: workflow interpolation, test inventory and doc hygiene surfaced at the release gate. →

Now: `release-gate.sh --fast-rows` runs at every lane merge and in Scoped Validation, with a test-shape lint and a ratcheted process-state lint that requires the shared test-env guard.

#### Learning loop

Was: 25 draft rules and no encode chores. →

Now: a mechanical rule files its check on first occurrence; `cas-retro` turns release evidence into tasks.

#### Contract registry

Was: hundreds of wording pins across skill tests. →

Now: one registry of reasoned contract phrases, with every negative safety guard kept.

#### Release train

Was: the gate re-ran the suite, and a latency overrun or a stale resume stopped the cut. →

Now: proof reuse names the first differing input, overruns are recorded, resume re-assembles, and rule-175 requires install proof of every merged change.

#### Terminal exchange

Was: keyframe-before-output order was pinned by a test that read source text. →

Now: one owned daemon step captures, drains and queues, and a test checks the order of delivered frames.

#### Store and sync

Was: JSON-array `proof_targets` were stored as fragments, and a team pull could revert `awaiting_merge`. →

Now: targets are normalised by migration 262, and lifecycle regressions are refused.
