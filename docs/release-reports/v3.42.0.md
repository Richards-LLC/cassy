## What you can do now

### Only reply (user)

#### Clear pairing status

Was: when your only paired machine's pairing was revoked, the header said "Needs pairing" but the footer kept saying "Reconnecting", as if waiting would help. →

Now: every part of the screen, footer included, says "Needs pairing".

#### Loops start reliably

Was: starting a loop could fail with a database error when another loop had started at nearly the same moment. →

Now: each loop gets a unique identifier, so starting one always works.

#### Tests that catch real problems

Was: some of Cassy's own checks could pass without testing anything. →

Now: they fail when something breaks; tightening them is how the loop problem above was found.


## Under the hood

### Only reply (dev)

#### Loop ID collisions

Was: `SqliteLoopStore::generate_id` kept the last 4 hex digits of the millisecond clock, so two `loop_start` calls in one millisecond, or IDs a multiple of ~65.5 s apart, hit `UNIQUE constraint failed: loops.id`. →

Now: `loop-` plus 64 random bits, checked against stored rows with bounded retries; existing IDs unchanged.

#### Revoked-pairing footer

Was: `machineFooterMarkup` chose "Reconnecting" from `everConnected` alone and ignored auth loss. →

Now: the footer uses the shared `machineConnectionLabel`; auth-lost rows are excluded from reconnect aggregation.

#### False-green tests removed

Was: six semantic-search tests returned before asserting; the cloud-sync CLI e2e was unwired and accepted auth/config failure; PTY smoke tests matched the echoed command; 41 tests for removed CLI commands sat ignored. →

Now: current-seam replacements with independent assertions, request counts and durable read-back.

#### Env-guard ownership

Was: 1,066 recorded unguarded env/cwd mutation sites and a private mutex in `mcp_tools_test`. →

Now: one canonical `TestEnvGuard` held for each test's lifetime; the baseline is 143 sites and `check-test-env` flags raw mutation under a held guard.

#### CI and journeys

Was: a stdin-race flake in the scoped-proof inventory, a 121 s network journey built on fixed waits, and a text-matching CI policy script. →

Now: a draining checker stub, a protocol-clock journey at 60 s, and parsed CI policy with PyYAML installed into an isolated venv only when missing.
