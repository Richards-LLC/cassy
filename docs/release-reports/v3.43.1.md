## What you can do now

### Only reply (user)

#### Updates finish with linked account configs

Was: if a Claude or Codex account's config file was a link to a shared file, `cas update` refused it and skipped the skills refresh in every project. →

Now: it updates the shared file through the link, keeps the link and its permissions, and finishes in every project. A broken or unsafe link is skipped with a warning that names it.

#### Each session shows its own conversation

Was: every session of a project opened onto the same old Commander conversation, so live sessions looked like copies of a stale one. →

Now: a session shows only its own messages. Earlier sessions appear in a labelled, collapsed section, and a session with no messages yet says so and shows what it last did.

#### Sessions are easier to tell apart

Was: several live sessions of one project looked alike. →

Now: they are grouped under the project, with the most recent one marked and each row's last activity shown. You can end a session from Commander after confirming.


## Under the hood

### Only reply (dev)

#### Symlinked profile migration

Was: the Violet retirement read profile configs through the symlink-refusing reader, and its error propagated through `retire_installed_hub` into the update and sync skills phase, failing all projects plus the user-level store. →

Now: profile config and skills paths are canonicalized and must resolve inside HOME or an explicit `CLAUDE_CONFIG_DIR`/`CODEX_HOME`. Shared targets are deduplicated and edited once through an atomic temp-and-rename that keeps the link. Dangling, cyclic, out-of-root, unparsable or directory paths become per-file warnings.

#### Config permissions kept

Was: the atomic writer created replacement files with default permissions. →

Now: it copies an existing file's mode, so a 0600 credential config stays 0600.

#### Session-scoped Commander history

Was: conversation history was project-wide, so every session of a project returned the same rows. →

Now: history binds to the requesting factory session. Earlier sessions arrive as separate read-only sections, and the catalog carries last-activity, most-recent and end-session data per live session.
