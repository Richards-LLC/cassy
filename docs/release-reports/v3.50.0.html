What you can do now

02 / 06
01

Many sessions on one machine

No more freezes

Waswith a dozen Cassy sessions running, the screen and messages could freeze for seconds while one session waited on another. →

Nowthe main screen never waits on the database, so it keeps up. In a test with 16 sessions working at once, the main screen finished 99.5% of its updates in under a tenth of a second, where before it stalled for more than two seconds at a time.

Storage stays bounded

WasCassy's database grew without limit, mostly from repeated delivery notes and old message transcripts. →

Nowroutine logs are cleared after 14 days and transcripts after 7, while task and code history is kept.

One code index per project

Wasevery copy of a project built its own code index, and copies left behind kept growing. →

Nowthere is one index per project, leftovers are cleaned up, and cas doctor --fix removes stray copies.

Codex starts one Cassy, not two

Waseach Codex session started two Cassy servers that competed for the same files. →

Nowit starts one.

The screen no longer pauses to refresh

Wasevery two seconds the main screen stopped to reread every task, agent and recent event, so with many sessions it hitched for a few tenths of a second each time. →

Nowthat reading happens in the background and the screen picks up the result a moment later, so it never stops to wait.

No more rare freezes when work finishes

Wasvery occasionally a Cassy process could freeze for good when two of its database connections closed at the same moment. →

Nowthat can't happen any more.

02

Slack

Hand-offs stay with people

Wasa Slack message that tagged a colleague woke Cassy as if it were meant for Violet. →

NowCassy sees it is for that person and leaves it to them.

See what Slack watching is doing

Wasthere was no way to tell which channels Cassy was watching or whether its Slack link worked. →

Nowthe status screen lists each watched channel, and cas doctor warns when the link keeps failing.

Connect a Slack channel yourself

Waslinking a Slack channel to a project needed a manual request. →

Nowcas integrate violet --channel <name> links it.

Violet setup no longer loops

Wassetup could keep saying "run cas login" for a Slack key that signing in never creates. →

Nowit uses this machine's own key and names exactly what to fix.

Claude Code check is honest

Wassetup said Claude Code was "already current" while Slack rejected its key. →

Nowit checks with Slack, says when the key is refused, and repairs other Claude Code profiles on the machine too.

Connected tools come back on their own

Wasafter one dropped connection, Slack and other connected tools stayed unreachable until Cassy restarted, and a stuck request could hang for over 15 minutes. →

NowCassy reconnects on the next request, gives up on a stuck one after 90 seconds, and says plainly what is wrong.

03

Cassy Cloud

Answers to terminal questions on your phone

WasCassy Cloud showed your terminal questions but not the answers. →

Noweach answer appears under its question.

Switching conversations always works

Wastapping a conversation sometimes did nothing or opened the wrong one, because the list reordered or refreshed while your finger was on it. →

Nowthe conversation you pressed opens every time, and an older load never replaces a newer choice.

Install Cassy Cloud as an app

WasCassy Cloud's icon was a pale, flat mark that was hard to see, and the site could not be installed as an app. →

Nowa new violet icon, and Cassy Cloud installs as an app on a phone or computer, fits around the iPhone notch, with a sharp icon on light and dark home screens.

04

Folders outside the project

Let a project write to other folders

WasCassy's agents could only write inside their own project, so updating a config folder elsewhere meant copying files by hand. →

Nowyou can let a project write to folders outside its own, from the terminal or from Commander on your phone, for the whole project or just one task.

You stay in charge

Wasnothing said which outside folders an agent could touch. →

Nowonly you can add a folder, after confirming it; agents can't add one themselves, each write there is logged, and with no folders added nothing changes.

Checks and sync

Screenshot checks wait for the real page

Wasstrict screenshot checks passed on a page still showing a loading spinner, and flagged text that was only fading in. →

Nowthey wait for the page to render and settle, and still fail on text that stays invisible.

Tasks owned by another project

WasCloud sync called a task already owned by another project an "unrecognized" problem. →

Nowit names that project and the fix.

Long jobs are not "stalled"

Wasa session busy in one long job set off repeated "stalled" alerts. →

Nowit is recognised as busy, and alerts are combined.

Under the hood

03 / 06
01

Many-agent scale

Lock-free daemon loop

Wasthe factory loop ran store reads and writes inline and could wait seconds on SQLite busy or flocks. →

Noweach pass has a 50 ms per-thread wait budget, CI-watch, lifecycle outbox, attention relays and task-dialog loads run on an ordered store worker, and loop.json reports max, p99 and ≥100 ms passes per window. Measured with scripts/many-agent-load.py (16 cas serve agents plus a headless daemon, code index on, two synthetic writers each holding the write lock about 400 ms in every second, 300 s): 3 of 636 daemon passes took 100 ms or more (0.47%, max 121 ms), MCP task/coordination p99 1.74 s and no wait on the task-sync lease. Without the writers it was 0.15% (max 120 ms) and p99 0.19 s, and at 32 agents 0.44% (max 114 ms) and p99 1.94 s. On 3.49.0 (0d670c33c), 16 agents under the same pressure (code index off) gave p99 2.05 s, 41 lease waits of 0.4 s or more and daemon passes of at least 2.35 s.

Task-store opens

Wasevery open reconciled under the exclusive task-sync-intents.lock. →

Nowthe lock is a shared per-process lease, mutations serialize on 64 per-entity stripes, reconcile takes a 100 ms bounded BEGIN IMMEDIATE and defers when busy, and opens reconcile once per process then every 60 s.

Pooled writers

Wasa pooled caller held the process-wide connection mutex through six busy waits (~31.6 s). →

Nowbegin_immediate_pooled takes the mutex per attempt and drops it before each backoff; history commit_batch takes the write lock first and skips unchanged FTS rows.

One code index per project

Wasevery worker and worktree indexed into the shared store, leaving per-worktree copies. →

Nowonly the canonical checkout's process indexes, reconciles and purges; worktree copies are purged in bounded rowid batches with FK enforcement suspended per transaction; doctor reports per-repo counts and --fix purges.

One cas serve per Codex worker

Wasa user-level [mcp_servers.cas] plus the spawn-injected cs key started two serves per worker. →

Nowother Cassy keys are disabled with a complete inline table and the config writer converges on cs.

Bounded event log

Wasevents was never pruned (1.08 M rows, ~450 MB with indexes, 800 k of them supervisor_injected). →

Nowtelemetry types expire after factory.event_telemetry_retention_days (14) in ≤1,000-row IMMEDIATE batches on the canonical daemon every 15 min, ungated on idle; lifecycle types are kept, identical injection retries are recorded once, and no-op re-offers are recorded as reoffered.

Prompt and queue retention

Wasprompts, prompt_queue and supervisor_queue grew unbounded. →

Nowmessages_json is nulled after factory.prompt_transcript_retention_days (7), delivered queue and outbox rows are removed after factory.supervisor_queue_retention_days (14), all in the same batched driver.

Refresh reads off the loop

Wasthe 2 s director refresh read every task, agent and recent event on the loop thread and delivery reread the snapshot before revalidating, while the agent and event stores took the process-wide connection with a plain mutex outside the pass budget (13.9% of passes ≥100 ms at N=16, max 402 ms). →

Nowboth reads run on one background reader with its own WAL connection, the loop applies the finished snapshot on a later pass (panels stale by at most one refresh; events are revalidated against a read taken after detection), the agent and event stores honour the 50 ms pass budget, and loop.json adds phase_latency (entries, max and ≥100 ms runs per phase, with refresh split into its steps).

SQLite close deadlock

Wasbundled SQLite 3.51.1 could deadlock forever when two WAL connections in one process closed at once (unixLock held the inode lock mutex while unixIsSharingShmNode took the global VFS mutex, and unixClose took them in the opposite order); no busy timeout or wait budget bounds that wait. →

Nowrusqlite 0.39 bundles SQLite 3.51.3, which carries the 3.51.2 fix for that deadlock and the WAL-reset corruption fix, and a test fails if an older SQLite is bundled.

02

Violet

Same-hub project override

Wasa project [servers.violet] at the machine's hub URL naming another machine's token kept integrate stale and advised cas login (GH #1164). →

Nowit is dropped, the machine token verifies the hub, a 401 names the variable and the re-mint path, and no hub-token advice names cas login.

Claude Code verification

Wasclaude-code reported "already current" structurally and only the CLAUDE_CONFIG_DIR profile was reconciled. →

Noweach entry carries the authenticated tools/list verdict, and every ~/.claude* profile that already registers violet is rewritten from literal or legacy refs to env references.

Push-wake follow-ups

Wasa wake could not tell a hand-off from a mention of Violet, and watch state was invisible. →

Nowmessage.mentions with only people marks the wake addressed="human", WatchBook.relay records every claim tick, cas factory status and --json show watches and relay health, and doctor adds a violet wake row.

--channel mapping

Waschannel→project mappings were registered by hand. →

Nowcas integrate violet --channel calls hub PUT /api/channels/{channel} with the Cloud login, with --channel-replace and --channel-remove.

MCP upstream reconnect

Wasafter a transport error the proxy dropped the upstream, so mcp_execute said "absent … restore its credential" for the rest of the session while proxy_health stayed healthy, and a hung call held ~1000 s (GH #1168). →

Nowa dropped upstream reconnects on demand once its backoff is due, every call is bounded client-side (90 s, call_timeout_secs in proxy.toml), proxy_health is republished when a call changes health, and the absent message names the cause.

03

Cassy Cloud

Terminal answers mirrored

Wasthe Commander reply mirror ran only after a verified paired-device send, so a terminal-only operator saw questions without answers. →

Nowany operator activity activates it, a ±120 s terminal-question match threads the answer via reply_to, and harness prompts are excluded.

Conversation switching

Wasa catalog update between press and release lost the tap: grouped rows re-sorted and insertBefore moved another row under the finger, and a session start or end rebuilt the shell and detached the pressed button. →

NowConversationList holds the pressed row by key for the gesture, redirects a stray click to it, opens it on a timer when no click arrives (0 ms mouse, 300 ms touch, late touch click absorbed), and a stale open never attaches after a newer selection.

App icon and install

Wasthe mark was flat ink inheriting --color-action (pale #A9B3FF on the dark Glass field) and there was no web app manifest. →

Nowa --look-send violet-gradient tile (#7656FA→#5B3FE0→#3E5BEA) with white and aurora ribbons; render-brand-icons.mjs paints favicon 16/32, apple-touch 180 and 192/512 any and maskable icons from favicon.svg; manifest.webmanifest (Cassy, standalone, theme #5B3FE0, background #0E0C20) and the iOS meta make it installable; headers and sheets pad env(safe-area-inset-*) (e2e/installed-safe-area.spec.ts); DESIGN.md "Brand" records sizes and contrast.

04

Write roots (GH #1169)

Operator write roots

Wasthe workspace contract sanctioned only the worktree, artifacts, scratch and the harness scratchpad, with no override. →

Now.cas/operator/write-policy.toml adds project roots (cas config set factory.write_roots "~/a,~/b:create+edit+delete") and per-task grants (cas config grant-write, expiring at task close), each judged per create/edit/delete mode, audited as workspace_write_root_used, and listed in refusals.

Operator-only, guardrail-grade

Wasthere was no operator-only setting; anything an agent could run, it could configure. →

NowConfig::set refuses the factory.write_roots key specifically; the CLI refuses agent env markers, agent or cas serve ancestors, factory cgroups and non-TTY runs, and asks for a typed confirmation; PreToolUse refuses agent writes under .cas/operator/ and agent calls of the commands. Agents share the operator's Unix user, so the hook is the gate, not a security boundary.

Commander grants

Wasgrants needed the operator's terminal. →

NowPOST /v1/sessions/{s}/write-grants (DPoP device auth plus factory:manage) has the hub write or revoke the grant as commander-device:<id>, note the task, audit it and post a verified operator receipt; hub-web adds a Write access panel with confirmation.

Unchanged by default

Wassed -i and mv sources were never judged. →

Nowwith a policy file they are judged as edits; without one the contract is exactly as before.

05

Visual QA

Readiness

Was--strict passed on a spinner-only page (GH #1159). →

Nowa bounded readiness wait (--ready-selector, --ready-timeout-ms) and a non-allowlistable page-not-ready finding.

Settle on quiescence

WassettlePage finished only animations already running, so a post-load enter transition read as invisible-text (GH #1158). →

Nowsettle waits for 500 ms without DOM mutations or animations, bounded at 3 s.

Scoped comparisons

Wasa per-source report with renders[].issues could not be compared (GH #1166). →

Nowit is flattened and paired by the same rules.

06

Closes, delivery and workers

Reviewed drop

Wasreviewed-drop rejected superseding commits older than the delivery anchor (GH #1160). →

Nowthey are accepted with per-path coverage on the target.

No-code close

Wasa no-code task without a work target needed a branch (GH #1167). →

Nowonly commits naming the task count as its own; retained anchors still bind.

Delivery stalls

Wasa Codex worker busy in one long turn raised repeated worker_delivery_stalled alerts (GH #1163). →

Nowexecuting liveness defers the probe, recipient replies and notes retire it, and alerts coalesce per worker per 5-minute window.

Build guard

Wasenv -u VAR cargo nextest … named VAR as the executable and ran raw cargo. →

Nowenv and sudo value options consume their value and env -S payloads are inspected.

Stale index.lock

Wasa killed git status probe could leave a zero-byte index.lock. →

Nowread-only probes run with GIT_OPTIONAL_LOCKS=0, and a worker may remove an unheld stale lock in its own gitdir.

Cloud duplicates

Wasduplicate_of_other_project was reported as an unrecognized reason. →

Nowthe owning project is kept in diagnostics, with the alias-fold and adopt-aliases remedy.

07

Release train

Integration identity

Wasthe integration branch name was derived from the checkout directory, and epics merged to main by PR had no assembly path. →

Nowit is persisted as cas.integrationBranch, from-main assembly is supported, and its gate refuses --reuse and --only.

Gate scratch and renderer

Wasgate scratch could land on another filesystem, and a missing report renderer surfaced only after publish. →

Nowscratch defaults beside the checkout, and preflight launches the renderer's headless Chromium.
