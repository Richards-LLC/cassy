## What you can do now

### Folders a project may work in, set per project

#### A normal project setting

Was: the folders a project could write to outside its own directory lived in a separate hidden file. →

Now: they are part of the project's settings and show up in `cas config list`.

#### Set it from where you work

Was: setting them asked you to retype a confirmation at a terminal, and running it with `!` inside a Cassy window was refused. →

Now: `cas config set factory.write_roots "~/Downloads,/mnt/models"` just works, including with `!` in a Cassy window.

#### Per project, as intended

Was: it was unclear which projects an outside folder applied to. →

Now: each project has its own list, so adding `~/Downloads` to one project leaves every other project unchanged.

#### Simpler and safer

Was: each folder needed separate create, edit and delete choices. →

Now: a listed folder allows all three, and Cassy refuses risky choices like your whole home folder or the project's own settings.

#### Only you can change it

Was: the old confirmation step was the main safeguard. →

Now: Cassy's assistants can't add folders or edit the project settings file themselves, and `cas config set factory.write_roots ""` clears the list.

#### Nothing to redo

Was: folders you added in v3.50.0 were stored in the old file. →

Now: they keep working and move into the project settings the next time you set the list. One-off folder grants for a single task work as before.


## Under the hood

### Project write roots in config.toml (GH #1182)

#### Config key

Was: 3.50.0 stored project roots in `.cas/operator/write-policy.toml`, invisible to `cas config list`. →

Now: `[factory] write_roots = [...]` in the project's `.cas/config.toml`, registered and shown by `config get`/`list`, read by PreToolUse from the owning project's cas root (also for isolated worktrees).

#### Operator set path

Was: `cas config set factory.write_roots` required no agent env markers, no agent ancestor, a TTY and a typed `ALLOW`, so the operator's `! cas …` from a pane was refused. →

Now: it refuses only a `cas-worker-*` or `cas-server-*` cgroup and writes config.toml directly.

#### Set-time validation

Was: entries were `path[:modes]`, canonicalized, refusing `/`, `$HOME` and `.cas/operator`. →

Now: plain paths, each allowing create, edit and delete. Paths are canonicalized; `..` components, `/`, `$HOME` and its ancestors, the project root, and anything containing or inside `.cas/` are refused. The hook re-checks each entry and skips unsafe ones.

#### Hook is the agent gate

Was: agents were kept out by the separate policy file. →

Now: PreToolUse refuses agent `cas config set factory.write_roots`, and agent writes, in-place edits, renames and deletes of `.cas/config.toml`, `.cas/config.yaml` and `.cas/operator/` (file tools, NotebookEdit, apply_patch, redirections, tee, cp, mv, `sed -i`, `perl -i`, rm). No root admits any project's `.cas/config.*` or `.cas/operator/`.

#### Other write paths

Was: `Config::set` refused the key because roots were not in config.toml. →

Now: it still refuses it, so MCP, the config TUI and reset cannot widen roots, and `cas config import` keeps the current value.

#### Compatibility

Was: roots and grants shared write-policy.toml. →

Now: legacy roots are unioned in the hook and migrated on the next set (an empty value clears both). Per-task grants (`cas config grant-write`, Commander) stay in the operator file, unchanged. With no roots configured, the workspace contract is unchanged except for the config-file refusal.

#### CLI output

Was: `cas config set --help` printed 337- and 486-column lines. →

Now: help, set/get output and refusals wrap at 78 columns in ASCII.
