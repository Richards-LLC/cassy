## What you can do now

### Starting Cassy works again

#### Start from your own terminal

Was: `cas factory` and `cas claude <account>` could stop with "… is set, so this runs inside an agent session", even in your own terminal, with default settings. →

Now: Cassy starts normally from your terminal. Starting a factory from inside an assistant's window is still refused, as intended.

#### Your shell settings are respected

Was: Claude Code preferences in your shell profile, or Cassy's own build settings, were mistaken for an assistant session. →

Now: only real assistant sessions are recognised, so these settings no longer block you.

#### Undo the workaround

Was: the workaround was turning off low-priority builds or unsetting shell variables. →

Now: after `cas update` you can set `nice_cargo = true` again in the `[factory]` section of your config files.

#### Finished work can be closed

Was: older work whose changes had already shipped could not be closed without re-running all checks on an old version. →

Now: it can be closed using a recent full check of the current version.

#### Jev removed

Was: Cassy included an optional decision helper called Jev. →

Now: it is gone. Settings files that still mention it keep working.


## Under the hood

### Operator launch, merged-epic close, Jev removal (PR #1191)

#### Operator-only gate

Was: `AGENT_ENV_PREFIXES` matched `CAS_FACTORY_`, `CLAUDE_CODE_` and `CAS_AGENT_`. `cas` exports `CAS_FACTORY_NICE_WORKER` itself when `factory.nice_cargo` is on (the default), so `cas factory` and `cas claude <account>` refused their own launch. A shell exporting `CLAUDE_CODE_NATIVE_CURSOR` was refused too. →

Now: the prefix list is gone and only exact markers count: `CAS_AGENT_NAME`, `CAS_AGENT_ROLE`, `CAS_AGENT_ID`, `CAS_SESSION_ID`, `CAS_CLONE_PATH`, `CAS_SUPERVISOR_NAME`, `CAS_FACTORY_MODE`, `CAS_FACTORY_SESSION`, `CAS_FACTORY_WORKER_NAMES`, `CLAUDECODE`, `CLAUDE_CODE_ENTRYPOINT` and the Codex sandbox markers. The harness-ancestor and worker-cgroup checks are unchanged. The refusal text names the remedy.

#### Merged-epic journey receipt

Was: the epic close gate required a full-suite journey receipt at the epic's own tip, inside its own artifact directory. That can't be produced honestly once the epic is in main, and branchless epics failed as "journey tip unreadable". →

Now: an epic contained in `origin/main` accepts a full receipt whose head is a trunk commit containing the epic tip (or a branchless epic's children's trunk deliveries), cited from any task artifact directory under the project root. Unmerged epics keep the exact-tip rule. The decision note records the containment proof.

#### Jev removed

Was: `cas jev`, the `jev` MCP tool, a PreToolUse shadow observer, the `cas-jev` builtin skill and the `jev.*` config keys. →

Now: all removed. A `[jev]` config section loads with a one-line note, and `cas update` prunes installed `cas-jev` skill copies.
