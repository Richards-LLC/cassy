## What you can do now

### Faster releases you can trust

#### Checks run side by side

Was: the final release check ran about thirty steps one after another. →

Now: independent steps run together within the machine's memory.

#### One build per release

Was: the same release was built three times on its way out. →

Now: it is built once and reused, and the Mac build is about half as long.

#### Quicker test runs

Was: every small change re-ran the full test suite of nearly 12,000 tests. →

Now: only the tests a change can affect run.

#### Mistakes caught earlier

Was: a typo or version number in a comment was found only after a long remote check. →

Now: it is caught in seconds, before the change is sent, with the exact fix shown.

#### Cassy always opens

Was: one release could not start for anyone on the default settings, and nothing noticed. →

Now: every release is started the way you start it before it ships.

#### Lessons stick

Was: the same release problem could be noted as learned again and again. →

Now: a repeat needs a real fix, and old noise was cleared from memory.


## Under the hood

### Release pipeline

#### Parallel gate

Was: about 30 release-gate rows ran sequentially (29 min on 3.51.1). →

Now: rows declare `cpu`, `mem=`, `excl=`, `after=` and `writes-tree`, run concurrently under the assembly-proof memory budget with private scratch, and keep canonical receipt order. `CAS_RELEASE_GATE_PARALLEL=1` restores serial.

#### One build

Was: the gate, the publisher and CI each built the release binary. →

Now: `release-binary-isa` records a manifest-bound archive, and `release.sh` reuses it on a full match (10 m 55 s rebuild → 33.7 s audit). The macOS asset builds with LTO off (1686 s → 912 s cold).

#### Scoped CI

Was: nextest's progress counter broke `ci-test-impact.py`'s FAIL parser, so every factory lane ran all 11,850 tests. →

Now: the counter parses, poisoned history is re-read from the uploaded logs, and a failed lib test reruns exactly (876 s → 332 s).

#### Shift left

Was: second-scale mistakes cost a CI or merge-queue round. →

Now: `--fast-rows` covers next-version literals, `CARGO_BIN_EXE_*`, call shapes and release-notes drafts, prints `FIX` lines, and runs in a factory pre-push hook. `test-release-gate.sh` went from 2165 s to about 115 s.

#### Operator launch smoke

Was: 3.51.0 shipped unable to launch `cas factory` on default config. →

Now: the `operator-launch-smoke` row and the install-path proof run the real binary from a clean operator shell (hidden `--check-launch`).

#### Budgets and learning

Was: latency regressions and repeat failures were found by hand. →

Now: versioned stage budgets (including commit-to-main) fail the report and file one P0, and a failure class learned twice needs an open P0/P1 cause task. `scripts/release_env.py` resolves Zig, scratch and toolchain for every caller.
