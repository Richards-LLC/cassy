## What you can do now

### Releases that ship themselves

#### One step to release

Was: a release passed a long chain of manual stages after the work was done. →

Now: one command prepares it, and landing the change publishes it.

#### Checked once

Was: the same checks ran again and again before a release. →

Now: each check runs once, in the shared queue.

#### Built once

Was: the release was built several times on its way out. →

Now: it is built while the final checks run, and those exact files ship.

#### Installs itself

Was: someone had to install each new release by hand. →

Now: the machine installs it within a minute of publishing.

#### Faster finishes

Was: finishing a task waited on extra local checks. →

Now: work finishes as soon as it is reviewed and merged.


## Under the hood

### Release pipeline

#### One-command release

Was: a release PR, its own queue cycle and a local tag push followed every epic. →

Now: `scripts/release.sh` commits the bump, CHANGELOG and draft to the epic PR, enables auto-merge and re-bumps when another release lands first.

#### Build once

Was: release binaries were built on the release branch, on main and by the local publisher. →

Now: `release-prebuild.yml` builds Linux and macOS on the `merge_group` run; `release.yml` adopts them by tree id, runs the ISA audit and launch smoke on both packaged assets, then tags and publishes.

#### Install on publish

Was: an agent hop installed each release. →

Now: a systemd user timer runs `cas update` within a minute and writes the PR-opened-to-installed time into the release notes.

#### Unpinned CI

Was: hundreds of text pins failed any CI edit and the queue preflight ran as one serial job. →

Now: `policy.json` holds only the required contexts and the preflight runs as independent jobs.

#### No re-runs

Was: the daemon swept and re-tested after every merge, and close, merge admission and push re-ran the fast rows, journey and lane-compile receipts. →

Now: lane CI runs the fast checks once and the merge queue is the only gate to main; the self-hosted release routing is gone.

#### Measured on this release

Was: code-done → main 193.7 min and main → installed 95.4 min (3.53). →

Now: PR opened → main 28 m 41 s, including one queue retry, and main → installed 6 m 17 s (published 5 m 18 s after the merge, installed 48 s after detection), against budgets of 30 and 20 minutes.
