## What you can do now

### Smoother sessions

#### Instant typing

Was: with many sessions busy, a keystroke could take about 80 ms to appear.

Now: it appears in about 13 ms.

#### Faster tools under load

Was: tool calls could take over 2 seconds while the database was busy.

Now: they stay under 2 seconds.

#### Starts reliably

Was: a session could fail to start while another was creating a task.

Now: it starts.

#### One alert for a crash

Was: when several helpers stopped at once, you got one alert per helper plus a group alert.

Now: one alert lists each helper's last output.

#### No stale alerts

Was: alerts for finished work, moved branches or old checks could arrive hours late.

Now: out-of-date alerts expire quietly, and the banner of undelivered alerts clears itself.

#### Focus kept on shutdown

Was: a project focus chosen just before shutdown could be lost.

Now: it is saved.

### Projects, Slack and the cloud

#### Batch QA

Was: every change needed its own QA pass.

Now: a project can choose one review walk for a whole batch of changes.

#### Two leads, one project

Was: starting a second lead session on the same project stopped the first one's Slack watches.

Now: each keeps its own.

#### Clean sign-off

Was: a busy cloud could leave a closed session listed for up to a day.

Now: sign-off retries until it goes through, and "rate limited" is named as the cause.

#### Right session after /clear

Was: after /clear, the old session could keep the heartbeat.

Now: the new session keeps it.

#### Fresh project branches

Was: new work could start from an unpublished or months-old project branch.

Now: the branch is published and brought up to date first.

#### Finished work merges

Was: finished work could not merge while its author had already started on something else.

Now: it merges, and the new work is left untouched.

#### Safer commands

Was: some read commands could be made to run other programs, while harmless searches were refused.

Now: risky options are refused and plain searches work.

### Commander

#### Designed type everywhere

Was: Commander used each machine's own fallback fonts.

Now: it ships Inter and JetBrains Mono, so it looks the same on every machine.

#### Interrupt says who has control

Was: Interrupt could fail with "Couldn't take control" when another device held the session.

Now: it names that device, and an admin pairing takes control and says from whom.

#### Readable receipts

Was: the last line of the Write access receipt sat in a faded edge.

Now: it is fully readable.

## Under the hood

### Daemon loop (#1211, in part)

#### Relay and director I/O

Was: relay, director-inject and director-refresh store I/O ran inline on the loop.

Now: it runs as store-worker jobs.

#### Spawn and wake gate

Was: the per-pass spawn-queue poll and the prompt-queue wake gate blocked the loop.

Now: both run off the loop; key-to-echo p99 under write pressure is 77.7 ms → 12.8 ms.

#### Turn probes

Was: the idle-unacked and normal-delivery probes read the agent store and transcripts on the loop.

Now: they run as off-loop relay jobs.

#### Epic focus

Was: `set_active_epic` wrote session metadata on the loop and could drop the last write at shutdown.

Now: the store worker writes it, and shutdown flushes and drains.

#### Lane enforcement

Was: nothing stopped I/O from creeping back onto the input path.

Now: `enforce_lane` panics under the test harness and logs once per site otherwise; a synthetic-PTY load harness writes p99 receipts.

#### Worker exit

Was: `mark_worker_crashed` reaped process groups and checked worktrees inside the PTY exchange.

Now: that runs after the exchange, and names stay reserved until crash cleanup ends.

### Store and serve

#### Write lock only on writes

Was: prompt-queue opens, inbox stale sweeps, empty drains and the Viktor watch expiry took the SQLite write lock without writing.

Now: they read first; MCP p99 under 16-agent pressure is 2.23 s → 1.88 s.

#### Heartbeat transaction

Was: a heartbeat and its task and worktree lease renewals took the write lock three times.

Now: one transaction that rolls back together.

#### Boot under concurrent creates

Was: `cas serve` exited when task-sync recovery found another agent's unclassified intent.

Now: a retired snapshot is rechecked under the write lock and skipped; real ambiguity still fails.

#### Empty prompt_queue.db

Was: a 0-byte `.cas/prompt_queue.db` sat beside the live queue in `cas.db`.

Now: a regular empty file with no sidecars is removed on a writable open.

### Relays and alerts

#### Folded deaths

Was: N Critical `worker_died` relays plus `workers_died_together`.

Now: one Critical fold per recipient with each worker's cleaned tail; the sweep owns recovery, and a give-up is logged.

#### Lifecycle expiry

Was: an `awaiting_merge` relay for a closed task reached the supervisor 8.5 h late.

Now: terminal-obsolete lifecycle relays expire atomically in every drain, with a durable reason.

#### Other stale relays

Was: CI-red relays for moved heads, verification dispatches past their deadline and old attention alerts were still delivered.

Now: they expire the same way; fresh and uncertain relays stay eligible.

#### Dead-letter rows

Was: `reminder_fired` and `task_lifecycle` rows were never processed, and the undelivered-relay banner never aged.

Now: rows are reconciled, and the banner is capped.

### Cloud, Violet and git

#### HTTP 429

Was: a 429 at session end was one-shot, leaving the agent listed for up to 24 h.

Now: `Retry-After` or bounded backoff for shutdown, claim release and peer ack, plus a durable shutdown intent and a named "rate limited" health cause.

#### Shutdown snapshot

Was: new shutdown intents were detected only by directory mtime.

Now: exact file identity, so a coarse mtime cannot hide a change.

#### Heartbeat after /clear

Was: `ensure_agent_active` moved heartbeat ownership to the fenced old agent.

Now: owner precedence keeps it with the new session.

#### Violet watches

Was: `watches.json` was per clone, so a second daemon stopped a peer's watches.

Now: watches are keyed per session, with owner routing and a login retry.

#### Epic publication

Was: `focus_epic` and the first spawn could leave a missing or stale epic branch.

Now: the branch is published to origin and fast-forwarded before lanes are cut.

#### Dirty reused worktree

Was: `worktree_merge` refused a pushed delivery while the worktree held the next task.

Now: it merges the parked SHA through an isolated temporary worktree.

### Policy, QA and Commander

#### Command policy

Was: base readers and `git` accepted flags that run other programs, while read-only `awk`, `find … | xargs grep` and `gh … | grep` were refused.

Now: fail-closed per-tool flag allowlists; grep-only `xargs`; a direct `cas config get` only.

#### Batch QA (#1203)

Was: `qa.evidence_gate` required a per-task QA bundle.

Now: with `qa.mode = "batch"`, one immutable batch receipt (ledger, task ids, staging SHA) satisfies each listed task.

#### Squash and stale-origin closes

Was: a squash-merged or stale-origin batch delivery was refused at close.

Now: the squash maps to its anchor and the local target counts; an override never clears batch debt.

#### Bundled fonts

Was: Commander shipped no fonts, so CI and users rendered fallbacks.

Now: Inter and JetBrains Mono woff2 (88,660 B) are served under `font-src 'self'`.

#### Interrupt on 409

Was: a refused take showed a generic failure.

Now: the holder is read and named; hub-admin pairings retry with force.

#### Write access receipt

Was: its last line sat in the rail's bottom fade at about 3.4:1.

Now: it is clear of the fade.

#### Deterministic tests

Was: the `flv2` inject and slot-cap tests flaked under parallel load, and the Doctor Neon test leaked MCP children.

Now: both are deterministic and hermetic.
