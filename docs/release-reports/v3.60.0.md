# Cassy v3.60.0

Published 16 October 2026 · 13:04:03 UTC · release commit `f15ccb5e9378921dee5949e7e871207efc60085b`.

Cleanup no longer competes with typing, proof receipts keep each number with its own field, and `cas peers --detail` shows who owns which work across machines.

## What you can do now

### Sessions

#### Typing during cleanup

Was: background cleanup could interrupt typing. →

Now: that cleanup runs separately from the input loop.

### Projects

#### Proof receipts

Was: a receipt could mistake one field's number for another or reject a valid short form. →

Now: numbers stay with their fields, and supported short forms work.

#### See shared work

Was: the peer list gave little context about who owned work. →

Now: `cas peers --detail` shows ownership, pending merges and working folders across machines, with private or outdated information labelled.

## Under the hood

### Sessions

#### Cleanup I/O

Was: fallback pointers, bounces and probe revalidation could delay the input or write path. →

Now: heavy work runs off-loop, with short durable writes and guarded retry and shutdown recovery.

### Projects

#### Receipt parsing

Was: neighbouring fields could lend numbers, and `-j16 x3` failed. →

Now: fields own their numbers; `-j16`, `--jobs 16` and bound `x3` work, while explicit low run counts refuse.

#### Peer board

Was: presence lacked work ownership context. →

Now: `cas peers --detail` and `--json` show splits, task owners and claims, PR heads, workers, waiting merges and roots, with private, stale and unknown evidence labelled. The board is read-only: it shows conflicts and does not prevent them.

#### Retarget regression

Was: double retarget to a remote-only target lacked a close-handler regression. →

Now: it proves unmerged work stays `MERGE REQUIRED` without a completion notice; the production guard is unchanged.

#### Previous release report

Was: v3.59.0 lacked its standalone report bundle. →

Now: Markdown, brief, HTML, PDF and visual QA evidence are committed.
