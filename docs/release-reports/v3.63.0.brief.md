# Brief: Cassy v3.63.0 release report

Prepared with cas-release-report, cas-html-reports, and cas-ui-craft.

## Single idea

Four of Cassy v3.63's seven changes make updates and builds safer; the other three improve sessions and Cloud sync.

## Hero form

A sandstone verdict sits above the release's labelled change map: four equal dots for Releases, two for Sessions, and one for Slack and Cloud. The map uses one dot per titled CHANGELOG change. Its 4:2:1 distribution makes the release's largest group visible without implying effort, severity, or user impact. The complete verdict and figure must fit above the fold at 1280×800 and 390×844.

## Emotional register

Assured and collected: sandstone paper, a regular serif verdict, system sans reading text, mono folio, quiet rules. There is no root DESIGN.md; the report renderer consumes the project's design roles from docs/design/design-tokens.json. The fixed release-report template retains the established map, section order, and type hierarchy.

## Distinctive move

Seven equal-area dots are grouped in named product areas, with the four-dot Releases group emphasized. A short decorative row returns beside Install. The dot distribution argues that update and build work is the largest part of this release; the section below gives each change its Was → Now evidence.

## Deliberately omitted

The hero omits the zero GitHub-issue count and every unmeasured stage or end-to-end latency; the counting note names them. It does not suggest a consumer Mac Gatekeeper/SIP GUI check ran: hosted macOS install proof does not cover that manual path. The dot map does not imply that all 17 user-facing bullets or 29 developer details are separate CHANGELOG titles.
