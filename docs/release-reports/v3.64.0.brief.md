# Brief: Cassy v3.64.0 release report

Prepared with cas-release-report, cas-html-reports, and cas-ui-craft.

## Single idea

Cassy v3.64's health checks, JSON output and recovery advice now say what is actually wrong, once, in the format you asked for.

## Hero form

A sandstone verdict sits above the release's labelled change map: three equal dots for Releases and one each for Commander, Sessions, and Slack and Cloud. The map uses one dot per titled CHANGELOG change. Its 3:1:1:1 distribution shows where the release's six change groups landed without implying effort, severity, or user impact. The complete verdict and figure must fit above the fold at 1280×800 and 390×844.

## Emotional register

Assured and collected: sandstone paper, a regular serif verdict, system sans reading text, mono folio, quiet rules. There is no root DESIGN.md; the renderer consumes the project's design roles from docs/design/design-tokens.json. The fixed release-report template retains the established map, section order, and type hierarchy.

## Distinctive move

Six equal-area dots are grouped in named product areas, with the three-dot Releases group emphasized. A short decorative row returns beside Install. Areas were corrected by hand from the generator's keyword placement (Codex and operator setup to Sessions, managed replies to Slack and Cloud, cache cleanup to Releases); the Evidence section says so.

## Deliberately omitted

The hero does not invent an issue count: the generator's counting window closed at 9:18 AM ET, and the eleven fixed issues were closed by hand at 9:23 AM ET, so the counted figure stays 0 and the Fixes ledger names them in prose. Unmeasured stages and end-to-end request latency are named in the counting note. It does not suggest a consumer-Mac Gatekeeper/SIP GUI check ran, and it repeats that unknown-owner cache reclaim is not verified on macOS. The dot map does not imply that the 10 user-facing bullets or 19 developer details are separate CHANGELOG titles.
