Under the hood

03 / 06
01

Setup and access

Neon workspace setup

Wasdiscovery checked only root packages, and multi-organization setup required a prompt.

Nowbounded scans find supported workspace packages; explicit organization and project flags support noninteractive setup.

Alternate Codex accounts

Wasa home-relative account directory reached trust preparation literally and failed with an empty parse error.

Nowthe home shortcut expands first, and missing hook setup gets a specific error.

Codex model checks

Wasan older or unversioned client catalogue could make supported models look unavailable.

Nowthose catalogues are unverified and cannot falsely refuse a model.

Safe retention preview

Wasclosed-task artifacts and task-created simulators could persist without ownership checks.

Nowpruning plans by age, size and keep reason; simulator ownership is project-bound, and apply requires confirmation.

Team queue recovery

Wasa team-linked project could hold personal-scope backlog without a safe recovery path.

Nowstatus and preflight expose the mismatch, and a plan-first migration queues only eligible rows with itemized acknowledgments.

02

Recovery and coordination

Violet reconnects

Wasa brief proxy reconnect could fail a claim, and each read could restart its Cloud budget.

Nowretry detection is structural, reads share a bounded budget, and a covering lease prevents concurrent pickup.

Rebased deliveries

Wasan unchanged delivery rebased onto a new target could keep a stale parked anchor.

Nowthe anchor rebinds only after patch identity and task ownership are proven; changed content still refuses.

Stalled project checks

Wasone unavailable repository configuration could hold up close or merge while unrelated roots were inspected.

Nowprobes are bounded and shared per root; healthy project identities stay fresh.

Project refreshes

Wasone stalled known-root configuration could delay every project refresh.

Nowobservations are bounded independently so healthy roots still refresh.

Idle-session wakeups

Wasreplayed Claude tool events could look unfinished and suppress a completion or recovery wake.

Nowonly actual turn records hold the wake gate open.

Repeated idle alerts

Wasan alert could be marked before delivery, while older expired-review relays starved newer ones.

Nowunanswered pages repeat until delivered, and already-sent relays no longer starve the sweep.

Actionable next steps

Wasblocked tasks, a missing focus or stale reminders could hide ready work or the lack of a wake source.

Noweligible suggestions respect peer ownership, and stop warnings identify a missing wake source.

Clearer provisioning errors

Wasfailed worker launches could omit project and spawn context.

Nowfailures name the worker, project and launch step.

03

Reports and proof

Credential boundaries

Wasdefault policy omitted Neon tools, and delegated commands could reach saved Neon or Vercel credentials.

NowNeon CLI/MCP access is denied by default, NEON_API_KEY stays out of delegated environments, and credential-store reads are blocked across command and script inputs.

Bounded cleanup reports

Wasa cleanup report returned hundreds of thousands of characters.

Nowthe default summarizes counts, sizes and samples, preserves machine-readable status lines, and bounds detail pages by bytes and lines.

Assembly proof selection

Wasan unsupported row name could be ignored while the command reported success.

Nowinvalid names fail before proof work begins and list the supported rows.

Fixture isolation

Wasa Codex trust test could dirty its checkout, and a provisioner dispatch test lacked its CLI companion.

Nowlaunch evidence is isolated and dispatch uses the built CLI fixture; strict reminder checks also hold under load.

Readable Violet posts

Wasdense messages could cite unavailable items or use unsupported time zones, and the CLI hid formatting violations.

Nowshared rules require attached references and CT times; the hub rejects unreadable posts with actionable fixes.
