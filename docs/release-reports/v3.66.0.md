## What you can do now

### Setup and access

#### Neon setup

Was: initialization checked only root-level packages and needed an interactive choice.

Now: it finds supported nested workspaces and accepts organization and project IDs directly.

#### Saved credentials

Was: automated commands could reach saved Neon or Vercel credentials.

Now: those reads and Neon CLI/tool access are blocked by default.

#### Clear setup errors

Was: a failed worker setup could hide where it stopped.

Now: the error names the project and launch step.

### Codex setup

#### Alternate accounts

Was: an alternate account in your home folder could fail to start.

Now: Cassy expands the home-folder shortcut before setup and names missing hook setup.

#### Codex models

Was: an older app could hide a model your account supports.

Now: that stale list alone cannot stop the model from starting.

### Keeping work moving

#### Team queue recovery

Was: a linked project could hide queued personal changes.

Now: preview a clear list before moving eligible changes to the team.

#### Brief Slack outages

Was: a short reconnect could interrupt a protected action.

Now: Cassy retries briefly and explains a persistent outage.

#### Branch updates

Was: unchanged work could stall after a branch update.

Now: it continues after Cassy confirms nothing changed.

#### Stalled projects

Was: one unresponsive project could hold up refresh or close.

Now: its check returns a cause quickly while healthy projects continue.

### Maintenance and reminders

#### Cleanup preview

Was: old task evidence and task-created simulators could accumulate.

Now: eligible items are previewed, ownership is checked, and removal needs confirmation.

#### Compact cleanup report

Was: a cleanup report could overwhelm the reply.

Now: counts and samples come first, with complete details available in bounded pages.

#### Idle recovery

Was: missed prompts or no selected project could leave ready work unseen.

Now: alerts retry until delivered and the next available task is surfaced.

#### Proof selection

Was: an unsupported check could be skipped while appearing successful.

Now: the command stops and lists supported choices.

### Readable posts

#### Violet formatting

Was: a post with unsupported times or unattached references could slip through.

Now: it is refused with clear fixes, and references must be attached.

## Under the hood

### Setup and access

#### Neon workspace setup

Was: discovery checked only root packages, and multi-organization setup required a prompt.

Now: bounded scans find supported workspace packages; explicit organization and project flags support noninteractive setup.

#### Alternate Codex accounts

Was: a home-relative account directory reached trust preparation literally and failed with an empty parse error.

Now: the home shortcut expands first, and missing hook setup gets a specific error.

#### Codex model checks

Was: an older or unversioned client catalogue could make supported models look unavailable.

Now: those catalogues are unverified and cannot falsely refuse a model.

#### Safe retention preview

Was: closed-task artifacts and task-created simulators could persist without ownership checks.

Now: pruning plans by age, size and keep reason; simulator ownership is project-bound, and apply requires confirmation.

#### Team queue recovery

Was: a team-linked project could hold personal-scope backlog without a safe recovery path.

Now: status and preflight expose the mismatch, and a plan-first migration queues only eligible rows with itemized acknowledgments.

### Recovery and coordination

#### Violet reconnects

Was: a brief proxy reconnect could fail a claim, and each read could restart its Cloud budget.

Now: retry detection is structural, reads share a bounded budget, and a covering lease prevents concurrent pickup.

#### Rebased deliveries

Was: an unchanged delivery rebased onto a new target could keep a stale parked anchor.

Now: the anchor rebinds only after patch identity and task ownership are proven; changed content still refuses.

#### Stalled project checks

Was: one unavailable repository configuration could hold up close or merge while unrelated roots were inspected.

Now: probes are bounded and shared per root; healthy project identities stay fresh.

#### Project refreshes

Was: one stalled known-root configuration could delay every project refresh.

Now: observations are bounded independently so healthy roots still refresh.

#### Idle-session wakeups

Was: replayed Claude tool events could look unfinished and suppress a completion or recovery wake.

Now: only actual turn records hold the wake gate open.

#### Repeated idle alerts

Was: an alert could be marked before delivery, while older expired-review relays starved newer ones.

Now: unanswered pages repeat until delivered, and already-sent relays no longer starve the sweep.

#### Actionable next steps

Was: blocked tasks, a missing focus or stale reminders could hide ready work or the lack of a wake source.

Now: eligible suggestions respect peer ownership, and stop warnings identify a missing wake source.

#### Clearer provisioning errors

Was: failed worker launches could omit project and spawn context.

Now: failures name the worker, project and launch step.

### Reports and proof

#### Credential boundaries

Was: default policy omitted Neon tools, and delegated commands could reach saved Neon or Vercel credentials.

Now: Neon CLI/MCP access is denied by default, `NEON_API_KEY` stays out of delegated environments, and credential-store reads are blocked across command and script inputs.

#### Bounded cleanup reports

Was: a cleanup report returned hundreds of thousands of characters.

Now: the default summarizes counts, sizes and samples, preserves machine-readable status lines, and bounds detail pages by bytes and lines.

#### Assembly proof selection

Was: an unsupported row name could be ignored while the command reported success.

Now: invalid names fail before proof work begins and list the supported rows.

#### Fixture isolation

Was: a Codex trust test could dirty its checkout, and a provisioner dispatch test lacked its CLI companion.

Now: launch evidence is isolated and dispatch uses the built CLI fixture; strict reminder checks also hold under load.

#### Readable Violet posts

Was: dense messages could cite unavailable items or use unsupported time zones, and the CLI hid formatting violations.

Now: shared rules require attached references and CT times; the hub rejects unreadable posts with actionable fixes.
