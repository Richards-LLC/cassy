## What you can do now

### Everyday use

#### Finish anywhere

Was: The finish command could be absent or duplicated across installations.

Now: The command ships with Cassy and keeps a personal version when you already have one.

#### Clean terminal input

Was: Mouse movement or leaving a session could leave raw escape codes on screen.

Now: Terminal input and display settings are restored when a session ends.

#### Reattach at your size

Was: Reopening a detached session could leave it stuck at a tiny screen size.

Now: The display follows the size of the terminal you attach.

#### Clean exits

Was: Background processes could survive after you left Cassy.

Now: Owned processes are cleaned up on a real exit, and closing a frozen terminal stays bounded.

#### Recover setup

Was: A failed setup could leave a folder that made a normal retry do nothing.

Now: The error names the force-retry command and keeps your existing settings.

#### Keep connection settings

Was: Setup could overwrite malformed connection settings or report success before connecting Claude.

Now: Unreadable settings stay untouched, and a successful setup creates the connection first.

#### Readable setup

Was: Setup text could disappear on a light screen or overflow a narrow terminal.

Now: It uses your text colors, respects plain-color mode and wraps its guidance.

#### Readable updates

Was: Warnings could run off screen, cut a path in half or join a step name directly to done.

Now: Warnings fit the screen, preserve path words and separate progress from status.

### Settings and recovery

#### Settings in the right place

Was: Some host settings were read or reset in project settings instead.

Now: Editors use the right settings location and save only the changes you made.

#### Usable settings menus

Was: A refusal or help hint could be clipped on a small screen.

Now: The cause and remedy stay visible in narrow and short terminals.

#### Keep unfinished repairs

Was: An unreadable Git guard could abort an update and lose its staged repair.

Now: The repair stays staged, with the warning needed to finish it.

#### Visible local repairs

Was: A local repair commit could quietly become the starting point for later work.

Now: Cassy points out changes that still need publishing and explains a missing upstream.

#### Safer copyable commands

Was: A folder with spaces or an invisible branch character could produce an unsafe or confusing remedy.

Now: Suggested commands quote folders correctly and refuse misleading branch names.

#### Reliable notifications

Was: Notification settings could accept a bad address or inherit unexpected curl settings.

Now: Bad addresses get an inline explanation and sends use bounded, isolated defaults.

#### Direct mentions

Was: A direct @Violet mention could wait like an ordinary conversation update.

Now: Recognized direct mentions wake Violet urgently.

#### Older conversations

Was: Recovered messages could arrive in the order a batch was returned.

Now: Cassy sorts each recovered batch by message time before showing it.

### Shared work and reports

#### Work handovers

Was: Reassigned work could remain locked to its previous owner.

Now: Obsolete locks stop renewing and a new owner can start.

#### Clear busy checks

Was: A busy-check refusal did not say which command was already running.

Now: It names the command, its process and when it started.

#### Less review disk use

Was: Repeated reviews could fill disk space with separate copies of the same build.

Now: Matching copies are reused and finished copies are cleaned up while real edits are kept.

#### Recovery that stays safe

Was: A failed repair could restart a connection too early or leave an abandoned pause behind.

Now: Confirmed waiting periods stay in place, while an abandoned pause is released when a retry cannot submit.

#### Report links that open

Was: A release report could link to a folder that existed only on one computer.

Now: Its source and print links open from the published repository.

#### Split announcements

Was: Replies or a report could attach to the last piece of a long announcement.

Now: They attach to its first piece, and receipts retain every delivered part.

#### Hub status and retry

Was: A custom hub could show the wrong service status, or a retry hint could wrap into confusion.

Now: Status follows the chosen service and each retry option gets its own line.


## Under the hood

### Messages and ownership

#### Explicit mention urgency

Was: Managed deliveries ignored event kind and idempotent enqueue discarded urgency.

Now: Optional delivery.event_kind=app_mention selects urgent delivery atomically. Missing or ordinary kinds stay non-interrupting and replay cannot escalate.

#### Recovery batch order

Was: Recovery walked returned admissions without sorting.

Now: The client sorts each returned batch numerically by Slack timestamp then delivery ID, placing missing or invalid times last. Cross-page ordering remains a separate Cloud change.

#### Mention addressing

Was: The push-wake contract omitted the mention alias.

Now: mention is documented as addressed to Violet. Source-age calculation remains the existing behavior shipped earlier.

#### Fold boundary integrity

Was: A message summary or guessed row boundary could imitate folded-message authority.

Now: Labels and delimiters are escaped before folding, with absorbed action wakes retained.

#### Mixed-version fold readers

Was: 3.72 wrote the earlier fold marker format.

Now: 3.73 writes escaped fold boundaries. Keep communicating sessions on the same release when upgrading.

#### Journal pause origin

Was: Every Paused journal row looked like a prior legacy-intake refusal.

Now: Only a strict matching-attempt refusal marks a durable quiet hold. Pre-submit failures release unmarked pauses without releasing Submitting, Unknown or Managed evidence.

#### Journal upgrade

Was: 3.72 journals did not record why a pause existed.

Now: An old quiet hold reads as unmarked after upgrade and its quiet window can end early once per host.

#### Journal downgrade

Was: 3.72 accepted only its older journal shape.

Now: It rejects a journal containing the new origin field and admits nothing. Rerunning cas update after a downgrade may be needed.

#### Conditional claim release

Was: A delayed rollback or release could erase a same-agent restart or re-claim.

Now: Synchronous, rollback and background paths release against the observed claim snapshot and confirm renewals.

#### Lease ownership

Was: An old assignee or missing task row could keep renewing a claim.

Now: Only the current assignee of running work renews it, and self-held transfers are identified correctly.

#### Split release persistence

Was: Retargeted tasks could retain split-owned Cloud claims or lose pending shares.

Now: Obsolete claims are released with a durable release ledger, while unknown releases keep their pending share.

#### Fail-closed split fallback

Was: Projection or release-read errors could erase a raw hold or resurrect a released child.

Now: Raw fallback keeps unknown holds and applies explicit child releases before admission.

#### Release-bound follow-ups

Was: New follow-ups could default outside the active release.

Now: Live follow-ups inherit its release binding without rerouting unrelated work.

#### Audited freshness override

Was: A stale-assignment refusal had no approved escape and the warning overstated the check.

Now: The audited override works and its caveat matches actual start admission.

### Runtime and command behavior

#### Version skew

Was: Installed binaries could change while long-running MCP sessions kept an unnoticed older version.

Now: Live epochs and process identity expose stale or unknown versions, including directly registered server PIDs and the newest daemon epochs.

#### Release notice

Was: Stale sessions could keep running without a visible update notice.

Now: One release notice spans the stale sessions. Restart long-running sessions after upgrading to activate the installed code.

#### Terminal restoration

Was: Signals, disconnects and unwind could leave input modes active or orphan children.

Now: The active client restores terminal state, daemon process sessions are isolated, and owned children are cleaned up on real exits.

#### Signal semantics

Was: A frozen terminal could trap termination, or parents saw an ordinary 128+signal exit.

Now: Cleanup is bounded and the client preserves death-by-signal semantics.

#### Attached geometry

Was: A detached 80x24 size could remain authoritative after attaching.

Now: The active input owner supplies the local TUI dimensions.

#### Initialization state

Was: A partial init could hide the retry path or replace existing settings.

Now: Force-retry advice is explicit, existing configuration is preserved and JSON init saves its full configuration before provisioning.

#### MCP initialization

Was: JSON init could succeed without Claude MCP, and malformed settings could be overwritten.

Now: Provisioning precedes success and malformed or non-object settings are refused unchanged.

#### Terminal presentation

Was: Fixed foregrounds, repeated init causes and wide hints broke light or narrow terminals.

Now: Setup and pickers inherit text color, NO_COLOR and locale precedence. Init causes print once, with bounded hanging continuations.

#### Update diagnostics

Was: Warnings split paths or lost complete values, and a full-width label touched its status.

Now: Warnings retain path tokens and complete JSON or verbose values, abbreviate home paths, and keep a separating gap before status.

#### Config editor writes

Was: Host-scoped edits used project configuration and batch saves could race.

Now: Host settings stay host-scoped, saves use the configuration lock, and only visible edits are persisted.

#### Config refusal layout

Was: Short or narrow terminals clipped the operator-only remedy or help.

Now: Wrapped row counts determine footer height and refusal text remains visible.

#### Managed repair guards

Was: A configuration-read failure aborted a staged managed-file repair.

Now: The repair remains staged and the diagnostic retains its recovery context, including detached HEADs.

#### Reconcile publication

Was: Local repair commits silently became a base and rebased history or deleted upstreams confused diagnostics.

Now: Unpublished repairs are surfaced, published-parent comparisons survive rebase, and deleted upstreams get the correct explanation.

#### Command boundaries

Was: A workdir override could widen an unbound turn root, and unsafe branch text leaked into remedies.

Now: Write and artifact fallbacks remain turn-bound. Trust commands are quoted, invisible refs refused, and Git causes retained.

#### Webhook isolation

Was: curl could read user defaults and legacy unsafe destinations could still be sent.

Now: Normalized URL checks, curl -q and a bounded runtime apply at send time, with inline configuration refusals.

### Merge evidence and QA

#### Merge observation recovery

Was: A committed merge could lose its completion observation or keep an obsolete wake intent.

Now: Observation writes retry within a bounded lock hold and record skipped close, ineligible close and later merge failure outcomes.

#### Advisory CI continuation

Was: A published no-check-runs merge stopped before normal close and verification dispatch.

Now: It continues through the ordinary proof gate with a persisted CI-unconfirmed note. Explicit failed-CI overrides remain separate.

#### Rebased delivery anchors

Was: A merge request could advertise a new tip while its parked anchor remained old.

Now: Ownership and the persisted anchor are validated before the rebased request is emitted.

#### Content attribution

Was: Empty checkpoints and merged builtin-history unions could look like dropped delivery content.

Now: Earlier non-empty effects and per-key history additions establish the delivered content.

#### QA range ownership

Was: Close could compare against a creation-time range or resolve a managed merge in the wrong repository.

Now: Recorded delivery boundaries and the task target repository govern QA evidence.

#### Proof diagnostics

Was: Declared sibling test modules could appear uncovered, complete pairs got waiver notes, and shortened references lost a measured commit.

Now: Declaration-aware scope matching, conditional waiver notes and preserved commit suffixes make the evidence specific.

#### Candidate isolation

Was: A scratch candidate could migrate the live store or its receipt could describe an earlier binary.

Now: Implicit scratch stores stay isolated and the copied binary is verified against the published candidate receipt, with a short task locator.

### Resource and publication contracts

#### Review target reuse

Was: Each dispatch built and retained another large target.

Now: Matching targets are reused and resolved ones enter bounded lifecycle cleanup.

#### Safe background reclaim

Was: A verdict waited on target deletion and interrupted trash could become unreclaimable.

Now: Targets are staged before asynchronous collection. Dirty edits are rechecked, ownership is atomic and private stale owner markers can be reclaimed.

#### Cleanup accounting

Was: Retained bytes looked reclaimable and report paths repeated expensive walks.

Now: Only eligible bytes count as reclaimable, pending bytes stay visible, JSON exposes deferral and staging errors are logged from one measurement per trash row.

#### Bounded test processes

Was: macOS discovery could hang on output and termination missed subprocess groups.

Now: The capped runner drains discovery, forwards wrapper signals, waits for slow cleanup and bounds escalation without signaling a reaped group.

#### Portable test control

Was: Discovery cleanup assumed Python waitid and macOS fixtures assumed proc or timed-out ports.

Now: Supported fallbacks, portable liveness checks, short-lived port reservations and unwind-safe schema restoration keep the regressions deterministic.

#### Capacity bookkeeping

Was: A busy check hid its holder and bookkeeping errors could stop admitted work.

Now: The holder process, command and age are shown, while episode or missing-row failures do not derail an admitted check.

#### Hub and tooling checks

Was: Custom launchd labels, narrow required-mode retries and stale GC help misled callers.

Now: Status follows the selected label, retry alternatives are separated and help names reachable options.

#### Journey diagnostics

Was: Corrupt or unknown-version history could remain unusable and progress exemptions hid real truncation.

Now: Bad debt history is reset explicitly and only complete known progress text receives an ellipsis exemption.

#### MCP future size

Was: Only one dispatcher had a future-size guard.

Now: Every public MCP tool dispatcher is checked against the 32 KiB limit.

#### Release artifact identity

Was: Report links named local files and split receipts retained only one message identity.

Now: Repository links, ordered part IDs, distinct PDF file/upload-message IDs and first-root thread selection retain the full publication evidence.

#### Shared command distribution

Was: The finish command depended on local copies and account refresh could fail silently.

Now: One builtin reaches all supported command catalogs, personal entrypoints take precedence and refresh failures are visible.

#### Portable documentation

Was: Design records could embed machine-specific paths.

Now: Documentation checks reject those paths, and the previous release report and receipts remain in the release history.
