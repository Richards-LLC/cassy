## What you can do now

### Release changes

#### Slack channels

Was: You couldn't see which Slack channels were linked to a project, or set up several together.

Now: `cas violet channels` lists them, and `cas update` checks the channels you configured.

#### Uncertain pattern changes

Was: A save or adoption could fail on the network after being sent, but look safe to repeat.

Now: Cassy marks the result uncertain and shows how to check it before trying again.

#### Readable terminal output

Was: Different commands wrapped long words and paths differently.

Now: Terminal output follows one consistent rule, keeping a long path readable on its own row.

#### Smooth shared terminal views

Was: A full-width view resizing without changing the layout, or taking input at the same size, briefly paused drawing for everyone.

Now: Those actions keep drawing; compact views and real owner-size changes still refresh.


## Under the hood

### Channels and patterns

#### Multi-channel inspection

Was: Projects declared one Slack channel, and existing links were difficult to inspect.

Now: `cas violet channels` lists configured, Violet and Cloud links; `slack.channels` feeds multi-channel `cas update` checks.

#### Pattern response handling

Was: Pattern reads assumed wrapped Cloud rows, and any transport error after create could imply an uncertain write.

Now: Reads validate bare or wrapped rows; create/adopt writes are uncertain only after request-body transmission and retain the error plus reconciliation ID.

### Task lifecycle

#### Merged task closes

Was: Squash-merged work could be refused, and already-live changes could trigger a redundant QA pass.

Now: Close proves tip containment plus target ancestry and skips independent QA for deliveries already on the target.

#### Origin-based merge advice

Was: A merge using an origin-only successor told users to merge on their stale local branch, then push a rejected result.

Now: Cassy says to fast-forward first; a divergent local successor keeps its own advice.

#### Supervisor identity after `/clear`

Was: A Claude supervisor's cached identity could register a second row after `/clear`.

Now: Session end preserves the live row, and session start rebinds it by process and name.

### Operations and recovery

#### Wake measurements

Was: Pasted-content and `Message from` wrapped turns with leading whitespace before the CAS envelope were missed by wake accounting.

Now: Those bodies are trimmed before turn matching, so token and latency reports include them.

#### macOS socket cleanup

Was: A refused connection could be mistaken for proof that a stream or datagram socket had no holder.

Now: A complete native holder inventory and ownership/inode fences gate removal; unknown results preserve the path.

#### Review checkout durability

Was: A failed directory sync left a fresh checkout that a retry reused without syncing.

Now: New task and scratch parents sync before Git, and a failed sync removes only that fresh checkout.

#### Repository runner registration

Was: Repository tokens were labelled as organization tokens and got an organization-only runner group.

Now: Diagnostics distinguish token types and repository registration omits that group.

### Terminal and release tooling

#### Consistent CLI wrapping

Was: Initialization, activity, doctor and release reports handled overlong words differently.

Now: A shared wrapper applies an explicit policy, with long initialization paths kept on their own row.

#### Factory viewer resizing

Was: A non-owner Full→Full resize or same-size input takeover scheduled a 100 ms shared layout resize.

Now: Only compact transitions or changed owner dimensions schedule that resize.

#### User announcement lint

Was: Forbidden user wording was checked only in the User top-level post.

Now: Validation checks both User bodies and leaves technical wording allowed in Dev.
