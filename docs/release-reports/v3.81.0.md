## What you can do now

### Release changes

#### Finishing reviewed changes

Was: A merge and passing review could still need another close request.

Now: Eligible merged changes finish automatically, while a failed review returns its findings for correction.

#### Ready sooner

Was: Pushed changes with passing checks could wait for an extra handoff.

Now: They signal readiness as soon as the evidence is available, while review and check requirements still apply.

#### Quieter readiness checks

Was: Unchanged ready changes kept causing repeat checks, and a restart could repeat the notice.

Now: Readiness is remembered across restarts, with failed checks revisited after 10 minutes and temporary lookup failures retried.

#### Latest fix recognized

Was: Finishing a change could check its first failing attempt instead of the pushed fix.

Now: Clearly identified follow-up commits are checked through the pushed fix.

#### Consistent finish checks

Was: Automatic finishing could miss passing evidence that a manual close could see.

Now: Both use the same delivery evidence; other unmet requirements remain visible and an unsuccessful close keeps its hold.

#### Saved service access

Was: The main session could be refused access to its saved Neon and Vercel sign-ins.

Now: It can read those recognized stores, while unrelated secrets and restricted background access stay protected.

#### Relevant alerts

Was: Already merged changes could still prompt a merge, and an existing review wait could trigger another blocker alert.

Now: The merge target is checked again before delivery, and a review wait already owned by its recipient stays quiet.

#### Disk space recovery

Was: Old build caches could survive a removed checkout and keep blocking new builds.

Now: Proven idle caches are reclaimed oldest first until enough space is free, while live work remains protected.

#### Reliable install checks

Was: A personal custom command could change the result of a clean-install check.

Now: That check runs with an isolated home, while your personal command keeps its usual priority.

#### Stable release review

Was: Later unrelated changes could shift the revision checked for a released group of work.

Now: The review stays tied to the merge that actually released it.

#### Completion across machines

Was: A remote completion or an ended session could leave a wait unnoticed.

Now: Saved completion is checked directly, the final completion sends a readiness notice, and a wait whose task is cancelled, or whose deadline passes first, notifies its owner.

#### Terminal check coverage

Was: Changes to terminal capture checks could miss their regression tests in lighter CI runs.

Now: Changes to either copy or its tests select the terminal test suite there too.


## Under the hood

### Release changes

#### Merge-bound close

Was: A pushed delivery could require another close request after merge and review.

Now: A green merge can park an eligible pushed tip and dispatch review at the merge; approval closes it, rejection returns findings. Explicit CI overrides do not authorize automatic close.

#### Green delivery signal

Was: Readiness depended on park or a merge request.

Now: An owned pushed-green tip signals READY TO MERGE even when park was refused; required CI and QA admission still apply.

#### Probe reuse

Was: Readiness and wait reporting fetched separately, repeated settled probes, and forgot READY admission on restart.

Now: One observation feeds both paths; per-task/tip receipts survive restart, failed CI retries after 10 minutes, transient evidence remains retryable, and terminal tasks’ READY receipts and cached observations for those deliveries retire.

#### Shared-branch close anchor

Was: A failing-first commit could remain the proof boundary after a pushed fix.

Now: Active shared-branch continuations advance it only when every commit subject names the same task and no conflicting delivery boundary intervenes.

#### Receipt parity

Was: Automatic close read evidence from a different checkout and could record close authority before success.

Now: It reads exact-tip receipts from the delivery checkout, restores a held close, and records authority after commit. Parking requires local-branch and origin evidence and sends one notice.

#### Credential access scope

Was: The operator-store guard also refused privileged and ordinary primary sessions.

Now: Nonrestricted sessions can read recognized Neon/Vercel stores; the generic exemption checks only the protected read operand, preserving unrelated secrets, writes and explicit protection.

#### Alert freshness

Was: Codex PTY merge alerts could outlive their target evidence, and owned verification waits could wake their recipient twice.

Now: PTY delivery refreshes the target like native-inbox delivery; positively identified sole-owned active review waits become quiet receipts. Independent blockers remain waking.

#### Target-cache reclamation

Was: Removing a checkout could hide its dead build cache from automatic reclamation.

Now: Durable ownership survives removal; pressure cleanup deletes eligible caches oldest first and remeasures actual capacity to the low threshold. Budgeted reports mark incomplete inventories.

#### Hermetic parity fixture

Was: A host's personal Codex finish skill changed the clean-install catalog count.

Now: The existing regression uses an isolated home and names the failing client; runtime personal-skill precedence is unchanged.

#### Immutable release boundary

Was: A release close dispatch followed the moving default branch and accepted later containing merges.

Now: It binds the introducing merge SHA, rejects receipts whose first parent already contains the released tip, and bounds the first-parent walk by that tip's ancestry.

#### Remote task waits

Was: Synced closes lacked a local event, finite defaults could expire long waits, and an orphan could stop a reminder pass.

Now: Persisted task states drive waits; filtered waits default to no expiry, a cancelled watched task or a passed explicit deadline notifies the owner, rows reconcile independently, and final split completion routes readiness to a live successor.

#### Terminal QA in CI

Was: The terminal Node suite had no changed-input route in lightweight CI.

Now: Either runner copy or its test selects it; normal fast rows and the slim workflow each run their own applicable path once, with empty/zero-base fallback.
