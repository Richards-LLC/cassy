## What you can do now

### Branded documents

#### Your project's look, every time

Was: A report, page or note could fall back to a generic style when nobody asked for branding.

Now: Every one starts from the project's design file, and a project without one gets one first.

#### Client brand, never ours

Was: A client document could silently wear our default colours and fonts.

Now: It uses the client's own colours, fonts and logo, and stops with a clear message if the client has no design file.

#### Ready-to-send files

Was: Screenshots, printing and the final checks were separate manual steps.

Now: One step builds a single file with its screenshots inside, plus A4 and Letter PDFs that are checked page by page.

#### Nothing internal reaches a client

Was: Ticket codes or behind-the-scenes words could slip into a client document.

Now: A client document containing them is refused and not saved, with each offending line named.

#### Feature reports

Was: Asking for a feature report had no dedicated format.

Now: It produces a branded report with real before and after views of the change.

#### Customer release notes

Was: Release notes for a client were the same Slack notes written for the team.

Now: Each client gets its own branded notes as a web page and a PDF, written in their words.

### Commander and checks

#### Usage you can measure

Was: Which Commander screens people use most was a guess.

Now: Commander counts how often each main action happens, without any message content, and shares the counts only with your own paired machines.

#### Watch what matters after a release

Was: The post-release check listed affected screens in no particular order.

Now: It names the most-used affected screens first.

### Smoother deliveries

#### Conflicts come back to their author

Was: A finished change that clashed with other work could sit stuck.

Now: It returns to the person who made it, naming the clashing files.

#### Quieter waits

Was: Someone waiting on an answered question could keep raising the same alert.

Now: Once that question is answered, the alert stays quiet until a new question comes up.


## Under the hood

### Deliverables core

#### Design file first

Was: Craft and report skills each restated their own styling fallback.

Now: One design-spec rule, linked from every reader and the close gate, sends all output through the project's design file; tasks record `design: <path>@<revision>`.

#### `cas deliverable brand`

Was: The release renderer read only a root design file with CSS `source:` + `maps:`, so design-spec value keys silently got Petrastella defaults.

Now: The profile's `design:`, the file nearest `--surface`, root, a single nested one, `inherits:`, then value keys; customer audience exits 1 instead of defaulting.

#### `cas deliverable finalize`

Was: Fill, inline, hygiene, print and check-pdf lived in separate skill scripts.

Now: One verb runs them in order, with a 120 KB per-image budget that drops lowest-priority pairs whole, audience hygiene and A4 + Letter check-pdf; exit 0/1/2.

#### Refused output is never written

Was: A refused deliverable could still be left at the output path.

Now: HTML and PDFs are built in a private workspace and moved into place only on pass; the receipt's `html` is null on refusal.

#### Release and SOW reports switched

Was: The release report shipped its own token code and the SOW skill its own print and inline scripts.

Now: Both render through `finalize`; `cas release report` gains `--audience`, `--pdf` checks A4 and Letter (PyMuPDF required), and `check-sow.py` keeps only `gap`.

#### Front-end skills

Was: Feature reports and customer notes had no front-end on the core.

Now: `cas-feature-report` and `cas-customer-release-notes` ship with contracts and templates; `cas-release-notes` hands customer notes off.

### QA and Commander

#### Usage ledger

Was: Journey traffic shares were estimates.

Now: Commander posts per-day action counts to paired hubs (max per device/day/action), and `cas qa journeys --traffic [--days N] [--write]` turns them into shares.

#### Post-release watch order

Was: The post-release check listed affected journeys unordered.

Now: It names them highest traffic share first, display only.

#### `[qa.capture]` config

Was: QA capture settings had no typed home.

Now: Typed keys for target or serve command, shots, viewports, masks, budgets and an anchored login whose credentials come from a named environment variable.

### Factory

#### Conflict and upkeep return

Was: A parked delivery stuck on a merge conflict or a post-merge upkeep gate waited for manual rescue.

Now: `request_changes` returns it Open to its assignee with the conflicting paths or gate text and one notice.

#### Answered blocker quieting

Was: Repeated blocker and idle alerts woke after an answer, and unrelated pings could silence them.

Now: Only `kind=answer` or a reply to the blocker records ownership; alerts re-arm on a new question or hold.

#### 3.81 follow-ups and `gc_report` paging

Was: Declined lanes re-alerted, a parked anchor could advance past origin, and `gc_report` pages skipped rows while host scans changed.

Now: Declined lanes settle until refs change, anchors stay on origin, and host scans render after store inventories.
