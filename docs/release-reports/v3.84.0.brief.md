# Brief: Cassy v3.84.0 release report

Workflow: cas-release-report, cas-html-reports and cas-ui-craft. The release contract fixes the section order and the equal-dot change map.

design: DESIGN.md@b43940e43

## Single idea

Every Claude and Codex subscription is listed by email, and the one with room is picked for you.

## Hero form

A serif verdict sits above directly labelled equal dots, one per CHANGELOG change: 13 changes in 3 areas. Sessions leads with 11, then Commander and Safety with 1 each. Every session starts on an account, so the account list, pickers, recommendation, lifecycle commands, reset times and limit recovery all sit under Sessions; the shape (one dense row against two single dots) is the argument that this release is about accounts. The generator's area order is kept. GitHub issues closed is a secondary count, and there are none this release.

The generator counted the summarized `### Added — …` section as one change and the two upgrade notes as changes (8 total). The Change map and glance count were corrected by hand to the 13 titled CHANGELOG changes (8 added, 3 changed, 2 fixed); the upgrade notes are named in the counting note instead. The generator defect is filed as its own fix.

## Emotional register

Collected and precise. The root DESIGN.md maps `hub-web/public/cassy-tokens.css` and `hub-web/src/fonts.css` to report roles: Commander's violet-to-teal aurora, glass chrome, opaque reading cards, Inter prose and JetBrains Mono labels. `cas deliverable brand` resolved it (source design-md-css, DESIGN.md@b43940e43). No second palette is used.

## Distinctive move

The equal-dot change map shows that this release concentrates on accounts before any detail is read: eleven Sessions dots in the verdict colour against two grey singles. One decorative row of six dots returns at Install. Dots count changes, never impact or severity.

## Deliberately omitted

- No before/after captures: the delivering tasks recorded no verified pairs for these account and CLI changes, and none were reconstructed.
- Stage timings are missing from the latency receipt (no STAGE_SECS), so they are named in scope rather than shown as zero. Request-to-published and cut-to-published were not measured.
- The report was produced after publication, from the published release, the CHANGELOG and the posted release-notes draft.
