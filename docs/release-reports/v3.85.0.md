## What you can do now

### A Codex coordinator that gets on with it

#### Acts instead of checking

Was: The Codex coordinator kept waiting and re-checking its inbox inside one long turn.

Now: It acts on each update as it arrives and stops when nothing needs doing. Cassy wakes it for the next one.

#### Remembers how to work

Was: Each time its conversation was condensed, it re-read its instruction files from the start.

Now: A short built-in playbook stays with it, so it carries straight on.

#### Fewer messages

Was: It replied to almost every status update, which set off more back-and-forth.

Now: It replies only when someone needs an answer, an action or a decision.

#### No running commentary

Was: It announced each step, and which instructions it was using, before acting.

Now: It stays quiet while it works and answers your status questions directly.

#### Your voice

Was: On Codex, the tone and style you set in your own instruction file were overruled.

Now: Your own instructions set the voice for Claude, Codex and Grok coordinators. Cassy's rules still set content and length.

### Fixes

#### Grok works with Cassy again

Was: Under Grok 1.0.70, every Cassy check failed on every step, so none of Cassy's protections ran.

Now: Grok 1.0.70 runs Cassy's checks normally.

#### Your unsent text is safe and messages wait

Was: While you had unsent text in a Codex coordinator's input box, waiting messages were dropped after 15 minutes and work stalled for 90 minutes or more.

Now: They wait without touching your text and go through once the box is clear. You get one alert after 9 minutes.

#### Honest delivery status

Was: The message status view promised retries and alerts that had not happened.

Now: It shows the retries and alerts Cassy actually recorded.

#### Approved checks finish the job

Was: An approved review of a task with no code change could leave the task open.

Now: The approval completes the close. The status view says when a task is waiting on its reviewer, instead of asking you to nudge anyone.

#### Codex logins carry through

Was: A Codex coordinator started on a second Codex login could not start helpers without naming that login again.

Now: Helpers start on the same login unless you choose another.

#### Clearer shared-file warnings

Was: A warning about a file someone else was editing showed an internal code and pointed you to the wrong person.

Now: It names who is editing the file and what they are working on, and who to ask.

#### Finishing a Codex session

Was: Typing `/finish` in Codex did nothing, and nothing said what to type instead.

Now: When a Codex session starts, it tells you to type `$finish` or say "finish" to wrap up.


## Under the hood

### Supervisor contracts

#### Act on the signal

Was: `CODEX_SUPERVISOR_INSTRUCTIONS` lacked "Act on the injected signal; do not poll", and Codex looped on sleep plus `inbox_poll` (7.6/h against 0.2/h on Claude).

Now: The Codex contract carries it, plus "end the turn when nothing is actionable". The `act-on-injected-signal` element is required in every supervisor launch shape.

#### Resident core

Was: The contract pointed at two skills, which Codex re-read through the shell after every compaction (8.1 reads/h against 0.8).

Now: A signal → action core lives in `developer_instructions`, which Codex keeps across compaction. The checklist is startup-only, within a 6,500-byte test budget.

#### Reply only when needed

Was: The contracts said to reply to every update, and Codex sent 9.8 messages per merge against 2.6.

Now: The Codex, Claude and Grok contracts carry `reply-only-when-needed`: reply for an answer, action or verdict, never to acknowledge a receipt or status.

#### Commentary policy

Was: Codex base instructions require commentary before tool calls and on skill use, and "Skip preamble" did not name that channel.

Now: The Codex contract keeps commentary silent on triage turns, allows one line before a step over 2 minutes, and bans skill announcements.

#### Voice precedence

Was: Codex sends the user-level instruction file as a user-role message below the developer-role contract, so "facts, not narration" won.

Now: The `user-instructions-voice` element in the Codex, Claude and Grok contracts hands voice and style to the user's own instruction file.

### Fixes

#### Grok 1.0.70 hook payloads (#1410)

Was: `HookInput` used serde aliases, so a payload with both `hook_event_name` and `hookEventName` failed as a duplicate field.

Now: All 16 aliased fields accept both spellings and prefer snake_case, including an explicit null. A captured 1.0.70 payload is a test fixture.

#### Dirty-composer relays (#1400)

Was: `DeferredComposerDirty` stamped a `GatedNotReady` retry, spending the 120-attempt, 900-second budget until the relay was abandoned.

Now: It parks with `ParkBusy` and a 2-minute recheck. `worker_status detail=true` lists every held relay with age, next recheck and alert ID.

#### Delivery status (#1383)

Was: `message_status` hardcoded a 60-second re-wake and the raw configured threshold, and inferred alerts from age.

Now: Status and watchdog share `delivery_attempts` and `next_attempt_at`, use the capped watchdog threshold and cite `channel_stalled_notice_id`.

#### Approved no-code close (#1388)

Was: `queue_approved_verification_close_retry` skipped tasks not InProgress or AwaitingMerge, so a Blocked verification wait got no retry.

Now: A task Blocked only by the current cycle's wait note for the approved dispatch gets the retry. Receipts name the real skip reason.

#### Verifier wait in worker_status (#1381)

Was: A merged delivery with a pending dispatch read "WAITING ON WORKER".

Now: It reads "WAITING ON VERIFIER" with the dispatch, owner and deadline, and "Do not message the worker to close."

#### CODEX_HOME reaches MCP (#1390)

Was: The Codex-injected Cassy MCP server lacked the pane's `CODEX_HOME`, so `spawn_workers` without `config_dir` checked the default Codex login.

Now: The effective `CODEX_HOME` is forwarded as `mcp_servers.cs.env.CODEX_HOME`. An explicit `config_dir` still wins.

#### Shared-file advisory (#1405)

Was: The advisory carried a static ticket id and always routed to "the other session's supervisor".

Now: A same-session holder reads "another worker in your session (name, task)" and routes to your own supervisor.

#### Codex finish hint (#1402)

Was: Codex slash commands are not extensible, so `/finish` did nothing and no Codex surface named the working form.

Now: Codex session-start context (native hooks and MCP startup) adds a budgeted line: type `$finish` or say `finish`. Other harnesses are unchanged.
