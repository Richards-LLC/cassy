## What you can do now

### Commander

#### Quick inspections are counted

Was: Opening and closing a diagram's source or a diff in quick succession could go uncounted.

Now: Each opening is counted, even when the browser merges the two clicks.

### Sessions

#### Work keeps moving

Was: A worker finished one task and could wait a long time for the next assignment.

Now: Each worker takes an ordered list of tasks and starts the next one on its own. The list can be inspected, reordered or cleared at any time.

#### One task per checkout at a time

Was: Starting a task by hand could race a queued start, leaving two tasks running in the same checkout.

Now: Every start waits its turn, so one checkout runs one task at a time.

#### A removed model stays removed

Was: A Codex worker whose model and effort were removed after setup could still use them.

Now: Only the launch's final model and effort are used.

### Tasks

#### Rapid response mode

Was: Every fix ran the full set of checks and reviews, even during an urgent outage.

Now: The operator can open a time-boxed window, at most 12 hours, for one project board. Checks scale down while a safety floor stays on: build, changed-test and secret checks still refuse, database changes wait for the operator's review, and every skipped check is caught up when the window closes.

#### Finished work cannot be rewritten

Was: Work already handed in could be overwritten.

Now: Overwrites are refused, and a recovery merge that restores the handed-in work is accepted.

#### Required checks cannot be skipped

Was: A push could skip the required checks with a skip flag or a settings trick.

Now: Those pushes are refused, while ordinary pushes work as before.

#### Checks run where they cannot be faked

Was: The finish line trusted a local "checks passed" note that anyone on the machine could write.

Now: The shared build server decides, and the local note is only an early warning.

#### Closes report correctly

Was: Closing a task could say nothing changed even though it had closed, when starting the next task ran late.

Now: The close is recorded first, so the reply matches what happened.

#### Capture keeps its receipt

Was: If time ran out while preparing before and after copies, a screenshot capture stopped with an error and no receipt.

Now: It prints a receipt that names the timeout.

### Messages

#### Kept messages all go out

Was: With two Commander tabs open, a message kept during an outage could wait until the page was reloaded.

Now: Each kept message is sent once when the connection returns, whichever tab sends it.

Source: this fix shipped in v3.90.0; its CHANGELOG entry was recorded in the 3.91.0 section.

## Under the hood

### Commander

#### Rich-content inspection counter

Was: Opening and closing a diagram source or unified diff in quick succession could collapse into one toggle event, leaving the inspection uncounted.

Now: The usage counter increments when the opening summary is activated, even if the browser coalesces the toggles.

### Factory workflow

#### Ordered worker queues

Was: One assignment at a time per worker.

Now: Spawn and assignment accept an ordered task list; close or park starts the next eligible task on its own target branch and keeps the prior delivery ref. Stale entries are skipped with notes, and a returned delivery can resume while its successor is held in place.

#### One start lock per worker

Was: A manual start could race the first queue assignment or a refilled queue and change branches in the same checkout.

Now: Every start holds the worker's start lock through its Git and lease work; unqueued starts wait, queued starts refuse a busy lock, and both re-read queue state.

#### Final launch model only

Was: A Codex worker launch whose model and effort were removed after setup still passed them to its CAS tools.

Now: Only the launch's final model and effort reach the CAS tools.

### Delivery process

#### Rapid response window and floor

Was: Per-task QA, close verification and batch receipts always gated a fix, and nothing recorded checks skipped under pressure.

Now: `cas qa rapid-response enable <epic> --for <duration>` opens an operator-only window of at most 12 hours: per-task QA is skipped, close verification runs for one task in four and fixes close without a batch receipt, while the post-release check stays a full gate. Build, touched-test and evidence secret checks still refuse; an unreadable diff, a secret-shaped line or a migration keeps every gate, and migrations wait for `cas qa rapid-response review-migration`. Each skip is recorded under `.cas/operator/`, and window close files one back-fill task.

#### Anchor rewrite refusal

Was: A push could replace a published delivery with rewritten history, and re-parking could refuse the recovery merge that restored its anchor.

Now: Worker pushes refuse non-fast-forward rewrites of a published factory tip, and re-parking accepts the unchanged recovery merge that restores the recorded anchor.

#### Hook bypass guard

Was: `--no-verify`, exported `GIT_CONFIG_COUNT` or `GIT_CONFIG_PARAMETERS`, `core.hooksPath` changes or unsets, `declare -x` and `set -a` could bypass factory push checks.

Now: Workers and reviewers are refused each form; inherited `GIT_CONFIG_GLOBAL` and `GIT_CONFIG_NOSYSTEM` no longer block a plain push, and supervisors keep the approved exception route.

#### CI-only fast-row proof

Was: Park required a local fast-row PASS receipt or a supervisor-approved exception file, both written by the same user as the worker.

Now: CI runs the fast rows once per lane and is the only fast-row proof; the pre-push hook stays early feedback, and the exception writer, validator and hook reader are gone. This closes the 3.90 known limit that same-user PASS receipts were still trusted.

#### Close before handoff

Was: A close could finish writing Closed, then report its status unchanged when starting the next task ran past the response deadline.

Now: The close is marked committed before the handoff; an interrupted handoff is recovered from the durable queue.

#### Capture timeout receipt

Was: If the capture budget ran out while Git prepared the private before/after checkouts, `cas deliverable capture` exited with a usage error and no receipt.

Now: It prints a receipt with a capture-timeout finding, as it already did for a slow server.

### Messages

#### Two-tab kept messages

Was: With two Commander tabs open, a message kept during an outage could stay "Waiting for the connection" under a Live header until reload.

Now: Each kept message is sent once when the connection returns, whichever tab sends it. The code shipped in v3.90.0.
