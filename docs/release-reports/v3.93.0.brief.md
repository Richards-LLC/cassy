## Single idea

Four fixes shipped, three of them in Commander: dismissals stick everywhere, idle reads as idle and Usage opens and closes, and the release went from PR to published in under 23 minutes.

## Hero form

A serif verdict with a directly labelled equal-dot map counts the four Fixed CHANGELOG entries by product area. Commander leads with 3 dots in the verdict color; Tasks has 1. Each dot counts one change, without implying effort or importance. The generator's stable area order is kept and zero rows are omitted. The generator's keyword matching had filed the idle-mark and dismissal fixes under Sessions; both are Commander changes, so the areas are assigned editorially and the counting note says so.

Assured, humane and collected. DESIGN.md gives the report Commander's violet-to-teal aurora, glass hero, opaque reading cards, Inter prose and JetBrains Mono numbers, all inlined locally with no network dependency.

## Distinctive move

A three-dot Commander row against a single Tasks dot makes the release's shape plain: almost everything here is something an operator sees in Commander. The numbered folio and six decorative Install dots preserve the report identity across releases.

## Deliberately omitted

No KPI row ahead of the map, no severity bubbles, no fabricated screenshots. Two real before/after pairs are shown: Usage on an idle Claude 2.1.312 supervisor, and the idle supervisor's status dot, both from the installed 3.92.0 (the Usage fix's own QA baseline) against the round 16 batch QA run of the release candidate. Dismissals have no before capture of the same surface, so their card has no figure; the takeover fix has no visual surface. The generator-owned GitHub issue count is zero and has no tile. Request-to-published, cut-to-published and per-stage times are unavailable and named in the counting note. No queue ejection occurred, which is stated in prose rather than as a zero tile.
