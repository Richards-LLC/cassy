## What you can do now

### Sessions and Commander

#### Quieter sessions

Was: Every prompt and tool step carried automatic memory cards that almost nobody used (5 uses in about 39,500 injections).

Now: Those cards are gone. Saved handoffs, memory search and related context on new tasks still work. In release QA, a session started on a copy of the real project store still opened with its saved handoff and no recall cards.

#### Steadier connections

Was: Replacing a machine's connection could leave the old one sending one late request.

Now: Stopping or replacing a connection cancels everything it had in flight.

#### Help text keeps secrets secret

Was: Showing help for login or the bridge server could print a token that was set in your environment.

Now: Help names the setting but never shows its value.

#### Correct login instructions

Was: Some errors told you to run a login command that does not exist.

Now: They name the real command, `cas login`.

### Measuring what helps

#### Friction you can see

Was: There was no record of manual rescues, release timing or which features were noise.

Now: Cassy records checks, rescues, escapes and releases, and each session can rate a feature in one line. `cas ledger report` shows it, and projects share metrics, never code, through Cassy Cloud. On a copy of the real project store, the first run turned existing history into 2,610 events, and a second run added none.

#### Fewer settings that did nothing

Was: `cas config` listed 16 pop-up notification settings that changed nothing, because the pop-ups never ran.

Now: Those settings are gone. A config file that still sets them loads normally, prints one note naming them and drops them on the next save.


## Under the hood

### Removed

#### Ambient recall

Was: Per-turn recall injection across every harness.

Now: Removed (about 7,700 lines); handoffs, explicit search and task-create context kept. The installed 3.93.0 binary carries the recall producer string once; the release candidate carries it zero times.

#### Dead subsystems

Was: A never-enabled notification pipeline, a recording index nothing wrote, a second factory session manager and dead search modules.

Now: Removed (about 8,400 lines); a forward migration drops the six empty tables, and retired notification keys still load. On a 1.76 GB copy of the real store, the first open applied migrations 289 and 290 in 1.1 s, left no recording tables and passed `quick_check`; a second open changed nothing.

#### Release train

Was: The pre-3.54 release train and its lane checkers.

Now: Removed (about 9,500 lines); release-cut lessons now follow the one-command release, proven by a whole-path release dry run.

#### Expired aliases

Was: Factory actions still ran through `coordination`, and the `bypass_code_review` close alias still worked. In 3.93.0, `coordination action=worker_status` ran and added a deprecation note.

Now: Both are refused with an error that names the live route: "Factory action `worker_status` is available only through the factory tool: `mcp__cas__factory action=worker_status`".

### Fixed

#### Merge admission

Was: A failed change classifier read as red CI, and a code commit with no runs of its own was admitted while the tip's CI was still pending.

Now: Missing code CI reads as unconfirmed, with the run link, and a pending covering run holds the merge.

#### Close gate

Was: A file renamed inside its own delivery read as dropped content.

Now: Measured against the delivery's net tree; real drops are still refused.

#### Store IDs

Was: The collision fix lived in one of four id generators.

Now: One shared generator for tasks, skills, specs and code. A burst of 15 task and 3 spec creates in one server session gave 18 distinct IDs.

#### Release gate

Was: An aborted row could leave Cargo children running.

Now: Cleanup terminates and reaps the whole tree, with bounded escalation.

#### Secrets in help

Was: `--help` showed env values for the Cloud and bridge tokens.

Now: Hidden, with a sentinel test.

### Added and changed

#### Friction ledger, phase 1

Was: Interventions, escapes and feature value were reconstructed by hand after each session.

Now: Append-only `quality_events` (check runs, interventions, escapes, releases, feature feedback), batched sync to Cloud's team quality-events endpoint (metrics, titles and links only), and `cas ledger report --release vX`. Update and delete on the table abort.

#### Test hygiene

Was: Test guidance warned against sleeps only, and a subset run could be reported as the full suite.

Now: Builtin test guidance names six measured bad-test patterns, proof claims must name what ran, style-pinning and copied-logic tests are gone, and slow tests use injected clocks.

#### CI coverage

Was: 16 script and visual-QA suites never ran in CI, and visual QA captured one page at a time.

Now: They run when their inputs change, and visual QA captures up to three pages at once.
