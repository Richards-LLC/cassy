## What you can do now

### Release changes

#### Safer cleanup

Was: a name-based cleanup command could stop unrelated coding sessions.

Now: common name-based, looped and piped stop commands are refused, while stopping a process by its known number remains available.

#### Reuse completed checks

Was: unchanged code was checked again after it had already passed the final merge checks.

Now: matching results are reused, while the required code-quality check still runs.

#### Focused checks

Was: unrelated tooling checks ran even when their inputs had not changed.

Now: checks follow the changed inputs, and a large temporary-repository check uses a small example instead.

#### Reusable update builds

Was: update builds could miss earlier build work or let it expire during a long compile.

Now: compatible saved work is restored, only missing pieces are prepared, and long compiles keep that saved work available.

#### Shared build copies

Was: manually started checks could save build copies that later updates could not reuse.

Now: shared copies are saved from the main release path, and manual checks can read existing copies without adding new ones.

#### Earlier download checks

Was: preparing an update waited for both platform downloads before checking either.

Now: each platform download starts its checks as soon as it is ready.

#### Lighter browser checks

Was: browser checks started an extra server and downloaded an unused browser component.

Now: each kind of check starts only its required server and uses the browser already selected for it.


## Under the hood

### Release changes

#### Process signal protection

Was: some automation roles bypassed the pattern-kill guard, and compound shell commands could separate a process search from its signal.

Now: every automation role refuses pkill, killall and dynamic or piped kill operands combined with process searches, including loops, eval and assigned command names. Literal PID and PID-file signals remain available.

#### Main check reuse

Was: main repeated test compilation despite an identical tree already passing the merge queue.

Now: Test Compile Guard reuses that receipt. A matching Darwin cache avoids download and compilation, a miss restores a partial cache, and Clippy always runs on main.

#### Scoped tooling checks

Was: visual-QA fixtures ran for unrelated changes, and the codemap fixture built a large repository.

Now: registered inputs select the fixtures, the measured codemap run fell from 226 seconds to 7 seconds, and unreachable PR-recording work is removed.

#### Release build reuse

Was: release prebuilds missed main-scoped dependencies, and sccache could expire during a long compile.

Now: compatible dependency and Zig caches restore from main, missing entries are seeded there, and the sccache idle timeout is disabled.

#### Main-only cache writes

Was: manual dispatches could save dependency and Zig cache entries that later main builds could not restore.

Now: only automatic main runs save cache misses. Manual dispatches can restore entries without saving new ones.

#### Browser job setup

Was: journey jobs started Vite as well as the built-app server and downloaded an unused Chromium headless shell.

Now: journeys use the built-app server, fixtures use Vite, and pinned Chromium runs without the extra shell download. One evidence upload remains per shard.

#### Platform publication

Was: Linux audit waited for macOS and the publisher checked out more source than it needed.

Now: each uploaded platform archive starts its audit independently, publication checks out only the release commit, and only a missing platform is rebuilt.

### Test coverage

#### Composer acceptance checks

Was: the real-hub test provider lacked the native composer needed to exercise Enter and Exit.

Now: the provider exposes that composer, and the acceptance checks exercise both controls through the real hub.
