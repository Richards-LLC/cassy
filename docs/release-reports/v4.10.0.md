## What you can do now

### Your settings are respected, and reviews read clearly

#### Your chosen account is used

Was: new helpers could start on a different Codex account than the one you set for the project.

Now: they use your configured account, and the receipt says where that choice came from.

#### Review questions stay readable

Was: a review question that mentioned a file location was replaced by a blank placeholder.

Now: only the location is hidden, and the question itself stays readable.

#### Release holds ask before they apply

Was: holding a release for checks could not be undone by anyone but you, without a warning.

Now: it must be confirmed first, and the message says only you can lift it.

#### Answered questions stop repeating

Was: after you or Cassy answered a stuck question, the same alert kept coming back.

Now: an answer closes it, and a new question gets its own alert.

#### Artifacts can be revoked

Was: a shared file could not be withdrawn once published.

Now: it can be revoked with a reason; viewing and new shares stop at once, and a record is kept.

#### Steadier builds and syncing

Was: a restarted helper could leave its build running and locking others out, and a working task could be reset by an old copy from Cloud.

Now: builds stop cleanly on restart, and a task you're working on keeps its status.

#### Slack replies stay with the right owner

Was: when the owner of a Slack thread was uncertain, an older intake could still pick up the message.

Now: it reports the problem and waits instead.


## Under the hood

### Release changes

#### Worker accounts

Was: the recommender picked a Codex home over the configured one, and lane changes dropped preferences.

Now: `factory.codex_home` applies when no batch or per-worker config_dir is set, and the receipt names its source.

#### Verifier redaction

Was: a local path anywhere in a summary replaced the whole field with a placeholder.

Now: only path spans are redacted, so supervisor_call questions stay readable in notices and show/latest.

#### Release freeze

Was: `train_freeze` applied an operator-only freeze with no warning.

Now: it needs `reason="release-freeze: …"`, and the refusal names the operator-only lift. The watchdog no longer reports frozen-train holds as a stall.

#### Blockers and alerts

Was: answered blockers kept waking the supervisor, and relays could expire undelivered.

Now: replies and decision notes retire the episode, relays queue a supervisor action, and auto-merges leave a landing receipt.

#### Close and recovery

Was: unpublished candidate commits blocked landed deliveries, and retired implementers broke verification.

Now: released-train landings close, local_merge recovers without a remote, and verification survives retirement.

#### QA evidence

Was: batch ledgers could not declare coverage, and repeated rounds shared directories.

Now: `--covers` declares receipt deliveries, rounds get head-scoped paths, and premerge review honors batch-QA deferrals.

#### Builds and tests

Was: recycle left guard and Cargo children holding target leases, and capped tests refused isolated-HOME prefixes.

Now: recycle settles owned runs and leases first, and named capped tests accept HOME, Cargo, Git and CI prefixes.

#### Sync and search

Was: team pull could reset a live InProgress task, and read-only search timeouts reported unknown writes.

Now: a live owner's task stays protected, and search timeouts are reported as non-mutating with stage timings.

#### Artifacts

Was: no revoke path.

Now: an audited revoke with a reason blocks fetch, preview and shares locally, with Cloud deletion confirmed separately. Store migration 298.

#### Slack intake

Was: a refused managed claim could fall through to legacy intake.

Now: only an explicit Unmanaged allows legacy fallback. Cloud-side owner selection is still open.
