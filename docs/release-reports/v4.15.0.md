## What you can do now

### Update deadlines and release cleanup changes

#### Updates don't hang

Was: on a Mac, one stuck project check held an automatic update for 4 hours 40 minutes, so the next release never installed.

Now: the shipped code stops that check after 10 seconds and falls back to its directory walk. This does not prove the complete update finished: pending release cleanup blocked installation on one production Mac.

#### Release cleanup says what really happened

Was: a release whose work was all held could look finished.

Now: the shipped notice separates what closed, what was already closed, what is held and what is left, with counts. The new cleanup behavior has not yet had a valid production test.

#### One missing record no longer stalls a release

Was: a single deleted task made a whole release fail to close its fixed issues.

Now: the shipped code reports that one task on its own instead of failing the whole run. Production validation remains pending.

#### Cleanup works across both machines

Was: release cleanup could not read a review published on the other machine.

Now: the shipped code downloads and verifies the review wherever it was published. Production validation remains pending.


## Under the hood

### Release changes

#### Explain a skipped context clear

Was: an oversized wake could skip a context clear without explaining why.

Now: one quiet explanation records the skip when the latest call remains below the context threshold.

#### Train CI wake

Was: the observer ran the train CI script from the checkout's working tree, so an older checkout failed every scan silently and a green frozen train got no ready-to-cut wake.

Now: it runs the script from the train tip.

#### Install hang

Was: `git rev-parse --show-toplevel` had no deadline inside `cas release installed`, and a blocked Git child under the LaunchAgent held it for 4h40m.

Now: the probe stops after 10 seconds and falls back to the directory walk.

#### Release closeout

Was: unstarted descendants created missing-anchor obligations, one purged quarantined task failed issue reconciliation for all 33 deliveries, and report proof was lost between cut and close.

Now: membership ignores unstarted work, a missing row fails only its own outcome, and report bindings are checked before freeze.

#### Merges and closes

Was: a failed push left the shared target moved, late park refusals were cut off, and conflict repairs were blamed for the target's journeys.

Now: merges publish from a detached checkout against the observed origin SHA, late refusals list every gate, and overview findings cover only the delivery's own journeys.

#### Epics

Was: a shipped epic could not close once its branch was deleted, and an approved epic merge parent was refused at close.

Now: the default branch proves shipped children, and a supervisor-approved merge parent is measured at its pushed tip.


### Production validation remains pending

At 8:07:23 AM ET, the publishing machine reconciled v4.15.0 using the older v4.14.0 binary before installing the new release. It reported 43 members and 41 residuals, with the same failure classes as v4.14.0. Those counts do not test the fixes in v4.15.0. On the other Mac, a pending v4.14.0 reconciliation blocked installation of v4.15.0. [Issue #1798](https://github.com/Richards-LLC/cassy/issues/1798) tracks installing first and replaying pending reconciliations with the newest binary. No production success is claimed for release cleanup.
