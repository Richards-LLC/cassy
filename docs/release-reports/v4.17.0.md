## What you can do now

### Replies that arrive, releases that check themselves

#### Commander replies arrive

Was: replies addressed to any device expired unread, even with Commander open.

Now: the first signed-in device to receive a reply settles it.

#### Commands reach an idle session

Was: Commander could refuse a command as "busy" while the session was idle.

Now: readiness is read from the live pane, not a scrolled view.

#### No unreviewed work ships

Was: a release could go out with its own changes never reviewed.

Now: the cut refuses until every change in the release has a review.

#### No self-graded approvals

Was: the session running the work could approve a design it had commissioned.

Now: anything you are asked to approve gets an independent review first.

#### One notice per review

Was: recording a release review sent one notice per held task.

Now: one notice lists what closed and what is held, grouped by reason.

## Under the hood

### Release changes

#### Commander delivery

Was: device_receipts matched a "*" recipient only against a literal device id, so 52+ supervisor replies were abandoned with 0 delivery attempts.

Now: a None or "*" recipient closes on any authenticated device's receipt; forwarding attempts are counted.

#### Supervisor readiness

Was: commander_native_input_ready and startup recovery read the scrolled viewport (dump_row).

Now: they read the live row (dump_live_row).

#### Cut preview

Was: refused only when would_close == 0.

Now: also refuses when any included task is REVIEW_MISSING; older-release residuals stay residuals.

#### Close-at-release

Was: approved verdicts bound to a synthetic candidate commit were held as REVIEW_MISSING.

Now: an approved verdict whose candidate manifest binds the delivery anchor and ships its tree closes the member.

#### Supervisor guidance

Was: supervisor_direct verdicts were invited for any deliverable; per-member close holds arrived one notice each.

Now: supervisor_direct is for mechanical evidence only, holds are grouped per receipt, and one close-recovery rule applies.

#### Tooling

Was: candidate builds rejected 8-character revisions; `bash -n` syntax checks were refused as nested shells.

Now: any abbreviated revision prefix is accepted, and syntax-only checks pass.
