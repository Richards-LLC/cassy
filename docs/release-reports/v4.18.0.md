## What you can do now

### Smoother hand-offs after a merge

#### Shipped work stays done

Was: a merged change waiting for its final review could hold up the next tasks, or be sent back to be redone.

Now: it stays accepted, unblocks what depends on it, and only new changes need a fresh decision.

#### Broken hotfixes go back for a fix

Was: a failed urgent fix could be left stranded.

Now: it returns to be corrected.

#### A steadier Commander check

Was: one Commander reading test failed at random and held up releases.

Now: it checks a reader parked mid-conversation and a reader following new messages separately, and passes reliably.

#### Test builds from the right version

Was: building a test copy of a newer version needed an updated checkout.

Now: the build uses the requested version's own tools.

## Under the hood

### Release changes

#### Post-merge recovery

Was: a landed delivery pending batch QA blocked dependents after administrative recovery, and post-merge close gates returned the worker to source delivery.

Now: accepted upkeep decisions cover narrower findings at the same immutable delivery; post-merge gates stay with the supervisor and keep the parked delivery.

#### Fast-lane hotfixes

Was: a failed fast-lane ReceiptGate went down the automatic-recovery path and stranded a reverted hotfix.

Now: it uses the corrective-return helper again.

#### HUB-J4

Was: on CI Linux fonts the fixture's reader sat at the tail, so a 17px note wrap failed a mid-thread stability assertion.

Now: the fixture scrolls off the tail deterministically before the drop, and tail-follow is asserted separately. Hosted pass: precheck run 43124043953.

#### QA candidates

Was: `cas qa candidate build` loaded its builder from the cwd checkout.

Now: it loads the builder and helpers from `--rev`.
