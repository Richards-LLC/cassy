## What you can do now

### Everyday use

#### Release scorecards

Was: the ledger report listed reviews, verdicts and notices, and nobody graded them.

Now: it scores five rubrics per release, cites the evidence for each score, and tracks how long a release sat ready without being cut.

#### Pushes test what they touch

Was: a push proved only the tests its author chose to name.

Now: CI runs the delivery's own tests first, then the tests around it, and says whether a failure was caused by the change or was already there.

#### One identity per delivery

Was: moving work between trains could drop its approval or attach it to the wrong cycle.

Now: every delivery records its cycle, approvals stay attached across moves, and one project resolver serves every check.

#### Fewer repeated checks

Was: a merge asked GitHub about its target up to four times, and some checks ran again at park.

Now: one read per merge, and each check runs once, in CI.

#### Clearer refusals

Was: many refusals were free text.

Now: every check has a stable code, and refusals name the fix.

## Under the hood

### Sessions

#### Coded checks and measured exceptions

Was: Refusals were free text; replay could inflate exception counts.

Now: Checks declare stable codes. `cas gates list` inventories them; reports count refusals and exceptions. Only accepted override tags add facts, and an audit inventory rejects uncovered policy sites.

#### Clearer refusals, fewer repeated checks

Was: Checkout refusals gave commit advice; ownership and lint checks repeated.

Now: Checkout refusals name the checkout fix. Ownership runs once after inference, before effects. Lint stays in CI; shared guards use stable codes, and recorded native child messaging is permitted.

### Tasks

#### Approvals stay with the reviewed work

Was: Sibling landings triggered repeat reviews; new reviews could obscure approved work.

Now: An unchanged patch and clean merge carry approval with an audit note. Policy stamps exclude later requirements but retain integrity checks; carried approvals keep cycle, registry version, source and shipped-tree checks.

#### Delivery detail and release scores

Was: Release totals hid delivery detail; events had no grades.

Now: Reviews carry cycle and provenance; sourced wakes, interventions and backfills avoid duplicates. Five four-label rubrics score reviews, verdicts, holds, green-but-uncut time and held/idle time, citing each hit. Scores do not gate work.

#### Test the delivery before it merges

Was: Pushes proved named tests; wider breakage appeared after merge.

Now: CI runs the recorded start-base impact set: own tests, then up to three shards. Broad changes run all tests. Every unsuccessful outcome, including timeout, signal and leak failure, must be inherited to stay nonblocking.

#### Durable delivery identity and successors

Was: Follow-up commits could appear foreign; park identity was reconstructed; local unpublished commits could enter start bases.

Now: A supervisor’s saved `merge_source=<full SHA>` grant adopts a commit and ancestors. Synced anchors persist cycles and tips; reopen starts another cycle. Starts use published targets; explicitly named successors can deliver cancelled predecessors’ recorded commits.

#### One target read and a working release close

Was: Three train entries made 24 origin reads; reports without cycles could hold release close.

Now: The locked fetch is reused: three reads for three entries; new review still refreshes. No-cycle reports use the reviewed-commit verdict, and cut refusals list holds and members missing review.

### Releases

#### Fragments and derived release inputs

Was: Parallel shared-doc edits conflicted; release proof inputs were assembled by hand.

Now: Release prep folds delivery fragments into shared docs once. Cuts derive proof from recorded references and ledgers; saved previews bind final trees and permit later review.

#### Reliable worktree and store previews

Was: Missing local configuration or a relocated store could break preview identity.

Now: Linked worktrees inherit canonical identity through Git’s common directory; local pins win. Relocated stores replay with repository, candidate-key, source and tree checks intact.

#### Recorded decisions and explicit policy failures

Was: Policy errors could fail silently; decision counts and identity-dependent refusal inventories had gaps.

Now: Policy failures name the bad value or revision and fix. Scripts, merge, CI, MCP and hooks record coded decisions. Refusal exits stay failures; a provenance-aware audit rejects new uncoded sites and only shrinks its baseline.

#### Accurate checks and declared test tokens

Was: Admissions and duplicate ejections inflated totals; registered codes could look like prose pins.

Now: Checks count this project’s actual results once, retaining run links, observed minutes, untimed counts and separate cohorts. Admission and lint accept declared bracketed codes; unknown tokens and prose pins still fail.

### Other

#### Clean-checkout validation and developer lint

Was: Legacy validation needed a store; quoted CLI arguments and repeated freshness codes caused friction.

Now: Explicit registry policy works without a store; strict policy needs base-aware validation. Lint accepts recorded `shlex.split` arguments. G-105 folds into G-110: 400 checks instead of 401.

#### One rebind identity and one project resolver

Was: Aliases could double-count rebinds; stamps and scope could resolve different projects.

Now: Live and backfilled rebinds share identity without deleting history or merging unrelated actions. Selector stamps and scope matching use the same ordered identities, including the main linked-worktree project pin.
