## What you can do now

### Fewer false refusals, fewer duplicate issues

#### Changed tests are judged fairly

Was: a delivery could be blocked over tests it never changed: a reverted edit, someone else's commits, or an older commit that didn't parse.

Now: only the tests the delivery itself changed are checked, at the version being delivered.

#### Table-driven tests work

Was: a test written as a table of cases (`it.each`) stopped the delivery outright.

Now: the table is checked as one test, and it passes when every row passes.

#### JavaScript and TypeScript tests run as typed

Was: common commands like `npx vitest run` were refused, and valid TypeScript test files failed with "parse error" and no location.

Now: those commands run, those files parse, and any real parse error names the exact line.

#### Database-backed tests run

Was: an integration test that switches on only when a database URL is set showed every case as skipped, so the delivery couldn't finish.

Now: those tests keep their names and run.

#### One issue per problem

Was: the same refusal on two different files opened two GitHub issues.

Now: it matches the issue that's already open and adds to it.

#### Quick fixes for docs-only review findings

Was: a second rejection over docs, evidence or simplicity waited for a person.

Now: Cassy sends one such finding straight back to the session for a single repair. Correctness, security and data findings still wait for a person.


## Under the hood

### Release changes

#### Changed-test discovery

Was: per-commit history, the stale start base and intermediate trees decided what a delivery owed; foreign PR lines counted.

Now: only the delivered head is parsed, over the net `merge-base(target, head)..head` diff blamed to the task's own commits.

#### Unparseable base

Was: a base revision that failed to parse refused the delivery.

Now: it counts as having no prior tests.

#### Parameterized identities

Was: `it.each` / `test.each` / `describe.each` refused as "dynamic/parameterized test title".

Now: a template identity selected by a placeholder regex, proved when every matching runtime test passes five times.

#### worker-check JS runners

Was: `npx`, `pnpm exec`, `yarn`, `bunx`, `vitest run`, cwd-relative paths and `--config`/`-c` hit the Cargo-only message.

Now: accepted; any other flag gets the JavaScript-shape refusal.

#### TypeScript parsing

Was: `importOriginal<typeof import('#imports')>()` and `prisma.$queryRaw<Row[]>` template literals failed tree-sitter-typescript 0.23.2 with no location.

Now: those type arguments are blanked, offsets preserved, before parsing.

#### Parse errors and `node:test`

Was: a base or non-test parse error blocked; `node:test` files went to Jest.

Now: neither blocks, `node:test` routes to `node --test`, and remaining errors name `path:line:column`.

#### Conditional describe

Was: `(url ? describe : describe.skip)('suite', …)` lost its title, so the exact-name filter matched nothing and Jest skipped every case.

Now: the title is kept, including through an alias; a conditional mixing describe and test is refused by code (G-61).

#### Superseded Rust edits

Was: park asked for five passes of a Rust test whose delivery edit a train sync had replaced, and the runner wouldn't repeat it.

Now: park and the runner share one changed-test function from merge-base to tip, so neither owes it.

#### test-shape

Was: `data-*` attribute state and explicit changelog fixture reads were refused as prose or source inspection.

Now: they pass; real prose and source-text pins are still refused.

#### Find-or-file key

Was: the refusal fingerprint kept file paths, so one refusal on two files filed two issues.

Now: path tokens collapse like ids and numbers; a path-only headline produces no key.

#### Pre-merge repair round

Was: a second non-behavioural rejection held for the supervisor.

Now: the first docs/evidence/simplicity rejection reopens to the same live worker once per cycle, bound by a dispatch receipt.
