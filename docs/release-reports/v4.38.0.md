## What you can do now

### Faster checks, cleaner releases

#### Finished work is checked in seconds

Was: handing in a large piece of work could take up to twenty minutes before Cassy finished checking it, and sometimes looked lost.

Now: the same check takes well under a minute, and its result is always recorded, even if a program crashes mid-way.

#### Reviews start when they should

Was: on a busy machine, the automatic reviewer could wait so long for its turn that it gave up.

Now: it no longer waits behind other work, and when something does hold it up, Cassy says exactly what.

#### Releases finish the job

Was: closing a release could time out and leave issues open, or wrongly hold back work that a later change had replaced.

Now: issues close with retries, replaced work closes once it is reviewed, and a slow step says how long it took and why.

### Fewer false alarms, straighter answers

#### Fewer false alarms

Was: Cassy sometimes warned about a page at night for work that was waiting on the operator, or said a message never arrived when it had.

Now: work waiting on the operator goes to the morning summary, and delivered messages stay delivered.

#### Clearer answers

Was: a session could say "merged" or "green" without checking.

Now: those words need real proof in the same turn. Hub status also now says why remote access failed.

#### Tests that test behaviour

Was: many tests checked exact wording.

Now: they check what the product does, so wording can change without breaking them.

## Under the hood

### Commander

#### Hub remote access

Was: with publishing denied, `cas hub status` printed only "Tailscale Serve: WARN - unavailable" and the hub wrote nothing to stderr; the cause was only in `--json` or `hub.log`.

Now: status adds a `Cause:` row, and the running hub writes one stderr line (the journal on Linux) each time the cause changes.

### Sessions

#### Supervisor startup and spawns

Was: a large lane pushed the supervisor's startup message to 10–15 KB, so the harness showed a 2 KB preview; a spawn whose task-queue binding failed returned with no notice and no freed slot; `tools/list` reached 59,037 bytes against a 59,000 budget.

Now: an over-budget startup collapses to counts plus a recovery receipt path; the failed spawn notifies the supervisor and frees its slot; the duplicate tool text is gone, budget unchanged.

#### Restarts and takeovers

Was: a recycled worker's task start was refused for up to 30 minutes by its predecessor's lease, and takeover advice pointed at a worker that was already gone.

Now: the same worker name reclaims its task at once, and takeover advice points the replacement to its own supervisor.

#### Codex turn observer

Was: the mux guessed when a Codex turn started or ended from sleeps or terminal quiet, which cannot tell a long tool call from idle.

Now: `RolloutTurnObserver` reads the rollout's own start, complete and abort rows and times out with a typed error that names what it saw.

### Tasks

#### Close-gate test discovery

Was: changed-test discovery rebuilt a full Rust inventory per changed file (42 builds, 513 s on one delivery).

Now: one inventory per close request and patterns compiled once (5 builds, about 25 s), with the same tests selected.

#### Durable close outcomes

Was: a close past the 55 s tool budget could lose its outcome if the watcher was cancelled.

Now: backend retirement waits for the outcome; a lost continuation records a failure and wakes the supervisor.

#### Test selection at hand-in

Was: the worker test check printed nothing while classifying (16 minutes observed); park diffed from a stale target after a rebase and asked for a predecessor's tests; helper files, escaped-quote titles and specs outside the nearest `jest.config` produced runs that could never pass.

Now: the check prints progress; park and the worker check use the same base; support files are skipped, those titles resolve, and each spec runs under the config that owns it.

#### Park and close refusals

Was: a never-pushed branch parked and passed two reviews before failing with PUSH FIRST; a citation such as `scripts/journeys-for-diff.py:743` read as a missing receipt; a close waiting on batch QA named only what was missing.

Now: park refuses first and names `git push -u origin <branch>`; line and revision citations pass; the batch refusal lists the delivery anchor and why each waiver or receipt did not count.

#### Batch QA evidence

Was: under `qa.mode=batch`, a park with unknown target ancestry requested a per-task QA bundle.

Now: parks honour batch mode, and integrated deliveries keep their final-close evidence path.

#### Verifier launch

Was: verifier launch ran on the client-input path under a 50 ms store budget and starved for 765 s; once a first verifier's deadline passed unstarted, every replacement failed.

Now: launch runs on the external job lane and contention names the holder; a replacement can claim a dispatch whose first verifier never started.

Source: [#2135](https://github.com/Richards-LLC/cassy/issues/2135).

#### Epics and merges

Was: an epic closed on its children's status while its branch never reached main (three epics, for days); `worktree_merge` refused an epic child with WORKTREE REPOSITORY MISMATCH; task start passed an empty start point when the epic branch was never pushed.

Now: closing an epic checks its own branch against its destination and `epic_status` prints an `epic_shipping` line; the child merges; start names the missing branch.

#### Two-machine evidence

Was: a delivery parked on one machine could stay in progress on the merge owner, and nested captures under `proof/` never arrived, so the merge refused.

Now: synced proof no longer outranks the park, and every park lists its evidence files by task-relative path for the owner to restore.

Source: [#2105](https://github.com/Richards-LLC/cassy/issues/2105), [#2079](https://github.com/Richards-LLC/cassy/issues/2079).

### Messages

#### Notices that stay true

Was: a withdrawn Director merge alert showed as MERGE REQUIRED at the next turn; resumed blockers kept re-emitting; the stall watchdog read an older blocker note ahead of the supervisor's hold and paged the operator at night.

Now: alerts for tasks no longer parked or active are held back; blocked emissions stop when the task resumes; holds route to the morning summary.

Source: [#1904](https://github.com/Richards-LLC/cassy/issues/1904).

#### Disk-pressure notice

Was: the notice reported "Reclaimable target caches: none found" while finished review walks filled the disk.

Now: the reclaimable total includes finished review build output, measured through the same guarded inventory as `gc_report`.

### Releases

#### Cut and sync

Was: a cut from a green train still compiled a full candidate locally (171 s in the v4.37.0 cut), and the next train stayed behind main until a manual merge (14 conflicts on 12–13 November).

Now: the cut downloads the CLI the green train run built for that exact tip (about 3 s), and the daemon merges main into every open, unfrozen train within one CI poll.

#### Release closeout

Was: one 6 s deadline covered the whole GitHub pass, so a slow call timed out every later `gh issue close` (22 of 22 on v4.22); members whose lines a later task replaced were held as reverted.

Now: each close gets 30 s and up to three attempts, and failures are listed by number; a reviewed drop is accepted at closeout and at tag time.

#### Trains and review receipts

Was: an ejected cut train refused its own repair; freezing an open epic gave no usable promotion; `train drop` and `train merge` refused from the supervisor's shell; a shared-checkout handoff read as self-review.

Now: a named `release-repair` child is accepted with red CI evidence; freeze returns a complete promote command; train commands resolve the live supervisor; the handoff counts only when the branch carries the delivery's commits.

#### CI and pre-push

Was: the journey-catalog row failed on a spent anonymous GitHub API quota; pre-push said only that fast rows failed; nothing pinned the agent-doc budget test on lanes; the step watchdog's process lookup and self-test were not portable to macOS.

Now: the installer uses the `releases/latest` redirect or a token and prints the HTTP status; refusals name rows and log paths; a fixture pins the lane test; the watchdog reads the process table on Linux and macOS.

#### Build capacity and installer

Was: prebuild concurrency was not scoped by platform; dependency-cache key changes skipped the release suite; an adapter killed at its deadline logged only "pending".

Now: fallbacks run per platform, cache-key changes select the release suite, light runner slots 3–8 install with one sudo prompt, and the timeout log names the phase and deadline.

### Safety

#### Completion claims

Was: any successful tool result satisfied a "merged" claim, and "green", "fixed" and "landed" were not checked at all.

Now: a delivery claim needs a same-turn ancestry check, a settled CI result, a task close or status, or a merge receipt that actually ran.

#### Credential guard

Was: Python source edits naming credential fixtures were refused, and a file-name listing under the home directory passed only as a lone command.

Now: literal replacement text and compound listings that feed only filters pass; direct, constructed and nested credential reads stay refused.

### Other

#### Test rules

Was: timing guidance was split between the test-writing skill and review guidance, and a loop over string literals flagged mock responses as prose.

Now: one rule covers timing in tests, and a literal-only loop variable passes test-shape lint.
