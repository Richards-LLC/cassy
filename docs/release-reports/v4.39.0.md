## What you can do now

### Releases that keep moving

#### The right check starts at freeze

Was: freezing a release didn't start its full check, and the guidance named the wrong one, so a release could wait over an hour for nothing.

Now: freezing starts the full check right away and shows its link.

#### Only the owner's machine cuts a release

Was: a second machine with default settings could freeze a release on its own.

Now: only the machine that owns the release can cut it, and every freeze says which machine did it.

#### No more work on a release that's already gone

Was: after a release was cut, unfinished work kept testing against it and was only turned away at the end.

Now: unfinished work moves to the next release automatically, and anything still aimed at the old one is stopped before tests run.

#### Reviews aren't repeated

Was: work that was already reviewed got reviewed again when it moved to the next release, and queued work was reviewed one at a time.

Now: an approved review carries over when nothing changed, and queued work is reviewed together.

### Quieter sessions

#### /standby

Was: pausing a session meant ending it and losing its place.

Now: `/standby` saves, pauses the session's helpers and goes quiet; Resume brings them back with their work.

#### Briefs follow the testing rules

Was: a brief could ask for a test per item or for exact wording checks with no warning.

Now: Cassy flags those asks when the brief is written.

## Under the hood

### Sessions

#### Brief warnings

Was: a spawn brief, a `request_changes` reason or acceptance criteria could ask for a test per item or for text assertions with no signal.

Now: each returns `N-106` (text assertions) or `N-107` (test per item) beside its normal receipt, never refusing; the phrases live in the cas-writing-tests skill.

#### Standby

Was: an idle supervisor kept its workers' memory, and `/finish` plus `/exit` threw the session away.

Now: `/standby` runs `finish`, stops each worker without force (a worker with unsaved work refuses), records workers, tasks and handoff, and `factory action=standby status=resume` respawns them.

#### Worker lifecycle

Was: startup cleanup could drop a same-name replacement's assignment, and a Codex worker could be woken before its Cassy MCP server listed `task` and `coordination` (GH #2128).

Now: assignments survive the replacement's lease reclaim, and a Codex worker's wakes wait, shown as "gated not ready", until its server has listed its tools.

#### Board refresh

Was: each two-second refresh parsed all ~7,900 task rows; the director snapshot was the slowest read job (235 over-budget completions, 203 s in ten minutes).

Now: a refresh re-reads only tasks whose change counter moved; a whole board load on the 1.7 GB store went from a median 364 ms to 127 ms.

### Tasks

#### Worker check admission

Was: `worker-check` spent about two minutes classifying changed tests on every capacity retry before build admission refused it.

Now: a saturated host (every builder slot held, or memory pressure over the guard limit) refuses before any classification.

#### Verifier launch

Was: a supervisor row marked active with a dead process passed launch authority, retries were chosen by searching message text, and the refusal printed the whole agent row.

Now: a gone owner process is refused at once, the leading refusal code picks never, wait or retry, and the refusal names only agent id, role and status.

#### Close and repair gates

Was: the start brief could name an older artifact; a repair could name only the two tests CI reported; a spike with no commits was judged by its epic's last commit and asked for Tier 2 and Hub journey evidence.

Now: the brief names the newest receipt by creation time; repairs need a `class_audit` filter and a passing receipt for the whole class; a lane its target already contains has an empty delivery.

### Releases

#### Freeze dispatch

Was: `train_freeze` never dispatched `full-validation.yml`, and the cut skill named `ci.yml`.

Now: freeze dispatches or adopts `full-validation.yml` at the tip and returns the run URL or an explicit skip reason.

#### Owner-only auto-cut

Was: a peer daemon cut a shared train from its own defaults while the owner set `auto_cut_max_per_day = 0`.

Now: only the train owner's machine auto-cuts; freeze notes name the machine.

#### Rollover at cut

Was: open children stayed on the cut train and were refused (G-100) only after receipts, lane CI and the verifier.

Now: the cut opens the successor and retargets them, and close refuses a cut or frozen target first, naming the successor.

#### Verdict carry-over and parallel review

Was: a merge-only retarget invalidated the approved verdict, and only the queue head got a candidate and verifier (three deliveries took about 22 minutes).

Now: an unchanged reviewed patch reuses its verdict; every queued delivery is prepared and verified on enqueue, while publication stays in queue order.

Source: [#2169](https://github.com/Richards-LLC/cassy/issues/2169).

#### Release scratch flake

Was: `test_sigkill_parent_leaves_descendant_owner_lease_held` could parse an empty ready file and fail the train (run 44552948256).

Now: that case is deleted; the remaining scratch-lease cases still run.

### Memory

#### Knowledge preview

Was: there was no way to see which sources a knowledge build would distil, or in what order, before running it.

Now: `cas knowledge build --dry-run --json` lists counts and every pending source path in distillation order, without calling a model.

### Safety

#### Write roots

Was: a user-level write root that a project refuses was stored and reported as set, then dropped with only a log line.

Now: `cas config get factory.write_roots` lists each ignored root and why (`ignored_roots`), and setting one warns per project (`ignored_in_projects`).

#### Supervisor reply evidence check removed

Was: a supervisor's message to the operator was refused or marked `[unverified]` unless every number, SHA and completion word matched a same-turn tool result (H-47).

Now: nothing inspects reply text, the markers are gone, and hook settings converge to a matcher without coordination calls.

### Other

#### Test checks and config notices

Was: bare `Identity::exact(...)` values tripped the prose check, and `--store here` with CAS_ROOT set still printed that CAS_ROOT wins.

Now: stability identities and machine codes compare as data, and an explicit `--store` choice keeps the notice silent.
