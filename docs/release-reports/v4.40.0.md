## What you can do now

### Helpers that stay reachable, and one owner for each release

#### Messages get through after an update

Was: once Cassy updated itself, Codex helpers stopped receiving messages, even urgent ones, until someone restarted them by hand.

Now: helpers that were already running keep getting their messages; only a helper that just started waits for its tools.

#### Restarting a helper keeps its work

Was: a helper with saved but unshared work could not be restarted, so the only way out was a forced stop.

Now: the restart goes ahead and keeps its branch and saved work.

#### One machine owns the release

Was: two machines each ran the release and passed approvals back and forth for every merge.

Now: the second machine just runs helpers, and the owning machine reviews, merges and closes everything.

#### Standby in Commander

Was: a paused session looked the same as a live one.

Now: Commander shows a Standby badge, and one Resume button brings the session and its helpers back.

#### Focus follows the release

Was: after a release or a handoff, the board could lose track of which release you were working on.

Now: focus stays on the active release and moves to the next one when a release ships.

#### Busy helpers don't look idle

Was: a helper running a long build or test looked idle, so it got interrupted for nothing.

Now: it shows as working until its build finishes.


## Under the hood

### Commander

#### Standby and Resume

Was: Commander had no way to park a supervisor, and a parked session looked live.

Now: Commands puts a supervisor on standby with one confirmation; its conversation shows Standby from the session's own marker, and Resume sends an operator message that restores its workers and handoff.

### Sessions

#### Codex wake after live-exec

Was: after a daemon live-exec, tools_listed was false with no record, so every running Codex worker's messages sat held as "tools not listed yet".

Now: spawn and recycle write an explicit awaiting record and the gate holds only on it (GH #2185).

#### Wake receipts

Was: a pane write to a Codex worker recorded nudge_not_attempted.

Now: a completed pane write records nudge_fired.

#### Recycle with local commits

Was: recycle_worker and clear_context refused a clean worktree with unpushed commits.

Now: recycle proceeds and keeps the worktree, branch and commits; uncommitted files still refuse.

#### Recycle and detached builds

Was: a recycle could tear a worker down while its own verified detached build still held the target lease.

Now: the recycle stays queued until that build releases the lease, then continues; unknown, completed and foreign-session holders still report a failure.

#### Liveness

Was: a finished turn read as waiting_for_input while the worker's own child build advanced.

Now: an advancing owned child reads as executing.

### Tasks

#### Carry-over and web proof

Was: inherited files could read as dropped (G-56), and base-identical web failures blocked park.

Now: carry-overs prove their own diff, and identical base failures are attributed instead.

#### Repair class selector

Was: a repair worker's spawn could not record which failure class its park proof had to cover.

Now: supervisors pass class_audit with the repair's task_id and spawn_brief; the selector is validated and saved before the worker is queued.

### Releases

#### Single train owner

Was: peer supervisors relayed approvals, merge intents and verdicts across machines.

Now: `cas factory --worker-host <train>` runs workers under the owner, which alone verifies, merges, waives QA and closes.

#### Remote admission

Was: peer approval relays granted authority.

Now: portable artifact and test-receipt claims are checked before remote admission; receiver-side expired-claim protection stays.

#### Focus pin

Was: a published-but-close-held merge returned before focus recovery, and a peer's focus_epic could take the owner's Cloud claim.

Now: merges and retargets restore the pin, the cut moves it to the successor, and peer pins stay local (GH #2173, #2174).

#### Merge safety

Was: an automatic CI-retry merge could land a duplicate gate ID on a moved train tip.

Now: manual and CI-retry merges check the combined registry and refuse with G-160 (GH #2167).

### Other

#### Worker-check store notice

Was: with CAS_ROOT naming another store, `cas factory worker-check --cas-root` printed the "CAS_ROOT supplies the default store" notice although it writes to the store named by --cas-root.

Now: the runner names its store explicitly, so the notice stays silent for it (GH #1918).
