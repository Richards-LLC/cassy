## What you can do now

### Stops the sync loop behind the slow, refused messages

#### No more sync loop

Was: since Nov 17, a team project re-sent the same 1,370 tasks to the cloud every 2 minutes and saved a fresh copy of each to its conflict log, about 41,000 rows an hour.

Now: the first confirmed send clears the queue, and repeat copies are recorded once.

#### Why it mattered

Was: that log reached 22 GB on one machine and kept Cassy's database writer busy, so messages from Commander waited or were refused.

Now: the source is gone; a one-time cleanup shrinks the file next.

#### Updates say what they wait for

Was: an in-place Cassy update could refuse with "jobs did not flush" and name nothing.

Now: it lists each unfinished job and how long it has waited.


## Under the hood

### Release changes

#### Team push echo

Was: since v4.33.0 (base `revision` on team writes), the sent body no longer matched the queued payload, so `acknowledge_team_write` never wrote a receipt and 1,370 personal rows re-pushed each cycle.

Now: the delivery digest ignores the transport-only revision; rows retire.

#### Conflict journal

Was: `record_conflict` deduped on local/remote revision, so byte-identical echoes added ~41k rows/h (2.28M rows, ~20 GB).

Now: revision-only repeats journal once.

#### Reexec refusal

Was: `flush_for_reexec` refused with no job identity.

Now: one coherent per-lane snapshot decides idle; the refusal names every unfinished job (lane, kind, key, age, writer wait) and the writer backlog.
