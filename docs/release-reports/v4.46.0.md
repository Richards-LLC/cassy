## What you can do now

### Work closes, trains cut, evidence stays

#### Finished work parks instead of bouncing

Was: a session's report-only close on a release train was refused outright, and a failed evidence upload could block an approved delivery.

Now: both park for review with the evidence they need.

#### One next train after a cut

Was: cutting a train while new work waited could open two next trains and split the work.

Now: the cut reuses the train that's already open.

#### Moving work between trains is safe

Was: a failure partway through a move could leave a task with no train.

Now: the move happens in one step or not at all.

#### Failed tests keep their evidence

Was: a failed browser or unit test run deleted the reports it had just pointed to.

Now: the reports stay in the task's evidence folder, and the error names where.

#### Fewer false alarms

Was: shipped trains kept asking to be cut, a live Mac session showed up as abandoned work, and the CI watchdog cancelled runs that were just waiting their turn.

Now: none of those happen.

#### Steadier workspace

Was: back-to-back session starts could refuse a working Codex account, a busy database could drop a session reset, and a Slack reply after an idle spell could fail.

Now: each one retries or recovers on its own.


## Under the hood

### Sessions

#### A reused worker starts from the latest epic

Was: a worker lane whose only extra commits had already shipped resumed on its old base, without the epic's newer commits.

Now: it resets to the epic tip.

#### Mac build checks read CPU load correctly

Was: build admission on macOS could lose CPU samples when the 32-bit tick counter wrapped.

Now: samples survive the wrap, the CPU threshold and load fallback are documented, and CPU and memory probes share one host-port helper.

#### A live worker is no longer listed as retired work on macOS

Was: the session-start banner compared checkout paths as text, so a live Mac worker under /var looked unowned next to Git's /private/var and was listed as recoverable retired work.

Now: paths that resolve to the same checkout match; retired workers' local work is still reported.

#### Back-to-back Codex spawns pick the same account

Was: when several spawns ran at once, a timed-out `codex login status` skipped the registered account and refused with "the default Codex home is missing".

Now: a timed-out check still selects the registered account; logged-out, disabled, stale or never-used accounts are still skipped, and the spawn's own login check runs before launch.

#### Worker recycles survive a briefly busy store

Was: a recycle that met a few milliseconds of database contention failed with "retry on a later pass" and nothing retried it.

Now: the request stays queued, the worker keeps running, and the next factory pass completes the recycle.

### Tasks

#### Report-only closes on a release train park for review

Was: a worker's artifact-only close on a child of an owned release train was refused as an owner-only terminal close.

Now: it parks for the pinned train owner's review; other supervisors keep the ownership restriction.

#### A merge retried after its target moved builds against the new target

Was: a retried merge could join a candidate build still running for the old target tip.

Now: builds are shared only for the same source and target commits.

#### Restored files pass the pre-push test check

Was: after a checkpoint, a file restored exactly to the task's recorded target still demanded unrelated test edits.

Now: the pre-push test lint accepts the restored file; newly added prose assertions are still refused.

#### Work moved to main on purpose merges to main

Was: a task a supervisor had explicitly retargeted to main still needed `allow_trunk` to merge.

Now: `task update target_branch=main` counts as the chosen target and merges with the trunk push reported; a trunk target carried over from before the epic is still refused, and the refusal names the retarget option.

#### Asking for changes on unfinished work says what to do instead

Was: request_changes on an in-progress task only refused.

Now: it still refuses, and gives two ready-to-run calls: one records the findings as a decision note, one sends them to the worker.

#### Vue components and test helpers get the right tests

Was: focused proof could prescribe a `.vue` component that worker-check rejected, or a helper with no tests.

Now: it runs `vitest related --run` from the config root, covers importing specs, and close accepts that proof.

#### Failed browser tests keep their evidence

Was: a failed capped Playwright run deleted the temporary directory its printed trace paths pointed into.

Now: traces, error contexts and JSON reports are written under the task's artifact directory, kept on failure and named in the error; passing runs clean up.

#### Failed unit tests keep their evidence

Was: a failed capped Vitest run left no assertion detail behind.

Now: the redacted assertion JSON is kept under the task's artifact directory and its path is printed.

#### Adding work to a running train answers in time

Was: queuing a delivery onto an active train could pass the MCP response deadline while preparing its review, though the append was already saved.

Now: the append returns the committed revision and positions first; the daemon starts reviews and resumes pending verifiers.

#### A failed evidence upload no longer blocks an approved park

Was: a close uploaded every file in the evidence folder, including folders copied from other tasks, and refused the park when any upload failed.

Now: the park requires only the ledger and the files it cites; uploads retry once within 20 seconds, and a retried close reuses what already uploaded.

#### Cited evidence must upload before work parks

Was: an ordinary delivery could park after a cited upload failed, and missing cited files were dropped silently.

Now: the park refuses and lists every unpublished path; log-only and waived-evidence parks keep local artifacts optional.

#### Reviews check rulings and faked test outputs

Was: verifiers did not compare a delivery with standing rulings or catch tests that fake outputs the real producer cannot emit.

Now: they check both and cite the ruling or real output contract and the offending line.

#### Pushing an earlier commit reuses its test proof

Was: pushing a commit other than HEAD demanded a clean checkout of it even when its proof existed.

Now: matching fast-row and web receipts for the push range are accepted; missing proof still needs the clean checkout.

#### Workers can prove builds without default features

Was: the capped runner could not prove a package's no-default-features repair.

Now: one `--no-default-features` flag is admitted for package-scoped `--lib` checks, with their own receipts; broader overrides stay refused.

### Releases

#### Epic history stays out of factory CI comparisons

Was: factory CI compared against epic refs that had already merged.

Now: merged epic refs are excluded, the task fork is found in two linear passes, and successful releases delete shipped epic branches, keeping any that moved during cleanup.

#### The CI watchdog stops cancelling queued runs

Was: the watchdog cancelled any run that had waited more than 20 minutes, so busy lane runners meant most factory CI was cancelled.

Now: a run waiting behind a busy runner that can take it stays queued; a run with no matching runner at work is still cancelled after 20 minutes.

#### Release readiness follows the supervisor that froze the train

Was: after a train moved to a supervisor on another machine, auto-cut and cut notices still acted for the old owner.

Now: the freeze moves ownership, refusals name the owner and machine, and the cut notice counts every delivery merged into the train.

#### A release cut keeps one next train

Was: when work filed during a freeze had already opened the next train, cutting opened a second one and work split across both.

Now: the cut adopts the existing train and opens one only when there is none.

#### Shipped trains stop asking for another cut

Was: a delayed green CI result could send `release_cut_ready` for a train that had already shipped.

Now: closed or cut trains and commits inside a version tag are suppressed; unreleased trains keep their notices.

#### Moving work to the next train can't strand it

Was: a retarget saved the target, then removed and re-added the train link in two more writes; a failure between them left the task with no train.

Now: the target and parent move save together, so a failure changes nothing and the retarget can be repeated.

#### Release recording works on a new machine

Was: `cas release installed` and `cas release published` stopped with "no such table: known_repos" on a host that had never registered a project.

Now: they create the empty host registry and record the release.

#### CI actions move to Node 24

Was: checkout, artifact, cache and Node setup actions ran on their Node 20 majors.

Now: they use their Node 24 majors with the same artifact paths, overwrite behaviour and cache settings.

#### Mac launch checks run in a clean environment

Was: macOS launch smoke cleared the environment but kept the factory process ancestry, so the operator guard refused it.

Now: smoke commands run as transient launchd jobs with captured exit status; agent controls still fail their launch gates.

#### Release previews keep the project's identity

Was: migrated private preview snapshots could lose a live project's identity, including projects without config files.

Now: the identity is preserved in the snapshot; live data, configuration and release defaults are unchanged.

### Slack and Cloud

#### Shutdown no longer skips the final cloud sync

Was: a shutdown during a background sync aborted it while it held the sync lease, so the final sync printed "nothing pending" without syncing.

Now: shutdown lets the in-flight sync finish, runs the final sync, then sends quality telemetry outside that bound.

#### Explicit syncs say when they were deferred

Was: `cas cloud sync` and `cas ledger report` silently showed stale data when another round held their lock.

Now: the sync summary marks knowledge and quality events deferred in text and JSON, and the ledger report says its fleet rows may be stale.

#### Slack replies survive a dropped connection

Was: the first managed Slack reply after an idle spell could go out on a closed Violet connection and be reported as "did not post".

Now: when Violet confirms it never received the post, Cassy reconnects and resends with the same request ID, so it posts once.

### Safety

#### The write-roots setter has a safe test path

Was: workers had no supported way to exercise the operator-only `factory.write_roots` setter.

Now: a capped fixture runs the real command in an isolated HOME and scratch project and checks that agent and worker calls are still refused.

#### Test temp folders can't sit inside a checkout

Was: a TMPDIR inside a checkout could reach Cargo and test children when Git discovery stopped at a ceiling or a symlink hid the checkout.

Now: the runner refuses any TMPDIR with a physical `.git` ancestor.
