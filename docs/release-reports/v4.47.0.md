## What you can do now

### The big four

#### Commander shows what really happened

Was: a command still queued when a session ended or crashed showed Unconfirmed, and a restart could lose the queue.

Now: Commander reads the saved result and shows Not sent, and queued commands survive a restart without ever being typed twice.

#### Merged work closes itself, on any branch

Was: work merged through a pull request, by hand or by a promotion into a branch other than main stayed open.

Now: Cassy spots it on its branch and closes it, running a review first when none exists.

#### Reviews check the exact version pushed from the other machine

Was: closing work done on the other machine could review a stale or unrelated copy.

Now: Cassy fetches the pushed version and reviews exactly that, and a review of the wrong copy is set aside instead of merged.

#### Flaky tests removed

Was: six tests failed at random and could turn a release red.

Now: they're gone, and a seventh now waits properly and passed 30 of 30 runs.

### Fewer stuck closes

#### Closes use the proof they already have

Was: a change merged locally still demanded a pushed copy, an approved research task with no code needed re-checking, and a skipped after-merge check blocked a release from closing.

Now: each closes on its existing proof.

#### Closes survive a shutdown

Was: shutting a session down mid-close could lose the close's publish and sync result, and a review fix made after reassignment could be credited to the wrong task.

Now: shutdown waits for the close to finish, a failed publish retries on its own with one notice, and review fixes stay with the task they belong to.

#### Branch choices stick

Was: a task aimed at a specific branch could be quietly moved to a different one, and checks lost track of work once it shipped.

Now: the chosen branch holds from start to merge, and checks follow work into staging and main.

#### Merges wait for green checks

Was: a direct pull-request merge could go through while its checks were pending or failing.

Now: it's held, naming the checks, and goes through once they pass.

### Two machines, one record

#### Review questions get answered

Was: a review question raised on the other machine had no way to be answered from this one.

Now: you read it in the task notes and answer it there, and the review carries on.

#### Evidence stays current

Was: a failed upload could refuse proof the other machine had already published, and an older copy could overwrite newer proof.

Now: published proof is reused, and the newest copy wins.

### Recovery and responsiveness

#### Reviews start and recover on their own

Was: a review could sit unstarted if whatever asked for it closed, and a crashed reviewer could block a merge.

Now: Cassy starts any unstarted review once and replaces a reviewer it has confirmed is dead.

#### Crash recovery in one step

Was: after a computer crash, unpushed work held by a dead session needed a manual release.

Now: one recovery step publishes it, keeps its history, and leaves live work alone.

#### Snappier Commander

Was: background bookkeeping could hold the database for up to 4 seconds, so Commander sends waited behind it.

Now: that reading happens separately, and sends no longer queue behind it.

#### Clear status on messages and checks

Was: an urgent message sent during a long step failed after 8 seconds, and a background check started from a subfolder never reported back.

Now: the message says it's held and when it will interrupt, and the check reports when it finishes.

#### Repairs cover the whole problem

Was: some failed checks lost the names of the failing tests, and a fix could go back without addressing related tests.

Now: failing tests are recorded from every check, and a repair must cover the whole group of related tests.

#### Reports aren't held by a release

Was: an unrelated support report could wait behind a release being checked.

Now: each report waits only for the release it belongs to.

### Mac

#### Stopping a runaway session works

Was: stopping a runaway session on macOS could be refused, and a runaway shell could use up the Mac's process slots.

Now: the stop ends the whole process tree, and a runaway hits its limit before your own shells do.

#### Release checks run on the Mac's built-in shell

Was: the release check failed on the old bash that ships with macOS.

Now: it switches to a newer bash on its own, or says in one line how to install one.


## Under the hood

### Commander

#### Hub receipt read

Was: a card still Queued at session end, exit or daemon crash showed Unconfirmed.

Now: Commander reads the retained receipt from the hub (authenticated, sending device only, read-only, waits while the recording daemon may be alive) and shows the stored outcome or Not sent.

#### Durable command receipts

Was: queued commands and receipts did not survive a daemon restart or reexec.

Now: they persist by session, device and command ref and resume at the next native turn boundary; a durable claim blocks replay, and a prior daemon's queue under reused names is marked Not sent.

#### Store writer contention

Was: prompt-queue selection and spawn-queue polls ran whole on the single store writer, holding it up to 4.1 s and 3.0 s.

Now: both read on their own select lane and take the writer only to write; an empty poll never takes it.

#### Held urgent sends

Was: an urgent send during a running tool call failed after 8 s with "could not confirm interrupt delivery".

Now: it answers `held`, says it surfaces when the call ends, and gives the interrupt time.

### Close and merge

#### Close on any target

Was: deliveries merged outside `worktree_merge` (a PR into develop, a manual merge into a feature branch, develop→staging) stayed parked.

Now: the daemon finds the delivery on its recorded target and closes on an existing approval or a post-merge verifier (four at once); the PR observer watches every target.

#### `local_merge` without origin

Was: an approved `local_merge` delivery still required its branch on origin and was refused as dirty when origin was down.

Now: it merges its exact local commit; `push_branch` still needs the matching fetched ref.

#### Close through shutdown

Was: worker shutdown or recycle could drop an in-flight close's publication and sync outcome, and a pushed review fix on a parked task's source branch lost that task's delivery identity after reassignment (GH #2193, #2250, #2274).

Now: shutdown waits for active close publication; a failed owner publication goes to a durable daemon retry journal with one supervisor notice; identified review fixes keep their recorded task, while foreign or unnamed commits still refuse.

#### Commitless spikes

Was: a `no_delivery` close recorded a delivery branch and needed a proof-scope correction.

Now: it parks without one and closes on its existing approval.

#### Shipped history and explicit targets

Was: frozen history hid later rewrites, and an explicit child target equal to the base was replaced by the inherited one.

Now: content checks follow published staging/main descendants, and explicit targets hold through display, start and merge.

#### Close CI reuse

Was: an intentionally skipped post-merge job blocked close.

Now: green required checks from the exact merge source count when the tree matches; skips must match successful checks by name and app; project-specific job names are supported.

#### CI-gated `gh pr merge`

Was: raw merges went through on pending or failed checks when the target had no branch protection.

Now: refused with `PR_CI_PENDING` or `PR_CI_FAILED`, naming head and checks; guidance uses gate evidence and `--match-head-commit`, not `--auto`.

### Cross-machine review

#### Pushed-tip binding

Was: closing a delivery from another machine bound the review to the local HEAD or an older cached commit.

Now: close fetches the branch and target from origin and binds the pushed tip, else the target tip; `origin/<branch>` is fetched as `<branch>`.

#### Unrelated-head reviews retired

Was: an approval bound to a commit with none of the task's work answered MERGE REQUIRED.

Now: it's retired with a task note, and a recovery close with the merged commit receipt closes the task.

#### Peer verifier questions

Was: a `supervisor_call` from a verifier on the other machine could not be answered by the train owner.

Now: `verification add` on the dispatch queues an authenticated authorization recorded verbatim; it grants no verdict, merge or close rights.

#### Evidence sync

Was: a transient Cloud upload failure refused EVIDENCE PUBLICATION INCOMPLETE on already-synced proof, and an older manifest overwrote a newer local ledger.

Now: parks cite the synced proof record, newer ledgers survive, and sealed train parks name the newer artifact.

### Recovery

#### Verifier launch

Was: a verifier launch retry lived only in the requesting MCP process.

Now: the daemon starts any never-launched review in its session, once.

#### Expired review claims

Was: a dead verifier's expired claim blocked merge.

Now: a merge retry releases it on registered shutdown, confirmed PID absence or fingerprint mismatch, revokes authority with an audit event and allows one replacement; unreadable fingerprints keep the claim.

#### Crash recovery

Was: committed work behind a dead holder's lease needed a release loop.

Now: `recover_branch` retires only the proven-dead local lease, publishes unpushed commits and keeps source attribution.

#### Detached checks

Was: `worker-check --detach` started outside the checkout root (such as `hub-web`) or in the task scratch checkout was untracked.

Now: both are tracked and wake once on finish.

### Repair class audit

#### Failing-test capture

Was: `--log-failed` lines with job, step and timestamp prefixes and colour codes yielded no names, and only merge-queue ejections fed the gate.

Now: prefixes are stripped, libtest and nextest lines parse, and lane-impact `caused` names merge in (deduped, 20-name cap).

#### Automatic repair holds

Was: a paperwork-only premerge rejection returned a task with recorded failing tests and no class audit.

Now: it holds with CLASS_AUDIT_REQUIRED so the repair names the whole test class.

### macOS and tooling

#### macOS kill

Was: `cas factory kill` refused the npm `claude.exe` client with a PID identity mismatch.

Now: it verifies the recorded client, kills the whole tree including Bash tool process groups, and sessions start below the per-user process limit.

#### Release gate on bash 3.2

Was: `scripts/release-gate.sh` failed on `declare -A` under `/bin/bash`.

Now: it re-runs under bash 4+ from PATH, `/opt/homebrew/bin` or `/usr/local/bin`, else exits 2 with an install line.

#### Report publication

Was: a release under review held unrelated report PDFs, and one verified report masked a held one in a batch.

Now: each post waits only for its attributed release.

#### Pre-push and test-shape

Was: a re-push after a train merge demanded a `hub-web/dist` commit, and `starts_with("CODE:")` was refused as a prose pin.

Now: re-pushes compare with the target merge-base, and an error-code prefix counts as machine data.

### Tests

#### Flakes removed

Was: six tests failed intermittently with and without the change under test (three Commander journeys at 7 of 14, three Rust tests in lane CI).

Now: deleted; the paste-upload journey waits web-first and passed 30 of 30.
