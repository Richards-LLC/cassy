## What you can do now

### The big four

#### Mac sessions run in a real sandbox

Was: on the Mac, a working session's shell was held back only by checks that read the command text, and some got through.

Now: each Mac session runs in a macOS sandbox that only lets it write to its own checkout and its own task's files. Shared Git settings and secrets are read-only.

#### Long release trains keep moving

Was: a train with 40 or more pieces of work could stall at the first one, and a train handed to a new owner could stay stuck behind the old owner's queue.

Now: the train finishes each piece in order, and a new owner picks up a stopped owner's queue on its own.

#### Proof works for table-style tests

Was: tests that run one check over a table of examples, or that read their cases from a data file, could never earn their proof, or only got part of it.

Now: every row is checked and counted, a data-file change re-runs the whole test file, and the totals match what the test runner says.

#### Four flaky tests removed

Was: four tests failed at random and could turn a release red.

Now: they're gone.

### Messages you can trust

#### Nothing lost in a recycle

Was: a message sent while a session was restarting could be dropped, and its replacement started without its instructions.

Now: the message waits for the replacement.

#### Commander keeps both sends

Was: during a network outage, a second message sent right after the first was quietly dropped.

Now: both are held and delivered once, in order, when the network comes back.

#### No repeats, no false alarms

Was: the same Commander message could be typed twice, stale notices arrived about finished work, and a session waiting its turn for a build slot was reported as stuck.

Now: each message arrives once, notices about finished work are dropped, and waiting sessions count as waiting.

#### A slow send is never a mystery

Was: a message still being written when the reply deadline passed came back "unknown", with no way to check it.

Now: it gets an ID you can check, and the final result arrives in your inbox, so nothing needs resending.

#### Overnight reviews don't page you

Was: work waiting overnight on a person's review woke Cassy every 45 minutes and headed toward paging you.

Now: Cassy can hold it until a set deadline, up to seven days.

### Two machines, one record

#### Work done on the Mac reaches the train

Was: finished work from the other machine could stay stuck as Open, and closes there didn't always unblock the next task.

Now: both arrive, and anything that changed since review is still held for review.

#### Evidence travels

Was: a review on one machine could miss evidence saved on the other, and evidence written on the Mac was refused here.

Now: the reviewer fetches and checks the evidence first, and evidence from the Mac is found in the same place here.

#### Mac paths fixed

Was: macOS's linked temp folders broke a session's connection to its own project, and several checks and tests too.

Now: paths are resolved before they're compared.

### Fewer stuck closes

#### Closes finish, and say so

Was: a slow close looked like an error, a merged delivery could be asked to close again, and some recoveries looped.

Now: a slow close returns a progress ID, merged work closes itself, and each recovery has one clear route.

#### A checkout isn't switched mid-run

Was: starting the next task could switch a session's checkout while a test was still reading it, which threw the result away.

Now: the start waits until the run finishes.

#### Proof survives paperwork

Was: adding the changelog note a close asks for threw away earlier test proof.

Now: that proof is kept, and only real code changes ask for a new run.

#### Faster with big projects

Was: a CI check held the database for up to 5.9 seconds on a 7,000-task project, and everything else waited behind it.

Now: it reads only the 271 tasks still open, so there's no wait.


## Under the hood

### macOS worker sandbox

#### Generated sandbox profile

Was: Bash writes were limited by hooks parsing command text, and confirmed bypasses kept getting through.

Now: macOS Claude workers launch under a generated profile: writes go to the worktree, artifact/scratch roots and capped runner state; shared `.git` config, hooks and secrets are read-only.

#### Exact Git paths

Was: Git writes were judged by command text.

Now: commits, `factory/*` branches and fetch work, other branches stay read-only, and `factory.claude.worker_sandbox=off` restores the old launch.

#### Per-task scope

Was: the profile let Bash write every task's artifact directory and the whole staging scratch root.

Now: only the current tasks' artifact dirs and the checkout's own temp/build dirs. A start the running profile does not cover relaunches through the normal recycle.

#### Shadowed guards

Was: text guards and the sandbox would both judge each command.

Now: for one release, H-11/12/14/16/22/28/29/33 let sandboxed Bash through and count a would-deny in a new `shadowed` column of `cas gates report`. Write/Edit, Linux workers and supervisors keep the guards.

### Trains and merges

#### Head-first advancement

Was: the daemon started every later delivery's review before the head's step, and on 40+ deliveries it lost the two-minute lease each pass (GH #2311).

Now: the head steps first, and later reviews renew the lease and stop once it's lost.

#### Dead-owner queues

Was: after an owner change, the ended supervisor's held queue refused the new owner's `train_merge` with an owner-generation error (GH #2316).

Now: once the recorded supervisor is not live, the current owner adopts the queue and settles entries already merged.

#### Train notices scoped

Was: non-owning supervisors got cut-ready and post-merge recovery notices.

Now: only the owner does.

#### Publication fences

Was: a merge could publish over unrelated unpushed target history, and an unpushed local rebase could integrate with a warning.

Now: both refuse. Merges need the live origin tip of a finished park.

#### Candidate retries and attribution

Was: a failed candidate-prep retry's notice was deduped away (GH #2106), and base builds could hide a delivery regression.

Now: each failure notifies, the delivery replay runs before the base build, and attribution uses the live target merge-base.

#### Cleanup and docs merges

Was: post-publish cleanup could delete the open next train, and lane CI that finished after a docs merge was not recognised.

Now: cleanup deletes only the epic in the version's cut record, and Advisory anchors accept their exact-anchor checks.

### Worker proof

#### Vitest and Jest table rows

Was: `it.each` rows expanding to one runtime name (`%s`, `$key`, repeated static titles) failed capped stability, and widened receipts counted distinct names (2955 vs Jest's 2957) (GH #2216, #2258, #2246, #2166).

Now: the source test is credited when every expanded row passes. Missing or substituted rows still refuse, and receipts count the runner's passing results.

#### JSON catalogues

Was: a changed or swapped JSON catalogue imported by a spec proved only the changed literal tests.

Now: it widens to a whole-spec run, and a catalogue-only change owes proof for every importing spec.

#### Playwright config selection

Was: specs in multi-config dirs ran under the default config and found no tests, and specs importing `test` from a local fixture were prescribed Vitest (GH #2195, #2294).

Now: the config that lists the spec decides. Setup projects that ran once are accepted beside five repeats.

#### Proof carry

Was: changelog, product-overview and bug-family fragments voided five-pass receipts (any `.yaml` counted as a test input), and a `main` sync added released commits to a task's owed proof.

Now: the fragments carry proof unless a Rust source names them, and only the task's own tests are owed.

#### Gate registry in worker-check

Was: a delivery touching an audited refusal parked green and went red on `gates::registry_tests` in lane CI.

Now: worker-check asks the scan's inventory and adds that test only when the changed lines fall in an audited item.

#### Lane impact

Was: the impact plan's regex own-test expression couldn't run in the capped runner, and journey-only diffs selected the whole Rust workspace.

Now: a `Worker proof` line gives runnable named-filter commands, and `hub-web/e2e/` paths select only Rust tests that name them.

#### Checkout holds

Was: a queued or direct start switched the checkout under a live detached run, `journey-eval.sh` or pre-push rows (GH #2286).

Now: a moving start waits with G-165, and each run holds the checkout for its process lifetime.

### Messaging and notices

#### Delivery honesty

Was: mail failed during a recycle was abandoned, late events said "cause unrecorded", and a Cloud "queued" read as sent (GH #1731).

Now: mail waits for the successor, delay labels name the measured wait, and peer sends are rechecked once at two minutes.

#### Send continuations

Was: a message still writing at the deadline answered `UNKNOWN` with no ID.

Now: it answers `IN_PROGRESS` with a `send-…` ID that `message_status` resolves, and the final outcome lands in the sender's inbox.

#### Inbox wake and batches

Was: a re-offer's brief claim could hide a message until other mail arrived, and a batch could split into two wakes.

Now: releasing the claim re-signals the inbox, and batches arrive as one turn.

#### Watchdog quiet paths

Was: stall alarms fired for workers waiting on their own reminder or a capacity retry, idle notices repeated during recycle, and closed-task notices asked for recovery (GH #1728, #2132, #1693, #2201).

Now: those are treated as waiting or retired. `state_patch={"merge_hold":…}` holds one parked delivery's escalation for up to seven days.

#### CI-unknown decisions

Was: the director re-asked "CI unknown" on repos whose workflows never run on factory pushes, and didn't say what it had read (GH #2273, #2051).

Now: it reads the workflow triggers at the tip and names the exact check-runs query.

### Commander

#### Outage sends

Was: a second Send during an outage was dropped (GH #2321).

Now: it queues behind the first, and both deliver once, in order.

#### Read messages, reconnect versions, palette

Was: a message already read via the inbox could be retyped, a reconnected MCP's version record was lost under write contention (GH #2183), and the slash palette stayed stale while connecting.

Now: the relay checks handled state first, the version record waits for the writer, and the palette updates on connect. Journeys run on Playwright 1.65.1 with role-based HUB-J27 controls.

### Two machines and Cloud sync

#### Peer parks and closes

Was: an owner's newer note blocked a peer's park or close from reaching merge and dependency checks, a reused short ID's quarantine hid a local task, and revision conflicts parked pushes for good.

Now: completions project over newer local notes, stale quarantines are ignored, and the pull adopts the cloud revision and rebuilds the push.

#### Peer evidence

Was: verifiers missed Cloud-committed artifacts and parent plans, and ledgers citing prowl absolute paths were refused.

Now: artifacts are fetched and checked by size and SHA-256 before review, and foreign paths resolve under the local task dir.

#### macOS symlinked roots

Was: `/var` vs `/private/var` broke worker-host project checks, base attribution (`/private/private`) and seven gc/receipt tests.

Now: paths are canonicalised before comparison.

### Close and recovery

#### Operator recovery decision

Was: contained historical deliveries with superseded paths hit mutually refusing `reviewed-drop` and missing-approval checks (GH #2270).

Now: `cas task recovery-decision --scope <epic>` records the waived checks once, and supervisors close with `operator_decision=` and a commit receipt.

#### Close and start responses

Was: slow closes and starts ended in bare deadline errors, and brief starts dropped the close checks.

Now: durable continuation IDs and inline close checks. `task list offset` is refused, not repeated.

#### Recovery routes

Was: revalidation, replacement branches, cancelled leases and supplemental work each needed manual loops (GH #1695, #1579).

Now: `no_delivery` revalidation, Blocked rebind, lease reconcile and direct resume. Same-tree merge anchors keep content history only inside a real work window.

#### Branch identity

Was: refusals named non-existent workers, `adopt_branch` picked the wrong tip, and overlapping worker names shared branches.

Now: precise ownership refusals, delivery-tip adoption and `WORKER_NAME_OVERLAPS`.

### Daemon performance

#### Store writer

Was: each CI poll read all 6,986 tasks under the writer (up to 5.9 s), and message selection took the writer a second time each pass.

Now: 271 active tasks, and the second turn only when something is pending.

### Tests

#### Flakes removed

Was: four tests (two delivery-merge, one SQLite latency, one Codex spawn) plus one HUB-J14 journey case failed intermittently.

Now: deleted; production code unchanged.
