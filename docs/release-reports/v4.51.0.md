## What you can do now

### Proof that can finish, merges you hear about

#### Vue components can be handed in

Was: a finished Vue change could be stuck because its required test command crashed.

Now: importing tests or the package's runnable tests can supply its proof.

#### Tagged browser tests count

Was: tags could hide a test from the stability check.

Now: tagged and untagged tests are found while similar titles stay separate.

#### You hear when an approved merge lands

Was: approved merges could land silently; one release waited 30 minutes.

Now: the owner hears when the merge lands and can start the next step.

#### Better guidance for browser tests

Was: one shared sign-in and missing background-job guidance limited the guide.

Now: it covers separate sign-ins, background jobs and opt-in paid or staging tests.

## Under the hood

### Worker check

#### Runnable component and tagged-test proof

Was: Vue proof could fail during transformation without a Vue plugin. Tagged Playwright tests were missed because title selection rejected their trailing tags.

Now: Vue components prove through importing specs or a runnable package test. Browser-test title matching permits trailing tags and still excludes look-alike titles.

### Pre-merge verification

#### Auto-continued merges wake their supervisor

Was: `approved()` ran the held merge directly, outside the supervisor-call merge-receipt wrapper, and pre-marked its only queue row delivered, so nothing woke the owner.

Now: a landed approval enqueues one `merge_outcome` notice keyed to its dispatch, and train-queue merges still defer to the train's own outcome.

### Tests and skills

#### Stale replay removed

Was: an older replay still demanded the superseded Vue proof, so runs selecting it failed against an obsolete expectation.

Now: the superseded case is gone, and the current Vue regression covers the supported proof routes.

#### Playwright authoring skill

Was: one shared storage state, opt-out live smoke, no async-job or `.mjs` guidance.

Now: async jobs are graded on server status, per-persona projects are routed by tag, paid and staging-only specs are gated by env in config, and `.mjs` helpers load as native ESM.
