## What you can do now

### Reload Cassy without restarting

#### Reload Cassy waits for a quiet moment

Was: a busy supervisor refused Reload Cassy.

Now: Commander shows a small waiting animation and reloads at the next quiet moment, without cutting into a running tool call. A supervisor already on the installed build just shows its badge, and nothing is sent.

#### Reload Cassy on Codex

Was: Reload Cassy was refused for Codex supervisors.

Now: after a one-line confirmation, Commander restarts the Codex supervisor on the installed build while its workers keep running.

#### See which build each supervisor loaded

Was: nothing showed which Cassy build a supervisor had loaded after a reload.

Now: the supervisor card, the conversation header and the factory status bar show the loaded build and its load time, such as "cassy 4.52.0 · loaded 5:44 PM ET", until the next reload.

#### A reload counts only on the installed build

Was: any replacement Cassy process counted as reloaded.

Now: a reload succeeds only when the running version matches `cas --version`; otherwise Commander says which version runs and what to do next.

#### The build badges stay whole

Was: at 1280 px the card's version badge painted over the machine name, and the header badge ran under Raw output.

Now: the card shows the version alone, with the load time in its tooltip, and the header shows a fixed "4.52.0 · 9:52 PM" pill whose neighbouring text shortens first, on desktop and phone.

#### No false reload failure

Was: a reload that worked could report a failure when another part of Cassy held the database for a few milliseconds.

Now: the reload's receipt waits briefly for its turn and retries instead of reporting a failure.

#### Type /reload-cassy

Was: only `/mcp` ran Reload Cassy.

Now: `/reload-cassy` runs the same reload, with the same Codex confirmation.

### One quota per login

#### One usage number per login

Was: each machine read an account's usage on its own, so two machines showed different numbers and reads went stale.

Now: with the hub dashboard set up, Accounts and New session take each login's usage from the hub, so every machine shows the same number. A machine that can't reach the hub says so and shows no number.

#### Hub accounts in Accounts

Was: Accounts listed each machine's own logins only.

Now: a read-only Home gateway section per machine shows whether the hub is ready and lists its accounts, each with its state and recent requests. Codex Team accounts are counted but not listed, and no key or hub address reaches the browser.

#### Accounts and New session redesigned

Was: the cards mixed "% used" and "% left", hid missing windows and offered duplicate and logged-out logins.

Now: one ledger shows the 5-hour and weekly windows as "% left" meters with their resets; old reads show their age, and the recommended login says why. New session opens with a plan strip and sets logged-out and duplicate logins aside under "N not offered".

### Choose how workers connect

#### Choose the worker route in New session

Was: turning the home gateway on meant editing the project's config, and every new worker read it again.

Now: New session offers Direct or Home gateway, says which workers move and that the supervisor stays direct, and keeps the choice for the whole session.

#### See each worker's route

Was: a worker's route showed only in a status command.

Now: each Team lane shows Home gateway, Direct, or Direct with a gateway fallback and its reason, and the Team header totals the routes.

## Under the hood

### Closing finished work

#### Park asks only for cited files

Was: a close reason that used the word "target" made park demand a file that didn't exist, fetched evidence copies were published again on every park, and each retry added another evidence note.

Now: only files the reason actually cites are required, fetched copies are skipped and a retry replaces its evidence note.

#### Operations-only epics close

Was: an epic whose children all closed without code could not close at all when its branch had no commits of its own.

Now: such an epic closes the ordinary way with an audit note naming its approved review; any child that shipped code still gets the full check.

#### Retargeted work keeps its history

Was: work moved from one release train to the next was refused at close, because the earlier train's reviewed commits counted as someone else's work.

Now: history from an earlier train counts as upstream; other branches still count as foreign, and a deleted target is named as missing.

#### Adopted work belongs to its new owner

Was: when one worker took over another's branch, Cassy kept measuring the old worker's branch.

Now: adoption records the new owner's branch and starting point.

#### The no-branch refusal gives a push that works

Was: the refusal told the worker to push to a name the push guard then refused.

Now: it names a branch to create locally and push under the same name.

#### The test check never asks for an impossible run

Was: a worker could be refused at park with no way out, for example when the prescribed test run selected no tests or a pass in one checkout didn't count in another.

Now: a selection that runs no tests runs its whole package or crate once instead, and park accepts that pass; deleted files owe nothing, and a pass at the exact commit counts from any checkout of the repository.
