## What you can do now

### Commander

#### Reload through a reconnect

Was: A reload could say its message wasn’t sent even though the restart was underway.

Now: Commander keeps showing waiting or restarting until it knows the outcome.

#### Reload a same-version build

Was: A hotfix with the same version number could show “Already current.”

Now: Cassy compares build hashes and counts the reload only once the installed build is running.

#### Fresh Codex quota without traffic

Was: The Accounts view could show hours-old quota after a quiet stretch.

Now: It uses the newest reading, including the hub’s 15-minute background check.

### Sessions

#### Start Codex workers through the hub

Was: Codex workers routed through the hub could be refused because the local login file was missing.

Now: Routed workers check the hub’s model list. Direct workers still check their own account’s list.

#### Restart without a backlog of duplicate checks

Was: Copies of the same background check piled up and could prevent a quick restart.

Now: A new check replaces the waiting copy, which the restart can discard and run again later.

#### New models with a Claude fallback

Was: Everyday coding used a retired GPT model and stopped if every Codex account hit its weekly limit.

Now: Everyday work uses GPT-6.2 Sol and can fall back to Claude Sonnet 5.5. Heavy and design work use Claude Fable 5.2 with an Opus 5.5 fallback.

#### Test runs wait for a slot

Was: Background tests and checks exited when a builder was full or short of resources, asking for a retry.

Now: Background runs keep their place in line, start when admitted and report once. Foreground runs still get a refusal.

### Releases · scorecard

#### See cost per task and model

Was: The release scorecard grouped tokens by who started the work; cost by task meant reading raw logs.

Now: It breaks down cost by task, harness, model and effort, with cached input kept separate.

#### Put measurement health first

Was: Missing samples and broken inputs both looked like zero.

Now: Each measure opens with OK, EMPTY or BROKEN and the reason, so a gap is not mistaken for a result.

#### Trace missing notices to the right project

Was: When a notification that woke an agent lacked a recorded kind, the report blamed a missing local agent, even across projects.

Now: The report names the project that sent it. Only local gaps point to local agents.

#### Open the report with `cas scorecard`

Was: The command was `cas ledger report`.

Now: Use `cas scorecard --release v4.54.0`. The old command still works.

## Under the hood

### Tasks

#### Catch missing docs before review

Was: Missing product documentation or a missing entry for a recurring bug could cost a review round.

Now: The handoff lists both gaps up front. Docs-only and test-only changes are unaffected.

#### Approved no-code tasks close themselves

Was: An approved no-code task could stay blocked until a supervisor repeated the close.

Now: Cassy closes it for the owning supervisor. If a check still blocks it, Cassy saves and reports which one.

#### Point to the right test target

Was: A missing audit result always prompted a library test, even if an integration suite owned it.

Now: The prompt names the registered test target, or asks for the harness when it cannot find one.

#### Require a checklist for handoff

Was: A delivery could leave part of its brief undone and only mention the narrower scope in a document.

Now: Every requirement and supervisor decision gets a checklist row. Unmet or narrowed work needs explicit supervisor approval.

#### Return every review finding together

Was: A review stopped at the first completeness failure, leaving other findings for later rounds.

Now: All phases run and one verdict lists every finding. Any blocking finding still rejects the delivery.

#### Find cited files on the right task

Was: Citing another task’s saved file in a parent plan could block every merge under it.

Now: Cassy checks the file against its owning task. An unresolved citation is flagged as missing context for the reviewer.

#### Flag code no one calls

Was: A refactor could remove the last caller of code and leave the reviewer to find it.

Now: The handoff names all newly uncalled code it finds in the change without a build or model call.

#### Remove comments that restate the code

Was: No pass checked whether comments added during a change still helped the reader.

Now: A new pass removes redundant comments from the diff and preserves public help and tool descriptions.

### Releases · test proof

#### Run the suite that owns the edited case

Was: Editing a Rust integration case file could trigger every integration suite.

Now: CI first runs the suite that compiles the file through a module or path declaration.

#### Treat intentionally skipped tests as inactive

Was: A JavaScript test switched off by its environment could fail a stability check on every repeat without running.

Now: It’s recorded as inactive, never as passing. Real failures and a run with no active changed tests still block delivery.

#### Run Jest from the package folder

Was: A config in a subfolder made Jest resolve fixture paths from that subfolder instead of the package.

Now: Jest starts from the nearest folder above the config that contains the package manifest.

### Safety

#### Keep macOS login items out of workers’ reach

Was: A configurable write allowance could make the macOS login-items folder writable from a worker sandbox.

Now: The sandbox always denies writes there, even if a write allowance lists the folder.
