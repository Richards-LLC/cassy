## What you can do now

### Releases · Mac install and update

#### Mac privacy permissions survive updates

Was: Each Cassy update looked like a new app to macOS, which asked again for access to Desktop and other protected folders.

Now: Cassy signs itself with the same local identity on every install and update, so macOS asks for each permission once and keeps it. There is no password prompt. If signing fails, Cassy warns and keeps working.

### Commander

#### Reload Cassy after a same-version rebuild

Was: After a rebuild that kept the same version number, Commander hid the Reload Cassy button and the session stayed on the old build.

Now: The button appears whenever the installed build differs from the one the session is running, even at the same version.

### Tasks

#### A stuck review no longer blocks merges

Was: If an automatic reviewer froze partway through, every merge retry for that work was refused until someone cleared it by hand.

Now: Once the review is overdue and shows no sign of life, the next merge retry starts a fresh reviewer on the same work.

### Slack and Cloud

#### Resend a Slack reply that never arrived

Was: When Cassy couldn’t confirm a Slack reply and Slack had no record of it, Cassy said not to retry. The reply was lost or posted again by hand.

Now: Cassy says to resend it. The resend reuses the same request, so it can’t post twice.

## Under the hood

### Releases · Mac signing

#### One signing identity for every Mac install

Was: Installs were signed ad hoc by the linker, so each build had a new code identity and macOS privacy controls (TCC) treated every update as a new app.

Now: Every install signs with one local identity, `dev.cassy.cas`, held in its own keychain and needing no login password. The designated requirement and the privacy grants tied to it carry over. The developer notes record a Mac update with the same requirement across two builds, distinct CDHashes and no privacy prompts.

#### Every install route signs, with a fallback

Was: No install route signed the binary.

Now: The installer, native updater, refresh-only update, both source installs and `cas-update` sign. An interrupted first setup recovers. If signing fails, Cassy warns and keeps a byte-identical ad hoc binary. Linux is unchanged.

### Commander

#### Reload compares build identity

Was: The Reload Cassy action was hidden when the installed and loaded builds reported the same version.

Now: Commander compares build identity, so a same-version rebuild offers Reload. Reload stays available when the supervisor can’t be reached.

### Tasks · pre-merge review

#### A stalled verifier releases its claim

Was: A verifier thread that stopped inside a live host process left its expired dispatch Claimed, and every merge retry was refused with “finish this exact verdict”.

Now: Past the deadline, the owning supervisor’s retry releases a Claimed dispatch that has no fresh verifier heartbeat and no active verifier lane, then starts a replacement on the same dispatch. The daemon verifier records its machine stamp.

### Slack and Cloud · Violet

#### A lookup miss is retryable

Was: An uncertain post whose outcome lookup found no record returned `not_posted` with `retryable: false`, so callers opened a second reply intent.

Now: `not_posted` with reason `request_not_found` is retryable with the same request ID and arguments, and the proxy reports only what the lookup shows.

### Releases · tests

#### Reconcile tests no longer depend on timing

Was: The reconcile suite included a relay test whose result depended on scheduler timing.

Now: That test is removed. Existing job-runtime tests still cover resubmit coalescing and reexec flushing.

#### Codex lane test checks each sign-in case once

Was: The Codex lane test probed recipes that share a capability key twice.

Now: Each auth scenario is probed once.
