## What you can do now

### Sessions

#### Interrupted work waits for recovery

Was: If a session ended mid-task, unfinished work could return to the ready list without an owner.

Now: The task stays held with its owner, branch and last recorded checkpoint so a successor can recover it deliberately.

#### Failed checks explain why

Was: A test that never ran could look like a failed assertion, and a failed process could get a generic stability error.

Now: Cassy tells you whether the selected test did not run or the runner exited with an error.

#### Shell checks follow the command

Was: Ordinary folder changes, background commands and arithmetic could be mistaken for unsafe access.

Now: The checks follow the command's working directory and values while guarding sensitive reads and changes outside the assigned checkout.

### Tasks

#### Checks match the change

Was: A small change could require an unrelated test suite or a command the runner could not use.

Now: Cassy selects a runnable check for the affected tests and configuration, without inventing test obligations for packages with no tests.

#### Full task details stay visible

Was: Asking for a full task could return only QA information.

Now: The response keeps task instructions, acceptance criteria and delivery details even when the QA information has an error.

## Under the hood

### Four runtime repairs

#### Interrupted task ownership and checkpoints

Was: Session teardown cleared ownership and reopened started assignments.

Now: Started tasks stay Blocked off the ready queue until a successor recovers and adopts the branch. Unstarted assignments still release.

#### Shared shell interpretation

Was: Credential, workspace and Git checks interpreted arguments and working directories separately.

Now: All three use the same working directory and values, including child-shell variable scope.

#### Runnable checks and honest failures

Was: Config files, JSON reads and fixtures could select unrelated tests. A nonzero exit or an unrun test could look like an assertion failure.

Now: Gate and runner use one scope: JSON case generation needs whole-file proof; test-time reads do not. Fixtures use their own config. Missing runs and exit failures differ. Literal `as const` rows are named; otherwise the spec runs five times. Playwright setup dependencies are allowed.

#### Complete MCP reads

Was: Structured `full=true` responses could replace the task body with QA information.

Now: `text` stays complete alongside QA fields, even when malformed QA input returns a diagnostic.
