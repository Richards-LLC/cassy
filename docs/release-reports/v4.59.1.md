## What you can do now

### Sessions

#### Fresh macOS installations show setup guidance

Was: the v4.59.0 installer could finish on a fresh Mac, but bare `cas` stopped with G-150 instead of showing how to get started.

Now: bare `cas` shows the setup hint on a fresh Mac. The v4.59.1 hosted job observed the hint after installing the published Apple Silicon archive and starting a fresh login shell.

Source: [v4.59.0 hosted install run](https://github.com/Richards-LLC/cassy/actions/runs/45922628695) and [v4.59.1 macOS job](https://github.com/Richards-LLC/cassy/actions/runs/45945916234/job/140330463682). These are separate runs; the older failure remains on record.

## Under the hood

### First-run detection

#### Distinguish signing setup from Cassy configuration

Was: the installer could create `~/.cas/macos-signing` before any project was configured. The first-run check treated that directory alone as state and tried the configured launch path.

Now: a lone real signing directory in `~/.cas` no longer marks the installation as configured. Project state, other global entries, symlinks and unreadable state are not treated as a fresh installation by this exception.

Source: [landed classifier repair](https://github.com/Richards-LLC/cassy/commit/34fc23f7e4) (`cas-17ef`, assembled by `cas-30cb`). This changes first-run detection, not the installer or the launch smoke checks.
