Harness

  • Commit 27829c400e02e0874e13a8817b4b7dba3a8af556; Rust 1.95.0; test profile.
  • Six labels: two lexical, two semantic paraphrases, two structural bindings; three lexical distractors per label.
  • Prompt sizes: 1, 8, 32, 72, 1,000, and 10,000 candidates.
  • Scope negatives: foreign project, foreign team, and owner-unprovable private rows.
  • Excluded: live provider latency/cost, live semantic-cache quality, daemon freshness, and numeric comparison to current SessionStart.

Results

Recall quality

BM25-only found both lexical labels in the top three and ranked the remaining four targets fourth. Fusion ranked every target first. The margin comes from paraphrase and structural binding; lexical labels did not regress.

Prompt overhead and repetition

Supervisor overhead measured 5,085 B p50, 5,087 B p95, and 5,087 B p99. The 10,000-candidate case stayed bounded through fixed caps, 320-character snippets, reserved disclosure space, and hard truncation. Revision-aware ledger tests suppress unchanged cards and re-inject changed revisions as deltas.

Isolation and fallback

Foreign scope rows and owner-unprovable private rows were rejected. Logged-out fallback opened only existing SQLite read-only, made no provider call, and created no code-vector directory. Card injection did not increase memory count.

Where the loser wins

BM25-only is cheaper for exact lexical lookup when semantic capability is absent: it needs no provider, vector cache, or query embedding. Fusion wins on paraphrase and structural binding. This checkpoint does not yet carry a live authenticated receipt for one shared query vector across knowledge, history, and code.

Threats to validity

  • Six deterministic labels establish ranker behavior, not population quality.
  • Semantic scores are fixture inputs, not a provider/model measurement.
  • Prompt percentiles are enforced byte overhead using a conservative four-bytes-per-token estimate.
  • Current SessionStart and authenticated live-provider baselines remain unmeasured.
