Harness

  • Code basis: authenticated harness commit 09b71cf3; runtime replay checkpoint b982bbd9; Rust 1.95.0, test profile, one test thread.
  • Fixed evaluation: six labels—two lexical, two semantic paraphrases, two structural bindings—with three lexical distractors per label.
  • Prompt sizes: 1, 8, 32, 72, 1,000, and 10,000 candidates; snippets exceed the 320-character card cap.
  • Live run: freshly migrated temporary git project with one Knowledge page, one History commit, and public/private Code symbols. The configured cas-cloud/cas-embed-v1 capability was read in place; no credential was copied or printed and the live project store was not mutated.
  • Held constant: query construction, scope gate, role policies, evidence schema, deterministic ordering, caps, omission disclosure, and ledger behavior.
  • Current SessionStart was not replayed numerically. The fixed corpus compares BM25-only with fusion; the live corpus validates production transport, scope, and ranking.

Results

Recall quality and bounded context

BM25 found the two lexical labels in its top three and placed the other four targets fourth. Fusion ranked all six targets first; the margin came from paraphrase and structural binding, with no lexical regression.

Supervisor overhead measured 5,085 B p50 and 5,087 B p95/p99, 2,113 B below budget. The 10,000-candidate and ~750k-token-style cases remained bounded. Unchanged evidence revisions were suppressed; changed revisions reappeared as deltas.

Authenticated semantic runtime

The isolated daemon drain embedded four units in three provider requests and reached pending_after=0 in 834 ms. It left an error-free History embedding attempt at 2026-08-08T21:54:50.224939958Z and error-free Code scan state at 2026-08-08T21:54:49.650311285Z. Cache counts were Knowledge 1, History 1, isolated Code 2.

Two role events issued exactly two provider requests. The worker event took 247 ms and ranked Code:sym-live first; the warm-local-cache supervisor event took 270 ms and ranked the History commit first. Both contained all three surfaces. sym-private-live was absent, proving scope filtering before comparison.

Cost, isolation, and fallback

The provider exposes neither billed tokens nor price. The honest receipt is 3 drain requests for 4 units plus 2 query requests for 2 events. Dollars remain formula-only:

one query-event dollars = (T_query / 1,000,000) * P + Q
run dollars = (T_drain / 1,000,000) * P + 3Q + 2 * one query-event dollars

P is dollars per million billed input tokens and Q any per-request charge; neither is published. Adversarial fixtures reject foreign/project/team/private rows. Logged-out fallback uses existing SQLite read-only, creates no vector cache, and makes zero provider calls. Cards never become memories; nested internal-model and irrelevant transitions create no ambient activity.

Where the loser wins

BM25-only is cheaper for exact lexical lookup or provider-absent operation because it needs no network request or vector cache. Fusion wins on paraphrase and structural binding. This run proves one request per semantic event, not free semantic lookup; no query-vector cache is claimed.

Threats to validity

  • Six labels establish deterministic behavior, not population quality; current SessionStart was not numerically replayed.
  • Live latency/freshness are single observations, not percentile distributions.
  • The four-unit live corpus isolates namespace, role, scope, and call counts; large-corpus prompt bounding is separate.
  • Prompt percentiles are byte overhead with a conservative four-bytes-per-token boundary.
  • Provider billing fields are absent. Requests, units, latency, and queue state are measured; dollars are formula-only.
