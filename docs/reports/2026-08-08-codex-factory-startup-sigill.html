Incident report · 2026-08-08

Codex factory startup crashed on an AVX-512 instruction

CAS 2.54.0 · Codex CLI 0.147.0 · x86_64 Linux without AVX-512

High impact Fix and gates committed 2.54.1 published and runtime-verified

Resolved with published-artifact proof. A native Zig build of the statically linked Ghostty VT library inherited the release runner's CPU features. The distributed CAS executable contained an unguarded AVX-512 instruction and received SIGILL on a supported x86_64 host without AVX-512. CAS 2.54.1 pins the target baseline; its official archive gate passed, and the downloaded release reached READY and SYSTEM READY on the affected host.

Impact

cas codex could not start a new Codex factory on the affected machine. Startup reached Spawning agents, the CAS daemon terminated, and the client reported [ERROR] Session '<name>' not found or not running. Repeated retries failed in the same phase.

The failure was inside the installed CAS 2.54.0 binary, not the standalone Codex CLI. Direct Codex startup, codex doctor, authentication, and network connectivity passed. An already-running factory was unaffected. The confirmed host is an Intel Core i9-13900K x86_64 Linux machine with AVX/AVX2 but no AVX-512.

Measured window: 17 minutes 35 seconds from the first retained failure at 21:49:57 EDT to the portable release build at 22:07:32 EDT. The exact onset and external blast radius remain unknown; this number is the observed diagnostic window, not a claimed total outage duration.

The immutable v2.54.1 replacement was published at 23:06:56 EDT. Its downloaded Linux artifact was installed on the same AVX-512-absent host, where a fresh Codex factory reached READY and SYSTEM READY and remained registered and attachable. The v2.54.0 tag and assets were not changed.

Root cause

Failure chain

  1. ghostty_vt_sys/build.rs used Zig ReleaseFast to build the statically linked Ghostty VT library.
  2. The Zig project uses b.standardTargetOptions; an explicit -Dtarget defines the portable target baseline.
  3. The prior Rust helper returned no mapping when Cargo target matched the build host, so native release builds omitted -Dtarget.
  4. Zig optimized for the release machine. The shipped CAS executable contained an unguarded AVX-512 instruction from Ghostty VT.
  5. Codex 0.147.0 startup output exercised that terminal-processing path on a host with AVX2 but no AVX-512.
  6. The CPU raised SIGILL. The daemon vanished before normal Rust/CAS error handling, leaving only the secondary client disconnect.

The fix always maps supported Cargo targets to Zig targets, including native builds. The mapping now lives in crates/ghostty_vt_sys/build_support.rs, is called from build.rs:79, and is covered by tests/portable_target.rs.

Trigger versus cause: Codex 0.147.0 exercised the bad library path and was newer than the validated 0.146.0 harness. The correctness defect remained the CAS artifact's missing CPU baseline; valid terminal output must not be able to invoke unsupported machine code.

Alternatives ruled out

  • Bad Codex flags: the same launch shape worked directly under a PTY.
  • Codex authentication/connectivity: doctor checks passed.
  • Recoverable Rust panic: the kernel recorded SIGILL, with no normal panic path.
  • Missing general vector support: the host has AVX and AVX2; AVX-512 was the unsupported boundary.
  • CAS state corruption: replacing only the rebuilt binary restored fresh startup without state repair.

Falsification criteria and remaining uncertainty

The diagnosis should be reopened if an explicitly targeted build contains the same reachable AVX-512 instruction or the published replacement reproduces SIGILL on this host; neither happened. The official release runner passed the bundled-archive ISA gate before packaging. The exact runner CPU was not inspected directly, and the number of other affected users remains unknown; neither uncertainty changes the artifact-level or same-host result.

Why this was not caught

  • Cross builds passed -Dtarget, but the common native release path silently selected build-host features.
  • No regression test required native Cargo targets to map to explicit Zig targets.
  • Release validation neither audited the native archive for out-of-baseline instructions nor ran the artifact with AVX-512 masked.
  • CAS had validated Codex 0.146.0. Preflight warned that installed 0.147.0 was stale but appropriately did not treat version drift alone as incompatibility.
  • Direct Codex version/startup/doctor checks do not execute CAS's Ghostty terminal-processing path.
  • SIGILL bypassed normal panic reporting, so the user saw only a daemon-disconnect consequence until a core dump was inspected.

No individual action caused the outage. The build contract and release portability gates did not define or enforce a distributed CPU baseline.
