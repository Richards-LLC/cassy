WikiSkill vs CAS: what the paper validates, and the three mechanisms it says we're missing

2026-08-29 · factory supervisor session · audience: practitioner · paper: Tang et al., WikiSkill: Compiling Agent Experience into Persistent Knowledge for Skill Evolution, Google Research, arXiv:2608.27454v1 (2026-08-27) · CAS surveyed at cas-src working tree @ f9692472

Verdict. WikiSkill independently validates the architecture CAS already has — raw experience → compounding knowledge → executable skills — and CAS is ahead of the paper on pruning and knowledge-page provenance. But the paper's measured results indict exactly the three mechanisms CAS lacks:

① measured validation gating on skill/rule changes (CAS promotes Draft→Proven on a single self-reported tool call) — ② immutable trace retention (CAS hard-deletes raw experience at 30 days) — ③ experience→skill provenance (CAS's link is a free-text tag no code reads).

Confidence: high on the CAS side (code survey, file:line verified). The paper's numbers are benchmark results; transfer to open-world dev work is argued, not proven — see caveats.

The paper in one screen

WikiSkill structures an agent workspace as three layers — an immutable raw layer of execution traces, a compounding wiki layer (pattern pages, an evolution log, a programmatically-maintained per-skill impact tracker) that is never reset, and an active skill layer where each skill carries a PURPOSE.md pointing at the wiki patterns that motivated it. Four components loop: Inference Agent (runs tasks, sees skills, denied wiki access), Wiki Maintainer (root-cause analysis over a stratified sample of ≤8 traces: ≤5 failing, ≤3 passing, 15k chars each), Skill Proposer (ReAct agent reading wiki index + impact history + outcomes; one atomic proposal per iteration), and Gating & Rollback (accept only if the measured validation score improves; skills roll back, the wiki never does).

The five sharpest findings

  1. One self-reported call promotes a rule to Proven. cas_rule_helpful (cas-cli/src/mcp/tools/core/rules.rs:39-75): a single rule action=helpful flips Draft→Proven and immediately syncs the rule to .claude/rules/ for every future session. No threshold, no second party, no measurement. harmful increments a counter and never demotes (rules.rs:191-216). The paper's equivalent decision requires a measured validation improvement — worth +15pts in its ablation.
  2. The skill validation schema is inert. Skill.validation_script, preconditions, postconditions (crates/cas-types/src/skill.rs:204-218) survive migration and round-tripping and are never executed or evaluated anywhere in the tree. WikiSkill's essential gate exists in CAS as three dormant columns.
  3. The only true measurement loop is firewalled from every decision that matters. retrieval_outcomes (used/helpful/ignored/corrected/harmful; append-only; privacy-hashed) is well-engineered — and by explicit design (crates/cas-store/src/retrieval_store.rs:1-6) "never mutates entry/rule counters or global search weights." Its entire effect is a ±0.20-clamped nudge to ambient-recall ranking (ambient_recall.rs:2178-2191). Promotion, demotion, injection order, and learning review consume none of it.
  4. No rollback exists for any knowledge artifact. Rules, skills, memories all update via destructive in-place UPDATE; the reviewer prompt says "archive" where the code does hard DELETE (rules.rs:219-232 vs .claude/agents/rule-reviewer.md:28). WikiSkill's loop is safe to run autonomously because every skill change is reversible and every proposal outcome is logged.
  5. Provenance is destroyed at every merge point. Consolidation (daemon/decay.rs:129-166) archives sources and writes a fresh merged entry with no link back; learnings derived from observations carry no source ids (daemon/observation.rs:52-59). The paper's case study shows the cost: its proposer avoided re-trying a rejected skill idea only because the audit trail recorded the rejection.

Where CAS is ahead

  • Pruning and lifecycle — decay, tiering, consolidation, dedup: the paper's named open problem, solved in CAS.
  • Knowledge-page provenance engineering — per-fragment source markers with a forgery threat model (knowledge/merge.rs:232-268), cascade deletes, tombstones, locked pages. Stronger than anything in the paper — it just points at files, never at experience.
  • A real immutable gate exists — for task closure. The verification subsystem (verification_store.rs, external gates, audit rows) is precisely WikiSkill's gating discipline, aimed at delivery instead of knowledge artifacts.
  • Cross-harness skill distribution. Table 2's transfer results empirically support shipping identical skills to Claude/Codex/Grok — with the paper's caveat that model-specific workarounds can transfer negatively.

Caveats

WikiSkill runs on benchmarks with ground-truth scoring and train/val/test splits. CAS works open-world with no oracle: "measured validation" must be proxied (verification verdicts, test outcomes, friction_score, retrieval outcomes) and proxies inherit the self-report problem. Full skill injection is the paper's confound-avoidance choice, so its acceptance numbers don't transfer directly to CAS's budgeted injection. And the −2.8pt Inference-Agent result concerns skill-development trajectory quality — it is not an argument against ambient recall for immediate task success.
