Root cause

→
Writer JSON-encodes an already-encoded deliverables value → string, not struct (cas-6980)
→
That session pushes the stringified rows to the team cloud
→
Every client pull rejects the 98 rows; partial results forever

The client's refusal is correct behavior; the gap is that the corruption reached the cloud at write time and pulls only report it as a per-run warning.
