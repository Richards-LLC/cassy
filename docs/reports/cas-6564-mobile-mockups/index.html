How A → B → C fit together

  1. A is the front door. The phone opens on the list of things that want a decision — not on a fleet, a session, or a terminal.
  2. Tapping an item lands in B. "Show me zen-eagle-20" is that agent's card, with its peers one swipe away.
  3. C is not a fourth screen — it is the composer for both, reachable from the bar at the bottom of A and the Talk button on every B card.
  4. A still works when the terminal does not. The quoted excerpt carries the decision, so a dead renderer (D3) costs you detail, not the answer.
  5. B is the answer to D15. A reflowed tail is legible at phone width; a 46-column ANSI grid is not, at any size the 12–16px clamp allows.
  6. C is the answer to D4. Voice never opens the keyboard that destroys the layout, and it is the only input that works while walking.
  7. Sequence: A, then B, then C. A runs against today's attention feed; B needs a logical-line tail; C is the only one needing new backend, so it must not gate the first two.
  8. None of this is the 53rem media query. Each direction starts from a different answer to "what is the primary object on this screen?", which is the one thing a narrower column cannot change.

What each state costs to build

Three tiers: client only is composition and CSS against data the hub already broadcasts; needs hub data means an existing payload has to carry more; needs new backend means a capability that does not exist yet. Every state that needs more than the client carries a needs hub: … tag drawn on the mock-up itself.

What these are made of

Tokens, verbatim

Every colour, size, radius and spacing step is copied from the :root block of hub-web/src/styles.css and consumed through var(...) — the same discipline DESIGN.md requires of the app. Cards use 12px padding and 6px radii, panes 8px, pills 999px; type stays on the 11 / 12.5 / 13.5 / 15 / 18px ramp; no weight goes above 600; saturated colour appears only as state.

Live data, not placeholders

The fleet shown is the one running on this machine on 2026-09-03: supervisor fast-kestrel-6 with zen-eagle-20, brave-raven-22, sharp-heron-50, golden-parrot-30 and fair-hound-98, against real task IDs cas-dc93, cas-0d61, cas-8b59, cas-67b6. Attention kinds (pane_exited, awaiting_merge) are real entries in MACHINE_EVENT_TEMPLATES; blocked_question is not, and is tagged on the mock-up as needing the hub.

Two honest caveats

  • Light theme is a proposal. Commander is dark-only today: one :root ramp under color-scheme: dark. The light column here is a derived ramp with the state colours darkened for contrast on white — it is a design question to settle, not an existing surface.
  • Terminal wells stay dark in both themes. Machine output is the deepest layer, and the Ghostty ANSI palette is deliberately independent of the application tokens, so the terminal foreground does not flip with the theme.
