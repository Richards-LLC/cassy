### [P3] `cas claude login` creates the credential directory with default perms and unvalidated name
`cas-cli/src/cli/claude.rs:405` — autofix: manual, confidence: 0.6, requires_verification: False

**Why it matters:** `execute_command` calls `std::fs::create_dir_all(&profile_dir)` (mode 0777 & ~umask, typically 0755) for a directory this change designates as the fallback OAuth credential store (`<secure-storage-dir>/.credentials.json`, per the new module doc). On a shared host other local accounts can traverse into it, leaving token confidentiality entirely to Claude Code's own file mode. Separately the profile name is interpolated unvalidated -- `resolve_profile_dir` builds `home.join(format!(".claude-{profile}"))` -- so a name containing `/` or `..` (e.g. `cas claude login x/../../../tmp/creds`) makes `create_dir_all` and the credential store escape the intended `~/.claude-*` layout. The invoker is the local operator or an agent acting for them, so this is hardening rather than a crossed trust boundary.
**Suggested fix:** Reject profile names that are not `[A-Za-z0-9._-]+` (and not `.`/`..`) before resolving the directory, and create the profile directory with mode 0700 on Unix (`std::fs::DirBuilder` + `PermissionsExt::mode(0o700)`).
**Evidence:**
- cas-cli/src/cli/claude.rs (diff) `ClaudeCommand::Login` arm: `std::fs::create_dir_all(&profile_dir).with_context(...)` with no mode restriction
- cas-cli/src/cli/claude.rs:57-63 `resolve_profile_dir`: `home.join(format!(".claude-{profile}"))` -- no rejection of `/`, `..`, or empty names
- cas-cli/src/cli/claude.rs (diff) module doc: "Claude Code falls back to `<secure-storage-dir>/.credentials.json` when Keychain is unavailable" -- the directory holds a long-lived refresh token
