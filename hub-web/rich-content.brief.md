# Brief: Commander rich content

## Single idea
A supervisor can show the evidence directly in its conversation, with readable source and the original file one action away.

## Hero form
Annotated flow: the diagram sits inside its existing reply bubble, and Diagram source unfolds directly beneath it; attachment previews sit above the dog-eared file sheet.

## Emotional register
Calm and inspectable: existing Glass reading surfaces, house type, restrained diff backgrounds and visible source controls.

## Distinctive move
The existing dog-eared attachment sheet becomes the caption to a reserved media viewport, preserving the file's name and Open action.

## Deliberately omitted
No extra toolbar or syntax-highlighter palette: the conversation stays the reading surface and the renderer loads only for rich content.

## Critique

Strict visual QA: four captures, 1280×800 and 390×844, light and dark; zero findings. Diagram text, source and diff controls, image viewport and the file caption all fit above the composer. The actual transport, PDF pixels and native playback are checked separately in HUB-J22.

| Dimension | Score | Evidence |
| --- | --- | --- |
| Distinctiveness | 4 | Glass surfaces and the existing dog-eared file caption make the evidence read as Commander. |
| Fit | 5 | Diagram, source, diff and original file are all reachable in the thread. |
| Hierarchy | 4 | Bold outcome, diagram, then quiet inspection controls; media reads above its caption. |
| Craft | 4 | Reserved dimensions, lazy line DOM, bounded diagram rendering and per-type chunks. |
| Accessibility | 4 | Semantic details controls, diagram source, native playback controls and image/PDF alternatives. |

## Delivery boundary

The normal HUB-J22 walk serves this checkout's committed dist through the existing static journey server. The supervisor supplies a registered candidate hub for `playwright.rich-content-hub.config.ts`; that repeats the same journey against embedded `/commander/chunk-*` assets. Hub protocol and artifact storage remain doubled in both runs, with real media decode and playback.
