# Brief: reload beside the supervisor version

## Single idea

When the installed Cassy is newer, the supervisor card puts Reload Cassy beside the evidence that needs it.

## Hero form

An inline action beneath the supervisor row names the repair without opening a menu. The existing conversation-header command menu keeps the same session actions reachable when versions already agree.

## Emotional register

Commander Glass stays calm: existing action ink, control spacing and named radii, with plain receipt sentences instead of a new warning panel.

## Distinctive move

The action and its queued, submitted or observed receipt stay with the exact supervisor and machine. The version badge changes only when the catalog reports the replacement process.

## Deliberately omitted

No new server command, daemon relaunch, guessed success, polling owner or second reload protocol. Unsupported harnesses name Claude Code; the shared command controller owns permissions, control and outcome.

## State and access

Reuse the card's observed MCP/installed versions from factory_binary_skew. Card controls are siblings of the navigation button, never nested buttons. The existing header menu exposes session actions; a skewed card shows its Reload Cassy action directly. Ordinary cards add no action line or extra Tab stop. Keyboard users reach Reload Cassy through the header menu; the direct pointer shortcut is outside sequential Tab navigation. Keep keyed controls and focus across catalog refreshes. Pending requests are bound to the selected session birth and cancelled on selection change or failed attachment. Both card and typed /mcp use the existing mcp command and receipt. The application requires JavaScript for authenticated session control; existing print and reduced-motion behavior applies.

## Header and receipt follow-through

The header slash button opens the same palette directly below itself, inside viewport bounds, with Escape returning focus to the opener. Typing stays attached to the composer. Completed/refused receipts replace pending text; Dismiss command status hides the presentation without cancelling a command or allowing a concurrent mutation. A later accepted retry removes its earlier refused busy row.

## Validation

Extend keyed card coverage for skew/current/unknown versions, supported and unsupported harnesses, receipt phases and stable focus. Preserve and extend typed /mcp coverage; extend the existing HUB-J27 reload journey at desktop and phone to use both card and composer, assert no chat send, and wait for actual observed receipt/catalog evidence.

## Critique

Reviewed production captures at 1280×800/light and 390×844/dark. Strict visual QA inspected the actual card and open dropdown DOM in both schemes at each viewport: PASS, zero findings, no allowlist. This application requires JavaScript for authenticated machine control; its existing declaration and noscript explanation remain.
